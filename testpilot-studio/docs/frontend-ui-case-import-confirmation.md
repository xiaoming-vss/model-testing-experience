# 已审核 UI 候选用例导入正式套件：前端适配确认稿

## 1. 文档状态

- 状态：已确认；正式规格见 `docs/specs/ui-approved-candidate-import.md`
- 范围：已审核 UI 候选用例导入已有 UI 测试套件
- 当前阶段：确认稿已转规格并完成实施
- 前置能力：UI 用例生成任务、源码 ZIP 上传、运行记录、候选 YAML 编辑和人工审核已经存在

## 2. 当前实现核查

### 2.1 页面与路由

- UI 用例生成任务详情路由为 `/ai-testing/ui-tasks/:taskId`。
- 当前没有独立的运行详情页或审核结果页；任务详情页同时包含任务信息、源码包、运行记录和所选运行的候选结果。
- 候选结果卡片已经支持结构化预览、YAML 编辑、保存、批准、拒绝和审核后只读。
- 审核通过后目前只显示“待导入”标签，没有导入按钮、套件选择或冲突确认。
- 正式 UI 套件详情路由为 `/ui-automation/suites/:suiteId`。

### 2.2 API 封装

已经存在并可复用：

- `GET /v1/requirements/{requirementId}/ui-test-suites`
- `GET /v1/ui-test-suites/{suiteId}/cases`

尚未封装：

- `POST /v1/ui-case-generate-task-runs/{runId}/import`

现有 UI 套件 YAML 文件导入接口 `/v1/ui-test-suites/{suiteId}/import` 与本需求不是同一流程，不应复用为候选导入请求。

### 2.3 类型定义

`UiCaseGenerateTaskRun` 已经包含：

- `importStatus`
- `importedTargets`
- `importedAt`

通用导入目标类型已经允许 `targetType="ui_suite"`。

仍需补充：

- UI 候选导入请求类型
- 导入结果类型
- 冲突用例类型
- 可保留未知字段的步骤类型

当前正式 UI 用例类型将 `stepsJson` 声明为字符串，但本次冲突响应中的 `stepsJson` 是结构化步骤集合。冲突响应应建立独立类型，不强行套用现有正式用例编辑类型。

### 2.4 状态管理

- 服务端状态使用 React Query 管理。
- 所选运行、弹窗、目标套件、冲突和加载状态适合保留为页面局部状态。
- 导入成功后可通过 `setQueryData` 立即更新所选运行，并同步更新或失效运行列表查询。
- 当前运行详情只对执行中状态持续轮询；已完成、已审核运行不会持续轮询。

### 2.5 导入目标契约核查

- API、功能和 UI 生成运行统一以 `importStatus`、`importedTargets`、`importedAt` 和 `importMigrationComplete` 表达正式资产导入状态。
- `importedTargets` 始终按数组处理；API/UI 各解析对应目标类型，功能流程支持展示多个功能套件目标。
- 审核批准与正式资产导入相互独立，不从 `reviewStatus` 推断导入结果。
- 运行类型和页面不保留单一导入目标兼容分支。

### 2.6 测试现状

- UI 任务详情测试已经覆盖运行状态、候选保存、批准、拒绝、只读和权限错误。
- 现有测试明确断言拒绝或审核后的页面不出现导入入口，这是上一阶段“不实施导入”的要求；本次实施时需要按新范围调整。
- 当前没有 UI 候选导入请求、套件选择、冲突预览、覆盖确认或导入错误重试测试。

### 2.7 文档冲突

以下现有文档明确将 UI 候选导入列为范围外或后续能力：

- `docs/specs/ui-case-ai-generation-source-archive.md`
- `docs/functional-specification.md`
- `docs/system-design.md`

本需求是对原范围的后续扩展。实施完成后应更新这些文档，不能保留“页面不提供导入能力”的旧结论。

## 3. 已确认产品与交互决策

### 3.1 导入入口与资格

- 导入入口只位于所选运行的候选结果卡片中。
- 运行记录表不提供重复的快捷导入按钮。
- 仅当以下条件全部满足时显示可用导入按钮：
  - `status === "success"`
  - `reviewStatus === "approved"`
  - `importStatus === "pending"`
- 未成功或未审核通过时隐藏导入按钮。
- 已导入时不再显示导入按钮，改为展示导入状态、时间、目标套件和“查看正式套件”。
- 未知导入状态只读展示并禁止导入。
- 运行记录表增加只读“导入”状态列。

### 3.2 目标套件选择

- 点击导入按钮后打开独立弹窗。
- 弹窗使用支持输入筛选的搜索下拉框。
- 只查询并展示该运行所属需求下的已有 UI 套件。
- 不支持跨需求搜索、手工输入 `suiteId` 或在弹窗内创建套件。
- 归属权限由后端最终校验，403 不作为普通表单错误。
- 实现时优先使用运行的 `requirementId`；缺失时允许回退任务当前的 `requirementId`，不额外处理历史需求变更风险。

### 3.3 首次导入

- 首次提交发送：

```json
{
  "suiteId": "<suiteId>",
  "confirmOverwrite": false
}
```

- 请求期间禁用导入和弹窗操作，防止重复提交。
- `requiresConfirmation=false` 时按成功处理。
- `requiresConfirmation=true` 时不显示成功提示，进入冲突预览。

### 3.4 冲突预览

- 冲突弹窗展示全部冲突，不只展示第一项。
- 多冲突使用可折叠列表，默认展开第一项，其他冲突标题始终可见。
- 标题展示序号、候选名称和规范化名称。
- 桌面端采用“现有正式用例 / 已批准候选用例”左右并排对比，窄屏自动改为上下排列。
- 每个冲突完整展示 `name`、`enabled`、`orderNo` 和 `stepsJson`。
- 弹窗底部固定整批确认操作区。
- 取消只关闭冲突弹窗，不发送第二次请求，也不改变审核状态。

### 3.5 字段可读化与未知字段

- `enabled` 显示为“启用 / 禁用”状态标签。
- `orderNo` 显示为“排序号”，缺失时显示 `—`，不补默认值。
- 已知步骤字段按步骤表格展示，每行一个步骤：
  - `orderNo`
  - `stepName`
  - `keyword`
  - `locatorType`
  - `locatorValue`
  - `operationValue`
  - `continueOnFailure`
  - `enabled`
- `continueOnFailure` 显示为“失败后继续 / 失败即停止”。
- 空字符串、`null` 和字段缺失分别展示，不能合并为同一种空值。
- URL、定位值和操作值使用可换行的等宽文本，完整展示而不截断。
- 每个步骤增加“其他字段”JSON 区域，展示未识别的键值。
- 提供“查看完整原始 stepsJson”折叠区。
- 冲突数据只读展示，前端不重组后再提交，未知字段不得丢失。

### 3.6 确认覆盖

- 后端只支持整批覆盖，前端不提供逐项勾选、跳过或部分导入。
- 确认请求必须复用预览时的同一 `suiteId`：

```json
{
  "suiteId": "<same-suiteId>",
  "confirmOverwrite": true
}
```

- 确认按钮文案明确为整批覆盖，并提示同名用例原位覆盖、非冲突候选同时新增、任一失败整批回滚。
- 确认请求期间禁用确认与取消按钮。
- 如果确认请求仍返回 `requiresConfirmation=true`，使用最新响应替换冲突内容，提示冲突已经变化，并要求用户再次人工确认；不得自动连续提交。

### 3.7 成功状态

- 成功后留在当前 UI 生成任务详情页。
- 立即使用响应中的 `run` 更新所选运行。
- 同步更新运行列表中的导入状态。
- 显示成功反馈、`importedAt` 和 `ui_suite` 目标。
- 禁止同一运行再次导入。
- 提供“查看正式套件”按钮，跳转 `/ui-automation/suites/{suiteId}`。
- 当前生成详情页不展示正式用例，因此成功后不在本页请求 `/v1/ui-test-suites/{suiteId}/cases`；正式套件详情页负责加载最新用例。
- 正常后端响应应满足所有成功字段约束。本次不增加专门的异常响应告警；只要 `importStatus="imported"` 就禁止再次导入，其他信息存在则展示。

### 3.8 失败、取消与重试

- 当前页面会话内按运行记录保留最近选择的 `suiteId`。
- 400、403、404、500 后保留选择并允许重试。
- 取消冲突覆盖后也保留选择。
- 刷新或离开页面后不持久化选择。
- 套件重新查询后若原选择不存在，则清除并提示重新选择。
- 套件列表查询失败在选择弹窗内展示阻断错误。
- 首次导入失败在选择弹窗内展示错误。
- 覆盖确认失败在冲突弹窗内展示错误，并保留全部冲突内容。
- 403 使用明确权限提示。
- 404 区分运行或套件不存在，并刷新运行和套件列表。
- 400 保留后端业务提示。
- 500 提示服务端导入失败、没有完成写入，并允许原地重试。

### 3.9 并发导入

- 不对已完成运行增加持续轮询。
- 打开导入弹窗前重新查询运行详情。
- 页面重新获得焦点、用户手工刷新时刷新状态。
- 提交返回“已经导入”的 400 后重新查询运行详情。
- 若刷新后为 `imported`，关闭导入和冲突弹窗，提示该运行已由其他操作完成导入，并展示只读成功状态。
- 若刷新后仍为 `pending`，按普通 400 展示并允许重试。

## 5. 测试确认范围

前端自动化测试至少覆盖：

1. 非 `success + approved + pending` 运行不提供可用导入入口。
2. 套件只按运行需求查询，空列表和查询失败正确展示。
3. 无冲突首次导入成功，立即更新运行详情和列表状态。
4. 冲突首次请求不调用正式用例写接口，并展示全部冲突。
5. `name`、`enabled`、`orderNo`、全部已知步骤字段和未知字段完整展示。
6. 空字符串、`null` 和字段缺失正确区分。
7. 取消冲突不发送确认请求，审核状态保持 approved，之后仍能重试。
8. 确认覆盖使用同一 `suiteId` 和 `confirmOverwrite=true`。
9. 确认请求返回新冲突时刷新内容并要求再次确认。
10. 成功后不能再次导入，并可跳转正式套件。
11. 400、403、404、500 在正确交互上下文展示并允许适当重试。
12. 失败和取消后保留当前页面会话中的套件选择。
13. 页面打开期间被其他操作导入后能刷新为只读成功状态。
14. UI 流程只根据新导入生命周期字段判断资格和展示目标。
15. 请求期间按钮禁用，避免重复提交。

“覆盖后正式用例 `caseId` 保持不变”由后端集成测试负责。前端契约测试验证浏览器只调用运行导入接口，不通过删除、重建或修改正式用例实现覆盖。

## 6. 不在本次范围

- 自动创建 UI 测试套件。
- 跨需求选择目标套件。
- 逐项选择、跳过或部分覆盖冲突。
- 在生成详情页展示完整正式用例列表。
- 为验证 `caseId` 而额外查询导入前后的正式用例。
- 改造 API 或功能生成流程之外的独立业务工作流。
- 对已完成运行增加持续轮询。
