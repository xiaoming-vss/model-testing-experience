# UI 用例 AI 生成与源码包上传——前端适配确认稿

> 状态：需求审查中，待逐项确认后制定实施计划
>
> 本次范围截止到候选结果编辑与审核；不接入正式资产导入。

## 0. 已确认决策

1. 运行请求以当前 Swagger 为准：本次只发送 `connectionId`，不展示或发送“本次运行补充指令”。待后端在 `AiGenerateTaskRunRequest` 中正式加入 `instruction` 后再扩展。
2. UI 生成任务加入当前 API、功能任务共用的统一任务列表，并启用“新建任务 > UI测试”入口；不恢复旧的独立 UI 标签页/列表。
3. 新建 UI 生成任务时就在创建抽屉中选择 ZIP 源码包；不采用“先创建空任务，再由用户进入详情手动选择文件”的主流程。
4. 若任务创建成功但紧随其后的源码包上传失败，保留已创建的空任务并进入详情展示错误、允许重试；前端不自动删除任务。
5. 创建表单中的源码 ZIP 为必选项；未选择、非 `.zip` 或超过 100 MiB 时不允许提交创建请求。无源码包任务只可能来自第二阶段上传失败等异常情况。
6. 创建请求完成后进入 UI 任务详情页：上传成功时继续选择 LLM 并运行；上传失败时在同一详情页展示错误并补传。
7. 创建和编辑 UI 任务时，任务名称、所属迭代、所属需求必填，生成指令可选；空指令交由后端默认生成策略处理。
8. 替换已有源码包需要二次确认，确认界面展示当前文件名和新文件名，并说明替换失败时原源码包仍有效；无源码包任务首次补传不需要确认。
9. 当任务存在 `pending`、`claimed` 或 `running` 的运行时，禁止替换源码包，并提示等待当前运行结束，以避免源码版本竞态。
10. 已存在审核完成的历史运行时仍允许替换源码包；替换只影响后续新运行，不修改历史运行及其候选结果。
11. 候选结果采用“预览候选 / 编辑 YAML”双标签：预览按 UI 用例和步骤结构展示，编辑页保留完整 `resultYaml`；后端继续负责最终结构校验。
12. `status=success` 但 `resultYaml` 为空或仅含空白时不允许批准或拒绝，并提示当前运行没有可审核的候选结果。
13. 查询任务列表、任务详情或运行详情遇到 403 时显示阻断式无权访问状态并隐藏业务内容；创建、修改、删除、上传、运行、保存或审核遇到 403 时保留当前安全状态和用户输入，在当前操作区显示明确权限错误。
14. 创建后的源码包上传失败并进入详情时，仅通过临时页面导航状态保留所选 ZIP 以便立即重试；刷新后要求重新选择，不将文件写入全局 store、持久化存储或查询缓存。
15. 本次源码包上传只显示整体上传中状态并禁用重复提交，不新增 XHR 或其他字节级上传进度传输层。
16. 实现完成时同步更新产品文档与系统设计，将 UI 生成从占位能力改为已接入，并把旧的三标签任务页描述改为当前统一任务列表。
17. 允许将 `yaml` 声明为前端直接依赖，用于结构化候选预览；解析失败时回退到原始 YAML，保存仍以后端校验为准。

## 1. 已确认的业务边界

1. UI 用例生成任务关联项目、迭代和需求。
2. UI 生成任务的唯一生成来源是 ZIP 源码包，不使用 `sourceContent`。
3. 任务必须先创建，获得 `taskId` 后才能上传或替换源码包。
4. 未上传有效源码包时不能运行。
5. 运行时选择一个可用的 LLM 连接。
6. Worker 可自动读取当前需求文档作为补充来源，前端不选择或冻结需求文档版本。
7. 成功运行产出可编辑的候选 YAML。
8. 候选结果只有在成功且尚未审核时可编辑。
9. 审核动作沿用现有 `approve` / `reject`。
10. 审核完成后候选结果冻结。
11. 审核通过后仍保持 `importStatus=pending`、`importedTargets=[]`。
12. 即使后端和 Swagger 已提供导入接口，本次也不展示导入按钮、不自动导入、不调用导入接口。
13. 浏览器不解压源码包、不读取源码文件内容、不调用 `/internal/ai-worker/**`。

## 2. 当前代码与文档现状

### 2.1 页面结构

- 当前代码中的生成任务页是 API 与功能任务共用的一张统一列表，不是产品文档描述的 API/UI/功能三个独立标签页。
- “新建任务”弹窗中已有 UI 类型，但被禁用并显示“暂未接入创建流程”。
- UI 任务尚无类型、API 方法、创建抽屉、详情页、路由和测试。
- 详情路由目前分别为：
  - API：`/ai-testing/tasks/:taskId`
  - 功能：`/ai-testing/function-tasks/:taskId`
- 产品文档和系统设计仍把 UI 生成标记为占位能力，实施完成后需要同步更新。

### 2.2 可复用能力

- 统一任务列表：任务类型标签、最新运行状态、运行/查看/编辑/删除操作。
- API/功能创建抽屉：迭代选择后加载需求，任务名称和需求校验。
- LLM 选择弹窗：只列出 `status=active` 的连接，空态可跳转基础服务配置。
- API/功能详情页：任务摘要、运行历史、轮询、结果编辑、保存失败保留草稿、批准/拒绝、审核后只读。
- 任务状态映射已包含 `pending`、`claimed`、`running`、`success`、`failed`，也兼容 `error`、`canceled` 和 `waiting_review`。
- 服务端状态由 React Query 管理；弹窗、选中运行、编辑草稿由页面局部状态管理，无需新增全局 store。

### 2.3 API 基础设施

- 通用请求层会注入 Bearer token，并从 `{code,message,data}` 中返回 `data`。
- JSON 和 `FormData` 请求已兼容；`FormData` 不会被错误设置为 `application/json`。
- 非 2xx 或业务码非 0 时抛出包含 `status`、`code` 和后端 `message` 的 `ApiError`。
- 401/业务码 1001 会统一登出；403 当前没有全局页面策略，主要由具体页面或 mutation 展示错误。

### 2.4 本地 Swagger 核验

已从 `http://127.0.0.1:9000/openapi.json` 核验以下用户侧接口存在：

- UI 任务创建、列表、详情、修改、删除；
- 源码包上传；
- 运行、运行列表、运行详情；
- 候选结果修改；
- 候选结果审核；
- 后续导入接口。

上传接口接收字段名为 `file` 的 `multipart/form-data`，返回完整 `AiGenerateTaskResponse`，其中包含 `sourceArchive`。

## 3. 已发现的契约冲突

### 3.1 运行补充指令与 Swagger 冲突

文字契约要求运行请求支持：

```json
{
  "connectionId": "...",
  "instruction": "可选的本次运行补充指令"
}
```

但当前 Swagger 的 `AiGenerateTaskRunRequest`：

- 没有 `instruction` 字段；
- `additionalProperties=false`；
- 只声明 `connectionId`、`llmConnectionId`、`triggerType`、`checkpointEnabled`、`configJson`、`resultYaml`。

因此前端若按文字契约发送 `instruction`，按 OpenAPI 应被视为非法附加字段。这是开始实现前必须确定的契约优先级问题。

### 3.2 创建/修改字段必填性不一致

文字需求明确 `requirementId` 必填，并给出包含 `name`、`sprintId`、`requirementId`、`instruction` 的请求示例。

Swagger 的通用 `AiGenerateTaskRequest` 将所有字段都声明为 nullable 且没有 required 列表。现有 API/功能创建表单则会要求任务名称、迭代和需求；功能任务的生成指令可选。

推荐前端继续执行比 Swagger 更严格的业务校验：名称、迭代、需求必填，生成指令可选。但该规则需产品确认。

### 3.3 页面信息架构不一致

文字流程说“进入项目下的 UI 用例生成任务列表”，产品文档还描述 API/UI/功能标签页；当前代码已改成三类任务共用的统一列表和统一新建类型选择弹窗。

推荐将 UI 任务加入当前统一列表，并启用新建类型选择中的 UI 入口，不恢复旧的独立标签页结构。

### 3.4 403 处理缺少统一定义

需求要求不要把 403 当普通表单校验错误，但当前前端没有全局 Forbidden 页面或 403 路由。现有模式大多是：

- 查询失败：页面级 `Alert`；
- mutation 失败：弹窗内 `Alert` 或消息提示；
- 功能生成页会将 403 文案明确转换为“无权限执行当前操作”。

推荐按场景统一语义，而不是新建全局权限系统：详情/列表查询 403 显示阻断式页面错误并隐藏业务内容；创建、修改、删除、上传、运行、保存、审核的 403 显示明确的权限错误并保留安全的当前页面状态。

### 3.5 现有结构化预览不能解析 YAML

功能生成页现有的结构化候选预览只调用 `JSON.parse`。项目没有直接声明 YAML 解析依赖，因此它无法解析本需求示例中的标准 YAML。若 UI 候选结果要同时提供结构化预览和 YAML 编辑，需要引入受维护的 YAML 解析库作为直接依赖，不能用手写字符串解析器猜测业务结构。

## 4. 推荐的前端结构（待确认）

### 4.1 统一任务列表

- 查询 UI 任务并与 API、功能任务合并排序、分页。
- 增加 UI 类型、来源“ZIP 源码包”和 UI 详情路由。
- 启用“新建任务 > UI测试”。
- UI 任务的列表运行按钮同时受两项约束：没有进行中的运行、已有 `sourceArchive`。
- 无源码包时禁用运行按钮，提示“请先上传源码 ZIP”。

### 4.2 创建/编辑抽屉

- 字段：任务名称、所属迭代、所属需求、生成指令。
- 新建模式增加源码包选择，用户提交前选择 ZIP；编辑模式不在任务字段表单中替换源码包。
- 不展示或提交 `sourceType`、`sourceContent`。
- 保存时前端先创建任务，取得 `taskId` 后再调用源码包上传接口。这是两个独立后端请求，不具备事务原子性。
- 编辑任务不承担源码包替换；源码包只在详情页管理。

### 4.3 UI 任务详情页

建议复用 API 详情页骨架，提供：

- 返回生成任务列表；
- 任务摘要与编辑、删除、运行；
- 独立的“源码包”区域；
- 运行历史和手动刷新；
- 5 秒轮询运行列表与选中运行详情；
- 成功候选的查看、编辑、保存、批准和拒绝；
- 审核后只读展示。

页面不得展示 `sourceContent` 或运行快照中的内部下载 URL。

### 4.4 源码包上传与替换

- 使用 `Upload.Dragger` 或等价拖拽上传区；客户端不自动提交，由页面调用 PUT 接口。
- 只根据文件名扩展名接受 `.zip`，不读取文件内容。
- 客户端在上传前拒绝 `size > 100 * 1024 * 1024`。
- 后端 400、403、404、413 均展示原始错误消息，并增加明确的场景前缀。
- 上传成功后用响应的完整任务更新任务详情缓存，展示：文件名、格式化大小、上传时间。
- SHA256 放入可展开的高级信息。
- 替换失败时保留当前已生效源码包信息和待上传文件，允许重试或取消选择。

### 4.5 运行

- 继续使用现有 LLM 选择弹窗，只展示 active 连接。
- 本次不增加“本次运行补充指令”，请求体只发送 `connectionId`。
- 运行 mutation 期间禁用重复提交。
- 即使页面已有 `sourceArchive`，后端返回“源码包无效/不存在”的 400 时仍展示服务端消息并刷新任务详情。

### 4.6 候选结果与审核

- 使用“预览候选 / 编辑 YAML”双标签；预览按用例和步骤展示，编辑页使用现有文本代码编辑器编辑完整 `resultYaml`。
- `status=success && reviewStatus=pending` 时可编辑和审核。
- 未保存的草稿不允许直接审核；关闭前提示是否放弃。
- 保存失败保留本地草稿和后端错误。
- 审核请求 action 仅使用现有 `approve` / `reject`。
- 审核成功后使用响应运行更新缓存，编辑器立即切换只读。
- 批准后显示“已批准 / 待导入”，但不提供任何导入入口。
- 拒绝后显示“已拒绝”，候选同样只读。

## 5. 推荐测试范围

### 5.1 列表与创建

1. UI 任务出现在统一任务列表并显示 UI 类型。
2. 可以选择 UI 类型创建任务。
3. `requirementId` 为空时表单阻止提交。
4. 请求不包含 `sourceType` 和 `sourceContent`。
5. 创建成功后使用返回的 `taskId` 上传创建表单中选择的 ZIP。
6. 创建返回 403 时显示权限错误且不发上传请求。
7. 上传失败时按最终确认的两阶段失败语义处理已创建任务。

### 5.2 源码包

1. `sourceArchive=null` 时运行按钮禁用并显示原因。
2. 非 `.zip` 文件在客户端拒绝，不发送上传请求。
3. 超过 100 MiB 的文件在客户端拒绝，不发送上传请求。
4. 上传请求使用 PUT、`multipart/form-data` 和字段 `file`。
5. 上传成功后显示文件名、大小、上传时间。
6. 替换成功后展示新源码包。
7. 替换失败时仍展示旧源码包。
8. 400、403、404、413 分别展示服务端错误。

### 5.3 运行、结果和审核

1. 有源码包时可选择 LLM 连接并运行。
2. 显示 `pending`、`claimed`、`running`、`success`、`failed`。
3. 轮询更新运行列表与详情。
4. 成功且待审核时可编辑并保存完整 YAML。
5. 保存失败后编辑器内容不回滚。
6. 批准发送 `{action:'approve', reviewComment?}`。
7. 拒绝发送 `{action:'reject', reviewComment?}`。
8. 审核后编辑器只读，不显示保存或审核操作。
9. 批准后仍显示待导入，但不出现导入按钮。
10. 运行、保存、审核返回 403 时显示权限错误。
11. 所有 fetch URL 均不以 `/internal/ai-worker/` 开头。
