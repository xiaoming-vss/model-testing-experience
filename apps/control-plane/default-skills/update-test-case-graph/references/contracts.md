# 输入输出协议

## 输入

顶层恰好四个必填字段，不传 `cases`，不用 `null` 代替数组或对象；`requirement_id: null` 专门表示未绑定需求：

| 字段 | 类型与内容 |
| --- | --- |
| `requirements` | 需求对象数组；每项 `requirement_id`、`requirement_title`、`requirement_content` 均为非空字符串；ID 唯一。每轮提供相关完整需求，正文可为普通文本或序列化的需求理解 2.0 JSON。 |
| `case_requirement_links` | 本轮用例清单及需求映射数组；每项只有 `requirement_id` 和非空字符串数组 `case_ids`。需求 ID 为非空字符串或 `null`；所有用例 ID 必须存在于临时文件。汇总所有项并去重，就是本轮待分析范围。空数组表示空批次。 |
| `case_file_path` | 可访问的本任务临时 JSON 文件绝对路径；内容见下文。 |
| `existing_graph` | 上次完整累计图谱；首轮传空的 2.0 图谱对象。 |

### 结构化需求正文

requirement_content 仍是字符串；若内容为 requirement_understanding JSON，解析后仅接受 schemaVersion="2.0"。以 businessFlows 的 moduleId/operationId 读取实际操作，以 conditionRuleIds 和 operation.ruleIds 读取业务规则，再按 evidenceIds → evidence → sources 追溯依据；多个条件规则表示同时满足。

事实的缺省确认状态为有证据的 confirmed；示例、未知和冲突不能形成确定关系，概述字符串及省略字段不补出未确认的条件。questions 的剩余影响仍有效。遇到失效引用或不支持的结构化版本，说明输入缺口，不将字段名、ID 或转义内容当作业务事实。

需求规则与流程节点仅用于理解和验证用例衔接，不作为图谱节点。多个用例引用同一规则不自动产生边；仍需读取两端用例，按实际前提、动作、结果判断 next/branch。图谱输出保留原有 schema_version/main_paths/edges，不复制规则和证据表。

映射规则：非空需求 ID 必须出现在本轮 `requirements` 中，每个需求至多一项；`null` 项至多一个，集中收录本轮所有未绑定需求的用例。单项内 ID 不重复，同一用例可绑定多个非空需求 ID，但不能同时出现在已绑定项和 `null` 项。`"null"` 或空字符串不表示未绑定需求。不在本轮映射中的用例不属于本轮清单，但可作为关联候选按需补查。

```json
{
  "requirements": [
    {"requirement_id": "R01", "requirement_title": "任务提交与处理", "requirement_content": "提交有效输入后生成待处理任务，执行成功后生成结果。"}
  ],
  "case_requirement_links": [
    {"requirement_id": "R01", "case_ids": ["C01", "C02"]},
    {"requirement_id": null, "case_ids": ["C07"]}
  ],
  "case_file_path": "/tmp/test-case-graph-demo/cases.json",
  "existing_graph": {"schema_version": "2.0", "main_paths": [], "edges": []}
}
```

以上说明四字段形状；真实用例 ID 必须来自指定文件，不能照搬示例。本轮建议最多 30 个去重 ID，包含未绑定需求用例；跨需求重复 ID 只计一次。30 是批量起点，不是模型硬上限或性能保证；正文、需求或历史图谱较大时减至 10～20 个。单次查询最多 10 条是脚本硬限制。

完整用例放在临时文件中，基础字段如下：

| 字段 | 值 |
| --- | --- |
| `case_id` | 唯一非空字符串，完整沿用原值，不限制必须为 UUID。 |
| `case_module` | 字符串，原始模块。 |
| `case_title` | 非空字符串，原始用例名称。 |
| `case_type` | 字符串，原始类型。 |
| `priority` | 字符串，例如 `"2"`；不改原优先级。 |
| `precondition` | 字符串数组，可为空。 |
| `test_steps` | 非空字符串数组，完整步骤。 |
| `expected_results` | 非空字符串数组，与步骤数量一致并逐项对应。 |

用例记录允许保留系统已有附加字段。完整正文只从临时文件读取，不在调用输入中重复提供；调用方保持本任务用例快照不变。需求对象和映射对象采用上表字段。未绑定需求用例依据完整用例正文分析，不能编造需求归属或仅因未绑定就认定无关联。

临时文件顶层只有 `cases`，存全测试集原始完整用例。不要把需求、映射、图谱或状态放入该文件。不能从文件中推测未提供的历史需求归属；需要时由调用方补充有关需求/映射上下文。

```json
{"cases": []}
```

上面是空文件的合法形状，实际任务应填入真实用例。查询与校验脚本对文件只读。

## 输出 2.0

```json
{
  "schema_version": "2.0",
  "main_paths": [],
  "edges": []
}
```

| 位置 | 字段 | 值及约束 |
| --- | --- | --- |
| 顶层 | `schema_version` | 固定字符串 `"2.0"`。 |
| 顶层 | `main_paths` | 主骨数组，可为空；不是所有 `next` 链的目录。 |
| 主骨 | `path_id` | 非空字符串，例如 `P01`；在图谱中唯一。 |
| 主骨 | `case_ids` | 按主骨方向排列的至少两个原始 ID；同一主骨内不重复；相邻项必须有同方向 `next` 边。 |
| 顶层 | `edges` | 有向边数组，可为空；数组存放顺序无业务含义。 |
| 边 | `edge_id` | 非空字符串，例如 `E01`；在图谱中唯一。 |
| 边 | `from_case_id` | 源用例原始 ID，必须存在于完整临时文件。 |
| 边 | `to_case_id` | 目标用例原始 ID，必须存在于完整临时文件，不能与源相同。 |
| 边 | `relation_type` | 仅 `next` 或 `branch`。 |
| 边 | `order` | 大于零的 JSON 整数；同一源节点的所有出边之间唯一，可不连续。`1.0`、布尔值、字符串均不合法。不代表执行顺序或分支深度。 |

对象字段必须齐全，不能额外增加字段。所有引用完整保留 ID 原值。孤立点不需要占位边；前端从原始完整用例集中取得节点。

同向端点对最多一条边，不能同时声明 `next` 和 `branch`。允许多入边、汇合及有实际依据的回边，不强制树或 DAG；主骨自身不能重复节点。多条主骨可共享节点或边，但不可重复整条序列或再列出已有主骨的连续子路径。只有分支关系、没有明确主骨时，可以 `main_paths=[]` 且保留边。

结果是**历史有效关系与本轮确认变化形成的完整累计图谱**。首轮确无关系才输出空图；后续无新增关系、空批次时保留历史结果。一次调用不等于全测试集完成。

## 历史关系变更

保留不变的历史关系无需再次查询完整用例。改变关系时则核实两端正文及相关需求；主骨调整需核实变化边界，未变长段无需重新全量读取。

- 旧边 ID 保留时端点和类型不可变；排序调整可保留 ID。
- 若原关系被新证据推翻，复核后删除旧边；不同端点或类型的替代边使用新 ID。
- 主骨延伸可沿用原 ID；删除、缩短、重排或延伸均需内部复核，避免把整条旧主骨漏掉。
- 新 ID 不得复用输入历史图谱中本轮退役的 ID。跨更早轮次已退役 ID 的永久保留若有需要，由调用方维护登记；该信息不在本协议输入中，skill 不能声称已经校验。

结构校验仅核实协议、ID、图结构与变更清单的一致性，不自动证明业务衔接、引用正文确被模型理解或整个测试集已覆盖。
