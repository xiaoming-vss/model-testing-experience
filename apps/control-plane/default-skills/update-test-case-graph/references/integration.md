# 调用、查询与临时文件

## 调用方如何组织一项任务

1. 创建任务独享临时目录，把全测试集完整原始用例写入 `cases.json`，顶层仅有 `cases`。固定该任务的用例快照；并发任务不共用文件。
2. 调用方按业务相关性拆分用例 ID 批次，同一条业务链尽量放在邻近批次；每轮只给出相关完整需求、本轮需求与用例 ID 映射、文件绝对路径和上轮完整图谱四个字段。未绑定需求的本轮 ID 统一放在 `requirement_id: null` 项中。首轮传空 2.0 图谱。
3. 运行同一个 `$update-test-case-graph`。模型需要时调用查询脚本，分析后生成候选累计图谱；校验成功再保存。不要只把 `SKILL.md` 作为提示词却不提供脚本调用能力。
4. 将成功保存的完整结果作为下一轮 `existing_graph`。一次批次失败不覆盖上一版结果；修复后基于同一成功版本重试。处理批次、已处理 ID 和图谱版本由后端任务状态记录，不加入公开图谱或用例文件。
5. 所有预定批次处理完，最终图谱校验并持久化成功后，调用方清理本任务临时副本；失败保留以便重试，过期任务由后端清理。脚本本身没有删除文件命令，不删除用户原始附件。

全流程仍是一个 skill。查询和校验是它的辅助脚本，不是额外的分析阶段或模型调用。

**每轮建议最多 30 个去重 ID，单次查询硬限制最多 10 条。** 汇总所有映射项（包含 `null` 项）后去重计数，不是每个需求各传 30 个。30 条通常可分 3 次查询读取，读取后还需检查不同组之间的关联；历史补查另行按需进行，每次仍最多 10 条。模型内部核对本轮全部 ID 都已获取正文并分析，查询返回缺失 ID 时不能当作已处理。

30 是起始批量建议，不是强制数据上限；超过 30 时输入校验返回提示而不判为格式错误，用例正文很长时建议每轮 10～20 个。需求、读取的用例和完整历史图谱均占上下文；调用方应估算整轮输入及输出余量，超限时调小批次或调整任务范围，不能裁掉步骤和断言、偷偷删旧边或截断图谱。去掉输入 `cases` 避免重复传输，不代表查询全文后的 token 消耗消失。

## 查询命令

命令中的 `<skill目录>` 指本 skill 的实际安装路径。脚本仅需 Python 3.8+ 标准库，无需第三方包。

```sh
python3 <skill目录>/scripts/query_cases.py get \
  --case-file /tmp/graph-job-001/cases.json \
  --case-ids '["真实ID-A","真实ID-B"]'
```

`--case-ids` 的值是 **JSON 字符串数组**，1～10 个、不重复，保留 ID 原值。返回对象固定为：

```json
{
  "cases": [],
  "not_found_case_ids": ["真实ID-A","真实ID-B"]
}
```

若存在匹配，`cases` 放匹配到的完整原始记录，按请求 ID 顺序排列；未找到的 ID 单独返回，不能用相似标题、大小写修正或虚构记录填补。

未知历史 ID 的候选检索：

```sh
python3 <skill目录>/scripts/query_cases.py search \
  --case-file /tmp/graph-job-001/cases.json \
  --query '任务 失败 重试' --limit 5
```

可选 `--module '模块名称'` 做精确模块过滤。关键词按空白分词，全部词都须匹配；匹配范围为模块、标题、前置、步骤和预期，标题匹配优先；返回至多 10 项，每项只有 `case_id`、`case_module`、`case_title`，以及顶层 `has_more` 布尔值。空关键词且没有模块、通配符列举、超出 1～10 的 limit 会失败；不提供翻页或全量列举接口。

`has_more=true` 表示可以按本轮业务对象细化检索词，不是要求遍历全部命中项。必须取候选全文后才判断关系。搜索是词语匹配的辅助定位，不能保证找齐语义相关用例；不同叫法应结合需求有针对性调整关键词。

退出码：`0` 成功；`2` 参数/数据错误并返回 `{"error":"错误原因"}`；`3` 部分或全部 ID 未找到，仍返回上述 `cases` 与 `not_found_case_ids`，对已找到结果可正常分析。脚本不输出整文件，不修改源文件。

使用模型 API 时，由后端暴露等价 `get_cases` 工具，参数 `case_ids` 为字符串数组、`minItems:1`、`maxItems:10`、`uniqueItems:true`，并在后端保留脚本的硬校验。后端可为本任务绑定 `case_file_path`；搜索工具绑定相同文件。通过参数数组启动脚本，避免将 ID 或关键词拼接成 shell 命令。路径字符串本身不能让模型获得文件访问能力。

## 校验命令

先校验输入，只返回总数摘要：

```sh
python3 <skill目录>/scripts/validate_graph.py \
  --input /tmp/graph-job-001/request.json --check-input
```

校验候选累计图谱：

```sh
python3 <skill目录>/scripts/validate_graph.py \
  --input /tmp/graph-job-001/request.json \
  --graph /tmp/graph-job-001/candidate.json
```

脚本读取完整用例文件建立白名单，检查本轮映射 ID、未绑定分组冲突、图谱字段、原始 ID、主骨相邻 `next`、同源排序和历史保留。输入检查中的 `batch_case_count` 是本轮映射的去重 ID 数，超过 30 时另有 `advisories` 提示，不影响 `valid:true`。失败返回 `valid:false` 和错误信息，退出码 `2`。这些工具结果不属于最终图谱输出，也不能证明模型已经读过全部本轮正文。

## 确需调整旧关系时

从需求和完整用例获得依据后，模型在本任务目录写一个本地复核文件，用于防止候选图谱意外遗漏旧内容。它不是用户新增输入，也不是第四个输出字段，不需要另调一个 skill 或人工逐条批准。

```json
{
  "edge_changes": [
    {
      "edge_id": "E09",
      "reason": "核对两端完整用例后，目标使用独立初始状态，旧后续关系不成立，因此移除。",
      "checked_case_ids": ["原始源ID","原始目标ID"]
    }
  ],
  "path_changes": [
    {
      "path_id": "P01",
      "reason": "本批新增了与原主骨末端实际衔接的结果检查，沿用 P01 延伸主骨。",
      "checked_case_ids": ["原始旧末端ID","原始新末端ID"]
    }
  ]
}
```

该片段仅说明字段，不是可复制到真实任务的证据。`edge_changes` 精确列出本轮删除的旧边；同一 ID 改端点或类型会被拒绝，应删除旧边并创建新 ID。`path_changes` 精确列出被删除或 `case_ids` 序列发生变化的旧主线。无对应变化就用空数组，不接受过期或多余的复核项。

删除边须检查两端完整用例；主骨修改须检查新旧相邻对有变化的所有端点，整条主骨退役至少检查首尾及真实调整依据。保留不变的中间长段不需要逐条取回。`checked_case_ids` 填本轮确实查询并读过完整正文的用例 ID；出现在输入映射中不等于已读，不能为了过校验虚填。脚本只核对该清单和结构，无法证明模型确实理解了业务证据。

```sh
python3 <skill目录>/scripts/validate_graph.py \
  --input /tmp/graph-job-001/request.json \
  --graph /tmp/graph-job-001/candidate.json \
  --changes /tmp/graph-job-001/change-review.json
```

正常仅增加边、添加新主骨或保留历史时，不需复核文件。仅调整 `order` 不改变关系语义，也不需列入复核。
