# 接口测试配置提取

## 工作流

1. 遍历 `interfaces`。
2. 逐接口提取：
   - `path`：取 `fullPath`，已包含软件仓库 base path
   - HTTP `method`
   - 请求头
   - 路径参数
   - 查询参数
   - 请求体 schema
   - 成功响应 schema
3. 只根据所给接口字段补齐元数据，不查外部文档。
4. 按 [字段规则](../references/field-rules.md) 转换为目标字典。
5. 严格执行标注与约束规则。
6. 除非调用方明确要求解释，只返回最终结构化结果。

## 转换顺序

1. 先检查接口级参数。
2. 谨慎合并 schema 推导出的请求体字段。
3. 检查成功响应 schema。
4. 标记可向下游传承的字段。
5. 复核没有虚构内容混入。

## 来源忠实

- 不虚构字段、值、默认值、长度限制、格式或业务含义。
- 尽量保留原始约束，同时适配目标格式。
- 输出必须清晰、无歧义。

## 字段与分区

字段字符串、认证、登录接口噪声过滤、响应标记、数组响应、`additionalProperties`、schema 转换和分区规则统一见 [字段规则](../references/field-rules.md)。

## 约束

- 不简化掉重要约束。
- 除字段规则中的 `security` 约定外，不推断未声明的认证方案。
- 不把响应包装结构与顶层 schema 形状混用。
- 调用方要求纯转换时不输出解释性文字。
