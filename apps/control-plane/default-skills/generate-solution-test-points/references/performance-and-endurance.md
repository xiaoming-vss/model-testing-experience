# 性能与长稳场景设计

只对当前业务适用的特征展开，以下是选取方法，不是必须输出的清单。遵守当前需求的评估范围，区分指标验收、基线测量与尚未确认的风险。

## 性能

| 业务特征 | 候选设计方向 |
| --- | --- |
| 批量处理或大数据 | 比较有代表性的数据量、大小及分布下的端到端耗时、有效吞吐；输入差异必须有处理价值，不机械排列 |
| 并发请求或任务 | 根据已知模型选择并发数或到达速率，分别观察排队与实际处理时间；并发数不等于每秒请求数 |
| 有峰值或增长需求 | 典型负载、峰值、阶梯增长下的时延、吞吐与错误情况；指标未知时测量变化，不宣称“峰值达标” |
| 共享资源竞争 | 已知共存业务下的相互影响与资源瓶颈；不得编造共存业务 |
| 容量评估 | 在指定环境和判定条件下测量可承载规模；没有服务标准时只能描述观察到的饱和或增长趋势，不能宣称最大合格容量 |

成功返回不代替结果正确性；资源使用率不代替业务处理性能。端到端耗时与执行耗时、到达量与完成量、平均值与分位数须按来源区分，名称保留会改变目标的关键口径。

## 长稳

- 对持续服务、流式处理或反复操作，选取有业务依据的持续负载、循环或负载波动。长期运行的时间维度须与短期压力区分，不将所有性能点附加“长时间”复制一遍。
- 按适用风险观察内存、连接、线程、句柄、临时空间等资源趋势，以及任务积压、时延或吞吐随时间变化；不要求每个系统监控所有资源。
- 涉及资源申请释放时区分业务数据正常增长、缓存预热、保留策略与异常累积。没有资源释放规则或判定基准时用趋势测量，不直接断言必须回到初始值或完全没有泄漏。
- 运行中及结束后验证需求已有的业务约束，如结果完整性、一致性、任务可处理性；长期“系统正常”不能替代具体目标。卸载后恢复仅在需求或评估范围包含时设计，不附带未知恢复时限。

## 名称与证据边界

以下均为假设示例，数值仅在当前输入明确时使用：

- 明确要求 100 并发下 P95 响应时间不超过 2 秒：可命名“验证100并发下查询响应时间P95不超过2秒”。
- 明确要求吞吐基线评估而未给阈值：可命名“测量不同输入规模下批处理的完成吞吐量”。不能改为“验证高吞吐”。
- 明确要求持续运行资源评估：可命名“观察持续任务处理期间内存占用随运行时间的变化”。不能预设无泄漏、增长率为零或持续72小时。
- 长期负载下结果仍须满足既有完整性规则：可生成该完整性验收点；不因性能没有阈值就删除已有业务断言。
- 仅描述可以批量提交，既无质量标准也未要求评估：识别潜在性能因素供确认，不自动生成每秒处理量或长稳达标承诺。

未知执行参数可关联需求分析缺口而保留明确名称；未知验收标准不能由测量目标替代，除非评估任务明确允许建立基线。覆盖按对象、负载变化、时间维度及指标差异选择，不设固定数量。
