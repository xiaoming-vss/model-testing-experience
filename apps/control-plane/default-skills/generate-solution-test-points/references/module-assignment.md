# 模块归属示例

假设某产品已明确设有“数据检索、数据集管理、转换数据”三个业务模块，下文演示如何按职责归属测试点。这是方法示例，不是任何任务的默认模块配置，也不构成用户偏好或业务依据。实际模块名称、数量与职责须从当前需求、需求分析和用户明确指定中识别，不能照搬本例。仍使用既定 categories/data/test_points 结构。

| 模块 | 职责与归属示例 |
| --- | --- |
| 数据检索 | 数据形态筛选、选取 Release 数据、数据级转换发起、Export 记录检索 |
| 数据集管理 | 数据集整体转换发起、结果 JSON 导出、数据集授权生效 |
| 转换数据 | 任务列表与详情、进度、状态、重试、中止、继续、删除，以及本例的共用转换运行能力 |

## 按目标归属，而非按第一步归属

- “验证数据检索发起的转换详情明细展示所选数据”：归转换数据；“数据检索发起”是前置条件。
- “验证数据级转换完成后数据检索出现对应 Export 记录”：归数据检索；转换完成是触发条件。
- “验证数据集管理授权后被添加用户可查看对应结果”：归数据集管理，检查授权生效。
- “验证默认角色可查看转换任务与结果”：本例归转换数据，检查默认访问控制；与主动授权生效不是同一目标。
- 格式转换、契约、任务日志、调度和运行侧存储归转换数据；通过数据集导出的 JSON 清单及下载行为归数据集管理。不得只因名称中有“结果”就统一归某模块。
- 数据级与数据集级创建弹窗的独立校验按各自发起模块归属。有依据的通用规则可以复用，但不能先假定两个流程相同而漏掉一侧的已明确要求。

## 避免两种错误

一个需求标题是“转换数据（Export）”，不能据此吞并已有的数据检索和数据集管理职责；一个模块存在三个菜单入口，也不能据此创建三个业务模块。

跨模块关系只保留一个主要归属；分别存在独立结果时拆成独立目标再归属。判断依据是业务职责及验收目标，不是为了平衡模块条数。
