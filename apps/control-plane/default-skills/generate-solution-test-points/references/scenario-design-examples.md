# 场景推导示例

这些是方法示例，不是当前需求来源，也不替代 approved-output-example.json 的认可表达。按适用方法阅读；列出的测试点为局部示范，不表示完整输出或固定数量。实际输出仍使用 assets/output-template.json。

## 等价类与边界

已确认规则：购买数量仅允许 1～99 的整数。可推导有效整数、低于下限、高于上限、小数、非数字与未输入；不推导界面提示样式。

名称示例：
- 验证购买数量等于下限时符合数量校验规则
- 验证购买数量低于下限时不通过数量校验
- 验证购买数量等于上限时符合数量校验规则
- 验证购买数量高于上限时不通过数量校验
- 验证购买数量为小数时不通过数量校验

边界点分别归边界场景；类型不合法等检查按异常/容错场景归类。具体数值可在内部用于识别边界，但不生成独立测试数据字段。“符合数量校验”不扩大为“下单成功”，因为下单可能还有其他条件。金额或时间规则未给精度时，不自行假定相邻值为 0.01 元或 1 秒。

## 判定表与条件组合

已确认规则：优惠券仅在有效期内且订单达到门槛时可用，其他组合均不可用。

| 有效期内 | 达到门槛 | 可用 |
| --- | --- | --- |
| 是 | 是 | 是 |
| 是 | 否 | 否 |
| 否 | 是 | 否 |
| 否 | 否 | 否 |

名称示例：
- 验证优惠券在有效期内且订单达到门槛时可用
- 验证优惠券在有效期内但订单未达门槛时不可用
- 验证优惠券不在有效期内且订单达到门槛时不可用
- 验证优惠券不在有效期内且订单未达门槛时不可用

后三种结果相同，但条件不同，不能只按预期相同去重。未规定提示优先级时，不为最后一种组合编造优先报错原因。有互斥或依赖条件时，先剔除不可达组合。

## 状态迁移与重复事件

已确认规则：待支付订单允许取消并进入已取消状态；已发货订单禁止取消；已取消订单再次取消保持已取消状态。

名称示例：
- 验证待支付订单取消后变为已取消状态
- 验证已发货订单不允许取消
- 验证已取消订单再次取消后仍保持已取消状态

正常迁移归功能场景，状态限制归功能场景，重复触发归时序与并发场景；状态限制不自动当作角色权限。已支付订单的取消规则未给出，内部记录缺口，不推定自动退款。

## 并发关系与唯一验证目标

已确认规则：同一库存单位最多被一个订单成功购买，不允许超卖。

名称示例：
- 验证两个订单并发购买最后一件商品时最多一个订单购买成功

这里验证的是多个订单之间的数量约束，是一个不可拆分的目标。不拆成“订单甲成功”和“订单乙失败”，因为规则未指定胜者；也不能改成“恰好一个成功”，因为规则只约束最多一个。库存释放时机、失败提示和自动重试规则未给出，不补造。

## 条件启用的方法与专项要求

- 明确规定商品顺序不影响计价时，可以生成“验证同组商品调整排列顺序后订单总额不变”；若包含顺序相关优惠规则，不能直接套用。
- 明确规定升级前后保留同一批记录及其字段值时，可验证升级前后数据一致；新旧接口结果存在差异，不自动判定新版错误。
- 明确给出“100 个并发用户、指定查询数据集下，查询响应时间 P95 不超过 2 秒”时，可生成对应性能测试点，名称保留负载及指标口径。只有“查询要快”时，不自行赋予指标。
- 给出了历史重复退款缺陷及当前“一笔支付最多退款一次”的有效规则时，可以推导重复回调场景；只有历史缺陷标题时，先核对适用性及预期。

## 入口、操作路径与业务目标的取舍

以下依据为各例明确给出的规则，不是对某份真实需求的补充。先判断目标是否成立，再判断拆分粒度。

| 已确认材料 | 处理与名称示例 |
| --- | --- |
| 从列表的删除菜单删除任务，删除后任务记录消失；无独立菜单布局要求 | 输出“验证删除转换任务后任务记录消失”，不追加“验证列表提供删除入口”。 |
| 已中止任务执行继续后恢复为转换中；列表提供继续操作只是路径说明 | 输出“验证已中止任务继续后恢复为转换中”，不追加继续入口点。 |
| 明确要求非发布数据集不显示转换操作，未说明其他渠道能否转换 | 保留“验证非发布数据集不显示转换操作”，不改写成“非发布数据集不能转换”。 |
| 明确要求离线时绑定按钮置灰，并要求拒绝离线绑定请求 | 按两个独立要求分别验证按钮置灰和请求被拒绝，不能用界面检查替代业务拦截检查。 |
| 只明确新增导出入口及其位置，未定义导出结果 | 可保留对应入口显示目标；不编造导出成功或导出文件内容，内部记录行为预期缺口。 |
| 同一删除流程可从多个页面访问，无独立路径要求或行为差异 | 不按路径重复生成相同删除目标；若明确要求各路径可达或具有不同规则，则保留对应验证。 |

approved-output-example.json 已移除单纯演示“提供入口”的条目，以减少对入口存在性检查的模仿。它仍保留有依据的操作置灰目标。此调整不是判定历史业务中的入口需求无效；当前任务仍按当前材料决定取舍。

## 独立要求覆盖与局部待确认

以下示例用于校准展开深度，不要求当前任务具有这些能力。遇到独立条件、多角色、结果分支或局部待确认时阅读。

| 输入依据 | 应生成或保留的目标 | 不应采取的处理 |
| --- | --- | --- |
| 转换形态和名称各自必填，提示方式未定 | 分别验证仅形态缺失、仅名称缺失时不能提交，其他字段有效 | 只测两项都为空；因提示方式未知删除必填校验 |
| 类型和状态各自可筛选，列表还支持刷新、分页、排序；默认排序未定 | 单条件筛选、刷新后显示最新任务信息、分页查看任务、按支持的排序规则排列等已明确目标；联合逻辑另行核实 | 一条“支持查询”代替全部能力，或编造每页 10 条及按创建时间降序 |
| 四种角色各自可查看任务和结果 | 各角色独立授权路径分别验证；任务与结果的独立访问要求分别覆盖 | 使用一个兼有四种身份的账号代表所有角色 |
| 重试后失败条数按实际结果重算 | 分别验证重试成功后的失败条数更新、重试仍失败后的失败条数更新 | 用“按结果重算”覆盖全部分支；自行规定无限重试 |
| 产物应为所选目标格式，支持格式已明确，具体格式规范另行提供 | 针对有差异的已支持格式验证产物符合目标格式；规范待用例展开时补齐 | 只验证出现文件或 export 记录；自行编造格式字段 |
| 沿用每租户独立 Bucket，跨租户协作授权未定 | 验证产物写入所属租户对应 Bucket | 因授权矩阵未定，连存储归属也不验证 |
| 统一输入输出契约、Worker 可替换升级，检查手段未定 | 保留契约对接及可替换升级目标 | 当成纯内部实现排除，或编造零停机升级承诺 |
| 扩展格式界面展示本期暂不考虑 | 记录范围排除，不生成界面必须隐藏的断言 | 输出“验证新增格式不在界面展示” |
| 已转换完成的数据再次处理时直接置为完成 | 保留“此前已转换完成”的条件 | 扩大为“只要以前发起过转换就直接完成” |

覆盖账在内部按“独立要求 × 有效分支”核对。例如同一条规则同时包含文件路径、直传、租户 Bucket，前两项有测试点不代表 Bucket 也覆盖。最终只输出既定 JSON，不输出覆盖账或补充字段。不设置条数指标，不因需要增加条数复制等价场景。

## 断言强度与阶段衔接

| 有效依据 | 有依据的目标 | 越界或漏测的目标 |
| --- | --- | --- |
| 失败后不允许重新编辑，未规定控件形态 | 验证失败对象不能重新编辑 | 验证重新编辑入口消失 |
| 发布按当前批次全量进行，未定义选择控件 | 验证发布范围为当前批次全部有效对象 | 验证页面不提供选择控件 |
| 页面准入失败时说明原因，后端也须校验准入 | 分别保留页面原因反馈与后端拒绝目标 | 默认接口返回页面文案或某错误字段 |
| 审核通过后进入待发布；待发布对象可以发起发布 | 分别保留审核放行的状态迁移与待发布操作 | 仅验证已待发布时发起操作，把状态迁移漏掉 |
| 状态选择器以所选状态做等值筛选 | 一个明确覆盖全部有效枚举的筛选目标 | 为每个枚举复制同一等值判断 |
| 排队与执行中均禁止重试 | 分别保留排队、执行中的重试限制 | 以“非失败时禁止”掩盖生命周期分支 |

先依据当前输入判断；这些示例不新增任何产品的入口、接口或状态规则。

阶段链示例：输入确认“扫描成功后进入复核，扫描等待、执行中、失败均不得进入复核”。应检查成功放行及各未完成状态的阻断；仅有“扫描中显示扫描中”“扫描失败可以重试”并没有覆盖复核被阻断。通用阶段规则应用到具体阶段后，先与已有准入目标比对去重，不新增输入未规定的失败恢复行为。
