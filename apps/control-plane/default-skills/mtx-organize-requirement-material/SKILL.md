# 整理需求材料

将提供的需求原文、表格、图片及明确的用户补充整理为一个 JSON 对象。默认阅读内容是按功能或原材料主题组织的连贯说明；材料和定位单独保留以便核对。输入包含平台提供的 sourcePath、documentType、sourceName 和 sourceLocation；富文本的 images 映射提供图片文件，Word 中需读取嵌入图片。原始文件路径仅供读取，不得写入正式来源。

平台提供产物交接路径时，保存完整 JSON 到指定文件，按平台要求返回固定文件回执；没有提供交接路径时直接返回完整 JSON。修订使用当前产物、原材料与本轮答复，保留未受影响的内容和稳定 ID。

## 按需加载

- 首次生成或继续修订时，起草前必须读取并遵循 [主提示词](prompts/material-organizing.md)；按实际情况读取该提示词链接的参考资料。
- 初稿完成后、输出前必须在同一次任务中读取并执行 [输出前自查](prompts/material-self-review.md)，修正可修复问题；不额外输出自查报告。
- 同一批材料已读取的参考无需逐条重复加载；输入、输出与修订范围以上述入口和下方协议为准。

## 输出 JSON

固定契约以 [output.schema.json](references/output.schema.json) 为准，不添加未定义字段。生成和修订后将完整 JSON 保存到文件，用 `python <skill目录>/scripts/validate.py <输出文件>` 校验（需要 Python 的 `jsonschema` 包）；修正错误后再次校验，直到通过。该脚本同时检查重复键、ID 唯一性、引用有效性及材料层级无环。缺少依赖或不能执行校验时，明确说明未完成校验，不能宣称通过。Schema 和引用检查不能证明业务语义、图片识读或来源支持正确，仍需对照材料核查。

正常完成时按交接方式返回完整 JSON 或文件回执，不带 Markdown 围栏。校验失败或无法执行时，报告具体问题，不将结果声称为已校验产物。

## 字段语义

结构、必填项和枚举以 schema 为准；重点保持以下语义：

- `sources` 保存稳定来源，`materialBlocks` 按原材料顺序保存正文、列表、表格及图片识读结果。表格未知单元格为 null，合并区域从 0 编号且不得越界或重叠；图片不可读时保留定位和读取状态。
- `functions` 保存可阅读的有效说明。每段关联具体材料块，按 `confirmed`、`unconfirmed`、`conflicting`、`example` 区分依据；章节只使用 schema 定义的四类，有内容才输出，同一功能不重复类别。
- `questions` 只保留影响业务理解的未解决问题，关联有依据的功能和材料；无法确定归属时关联数组为空。未识别成明确功能的相关内容仍保留在材料块或问题中。
- ID 在各自集合内唯一，引用必须有效。空数组表示未记录，不证明不存在或不适用。
