# 需求材料整理 Prompt

输入、修订范围和输出协议沿用 SKILL.md。以下只规定本阶段的方法。

遇到截图解释、部分答复或范围排除时，读取 [整理边界示例](../references/decision-examples.md)；需要检查字段组合时可参考其中的完整 JSON。示例假设只适用于示例。

## 整理方法

1. 完整阅读可用材料，记录来源、章节、正文、列表、表格和有业务意义的图片；图片不可读或未提供时说明限制。来源只记稳定的文档标识和定位，不写临时路径、签名 URL 或凭据。保留表格行列关系；图片保留原图定位，并提取与本次需求有关且可可靠识别的内容，无法读取的相关部分标为未知。
2. 按可识别的模块、功能或原材料主题组织说明。按统一分类“功能目标与背景”“页面入口”“功能使用与业务规则”“完整业务流程”归纳，只输出有内容的分类；各分类在同一功能中最多出现一次，不以需求特性另创分类标题；把相关事实放在一起，避免为凑章节重复规则。多功能材料分开组织；归属不明时沿用原文结构，不编造模块。
3. 对涉及页面的功能，整理材料中与本次需求相关的已知路径、控件、操作、条件和反馈；根据实际材料选择小节，操作顺序只写有依据的部分。结合需求主题判断图片信息的关联性：提取影响本次功能位置、操作、条件、反馈、规则或流程的页面元素及图中分支；将这些信息写进正文并关联图片材料块。与需求无关的账号、任务名、示例记录、进度、时间戳和旁边功能不进入说明或图片文字清单；若它们确实影响本次规则则保留。不要逐字抄录整张截图。必要标签辨认不清时说明不确定，不能猜测。通过来源引用标明截图依据；示例记录、示例数值和旧界面文案不能当作现行或新需求规则。入口路径、触发方式、保存与反馈等未说明时保留已知部分，按下方“待确认问题筛选”决定是否提问；不要推断按钮行为、选项或操作顺序。纯后端功能无须强行生成页面章节。
4. 用自然段和列表直接描述功能、页面和操作，每段或列表项关联材料块；正文不加“用户补充确认”“原文展示”“截图中”等来源前缀，也不叙述信息如何获取。来源、确认状态和示例性质保存在 JSON 的引用和状态中；当区分截图现状与需求变更对理解有必要时，在正文写清现有与目标状态。允许忠实的归纳，但保留原文的范围、条件、数量、先后和例外；材料不足以支撑完整流程时只写已知部分。静态截图只支持其可见内容，不推断动态行为。示例不能冒充正式规则，历史与当前信息冲突时标出冲突。
5. 按下方“待确认问题筛选”处理缺失、歧义和冲突；没有提及不等于不存在。按“落实用户反馈”更新功能说明、问题和来源，不将新增信息扩展到未覆盖的功能、页面、对象或规则。
6. 对照原材料逐项核查：关键条件、例外、表格和图片有没有遗漏；每条说明是否有足够依据；与需求相关的页面、入口、操作及截图信息是否在正文呈现，图片示例和无关信息是否排除；每条反馈是否在适用范围内落实，未答复的子问题是否保留；未知、示例、冲突是否未被写成已确认事实；问题是否具体且没有重复。保留识读局限，不能读取的内容不能假装已检查。

## 待确认问题筛选

- 优先提出与本次需求有关、且会妨碍确定功能行为、适用条件或业务结果的缺口和真实冲突，指出涉及的功能及无法确定的内容。同一业务决策的相关缺口合并，先问确定方向所必需的问题。
- 材料未提供页面入口、控件、展示方式、实现或验证细节时，记录与需求相关的已知内容；只有缺失会妨碍上述判断时才提问，不为补齐页面或流程说明逐项追问。不提问不意味着该细节已确认、无需测试或不存在。
- 先核对不同来源的对象、阶段和语境，再判断是否冲突；截图标签与流程状态名称不同本身不足以证明它们是同一状态或业务冲突。确有影响需求理解的歧义时保留问题，不猜测答案。
- 对用户已明确答复的内容按“落实用户反馈”处理，不重复追问；部分答复只保留符合筛选条件的剩余缺口。不能仅为减少问题数遗漏影响功能、条件或结果的关键问题。

## 落实用户反馈

逐条识别反馈所针对的功能、说明和问题，在其明确适用的范围内更新当前产物，而不是只追加一段答复供下游解释：

- 补充或确认业务事实时，将事实写入对应 `functions` 说明，更新状态并引用用户补充来源；纠正原描述时，修改所有受影响的说明及引用，避免新旧内容并列为现行事实。
- 用户明确要求移除、排除或不再关注具体事项时，从当前功能说明和待确认问题中移除该事项；只处理反馈覆盖的范围，保留其他仍适用的规则。“不关注某项细节”不能推定为排除整个功能、环节或业务范围；仅在用户明确排除业务范围时，在对应功能说明中写明该范围并引用答复，供下游识别。
- 逐项核对原问题及其子问题：删除已解决或用户明确不再要求确认的部分，部分答复只保留仍影响理解的未解决部分；全部处理完则移除问题。反馈无法可靠判断其对象、意图或范围时，不自行推定业务事实或删除相关内容，保留准确、简短的澄清问题。
- 保留原材料和用户答复作为 `sources`、`materialBlocks` 中可追溯的依据，更新有效说明的引用及状态；来源记录不能代替对 `functions` 和 `questions` 的实际修改。原始材料中被纠正或排除的内容不是现行规则；有实际业务冲突且反馈不足以消解时保留冲突状态。
- 修订后回查每条反馈：相应说明是否已更新，已处理的问题是否移除，相关说明和引用是否一致，未受影响的内容是否保留。保留来源中的历史内容不意味着保留为当前需求或重新提出已处理问题。
