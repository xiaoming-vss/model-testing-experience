# 程序分派的测试点初稿

收到“程序分派的测试点初稿分组”时，当前 Agent 只生成指定范围的候选。完整材料和已审核范围分析仍全部可读；分组是工作分工，不是业务模块、范围排除或新增需求。按主技能回查材料，保留 confirmed、inferred、unconfirmed 等来源状态，不因分组而补造预期。

## 归属与边界

输入给出本组 `group`、`assignedTestObjectIds`、全部 `groups` 及 `sharedGroup`。各对象 ID 只归属于一个对象组：

- 一条测试点或缺口的真实 `testObjectIds` 非空，且全部属于同一对象组，由该对象组生成。
- 真实引用涉及不同对象组，或没有可关联测试对象，由“跨组与公共规则”组生成。该组检查有材料支持的跨组流程、条件组合和未归属规则，不重复对象组的独立目标。
- 依据实际业务关联填写引用。不要删除、添加或替换引用来改变条目归属。有关联但未确认的业务结果形成覆盖缺口；已确认的交互生成测试点。分组边界或另一个 Agent 负责某项本身不是业务缺口。

按分派范围执行设计和输出前自查；范围外的材料是背景，交互与公共目标由其责任组处理，不把本组结果未覆盖全需求当作遗漏。各组完成后，平台针对完整汇总候选执行一次全局依据、覆盖与拆分、缺口审查，发现跨组遗漏、重复或冲突后按增量复核流程处理。

## 输出与交接

输出沿用 `traceable_test_points` JSON 外壳，`testPoints` 和 `coverageGaps` 只包含本组条目。没有有依据的条目时使用空数组；不为凑数量补点。`reviewStatus` 固定为 `self_review_only`，不提交 `reviewIssues`，不输出额外说明或跨组笔记字段；真实跨组目标通过公共组的标准条目表达。

当前组内的测试点和缺口 ID 分别唯一；平台合并后会统一编号。所有上游来源 ID 原样保留。平台仅去掉内容完全相同的条目，语义上的等价、重叠、独立价值仍交给全局审查，不由程序按标题相似直接删点。

程序负责并发、工作区和会话隔离，本组直接完成分派任务，不再自主委派。格式、引用或归属校验失败时，只修复本组输出。任一组失败时不发布其他组的部分结果。后续审查修订使用合并候选及稳定 ID，修改有问题的内容，不重新生成所有分组。
