# 业务判据与执行准备

本技能生成业务级用例设计，不执行测试，也不承诺测试环境已经就绪。需求说明通常不会包含全部接口地址、日志路径或故障工具；这些缺失不等于业务规则不明确。

## 三类缺口

| 情形 | 判定与处理 |
| --- | --- |
| 允许/拒绝、默认行为、计算公式或完成条件尚不明确，当前断言必须依赖它 | 真实业务判据缺口，集中澄清；未知公式不能用“准备正确公式”掩盖 |
| 规则明确，但具体API、存储读取、审计查询、测试账号、素材或故障控制未落实 | 写成可检查的前置准备，照常生成步骤与预期；执行前绑定实际环境，不编造工具已存在 |
| 普通有效数据、既有阶段、页面字段、输入回读能完成观察 | 直接设计，不额外要求数据库或全链路日志 |

技术设计已明确负责的帧基准、物理字段、API映射以及既有配置，可作为执行准备读取并记录。若不同选项会改变本次尚未决定的业务结论，才需需求确认。局部问题按标题生效，不沿整个流程无限传播。

## 可操作的准备与验证

| 目标 | 用例应写出的内容 | 不应采用的处理 |
| --- | --- | --- |
| 后端准入 | 准备对应操作的实际接口绑定及有权账号；设置data/管线及完成状态，发起请求，核对是否受理和阶段变化 | 猜URL、HTTP码；缺URL就不写；用页面按钮代替后端请求 |
| 没有启动下游任务 | 准备可按业务对象定位任务活动的观察能力；操作前后读取任务实例/启动事件，核对目标阶段及新增集合 | 仅看页面不变就通过；因为PRD没有日志路径而要求补需求 |
| 重试、幂等及并发 | 准备可复现故障或可控制事件的测试环境，指定同一任务/不同任务、事件身份与顺序；确认触发实际发生，再检查执行次数、影响范围与结果 | 将刷新当重复回调；仅写“制造故障”而不说明需具备的控制能力、对象和时序 |
| 全量产物/关联 | 准备由测试输入及已知来源关系建立的预期清单；绑定产物读取渠道，逐标识与关键字段比对遗漏、混入及关联 | 用本次待测结果自身作为全集；必须由需求方提供真实生产数据清单 |
| 原始视频引用、审计、对象存储 | 要求可读取相关资源的测试权限与观察映射，明确业务身份、来源、层级、阶段和核对范围 | 发明详情页字段、数据库表名或物理路径；只看页面存在就证明底层保留 |
| 分页与懒加载 | 准备超过实际页容量的数据；记录浏览器/测试工具中的视频资源请求，翻页前后对照访问与未访问集合 | 固定需求未规定的页大小；把工具准备误作性能需求缺失 |
| 有效字段编辑/保存 | 选择已知合法且不同的值，记录提交值，重新进入或切换后回读比较 | 普通修改也先索取所有合法值边界 |
| 状态筛选 | 记录本次命中/排除样本及状态，设置明确筛选值，读取相关页并逐标识比较；动态状态前后复核 | 用默认筛选未知阻塞主动筛选；样本数量相等就认定全集正确 |
| 视频播放及帧时间一致性 | 准备已知时长、内容标记和帧信息的素材；需要时读取技术设计边界约定，核对对应位置 | 用两个同源显示自证媒体正确；把技术映射未附在PRD当作所有播放测试的业务缺失 |
| 恰好阈值 | 准备按输入时长口径精确构造并验证的阈值素材，记录实际时长；已明确包含端点就按明确规则判断 | 因未给帧换算算法而取消所有秒级阈值测试；无依据猜取整规则 |
| 既有配额或重试结果 | 执行前读取既有配额值及范围，准备可恢复或持续存在的故障条件；分别执行并检查对应结果 | 凭空填固定并发数；为写用例要求PRD提供具体故障注入命令 |

前置条件要描述资源的属性和能力，而不是留一个“待补资料”的空位。例如：

- 可写：“测试环境具备按data、管线及segment查询语义任务实例、状态和启动次数的观察渠道；执行前完成实际字段映射并确认能记录前后快照。”步骤再指定本次对象及集合比较。
- 不可写：“按实际情况检查后台，结果正确。”它没有观察对象和判定方法。
- 可写：“准备故障可解除的失败任务；记录故障来源，解除后重试并观察该任务从执行到完成。”不预先要求本次重试成功。
- 不可写：“准备已经重试成功的任务，确认重试成功。”这跳过了被测过程。

## 局部范围与真实冲突

- 已保存内容隔离不依赖未保存切换规则；主动筛选不依赖默认筛选。
- 完整选项集存在冲突，不必阻塞已确认取值的独立业务含义。
- 如果本条验证全部/部分核验的准入，核验完成判据确实影响预期；仅验证切片执行中展示或后续迁移时，可以使用已经进入切片执行阶段且可核实的对象，不需重做上游核验。
- 若只确认审核完成后进入待发布，不能自行规定审核如何通过；涉及审核条件本身的目标保留问题，待发布状态下的操作可使用既有待发布对象。
- 一个未知公式可影响多条精确数值目标，只形成一个判据问题；参与聚合的对象范围与关联仍可单独验证。

## 保留检查力度

准备未落实时执行结果是未就绪，不是通过。字段语义、单位、取整方式、时间来源不得混用；前一状态值不自动成为后一状态必须保留的规则。集合核对逐标识，完整范围不可用两个样本代替。假设产品出现错片、漏项、重复任务或错误阶段推进，检查应能发现；所需观察能力写入准备，只有无法确定应判什么结果时才回到业务澄清。
