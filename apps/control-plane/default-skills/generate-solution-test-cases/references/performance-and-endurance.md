# 性能与长稳用例执行依据

本 skill 只写用例。以下内容按目标适用性纳入既有字段，不要求所有用例具备所有指标，也不新增测试点。

## 前置条件与负载

- 明确被测环境、版本、资源配置、数据规模和分布、相关依赖以及可用负载与监控方式。不能虚构产品接口、压测工具或监控字段。
- 定义负载模型：并发执行数或到达速率、业务操作比例、输入数据及完成量的计算单位；不要把提交成功数作为完成吞吐。
- 说明本次采用的档位、持续时间、必要预热和采样周期；多组数据分别运行，说明恢复或隔离方法。参数是实验设置还是产品要求须可分辨。
- 基线比较要保持关键环境和数据可比；不能用不同环境下的绝对值直接判断退化。长稳时长应匹配要观察的周期，短时试验不能声称完成长期验证。

## 操作和观察

按适用顺序安排：记录起始状态 → 建立并核实负载 → 持续采样与业务检查 → 结束或满足停止条件 → 汇总证据 → 必要恢复。

- 队列负载须核实实际到达、处理及积压，不把“有一个任务执行”当作已饱和。
- 长稳同时保留时间序列与关键业务结果，不能只比较起点和终点，或只看一次页面成功。
- 根据已知来源记录指标，说明统计窗口、单位及分位数/吞吐/错误率的口径；采样缺失、负载未达到或运行被提前中断时，不能将结果判为完整试验通过。
- 写明正常结束条件；需要故障或资源风险停止条件时使用已有环境限制、测试计划或确认值。不臆造百分比阈值，也不默认无限加压直到崩溃。缺少直接影响执行的条件时按可展开性规则澄清。
- 恢复修改过的配置、释放测试资源并保留证据；不能为了清理删除需求要求保留的业务产物。

## 两种预期

**指标验收**：在明确环境和负载下，实际采样满足已确认阈值和统计口径；长期业务断言仍按既有规则判断。具体数值必须有依据，不能只写“无衰减”“无泄漏”“正常运行”。

**基线测量**：expected_results 写应形成的有效证据，例如“记录各输入规模下的实际完成数、测量窗口与完成吞吐，保留失败统计用于解释结果”，或“形成覆盖观察周期的内存时间序列，标记负载与数据规模变化”。不预设最终趋势、固定数值或产品合格结论。出现异常须如实记录，不能以记录完成掩盖已经违反的明确业务规则。

资源增长应结合预热、业务数据保留及释放机制分析；只看到内存增长不能直接证明泄漏，只看到末值降低也不能证明长期无泄漏。测量可完成与产品性能达标是两种不同结论。
