# 覆盖规则

## 正向

- 每个接口至少 1 条全参数正向用例，预期 `2xx`。
- 接口存在可选字段时，增加 1 条仅必填最小参数正向用例：以提取基线为准，删除可选字段，预期 `2xx`。
- 正向用例可带 0–2 条响应字段断言，只使用提取产物 `response` 中明确存在的字段。
- 优先使用 `exists` 或稳定字段（如 `id`、`code`、`status`），不猜测服务端生成的动态值。

## 反向

- 必填缺失：每个必填字段最多 1 条；包括 `headers` 中标记 `[必传]` 的字段。一次只缺一个字段。
- 必填字段超过 3 个时，按字段顺序和业务重要性取前 3 条，其余写入 `uncovered`。
- 类型非法：字段有明确类型时设计，每个接口最多 1 条，优先级最低。
- 枚举非法：字段有 `enum` 时设计；与格式非法合计最多 2 条。
- 格式非法：字段有 `format` 时设计；与枚举非法合计最多 2 条。
- 反向用例预期 `4xx`，`assertions` 为空。

## 边界

- 只对提取产物中明确出现的 `minimum`、`maximum`、`minLength`、`maxLength` 约束设计边界。
- 每个被选中的约束设计一对：边界内取恰好等于边界值，预期 `2xx`；越界取边界外相邻值，预期 `4xx`。
- 每个接口最多选择 2 个约束做边界，优先必填字段和业务关键字段。
- 没有明确约束的字段不设计边界。

## 数量与顺序

- 每接口目标 8 条，不设硬上限。
- 达到目标时的取舍顺序：正向全参数、正向最小参数、必填缺失、枚举/格式非法、边界内、越界、类型非法。
- 超出目标且价值较低的约束写入 `uncovered`，不静默丢弃。
- 用例数组按上述顺序排列；生成阶段严格按设计数组顺序产出。

## 参数变异

- `patch` 的 `path` 是相对 section 的 JSON Pointer，例如 `/password`、`/profile/age`、`/profile/roles/0`。
- 以提取产物对应 section 为基线，按数组顺序应用。
- `path_params` 补丁指向单个参数名；生成阶段把补丁值替换进 `urlTemplate` 的 `{name}` 占位符。
- 只修改目标字段，不用完整请求体覆盖基线。
