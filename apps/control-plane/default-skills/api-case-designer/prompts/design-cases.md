# 设计提示词

## 工作流

1. 读取 `batch.interfaceNames`，只处理本批接口。
2. 逐个接口读取 method、path、headers、path_params、query、json/data 和 response。
3. 先设计正向全参数用例，再按需设计正向最小参数用例。
4. 收集必传字段、类型、enum/format 和数值/长度约束。
5. 按覆盖规则设计必填缺失、类型非法、枚举/格式非法和边界用例。
6. 为每条用例写结构化 `basis` 和最小 `patch`。
7. 按优先级顺序排列用例，把未覆盖约束写入 `uncovered`。
8. 输出本批完整设计 JSON。

## 核心规则

- 一条用例只验证一个明确场景；必填缺失一次只缺一个字段。
- `basis` 的字段和约束必须能在提取产物中逐字找到。
- 反向和越界用例只断言状态区间，不发明错误响应字段。
- 正向断言只来自提取产物明确声明的响应字段。
- 继续优化时以 `currentDesign` 为基线，保留未涉及接口和用例。
