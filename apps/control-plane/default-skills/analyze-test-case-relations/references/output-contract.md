# 用例关系输出协议 2.0

用于由原始用例直接构成的鱼骨图。字段固定，所有字段必填，不允许额外字段或 null。schema_version 是协议版本，不是用例集版本。

## 字段

| 对象 | 字段 | 类型与含义 |
| --- | --- | --- |
| 顶层 | schema_version | 字符串，固定 "2.0" |
| 顶层 | main_paths | 主骨定义数组，允许 [] |
| 顶层 | edges | 全部直接关联边，允许 [] |
| main_paths[] | path_id | 非空字符串，文件内唯一，例如 P01 |
| main_paths[] | case_ids | 至少两个不重复的原始用例 ID，数组顺序就是主骨顺序 |
| edges[] | edge_id | 非空字符串，文件内唯一，例如 E01 |
| edges[] | from_case_id | 原始用例 ID，关联起点 |
| edges[] | to_case_id | 原始用例 ID，关联终点，与起点不同 |
| edges[] | relation_type | 仅 next 或 branch |
| edges[] | order | 正整数，同一起点所有出线中唯一；不接受布尔值、字符串或小数 |

顶层不重复 case_ids。仅 main_paths 内保留 case_ids。边没有 label；其余未列字段也不输出。

## 关系语义

- next：目标验证源业务场景的后续阶段，须有状态或业务结果的衔接依据。主线和分支内部都适用，不表示测试执行依赖；正常阶段的顺序不能直接套用到这些阶段各自的失败、重试或不同条件用例上。
- branch：目标验证源场景的替代、派生或补充情形；方向由基础场景指向派生场景。分支可以继续 next 或再次 branch。
- main_paths 显式指定哪些用例组成主骨；不是所有 next 都属于主骨。每对相邻 ID 必须在 edges 中有同方向 next 边。单个独立用例不需要创建单节点主骨。
- 汇合由多个不同起点指向同一个 ID 表达；图中仍是同一个用例节点。该结构不包含并发或等待条件，也不证明多个测试应同时运行。
- 不要求所有边或用例都能从某条主骨到达。无明确主线的关联组件合法。没有入边和出边的原始用例是独立节点，不另建独立用例数组。
- 同一有向端点对只允许一条边，不可同时标 next 和 branch；依据不足时不生成。禁止自环。全图不强制为树；若确有返回关系，必须有业务证据，消费者遍历应防循环。主骨内不得重复用例。
- order 只控制同一起点下的展示次序，不表达执行先后、层级、互斥、并发或左右位置；升序读取，允许不连续。新生成通常从 1 连续编号。输出 edges 数组本身的顺序不构成连线依据。
- 先确认完整业务链和直接关系，再选主骨。同一业务链中的短段能合理衔接时应组织为一个骨架；有独立业务理由时才新建主骨。替代路径及其后续通常作为分支，分支内的 next 不必声明为主骨。不强制所有组件连通，也不以主骨最少或最长为优化目标。
- 多条主骨确需共享节点或边时，消费者按 ID 复用；禁止重复输出相同主骨序列，不把已有主骨的子路径或已有分支后续反复列为主骨。

## ID 与完整性

原始用例是全量节点清单；case_id 和 case_title 不在关联阶段改写。path_id 与 edge_id 各自全局唯一，保留仍适用的已有关系 ID。没有历史关系输入时不能保证新关系 ID 跨次生成一致。

所有引用都必须逐字存在于本次原始 cases 的 case_id 集合，包括 main_paths[].case_ids[]、edges[].from_case_id 和 edges[].to_case_id。禁止生成、替换、截断、补齐或规范化 case_id；仅 path_id 与 edge_id 可以为新关系生成。示例 ID、历史关系 ID 若不在本次输入集合中，同样不可引用。未出现于结果的用例表示独立，不代表被删除或漏传；关联分析内部仍需逐条检查。输入重复/缺失 ID 是输入错误，应先澄清。

## 消费方解析规则

1. 先从原始 cases 建立 case_id → case_title 节点映射，保留完整名称。
2. 校验所有关系引用；未知 ID 报错，不建立占位业务节点。
3. 读取 main_paths 的有序 ID 确定主骨，再根据 edges 建立邻接表。
4. 同源出边按 order 升序。主骨相邻边放在主轴；其他 next 延续所在分支，branch 形成新分叉。对共享节点和回边作图引用，避免无限递归或重复创建用例。
5. 没有入边、出边的原始用例独立展示；多组件不强行连接。

横向或竖向、左右交替、间距、坐标由渲染器确定。此协议保证连接关系明确，不保证不同渲染器像素布局相同。

## 空结果与迁移

没有可确定关系或输入 cases=[]：{"schema_version":"2.0","main_paths":[],"edges":[]}。

旧协议 flows/links 记录业务节点与用例覆盖路径，不能确定用例之间的直接关系。必须结合原始用例重新分析，不能把覆盖相同路径的用例自动串联。校验器拒绝旧版结构，不做隐式迁移。
