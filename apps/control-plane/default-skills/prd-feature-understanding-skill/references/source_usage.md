# 输入与来源承接

材料提取中的 confirmed 只表示提取阶段的判断，不保证其解释与原话一致。优先核对用户原话、原文内容与提取总结的含义边界；争议按 SKILL.md 的来源预检处理。

读取完整 document_extraction JSON、已提供的原始补充依据和用户明确答复；修订另读取当前 2.0 需求理解及修改要求。材料提取的 sourceReferences 用于查回原文，最终需求理解将采用的证据集中登记到 evidence，通过 evidenceIds 引用。

sources 登记实际使用的材料；evidence 的 sourceId 必须指向已登记来源，locator 保留可核对的真实定位。相同来源、定位和摘录复用一个证据 ID；同一定位下有不同含义的必要摘录可分别登记。普通背景只保留定位，关键阈值、特殊口径、冲突和用户明确答复可保留必要短摘录。

用户答复登记 user_confirmation 来源，并将结论写入受影响的业务规则或操作。来源位置和版本未知时可省略，不能伪造章节、答复、短时效链接或私有工作目录。

来源冲突按用户指定优先级和最新明确业务确认处理；没有明确优先级时保留冲突证据和问题。日期、文件名和阶段审核本身不证明某一业务说法胜出。来源是 example 的内容不能单独支撑 confirmed。

完整提取仍不能恢复图片含义时，读取可用原材料或保留识别缺口。可见控件不证明选项穷尽，已知刷新动作不证明只有刷新生效。去重必须保留每条独立规则及其条件、范围和观察依据。

输入 confirmationReferences 是程序从本次提取和当前稿中收集的已引用用户确认定位。保留这些来源 ID、定位和 user_confirmation 类型，并在受影响正文或剩余问题中引用。它不包含其他运行，也不能代替对本次自然语言补充的理解。
