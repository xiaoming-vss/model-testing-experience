# 仓库画像分析主提示词

1. 阅读已审核的材料整理结果和仓库清单，确定本次需求涉及的功能和业务对象。以清单中的 `repositoryId` 和 `pathWithNamespace` 标识仓库，逐字保留两个字段。
2. 对每个可分析仓库先看顶层目录、README、依赖与框架配置，再读取少量与需求相关的源码。结合 [角色分类](../references/role-taxonomy.md) 和 [证据规则](../references/evidence-rules.md) 判定仓库级角色，记录足以支持判断的可见证据。
3. 用一句话描述仓库对当前需求承担的职责。技术栈使用可读的主要语言或框架名，关键路径使用仓库内真实存在的相对路径。证据不足时填 `role: "unknown"`、`confidence: 0` 和 `evidence: []`，并在职责摘要中说明证据缺口。
4. 核对清单中每个可分析仓库均已覆盖一次。汇总当前需求的实现分布，输出一句跨仓库总结。
