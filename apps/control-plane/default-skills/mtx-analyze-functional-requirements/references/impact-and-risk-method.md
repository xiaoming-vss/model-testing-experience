# 业务影响链与风险识别方法

此方法以已审核材料整理 JSON 为唯一输入。用它检查每个有依据的变更对象，将有价值的结论写入既有 `impactAreas`、`risks` 和 `openQuestions`；不要增加新的输出字段，也不要把检查表逐项变成输出。

## 影响链

1. **确定起点**：从功能说明和材料块中识别新增、修改、移除或保留的业务对象、功能、操作或状态。材料只描述目标而未交代旧状时，记录目标与未知，不自行判断旧新差异。
2. **沿业务关系追踪**：对每个起点回看已知的上游入口、角色、触发条件和前置状态；向下追踪后续业务活动、状态变化、产物及其已知使用方；再检查材料明确提及的并行功能或共同依赖。只在材料支持时连接节点，直到找不到更多有依据的关系。缺少关键连接时记录中断，按 [待确认问题筛选](../prompts/scope-analysis.md#待确认问题筛选) 规则筛选问题，不补造关系。
3. **沿数据与状态追踪**：检查业务对象或数据从产生、修改、保存到被查看、使用的已知环节，以及状态进入、变更和退出的已知关系。若涉及存量数据、历史产物、迁移或新旧流程，分别识别材料明确的处理范围；未说明的部分保持未知，按 [待确认问题筛选](../prompts/scope-analysis.md#待确认问题筛选) 规则筛选问题，不推定兼容或不兼容。
4. **检查开关及适用范围**：仅当材料提到开关、配置、阈值、角色或适用对象时，检查其与业务路径的已知关系。配置组合或影响须有本次变更的关联依据，才能按 [待确认问题筛选](../prompts/scope-analysis.md#待确认问题筛选) 规则筛选问题；控件相邻或假设存在依赖本身不构成关联依据。
5. **记录最小可追溯链**：每条有独立影响的关系写入 `impactAreas`：`area` 命名受影响的业务范围，`impact` 按“变更起点 → 已知关联 → 受影响对象或待确认处”描述。`testObjectIds` 引用相应对象，`sourceBlockIds` 覆盖链中每个关键关系的材料块。单个变更有不同影响时拆分；相同影响合并。不强行构造完整链路。

## 风险识别

对上面识别出的对象、影响及未解决问题，按实际相关性检查：

- **流程与关联**：变更是否涉及已知上下游、共享业务对象或关联功能；明确关联被影响时，关注其业务后果。关联存在但影响未知时，标记为潜在风险，不断言会发生连锁失败。
- **数据与状态**：材料涉及数据流转、状态切换、产物或存量记录时，关注其一致性、关联、生命周期和新旧衔接是否有明确依据。只从材料识别的对象出发，未知结果留待确认。
- **条件与范围**：涉及角色、可见范围、开关、阈值或适用对象时，检查条件、边界和适用范围是否明确；某条件下成立并不能推出其反面一定不成立。
- **异常与恢复**：材料提及失败、重试、部分完成或中断时，检查业务状态与后续处理是否明确；没有提及相关行为时，仅在它确实影响理解当前需求的情况下提出问题，不发明失败处理规则。
- **理解与验收**：检查材料之间的冲突、示例与正式规则混淆、子问题未答完、图片或信息不可读，以及结果或顺序表述不清；这些风险应说明缺少什么和可能影响什么判断。

每个风险用 `description` 写清“已知变化或不确定性 → 可能影响的业务对象或判断”，并用 `testObjectIds`、`impactAreaIds` 和 `sourceBlockIds` 指向实际相关项；相关项无法确定时关联数组可为空。风险是尚需关注的可能性，不是已发生的缺陷。`confirmed` 仅表示风险所描述的前提及其适用范围有明确依据，不表示风险必然发生；关系或适用范围尚待核实用 `inferred` 或 `unconfirmed`。风险需要补充事实时，按 [待确认问题筛选](../prompts/scope-analysis.md#待确认问题筛选) 规则决定是否提问；符合条件的问题通过 `riskIds` 关联，已有材料问题通过 `sourceQuestionIds` 关联。

不套用固定风险权重、分数或优先级：材料通常不足以支持这些量化判断。风险不直接生成测试点或确定性预期，后续阶段仍须以材料中的已确认内容为依据。

## 依据状态示例

以下为方法假设，不是当前产品事实。判断 `basisStatus` 时覆盖结论的全部关键部分：

| 已知材料与候选结论 | 状态及处理 |
| --- | --- |
| 材料明确“禁用账户不能新建订单”；分析对象为账户状态对新建订单的限制 | `confirmed`，引用该规则；不自动扩大到查看或取消订单 |
| 材料明确新旧报表共用同一统计口径，但未说明此次口径变更如何影响历史报表 | 对历史报表的潜在影响用 `inferred`；若历史处理会改变本次范围，提问确认 |
| 两份现行说明分别要求保留和重算历史报表，尚未确认取舍 | `unconfirmed`，保留两侧引用，在问题中说明影响历史数据预期 |
| 材料只提到新报表，候选写“数据库缓存可能失效” | 缺少关联依据，删除该通用猜测；不为它制造待确认问题 |

风险的 `confirmed` 表示其前提明确，不表示风险已经发生。上述对象、影响或风险均不是测试点名称，也不独立确立产品预期。
