# 测试范围与风险分析 Prompt

输入、修订范围和输出协议沿用 SKILL.md。以下只规定本阶段的方法。

## 分析方法

识别对象后，按 [影响链与风险识别方法](../references/impact-and-risk-method.md) 分析相关业务关系、数据与状态、条件及未确认风险；方法中的检查方向按材料适用性使用。

1. 遍历已整理的功能及相关材料，识别需要测试的业务功能、用户操作、页面入口、业务对象、状态、角色、数据、产物和配置开关；只列对本需求有实际意义的对象，合并同一对象的重复表述。每个对象指出关注原因和来源，不复述一套业务规则。
2. 围绕变更对象检查业务流程上下游、关联功能、角色、状态、数据及存量记录、既有行为和开关影响。区分材料明确的影响与需验证的潜在影响；未提供旧行为、实现或技术资料时保留不确定性，不声称影响范围完整。当前不分析接口对象，不推断服务调用链或数据库结构。
3. 从可辨认的影响与未知中识别会影响测试覆盖或业务结果的具体风险，写明受影响对象及原因。风险是关注方向，不是已发生的缺陷，也不自行赋予业务预期；没有实际依据的通用风险不强凑。
4. 按下方“待确认问题筛选”处理材料问题和新发现的缺口；修订时按“落实用户反馈”更新分析。
5. 回查各条来源是否存在且支持该条实际结论；检查对象、影响和风险间引用有效，未确认、冲突或示例没有被写成已确认事实。只输出分析，不输出测试点名称、测试步骤、用例或一套独立业务规则。

## 待确认问题筛选

- 提问前先回查材料和用户答复，指出与本次变更有关的具体缺口及受阻判断。只有不同答复会改变本次测试范围、关键业务流程或核心结果判定，才输出问题；仅出现同一对象或术语不等于材料支持所假设的关联或用途。
- 已明确业务预期时，沿用已知预期分析；不要仅因缺少实现机制、状态标识、页面展示或验证手段而追问。若材料有具体冲突或未覆盖的业务条件，且会改变上述判断，只问该缺口。
- 对沿用既有规则的明确答复，按其适用范围分析，不为复述旧流程的内部依赖或细节追问；材料显示本次变更与旧流程存在具体冲突或交接缺口且影响上述判断时，可以询问。
- 不从理论上可能的追溯、统计、分类或其他用途反推新需求；材料须支持该用途与本次变更的关系，且其缺失会影响上述判断，才可询问。
- 同一业务决策的相关缺口合并，只问决定方向所需的核心问题；不附带假设的提示、状态或处理选项。已答复部分不重复追问，只保留符合筛选条件的剩余缺口。用户明确排除的事项不再展开；“不关注”等答复的范围含义不清且会实质改变本次分析时，只澄清范围。
- 不提问不代表未知已确认或自动排除测试；不能把用户答复扩展到其明确范围之外。不能仅为了减少问题数遗漏会改变核心业务判断的真实冲突或缺口。

## 落实用户反馈

逐条识别反馈针对的对象、影响、风险和问题，在明确适用范围内修改分析内容，而不是仅复述反馈或原样保留被纠正的结论：

- 对分析范围、表述、合并拆分或误判的明确修正，更新相关对象、影响和风险；用户要求移除或不再关注的分析事项及相关问题不再保留。只调整反馈覆盖的内容，保留其他适用的分析。
- 用户答复涉及新增或纠正业务事实时，先将答复补充到材料整理并审核，再依据更新后的材料修改分析、来源和依据状态。材料尚未确认时不将答复写为已确认事实，也不将依赖该答复的问题标为已解决；保留需要上游确认的缺口。
- 逐项核对问题及其子问题：依据已审核材料或明确的分析范围调整，移除已解决或不再要求确认的部分；部分处理只保留剩余缺口。反馈的对象、意图或范围无法可靠判断时，保留必要的澄清问题，不推定业务事实。
- 修订后回查反馈是否已落实到所有受影响的对象、影响、风险和问题；更新依据状态和来源，清除失效引用，保留未受影响条目的 ID。原始材料用于追溯，不因材料块中仍有旧内容就恢复已纠正的分析或重复提出已处理的问题。

## 依据状态

每条对象、影响和风险必须选择一个 `basisStatus`：

- `confirmed`：内容及其适用范围由已确认材料直接支持，或是这些内容必然且无歧义的逻辑推论；来源必须覆盖结论的全部关键部分。
- `inferred`：材料支持关注该对象或可能影响，但影响是否发生或范围尚未确认；描述须表达可能性，不写成既定事实。
- `unconfirmed`：材料存在未答复、歧义、冲突、示例或不可读信息，无法确认该结论；明确缺什么信息，符合[待确认问题筛选](#待确认问题筛选) 条件的问题列入 `openQuestions`。

状态描述分析的依据，不改变源材料状态。发现来源冲突时保留两侧引用，不自行选择一侧作为事实。空数组代表本次未识别或未记录，不代表不存在或不适用。
