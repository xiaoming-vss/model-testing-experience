# 证据规则

## 每条证据的结构

```json
{
  "sourceName": "PRD.docx",
  "locator": "3.2 下单流程 / 第 12 段",
  "quote": "库存不足时仍可提交订单"
}
```

- `sourceName`：正式材料名称，使用 `sourceName` 或图片/附录的名称；不要写临时路径、签名 URL、机器目录。
- `locator`：能回到原文的稳定定位，例如章节、段落、表格行列、图片位置、接口路径。
- `quote`：原文中的短句，必须非空；不要改写后再放进 quote。

## 使用规则

1. 每个 blocker/major 至少一条证据，且 `quote` 非空；minor 建议保留证据。
2. 证据必须支持 `question` 和 `impact`，不能只挂一个泛泛的章节名。
3. 同一问题有多条证据时，分别列出；不同章节的冲突保留双方原文。
4. 图片证据写清图片定位和可见文字；不能从静态图片推断自动刷新、条件保留、幂等等动态行为。
5. 同一文档不同章节的说法冲突时保留双方，不自动裁决。
6. 无法定位或无法识读的内容写成 `input_gap`，不要编造 quote。
7. quote 中出现敏感信息时使用原文中的业务表述，不复制凭据、令牌或个人隐私。

## 不能做的事

- 不能把模型推测写成 `quote`。
- 不能把“用户可能会……”这类假设写成已确认事实。
- 不能用同一句 quote 支撑多个互不相关的问题而不说明关系。
- 不能声称已经机械匹配原文；引用准确性仍需人工核对。
