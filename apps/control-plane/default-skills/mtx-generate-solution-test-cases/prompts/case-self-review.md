# 用例输出前自查

对照冻结输入、本批测试点、当前候选与本轮修改要求检查；发现可修复问题直接修正，自查不代表独立审查或测试执行。

1. **目标**：本批测试点是否由一条或多条用例承接？典型目标错误发生时，观察能否识别？条件、操作、结果相同的重复是否消除，独立分支是否保留？
2. **依据**：每项确定预期是否由有效材料支持？对象、时间、范围、例外是否保留，是否把示例或风险升级成事实？
3. **准备与时机**：按编写方法第 3 节检查每项前置是否必要；重复确认、通用环境说明和常规入口绑定是否删除，记录/核实动作是否只在实际步骤执行一次？精简后，设备与数据条件、阈值口径、历史产物、账号状态及必要干预/观察能力是否仍保留，且未预设结论？
4. **可执行性**：每步对象、动作、输入或检查范围是否明确且可达？实际故障/事件触发是否执行并核实？集合、否定结果及历史顺序是否有足够证据？
5. **表达与对应**：标题、步骤、预期是否指向同一场景？每步预期是否仅断言本步可观察的结果？普通表单是否被拆成无必要的逐字段检查，预期是否混入猜测文案或本条无关断言？冗余导航、重复全称、无关记录和过长复合步骤是否精简，必要恢复是否保留？
6. **修订范围**：是否保留本轮未涉及的候选和用户编辑，未恢复已删除用例？
7. **交付**：按主技能执行脚本。业务判据未知按澄清分支，执行准备不足写前置；只返回本次模式的结果，不附自查报告。
