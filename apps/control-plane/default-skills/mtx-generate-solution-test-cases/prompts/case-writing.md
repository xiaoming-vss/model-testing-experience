# 完整用例编写方法

输入、冻结依据、用户编辑保护及输出分支以 SKILL.md 为准。先确定要证明的业务目标，再选择足够且清楚的操作和观察。

## 1. 判断能否展开

逐点核对已确认规则、全局限制、例外及关联问题。对每个目标区分：

| 情况 | 处理 |
| --- | --- |
| 允许/拒绝、公式、完成条件或目标依赖的完整范围未知 | 按主技能集中澄清受影响目标 |
| 业务判据明确，但账号、数据、接口绑定、日志或故障控制未配置 | 正常生成；仅列本条必需且尚未包含的准备，按第 3 节控制粒度 |
| 已有合法数据、状态、页面或工具类别足以完成观察 | 直接设计，不索取无关实现细节 |

`coverageGaps`、`reviewIssues` 和历史阻塞结论须结合本条目标重新判断。上游未知不自动阻塞所有下游目标，但不能将未知公式或全集规则伪装为“执行前准备正确答案”。涉及完整性、否定结果或难以区分两类缺口时，读取 [判据与执行准备示例](../references/evidence-and-readiness.md)。

## 2. 确定场景与名称

- 首次生成按测试点原顺序展开，`case_module` 原样取 `module`。一个测试点可展开多条有独立判定价值的场景；等价取值可参数化，写清每组数据、执行轮次及结果，避免组间隐含依赖。
- 比较规则正确与典型错误时的观察结果。若两者相同，先查是否有依据采用其他观察或条件；若混入独立规则而无法在原目标内处理，按澄清协议回上游，不丢弃分支后声称完整覆盖。出现此情况或拆分困难时读取 [场景拆分示例](../references/scenario-case-splitting.md)。
- 标题以自然语序说明本条动作与结果，保留区分场景的必要条件及准确对象范围；一般准备放入前置。默认沿用测试点的功能项前缀，同模块标题唯一；优化时尊重用户明确改名。基线测量使用“测量”或“观察”。
- 首次生成或需要调整分类、优先级时读取 [字段规则](../references/field-mapping.md)。类型列表仅供归类，不授权新增测试点。来源关系由有能力的平台保存，正式 JSON 不添加测试点 ID，也不按数组位置假定映射。

## 3. 准备数据和起点

前置说明执行起点。逐项判断：删去它是否会改变场景或预期、引入无关失败原因，或使必要的操作和观察无法完成？会则保留，不会则删除或合并。按实际需要写，不设条数或字数上限，不把多条内容挤成一个长句。

| 信息 | 放置方式 |
| --- | --- |
| 本条需要的账号权限、数据及初态、业务配置 | 前置简要说明；同一对象的相同属性只写一次 |
| 启动、切换、记录基线、核实动态状态、查询和比较 | 放到实际执行的步骤；已作为可靠输入提供的清单可留前置，步骤不重复制作 |
| 系统已部署、网络正常、页面可访问等通用条件 | 平台已有统一说明时直接沿用；普通用例无需逐条复述，涉及特定网络、版本、浏览器或权限差异时写明对应条件 |
| 故障注入、暂停窗口、后台任务活动等特殊能力 | 仅在本条无法用已有常规操作完成或判定时，说明所需能力和作用对象 |

- 每条用例独立可执行，不默认前一条已准备好数据。登录不是目标时，可简写账号及所需权限；验证登录时从未登录状态开始，准备启用的账号和凭据，不写“已确认该账号可登录成功”预设结论。
- 将重复的“数据满足条件”和“已确认数据满足条件”合并为具体数据要求。普通页面查看、编辑或文案检查直接在步骤表达入口与动作，无需另写“具备查看渠道”“执行前绑定入口与字段”。不因未附 URL 或工具名而机械增加准备项；真正必要的特殊能力不能因精简删掉。
- 保留决定判断的业务差异：设备与数据适用条件、阈值及计量口径、历史产物、账号锁定与失败计数、角色和渠道、会话保存设置等，仅在本条目标实际依赖时写入。不要统称为“准备正常数据”而丢失这些条件。
- 已有记录可作为起点，写清必要状态；验证迁移本身从迁移前开始，验证迁移后能力可使用已有终态。核实初态、启动时配置或干预时机的动作放在对应步骤，前置不提前完成待测写入、迁移或结果验证。
- 记录基线是动作时在操作前做一次。仅保留比较实际用到的标识、时间、字段或内容；普通查看不增加全套日志、哈希和清单，验证历史产物未改写等目标仍保留足够的比较依据。
- 测试数据给出合法取值或明确属性，只有数量影响目标时才规定最小数量；有限样本不证明无限范围，真实 ID 由执行人员定位或记录。普通编辑不因全部合法边界未知而停止，精确边界目标须确认对应口径。
- 用清楚的业务名称区分对象，必要时就地解释简称；指向唯一时可用“该记录”。反向用例排除无关失败条件；集合验证仍需独立预期清单、正反样本及逐标识比较，不能用当次结果自证。

例如：开关文案检查保留有权账号和可查看任务即可；运行中切换开关还需满足生成条件的数据和可干预窗口；锁定测试还需已确认的阈值、锁定时长及初始失败计数。可参考 [完整用例](../references/concise-case-writing.md) 与 [登录示例](../references/login-examples.md)，只取当前分支需要的信息。

## 4. 编排操作与观察

按“准备 → 操作 → 观察 → 必要恢复”写清最短业务路径，不设固定步数。每步有明确对象、动作、必要输入或观察范围；同位置的设置与提交、同对象的读取与比对可合并。登录等普通表单可将输入必要字段并提交合为一步；仅当输入过程、即时校验或交互本身是目标时，再拆分并检查对应表现。跨阶段等待、阶段确认与后续干预应分开，保持步骤可达且预期逐步对应。

- 只有目标需要跨阶段流程时才展开各阶段，分别核对完成证据与下一阶段准入。可选查看不写成推进必做步骤；拒绝或终止后不安排依赖成功的动作，空后继也不证明成功结束。
- 操作路径用已知业务对象与动作表达。常规页面操作按已知业务入口表达；只有必需的特殊接口、日志或故障工具尚未落实时才补充具体准备能力，不虚构实现，也不能只写“按文档检查”。
- 启动前状态影响目标时在启动前确认；需要事后追溯或区分多次运行时，记录必要配置或使用可核实的启动记录；运行中干预前即时确认目标阶段，错过窗口则重新准备。短暂状态需要事件记录或受控观察窗口，不能从最终页面反推经过某阶段。
- 证明未启动或未重复执行时，观察到请求处理及相关调度评估完成的界点，再比较任务活动；立即读一次页面不足以排除延迟启动。并发请求不等于同时执行，场景须符合实际配额。隔离旧事件时按因果归属比较，不要求自然推进的状态绝对不变。
- 故障、回调、暂停或调度控制能力写入前置；实际启用、核实、释放和恢复写入步骤。刷新不等于重复回调，拥有工具不等于触发已发生；验证保存时实际修改并提交不同合法值，不在前置提前完成本次待测写入。
- 需要前后比较时才记录基线、标识与快照；不为普通页面操作机械增加日志、回读或文案检查。多组数据写清重复操作及隔离/恢复方式，动态条件每轮复核。

查询、筛选、分页或排序目标：读取 [步骤粒度示例](../references/step-detail-example.md)。交代初始条件、明确取值、查询触发、结果读取和比对依据；切换时仅在必要且产品支持时清除条件。完整集合跨页时读取相关页，不自动增加分页测试。排序只使用已知字段、方向与同值规则。

## 5. 写逐步预期

- 每个业务判断对应本步实际触发或观察的结果，具体到对象和条件；不以“正常”“正确”代替判据，不提前断言下一阶段能力。普通输入不附加本条目标无关的掩码、控件可操作或“无即时错误提示”等断言。
- 每个确定场景给出由材料支持的明确结果。精确提示有依据时引用；只确认提示含义时写该含义，不拼接多个猜测文案或“常见实现”。存在已确认分支时逐一对应条件与结果；业务规则本身未知时按澄清协议处理。
- 区分受理、启动、完成、产物保留及可查询。材料只支持其中之一时不补齐其他结论；支持执行不等于保证成功，必要条件不等于充分条件。
- 精简时保留时间、数量、范围和例外。例如“尚未完成”不等于“尚未开始”或“没有任何产物”；特定对象的规则不自动推广到整个类别。
- 比较前确认字段语义、单位、精度和来源。当前状态不等于完整历史，页面回显不等于后台生效；已取整显示值不能直接当作精确计算依据。目标依赖未知换算规则时才澄清。
- 将执行中的不变量与稳定后的最终结果分开核对；不能把最终总数套在中间采样。重试目标仅为重新发起时不追加最终成功；目标为恢复后完成时须准备可解除的故障并实际解除。

## 6. 特殊目标、恢复与交付

- 性能或长稳目标读取 [性能与长稳规则](../references/performance-and-endurance.md)。区分已确认阈值的验收与没有产品阈值的基线测量；缺少实验资源可列前置，缺少验收判据才澄清。不自行设定时长、并发或安全阈值，也不把完成测量写成达标。
- 修改共享环境时按需要记录原值，末尾恢复并配对预期；保留测试证据及需求要求保留的产物。恢复不构成新增业务目标。
- 每个已要求分支须有实际操作与观察，或明确参数化轮次；仅在准备清单中出现不算覆盖。逐个核心断言检查：目标失效时，本条是否仍可能通过？补足必要观察，不借此扩展范围。
- 完成主技能指定的自查与结构校验。业务未知按主技能澄清分支交付，其他情况返回正式 JSON；不输出内部分类或准备清单。
