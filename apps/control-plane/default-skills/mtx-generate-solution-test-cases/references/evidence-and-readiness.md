# 判据与执行准备：决策示例

仅在缺口归类、完整性或观察证据容易混淆时读取。以下每例的产品规则都是假设；实际任务仍以冻结输入为准。分类和输出动作以主技能及编写方法为准。这里展示的是确实需要特殊能力的情况；普通页面查看、编辑或提示检查不套用这些准备项。

## 缺少工具，不等于缺少业务规则

已确认规则：订单重复提交不创建第二张订单。未提供实际接口地址和审计查询工具。

- 推荐：仅在常规页面无法精确重复同一请求时，前置说明“测试环境支持重复提交同一请求，并可查看对应订单及请求处理状态”。实际提交、确认处理完成和比较订单标识放入步骤；预期只有一张关联订单。具体接口与字段在环境准备时落实，不在每条用例重复写绑定清单。
- 错误：因为没有 URL 就要求补需求；或者只刷新页面并据此声称已模拟重复请求。
- 边界：如果“同一请求”如何识别本身尚未定义且会改变预期，这部分是业务判据缺口。

## 缺少判据，不能用准备事项掩盖

已知报告需要计算“综合得分”，但公式未确认。

- 精确数值目标：按澄清协议指出缺少公式，不能写“准备正确得分后比较”。
- 独立显示目标：若已确认仅显示输入的得分字段，可准备已知值验证字段对应，不因无关公式未知阻塞。
- 对“所有文件内容完整才放行”，仅确认文件名不足以判断内容完整；若目标仅为指定文件存在，则可以按已知清单展开。

## 独立预期集合

假设测试范围内仅有三条已知记录：记录 A、B 状态为待审核，记录 C 为已发布；筛选规则已确认。

- 推荐：筛选待审核后，逐标识核对实际集合等于 A、B，排除 C，并检查重复；若跨页，读取相关页。
- 错误：只比较数量等于 2。返回 A、C 也有两条，却违反筛选规则。
- 错误：把当次筛选结果抄成预期清单，再与其自身比较。

## 动态与否定证据

假设任务按启动时开关值处理，运行中修改不影响本次任务。

- 在启动前确认开关值，或使用可核实的启动记录；需要事后追溯时再记录必要信息，运行中看到开启不能证明启动时也开启。
- 干预前确认任务尚处于目标阶段，必要时准备受控观察窗口；已结束任务不能用来证明运行中修改的效果。
- “未创建下游任务”需要在本次处理和调度评估完成后查看任务活动；页面暂未变化不是充分证据。
- “尚未完成产物”允许存在处理中间内容，不能改成“没有任何产物”。

## 局部阻塞与执行结果

假设已确认审核后可发布，但审核通过条件未知：验证审核准入时需要澄清；验证待发布状态的发布操作时，可以使用状态可核实的已有记录。若发布目标自身依赖未知审核判据，则仍需澄清。

准备能力未落实时，执行人员记录“未就绪”，不能判为通过；skill 可以先生成准备、操作与判据清楚的业务级用例。只在业务答案无法确定时返回需求澄清。
