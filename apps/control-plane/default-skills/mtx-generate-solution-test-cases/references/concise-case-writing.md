# 简洁而可执行：完整用例示例

普通编辑参考示例一，运行中干预参考示例二；登录与输入校验参考 [登录示例](login-examples.md)。只读取当前目标需要的分支。每例均有独立假设，示例中的业务规则、数量、优先级和产品词不能直接用于其他需求，不固定前置条数或步骤数量。

## 示例一：普通编辑

假设已审核需求确认：有权用户可以修改报告名称，非空合法名称保存后重新打开仍显示新名称；报告列表和详情入口已提供。使用独立测试报告，无共享配置恢复要求。

```json
{
  "cases": [
    {
      "case_module": "报告编辑",
      "case_title": "【报告编辑】验证修改名称并保存后重新打开显示新名称",
      "case_type": "功能测试",
      "priority": "2",
      "precondition": [
        "1. 已登录具有报告编辑权限的测试账号。",
        "2. 准备一份独立测试报告，以及一个与原名称不同且符合已确认规则的新名称。"
      ],
      "test_steps": [
        "1. 从报告列表打开该报告，将名称改为准备的新名称并保存。",
        "2. 返回报告列表，重新打开同一报告，读取名称并与提交的新名称比较。"
      ],
      "expected_results": [
        "1. 名称修改被保存操作受理。",
        "2. 同一报告的名称与本次提交的新名称一致。"
      ]
    }
  ]
}
```

前置只交代身份、对象和用于修改的新值。实际修改、保存和重新打开在步骤执行；不会因读取普通页面而另列入口绑定、日志权限或基线哈希。

## 示例二：运行中关闭深度开关

这是本轮用户认可的表达粒度。示例假设已审核需求确认：设备与数据满足条件时，任务按启动时的开关值处理，运行中关闭不会中止本次深度生成，最终仍生成完整的深度信息和深度预览视频；完整性判据已明确。界面可查看运行阶段及本次产物，阶段持续时间足以完成切换；使用独立测试任务。

```json
{
  "cases": [
    {
      "case_module": "深度开关",
      "case_title": "【深度开关】验证深度生成过程中关闭开关，本次运行仍生成完整深度产物",
      "case_type": "功能测试",
      "priority": "2",
      "precondition": [
        "1. 已登录具有任务配置和处理结果查看权限的账号。",
        "2. 准备一条设备和数据均满足深度生成条件的视频任务，能够在深度生成完成前修改开关。"
      ],
      "test_steps": [
        "1. 打开任务详情，确认深度开关开启，启动本次处理。",
        "2. 等待并确认任务进入深度生成阶段，且尚未完成。",
        "3. 将深度开关关闭。",
        "4. 等待本次处理完成，查看本次运行的深度信息和深度预览视频。"
      ],
      "expected_results": [
        "1. 开关为开启状态，本次处理已启动。",
        "2. 本次任务正在生成深度产物。",
        "3. 开关显示为关闭。",
        "4. 本次运行仍生成完整的深度信息和深度预览视频。"
      ]
    }
  ]
}
```

保留了设备与数据条件、启动时开关开启、进入生成阶段且未完成、在运行中关闭和只查看本次产物。启动状态及干预时机在对应步骤核实，不在前置再写“已确认可进入阶段”或重复记录运行基线。

若实际必须暂停任务才能抓住窗口，则补充该特殊准备并在步骤启用、释放；若界面不能区分本次与历史产物，则补充必要的运行标识或查询能力。新增准备应解决具体缺口，不套用一整套渠道和字段绑定说明。特殊产物完整性目标仍须按已确认判据展开具体检查。

## 前置精简对照

| 繁杂写法 | 推荐处理 |
| --- | --- |
| 数据满足生成条件；另列“已确认数据满足生成条件” | 合成具体的数据要求，保留设备和数据两方面条件 |
| 已记录旧产物基线；第一步再次记录相同基线 | 若是本次执行动作，步骤中在变更前记录一次；前置只说明已有历史产物 |
| 具备查看开关文案渠道；执行前绑定入口和读取方式 | 步骤直接打开任务详情查看文案；前置只保留账号权限及可查看任务 |
| 系统部署完成、网络正常、页面可访问逐条列出 | 普通用例省略通用环境清单；本条特定网络、版本或权限限制仍需保留 |

删除或合并后，回看场景是否仍能区分目标错误。复杂集合、否定结果、故障恢复所需的条件与观察不能被“简洁”省略；判断见 [判据与准备](evidence-and-readiness.md)，查询粒度见 [查询示例](step-detail-example.md)。
