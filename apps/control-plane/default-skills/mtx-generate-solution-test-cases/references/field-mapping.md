# 字段分类与优先级

首次生成或需要修改类型、优先级时读取。本文件给出默认分类，不授权新增测试范围。

- `case_type` 的默认允许值以 [输出 schema](output.schema.json) 中的枚举为准，按下表映射场景；不要把场景名直接当作类型。
- 按当前测试点的实际验证目标选类型，每条只选一个。类型列表仅用于分类，不授权增加对应场景或改变解决方案测试范围。用户明确提供其他平台类型规范时按其规范执行。

| 输入测试维度 | 默认 case_type | 目标明确时的细分选择 |
| --- | --- | --- |
| 功能场景 | 功能测试 | 配置行为选配置相关；安装部署行为选安装部署 |
| 异常/容错场景 | 异常测试 | 可靠性保障目标可选可靠性测试 |
| 用户体验场景 | 易用性/体验测试 | 按当前目标填写 |
| 兼容性场景 | 兼容性测试 | 版本升级行为选升级测试 |
| 权限与渠道场景 | 安全测试 | 仅验证渠道业务支持、不涉及访问控制时选功能测试 |
| 数据与一致性场景 | 功能测试 | 明确验证规格符合性时选规格一致性测试 |
| 边界场景 | 功能测试 | 无效输入或异常处理目标选异常测试 |
| 时序与并发场景 | 功能测试 | 以容错、可靠性或性能为目标时分别选异常测试、可靠性测试或性能测试 |
| 性能场景 | 性能测试 | 指标验收与基线测量均按性能测试归类 |
| 长稳场景 | 长稳测试 | 持续负载、资源趋势及长期业务正确性 |

未列出的输入维度按实际目标从允许列表选择；确实不能归类时使用其他，不直接输出未经允许的类型名称。不得将类型值与优先级值颠倒。

- `priority` 必须是 `"1"`、`"2"`、`"3"`、`"4"` 之一，不能使用数字类型。根据失败的业务影响分配，不仅按测试类型、场景频率或步骤数量判断。用户已指定等级时沿用。

| priority | 判断标准 |
| --- | --- |
| "1" | 支撑核心业务流程，缺失或故障直接导致业务中断或系统无法使用，必须优先实现和验证 |
| "2" | 支撑非核心但重要的业务流程，不阻断核心业务，但严重影响体验或业务完整性 |
| "3" | 支撑非核心、非高频需求，故障仅影响局部体验，对整体业务和多数用户无显著影响 |
| "4" | 支撑个性化、极低频的特殊需求，影响有限，可延后验证 |

优先级是测试设计判断，不是新业务规则。低频但高影响的场景不能仅因低频降为 4；没有明确影响依据时默认 2，不编造风险结论。

- `precondition`、`test_steps`、`expected_results` 均为字符串数组，各自从 `1. ` 连续编号。无前置条件时为 []。
- 测试数据放入前置条件或相关步骤，不新增数据字段。必要的环境恢复动作可作为末尾步骤并配对结果，不新增后置处理字段。

除首次生成的模块和固定协议外，用户的字段内容要求可覆盖本文默认值；名称仍需准确描述本条场景，不改变固定 JSON key。
