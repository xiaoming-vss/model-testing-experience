# 步骤详细度示例

查询、筛选类用例生成前读取。本文件用于校准步骤展开粒度，不定义当前产品规则，不授权增加测试点。

## 不合格的简略写法

1. 进入 数据管理 → 转换数据，记录当前列表中的任务条数与任务清单。
2. 在查询条件中选择转换类型为数据检索发起的数据级转换，点击刷新，查看列表结果。
3. 在查询条件中选择转换类型为数据集管理发起的数据集级转换，点击刷新，查看列表结果。

即使预期写了“仅展示对应类型、条数一致、未混入其他类型”，仍未给执行人员具体的结果读取、字段记录、清单比对过程。不能仅在原句中追加“逐条核对、无遗漏”等词语；应像下例一样，将查询后的检查过程展开为可逐步操作和判定的阶段。

## 应学习的展开方式

- 第 1 步明确页面入口、初始条件与记录内容。
- 第 2 步设置条件并触发查询；第 3 步读取、记录实际结果；第 4 步与预先准备的清单比对，分别配对预期。
- 第 5 步切换条件并查询；第 6 步明确另一组结果的检查范围、字段和比对清单，允许合并清楚的同类检查，不让执行人员猜测。
- 采用相同的详细程度，不机械要求六步，不复制业务选项、数量或未经确认的交互。实际结果只有一页时检查该页；跨页且需要完整集合时检查相关页。
- 输出前以此示例对照：执行人员能否逐步照做，还是需要自己把概括描述补成操作步骤？后者必须重新展开。
