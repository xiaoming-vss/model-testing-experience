# 领域文档

本文档说明工程技能在探索代码库时，应如何读取和使用本仓库的领域文档。

## 探索代码前需要读取

- 仓库根目录下的 **`CONTEXT.md`**；或者
- 如果根目录存在 **`CONTEXT-MAP.md`**，则根据其中的索引读取与当前任务相关的 `CONTEXT.md`；
- **`docs/adr/`** 中与当前工作区域相关的架构决策记录。

如果这些文件或目录尚不存在，直接继续工作，不需要报告缺失，也不要预先建议创建。

`domain-modeling` 技能会在领域术语或架构决策真正明确后，按需创建这些文件。

## 文件布局

本仓库采用单上下文布局：

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-示例决策.md
│   └── 0002-另一项决策.md
└── src/
```

## 使用术语表中的词汇

当 Issue 标题、重构建议、假设或测试名称提到领域概念时，应使用 `CONTEXT.md` 中定义的术语，不要改用术语表明确排除的同义词。

如果需要的概念尚未记录在术语表中，可能意味着：

- 正在引入项目中不存在的语言，应重新考虑；或者
- 领域模型确实存在缺口，应将其交给 `domain-modeling` 技能处理。

## 标明与 ADR 的冲突

如果输出内容与已有 ADR 冲突，应明确指出，而不是静默覆盖既有决策。

例如：

> 与 ADR-0007（订单采用事件溯源）冲突，但由于……，值得重新讨论。
