# 迭代状态由计划时间实时推导

迭代状态是相对于当前时间的时态，而不是需要持久化或触发副作用的生命周期事件：当前时间早于开始时间为 `planned`，处于开始与结束时间之间为 `running`，达到或超过结束时间为 `completed`。后端在响应时实时计算只读的 `status`，写接口不再接受该字段，数据库删除 `sprints.status`；因此修改计划时间后状态会立即重新计算，也不需要定时任务维护可能过期的副本。

每个迭代必须提供带时区的开始和结束时间，且结束时间晚于开始时间；后端统一按 UTC 存储和比较。页面若跨越开始或结束边界，应在边界到达时重新请求后端，但前端不负责写入状态。

**Considered Options**: 使用周期任务把持久化状态从 `running` 更新为 `completed`，但这会引入调度延迟、停机补偿、多实例并发和计划时间修改后的状态修复问题；由前端更新状态则会把领域规则分散到客户端，并产生不可信的事实来源。若未来迭代结束需要冻结数据、审计、通知或触发下游流程，应另行建模显式的关闭事件，而不是改变本 ADR 中的时间状态语义。
