# TestPilot Studio 功能文档

## 1. 文档说明

本文档描述 TestPilot Studio 当前前端版本已经提供的功能能力、页面操作路径、业务规则和已知限制，面向内部产品、研发和测试协作使用。

- 基准范围：当前仓库中的前端实现
- 文档目标：帮助团队快速理解“现在能做什么”“从哪里进入”“依赖什么前置条件”
- 说明原则：不臆造未落地能力；未接入部分明确标记为占位、Coming Soon 或待后端接入

## 2. 产品定位

TestPilot Studio 是一个测试平台工作台，围绕项目、迭代、需求组织测试资产和测试活动。当前产品重点不在公开展示，而在内部测试协作流程的统一承载，核心覆盖：

- 项目管理与需求承接
- 功能测试资产管理
- API 自动化测试资产管理与执行
- UI 自动化测试资产管理与执行
- AI 测试任务录入与跟踪
- 禅道连接与业务绑定

## 3. 典型用户路径

### 3.1 项目与需求主路径

1. 用户登录系统
2. 进入工作台后选择当前项目
3. 在项目总览中创建或维护迭代
4. 在迭代下创建或维护需求
5. 进入某个需求的测试工作台
6. 在功能测试、API 测试、UI 测试之间切换并维护测试资产

### 3.2 API 测试主路径

1. 选择当前项目
2. 进入测试页并切换到 API 标签
3. 选择迭代和需求
4. 配置或选择 API 环境
5. 创建 API 测试集
6. 进入测试集详情维护 API 用例、断言和提取规则
7. 发送单用例请求或运行整个测试集
8. 查看运行历史、运行报告或导出 HTML 报告

### 3.3 UI 测试主路径

1. 选择当前项目
2. 进入测试页并切换到 UI 标签
3. 选择迭代和需求
4. 创建 UI 测试集
5. 在测试集详情维护测试用例与步骤
6. 对单用例执行调试运行
7. 对测试集执行批量运行并查看报告

### 3.4 AI 测试主路径

1. 选择当前项目
2. 进入 AI 测试页
3. 先进入 `Skill库` 或 `生成任务`
4. 在 `Skill库` 中查看当前项目的 AI 资产入口与接入状态
5. 进入 `生成任务` 后，在 `API测试` 或 `功能测试` 中创建任务
6. 选择迭代、需求，填写来源内容和生成指令
7. 运行任务并查看详情页中的结果

### 3.5 基础服务主路径

1. 进入基础服务页
2. 切换到禅道模块
3. 创建禅道连接
4. 在项目、迭代或需求处发起禅道绑定

## 5. 业务规则与约束

### 5.1 项目上下文优先

多数业务操作依赖先选择当前项目，包括：

- 迭代与需求加载
- API 环境加载
- AI 生成任务加载
- 测试工作台中的范围筛选

### 5.2 需求是测试资产的核心归属

当前三类测试资产都围绕需求组织：

- 功能测试集归属需求
- API 测试集归属需求
- UI 测试集归属需求

因此常见前置关系为：

`先有项目 -> 再有迭代 -> 再有需求 -> 再有测试集与测试用例`

### 5.3 Requirement Scope 锁定

从需求测试工作台进入时：

- 迭代和需求上下文会被自动带入
- 子模块不再允许任意切换到其他需求
- 适合围绕单一需求持续完善测试资产

### 5.4 API 运行依赖环境

API 自动化执行前需要：

- 已选择当前项目
- 已存在并选中 API 环境

否则：

- 测试集运行按钮不可用
- 单用例调试也无法获得完整环境上下文

### 5.5 占位能力必须按现状说明

当前文档和产品说明中，以下模块必须明确写为未完成而非默认可用：

- AI 测试中的 UI 生成
- AI 测试中的功能生成
- 基础服务中的 GitLab 服务
- API Body 的 `form` 类型完整编辑能力

## 6. 当前限制

### 6.1 README 与业务不一致

当前根目录 `README.md` 仍是模板内容，不能作为项目说明使用。

### 6.2 部分模块只有前端骨架

以下模块仍处于接入预留状态：

- GitLab 服务
- AI 测试中的 UI/功能生成流程

### 6.3 接口字段风格存在兼容成本

后端字段存在 camelCase 与 snake_case 混用现象，前端已经通过 `normalize*`、`pick*` 等工具函数兼容，但这意味着：

- 页面逻辑中需要频繁做字段兼容
- 后续接口统一化仍有优化空间

### 6.4 部分能力以资产维护为主

功能测试当前重点在测试集和测试用例维护；是否接入完整执行闭环，需要以后端实际能力为准。

## 7. 使用建议

对于当前版本，推荐团队按以下方式使用：

- 用“项目总览”承接项目、迭代、需求基础数据
- 用“需求测试工作台”围绕单个需求沉淀功能/API/UI 测试资产
- 用“测试主工作台”做跨需求的统一浏览和管理
- 用“AI 测试 > Skill库”承接项目级 AI 资产入口，但当前先按后端待接入骨架理解，不要把占位按钮当作已上线能力
- 用“AI 测试 > 生成任务”承接 API/功能生成任务，并在运行前选择合适的 LLM 连接；不要把 UI 占位入口当作已上线能力
- 用“基础服务 > 禅道”统一维护禅道连接，再回到业务页执行绑定
- 用“基础服务 > LLM 模型服务”统一维护可用模型连接，供 AI 测试运行时选择

## 8. 结论

当前 TestPilot Studio 已经形成清晰的测试平台工作台形态，其中成熟度较高的功能集中在：

- 项目、迭代、需求管理
- API 自动化测试
- UI 自动化测试
- 禅道连接管理
- LLM 连接管理
