# 禅道 Bug 同步到平台：需求文档

日期：2026-10-04。版本：v0.1。状态：需求草案，两个业务范围已确认，其余规则待审核。本文用于需求评审和后续拆分实现工单，不代表功能已经实现。

## 1. 已确认需求与背景

用户已确认以下两个范围都要支持：

1. **已关联 Bug 的反向更新**：平台推送到禅道并建立对应关系后，将禅道上的修改同步回同一条平台 Bug。
2. **禅道新建 Bug 的导入**：将禅道中尚未在平台建立对应关系的 Bug 导入平台，并建立后续可持续同步的关联。

当前平台已支持手动向禅道创建 Bug、同步附件和正文图片，并核对远端结果。禅道到平台的 Bug 导入、字段更新及状态回写尚未实现；现有核对入口不能视为反向同步。平台到禅道的状态同步也仍待实现，不因新增反向同步就宣称已完成全部双向同步。

本文沿用平台 Bug、项目成员、服务个人授权、发现迭代、计划修复迭代、处理记录与动态等既有概念。除上述两个业务范围外，后续章节中的功能规则是本草案的建议，特别是触发方式、状态映射、成员映射和冲突处理，需审核后才能作为确定的实现规格。

## 2. 业务目标与边界

- **R01** 两种入口最终都形成平台正式 Bug，而不是仅展示一份禅道只读详情。平台 Bug 可以继续按现有权限查看、筛选、处理和关联测试执行。
- **R02** 已关联 Bug 的反向同步沿用原平台 `bugId` 和项目内 Bug 编号；不得重新创建一条平台 Bug。
- **R03** 禅道新建 Bug 导入时分配新的平台 `bugId` 和项目内 Bug 编号，保留禅道实例、Bug 编号及来源信息。两侧编号不要求相同。
- **R04** 反向同步覆盖草案中的标题、描述、正文图片、独立附件、严重程度、优先级、当前状态，以及已完成映射的责任人；具体处理规则见字段表。
- **R05** 保留平台原有处理记录与动态，追加同步产生的修改记录。不得用禅道历史覆盖平台历史，也不得将同步操作伪装成平台用户过去亲自执行的处理动作。
- **R06** 本期建议先支持用户主动拉取和导入。定时任务、Webhook、实时双向同步及其执行身份另行确定；不得默认借用项目所有者或其他成员的 Token 建立后台同步。

### 2.1 建议的首期入口

| 场景 | 入口 | 建议行为 |
| --- | --- | --- |
| 已关联 Bug | Bug 详情的禅道同步区域 | “从禅道同步”：读取远端变化，展示预览，确认应用 |
| 禅道新建 Bug | 当前项目的 Bug 列表 | “从禅道导入”：选择 MCP 服务和远端范围，勾选候选 Bug，预览并导入 |
| 上次部分失败 | 原详情或导入结果 | 继续未完成部分，跳过已成功的 Bug 和文件 |
| 两端冲突 | 同步预览或结果 | 显示具体字段及两侧内容，按用户明确选择处理 |

项目级批量更新已关联 Bug 可作为后续扩展，不默认包含在首期入口中。入口名称和布局为建议，不要求此时新增独立同步进度面板。

## 3. 实例、项目与身份关联

- **R07** 外部访问继续经过项目配置的禅道 MCP。实际实例必须与当前服务、项目绑定及既有关联一致；使用本次操作者自己的有效 Token。
- **R08** 禅道新建 Bug 的候选范围限制在当前平台项目绑定的禅道项目中，可进一步按禅道执行、状态及关键字筛选。不得使用全实例查询结果直接导入当前项目。
- **R09** 已关联 Bug 的拉取使用原关联实例和禅道 Bug 编号；当前项目默认服务切换不能悄悄改变原关联目标。
- **R10** 一个禅道实例与 Bug 编号组合建议只建立一条有效的平台关联。不同 MCP 端点连接同一实例时，也应识别为同一外部身份，不能因端点不同重复导入。
- **R11** 重复选择、重复提交、并发导入、接口超时后重试，都应返回既有结果或恢复未完成操作，不再分配第二个本地 Bug 编号。不能按标题识别同一 Bug。
- **R12** 若外部 Bug 已关联到其他平台项目，返回当前用户可见的冲突提示，不擅自转移关联，不泄露用户无权读取的项目或 Bug 信息。是否允许同一外部 Bug 被多个平台项目分别跟踪，属于待确认规则。
- **R13** 导入来源与平台创建后推送的来源必须可区分。导入不能伪造一次“平台创建禅道 Bug 成功”的历史；后续平台推送应复用该关联，不再创建同一禅道 Bug。
- **R14** 远端 Bug 移动到其他项目、被删除或失去访问权限时，停止应用变化并说明原因，不自动迁移、删除或解除平台关联。

## 4. 权限与成员身份

### 4.1 建议的角色权限

| 平台角色 | 查看已有同步结果 | 读取远端预览 | 导入新 Bug / 应用完整更新 | 维护项目、迭代、需求和人员映射 |
| --- | --- | --- | --- | --- |
| 项目所有者 | 可以 | 使用本人 Token | 可以 | 可以 |
| 普通成员 | 可以 | 使用本人 Token | 可以 | 只能使用已有共享映射，不能改变所有者管理的绑定 |
| 只读成员 | 可以 | 首期建议不开放主动远端操作 | 不可以 | 不可以 |
| 开发成员 | 可以，限项目 Bug | 首期建议不开放完整更新预览 | 不可以 | 不可以 |

- **R15** 完整导入及应用更新建议要求项目 `write` 权限。不能因为开发成员拥有 `bug_handle` 就授予创建、编辑基本信息、修改归属或导入附件的额外权限。
- **R16** 若后续允许开发成员仅拉取状态或责任人，应作为明确的字段级能力另行设计，不扩大其需求、测试资产或其他项目的访问范围。
- **R17** 预览后真正应用前，再次检查项目角色、本人授权、实例、远端归属和本地版本。预览成功不代表操作权限始终有效。
- **R18** Token 未配置、过期、撤销或无远端读取权限时，停止该操作，保留已有平台数据，并提示操作者处理自己的授权。不得回退到他人的 Token。
- **R19** 禅道用户账号与平台用户 ID 建立显式映射；不按姓名相同自动认定为同一人。责任人必须是当前平台项目中允许被指派的成员。

## 5. 字段同步规则

### 5.1 字段范围与来源

| 字段 | 禅道新建 Bug 导入 | 已关联 Bug 反向更新 | 约束或待确认项 |
| --- | --- | --- | --- |
| 标题 | 导入为平台标题 | 无冲突时更新 | 不静默截断；超出平台限制时提示人工处理 |
| 描述 | 消毒并转换为平台富文本 | 将描述与正文图片作为一组比较、应用 | 图片转成本地 `data-file-id`，不保存外部登录链接作为正文图片 |
| 正文图片 | 下载入平台文件存储并恢复原位置 | 增量下载、复用已有映射 | 成功文件不得因描述重试再次生成副本 |
| 独立附件 | 下载并关联到平台 Bug | 拉取新增文件和明确的内容变化 | 远端删除的处理见文件规则 |
| 严重程度 | 映射为平台等级 | 无冲突时更新 | `1/2/3/4` 建议对应 `fatal/serious/normal/minor`；其他值须报异常 |
| 优先级 | 映射为平台等级 | 无冲突时更新 | 平台仅有 high/medium/low；禅道优先级 2 的归属需确认 |
| 当前状态 | 按已批准规则设置当前状态 | 按变化和映射更新 | 不将所有 active 状态都归为“处理中” |
| 责任人 | 使用成员映射或导入时人工选择 | 映射有效且无冲突时更新 | 未映射、不在项目、已离开项目时不任意指派 |
| 原始提交人 | 保留为外部来源信息 | 不改写本地原始提交人 | 新导入 Bug 的平台创建人建议为导入操作者，外部作者单独保留 |
| 发现迭代 | 从禅道执行的有效绑定解析，或人工选择 | 首期建议不自动改变 | 缺少本地必填发现迭代时不能静默导入 |
| 所属需求 | 通过有效需求绑定解析，可按本地规则留空 | 建议人工确认归属变化 | 不创建同名需求来代替真实绑定 |
| 计划修复迭代 | 导入时按平台规则人工填写或留空 | 默认保留本地值 | 不将禅道构建或执行编号当作平台计划修复迭代 |
| 测试单、执行条目、用例来源 | 新导入时为空 | 保留现有平台来源 | 不猜测本地执行来源 |
| 创建时间与历史作者 | 保留远端原始信息，另记录本地导入时间 | 保留平台原有身份和时间 | 不覆写平台历史动作的操作者和时间 |
| 普通评论及完整远端历史 | 首期是否纳入待确认 | 首期是否纳入待确认 | 之前普通评论非必需；本次两种反向范围确认不自动扩大为历史全量复制 |

- **R20** 字段映射必须有一致规则，导入和后续拉取不能使用两套口径。空值、未知枚举、超长内容和无效时间都应明确提示，不冒用默认值表示远端真实内容。
- **R21** 未映射责任人时，新 Bug 的候选项需人工补齐有效责任人；已有 Bug 保留本地责任人并显示该字段待处理。不得自动指派给导入者或项目所有者。
- **R22** 禅道执行、需求不具备有效本地绑定时，显示待映射项；本地必填项未解决前不进入正式 Bug。人工补齐本地归属不表示在禅道创建或修改资源绑定。
- **R23** 同步严重程度或优先级时，保留原始远端值及本轮映射结果，便于核对有损映射。不要对无法判断的值直接取“普通”或“中”。

### 5.2 已确认的状态模型（2026-10-06）

用户已确认本地状态模型按禅道对齐，见 [ADR 0005](adr/0005-bug-zentao-lifecycle.md)。反向同步仍未实现；下表约束后续字段解释，不把模型调整视为反向同步交付。

| 禅道字段 | 平台字段 | 规则 |
| --- | --- | --- |
| status | status | active/resolved/closed 原值保存，未知或定制状态停止并提示 |
| confirmed | confirmed | 读取真实确认标志，不按责任人或主状态猜测 |
| resolution | resolution | 保留八种处理结论，非 fixed 不当作已修复；postponed 表示延期处理 |
| resolvedBuild | resolvedBuild | 保存明确的解决版本，不用计划修复迭代代替 |
| duplicateBug | duplicateBug | 远端编号先解析同项目平台 Bug 关联，不直接透传为平台列表 ID |
| activatedCount 与动作历史 | activatedCount 与处理记录 | 保留重新激活证据，不新增独立 reopened 主状态，不伪造历史操作 |

- **R24** 状态同步必须一起核对 status、confirmed 和 resolution；信息缺失时提示未完成，不猜测值。
- **R25** 状态变化所附的修复、回归、关闭、拒绝及重开说明建议属于本期必要业务信息，和普通评论分开处理。不得编造修复说明、回归结果、拒绝原因或本地处理人。
- **R26** 已关联 Bug 拉取后的状态可能跨越本地常规单步流转。建议以“禅道同步”来源记录外部变化及原始状态，不通过捏造多次本地人工操作来补齐历史；是否允许直接跨状态应用须确认。
- **R27** 新导入 Bug 可以按批准映射初始化到远端当前状态；首次导入不强制先生成“激活/未确认”再回放全部历史。无法映射的候选项留在待处理区，不静默作为已完成导入。

## 6. 已关联 Bug 的反向更新

- **R28** 点击“从禅道同步”后，以原关联读取当前 Bug、文件信息和本期所需的状态说明；展示本地值、远端值、变化字段、文件数量和待处理项。
- **R29** 没有有效变化时，返回“无变化”，不产生重复处理记录，不改变平台 Bug 编号和业务更新时间。
- **R30** 已确认的字段可在无冲突时应用。描述与正文图片属于一个完整内容单元，不能图片未导入却把描述标记为同步完成。
- **R31** 预览应包含两端版本或内容摘要。确认时任一端发生相关变化，应重新预览，不继续使用过期确认覆盖当前数据。
- **R32** 同步成功后，保存本轮实际确认的两端内容与文件映射，作为下一轮比较基线。没有成功应用的字段不能被标为已同步。

### 6.1 双端修改与冲突

建议按字段组比较“上次同步基线、本地当前值、远端当前值”，不只比较哪个更新时间更新。

| 相对上次基线的变化 | 建议处理 |
| --- | --- |
| 本地未变，禅道有变化 | 可在预览确认后应用远端变化 |
| 本地有变化，禅道未变 | 保留本地修改，提示该内容尚未推送 |
| 两端最终值相同 | 记为已一致，不重复写入或制造冲突 |
| 两端均有变化且内容不同 | 显示冲突，不自动覆盖；用户选择采用禅道或保留平台 |
| 不同字段分别变化 | 可以分别合并；描述与正文图片仍按同一组判断 |
| 缺少可靠基线的旧关联 | 首次展示两端对比，由用户确认建立基线，不直接认定一方正确 |

- **R33** 选择“保留平台”只处理本次拉取的冲突；不得因此立即向禅道发起推送。向禅道修改仍需独立明确的操作。
- **R34** 向平台写入的内容不得马上触发反向推送，避免两侧互相覆盖、重复文件和循环处理记录。同步来源及已应用版本应可识别。
- **R35** 当前只记录创建及图片写入快照，尚不足以作为所有字段的双向基线。不能把一条创建成功记录当作状态、责任人和所有附件都已一致。

## 7. 禅道新建 Bug 的导入

- **R36** 用户在当前项目中选择有效 MCP 服务，查询其已绑禅道项目下本人可访问的 Bug。候选列表分页展示远端编号、标题、状态、责任人、执行、需求和是否已有关联。
- **R37** 支持勾选一条或多条候选 Bug。已关联项不作为“新导入”再次创建，提示从现有平台 Bug 进行同步。
- **R38** 导入预览展示字段转换、图片及附件、本地发现迭代和责任人等必填项，以及无法映射的原因。提供人工补齐必要本地信息的方式，不自动新建成员、迭代或需求。
- **R39** 只有必填项、权限、归属和映射校验通过的候选项才能创建正式 Bug。标题为空、描述无有效内容、状态不可映射等情况应明确显示待处理，不悄悄丢弃候选。
- **R40** 创建正式 Bug 与保存外部关联应保证本地事务一致：不存在“本地 Bug 已创建，但关联丢失，重试又创建一条”的结果。文件操作另按持久化结果恢复。
- **R41** 若先建立 Bug 再传文件，页面必须标记“导入未完成”，不得把缺图的内容展示为完整成功；文件补齐后才完成描述应用。该过程应可恢复，而不靠重新创建 Bug 解决。
- **R42** 批量操作逐条返回创建成功、已存在、待映射、冲突、失败或处理中。单个 Bug 失败不影响其他已成功项，也不能以请求 HTTP 成功代替所有条目成功。
- **R43** 操作中断后，重试只恢复未完成条目及文件。已创建并关联的条目转入补齐或更新流程，保留原编号。

## 8. 描述、图片与附件

- **R44** 读取禅道正文时识别实际 GET/PATH_INFO 文件引用及安装子路径；只有能够验证属于目标 Bug、当前用户可读取的禅道文件才允许下载。
- **R45** 不因远端描述包含任意外链就访问该地址；脚本、事件属性、iframe、任意外部图片及其他不受支持内容应在预览中说明并按平台富文本规则处理。
- **R46** 图片下载到平台统一 S3 私有存储，完成大小、内容摘要和类型校验后，转换为平台 `<img data-file-id="…">` 引用，保持图片的正文位置、顺序和重复引用。
- **R47** 独立附件保留文件名、类型、实际大小和关联。图片同时出现在正文和附件列表时，只保存一份对应文件，不按引用次数重复下载和建档。
- **R48** 文件去重使用禅道实例、远端 Bug、文件 ID 和实际内容版本；不能仅凭文件名或大小认定为同一文件。同名不同 ID、同 ID 内容变化需能够识别。
- **R49** 平台之前推送并已保存映射的文件，反向拉取时优先核对并复用，避免把自己刚上传的文件再导入一份。禅道处理或压缩过的图片按实际下载内容判断，不冒称与原始字节一致。
- **R50** 文件已下载成功但正文应用失败时，保留可恢复的映射，重试复用该文件。临时未完成对象仍须遵守已有清理规则。
- **R51** 远端附件删除、替换或取消正文引用时，建议先显示差异，再按确认结果更新当前附件和正文；平台已有历史证据继续保留，不自动物理删除 S3 对象。
- **R52** 本地新增、尚未推送的附件不能被一次远端拉取移除；无法确认来源的旧文件也不直接归为“远端已删除”。
- **R53** 超限、不支持类型、下载失败、权限拒绝或校验失败的文件，返回明确的逐项结果并保留重试入口；有未完成正文图片时整体结果不能为“全部成功”。
- **R54** 文件访问继续使用平台项目及 Bug 权限。不得将禅道 Token、长期登录链接、S3 凭据或过期签名写入正文、持久化快照、前端结果和日志。

## 9. 同步结果、恢复与动态

- **R55** 区分无变化、处理中、成功、部分完成、冲突、待映射、失败及结果待核对；状态名称可在接口设计时细化，但前端不能混淆这些业务结果。
- **R56** 本地修改成功而响应丢失时，应可查询或重试同一操作得到确定结果，不重复创建 Bug、文件或处理记录。
- **R57** 每轮保留操作 ID、发起人、目标实例、远端 Bug 编号、方向、原始版本、实际应用字段和结果。不能把一次文件成功代表成整个 Bug 成功。
- **R58** 动态显示“从禅道导入”或“从禅道同步”，记录本地实际操作者和本轮时间。远端原处理人、时间、动作说明作为来源信息单独展示。
- **R59** 相同外部事件或相同版本重复拉取，不重复追加状态说明和历史。若历史字段无法稳定识别，则暂保留来源快照，不宣称已实现完整历史复制。
- **R60** 归属切换、原关联重置、权限撤销和并发本地编辑都须与同步执行权协调；操作前后重新核对有效关联，不允许旧操作写入新目标。

## 10. 现有能力与需要补齐的能力

| 能力 | 当前情况 | 本次需要 |
| --- | --- | --- |
| 项目 MCP、个人 Token 与实例核对 | 已有 | 复用本人授权及原实例保护 |
| 读取单个禅道 Bug | 已有，用于推送核对 | 支持反向预览与字段转换 |
| 禅道 Bug 候选列表与导入入口 | 平台未提供 | 增加有项目边界的查询、预览、正式导入与去重 |
| 附件映射 | 已有平台到禅道的上传记录 | 支持反向来源、实际内容版本与双向复用 |
| 禅道文件内容到平台 S3 | 尚无正式反向业务流程 | 验证 MCP 的授权下载和受限传输能力，再接入本地文件生命周期 |
| 正文图片转换 | 已有向禅道的原生链接生成与回读 | 增加禅道链接到本地文件引用的转换 |
| 多字段同步基线与冲突预览 | 未实现 | 独立保存实际已同步的字段版本，支持旧关联初始化 |
| 状态及成员映射 | 反向未实现 | 业务规则确认、兼容验证及实际落地 |
| 导入/反向同步结果与动态 | 未实现 | 持久化、重试、幂等和完整业务提示 |

当前 `get_bug_attachment` 的核对结果不等同于已将文件内容导入 S3。实现时需验证真实文件下载能力、目标禅道版本和 Token 权限，不能仅根据模拟测试或工具名称宣称可用。继续使用 MCP 作为唯一禅道通道，不重新引入旧连接器；具体 API、数据表、镜像升级及传输协议留待方案设计。

新增反向同步与 ADR 0004 的“平台 Bug 与禅道缺陷独立存在”有关联关系扩展，但不应合并两侧编号、重写既有执行来源或删除历史。本文不改变迭代指标和测试报告的数据来源；若实施方案需要改变这些口径，另行提出需求和 ADR。

## 11. 验收标准

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A01 | 已关联 Bug 仅远端修改标题和描述 | 预览准确，确认后更新原平台 Bug，编号和执行来源保留 |
| A02 | 已关联 Bug 远端新增正文图片与附件 | 原位置显示图片，附件可下载；文件与来源映射正确 |
| A03 | 平台推送的图片再次反向拉取 | 复用已确认映射，不多出相同文件，不循环推送 |
| A04 | 同一图片正文引用多次，且列为附件 | 存储一份文件，正文全部位置正确，附件展示符合确认规则 |
| A05 | 导入禅道新建 Bug | 生成一个平台编号，保留远端编号，建立有效关联，进入本地列表和详情 |
| A06 | 重复、并发或超时后重复导入 | 不生成第二条平台 Bug、附件副本或重复动态 |
| A07 | 两端修改同一字段 | 显示双方值和冲突；未经明确选择不覆盖任一端 |
| A08 | 两端修改不同字段 | 按基线分别处理，描述与图片不拆成失去上下文的更新 |
| A09 | 预览后本地或远端继续变化 | 阻止使用过期预览确认，要求重新核对 |
| A10 | 状态及状态说明 | 符合已批准映射，原始原因和来源可查，不伪造人工流转 |
| A11 | 责任人未映射或已退出项目 | 不任意指派，显示待处理；满足本地必填后才完成导入 |
| A12 | 发现迭代缺失、需求未绑定 | 按必填/可空规则处理，不自动创建同名本地资产 |
| A13 | 远端已删除、移动项目或不可访问 | 保留已有平台 Bug，停止错误更新并返回具体原因 |
| A14 | 不同 MCP 端点连接同一实例 | 按实例和 Bug 身份去重，不按端点名称重复导入 |
| A15 | 不同实例存在相同 Bug 编号 | 分别识别，不将文件和内容写到错误关联 |
| A16 | 文件超限、下载中断或类型不符 | 明确部分失败，成功文件保留，补传不重新创建 Bug |
| A17 | 正文含 GET/PATH_INFO 图片链接、站点子路径 | 正确识别并转为本地引用；不出现花括号编码或过期签名图片 |
| A18 | 远端文件被移除，本地存在历史证据 | 按确认规则调整当前内容，历史证据可继续查看 |
| A19 | 本人 Token 或项目权限在操作中被撤销 | 停止后续应用，不使用他人凭据完成操作 |
| A20 | 只读或开发成员尝试完整导入、覆盖 | 返回权限拒绝，不扩大既有角色权限 |
| A21 | 批量导入包含成功、冲突和失败项 | 逐项结果准确，成功项不被失败项回滚，重试只处理未完成项 |
| A22 | 未配置定时同步，用户只读取 Bug 列表 | 不擅自触发后台远端查询、导入或回写 |

只有两条业务链路和图片、附件、权限、冲突及恢复场景完成真实部署验收，才能宣称本期反向同步可用。普通评论是否构成验收门槛，以待确认范围的结论为准。

## 12. 待确认项

| 编号 | 需要确认的业务规则 | 本草案建议 |
| --- | --- | --- |
| Q01 | 首期手动拉取、定时同步还是实时同步 | 首期手动预览和确认；定时/实时另行设计执行身份与触发规则 |
| Q02 | 双端修改时谁优先 | 按字段基线判断，冲突由用户选择；不默认“禅道永远优先” |
| Q03 | 状态映射及跨状态应用 | 审核第 5.2 节；外部变化保留来源，不伪造本地历史动作 |
| Q04 | 优先级 2、duplicate、willnotfix 等有损映射 | 未确认前显示待映射，不静默归入默认等级或拒绝原因 |
| Q05 | 成员映射由谁维护，未映射时如何处理 | 所有者维护显式账号映射；新导入人工补齐责任人，已有 Bug 保留本地值 |
| Q06 | 远端执行或需求没有本地绑定时能否导入 | 必填发现迭代由用户补齐；需求按既有可空规则处理，不自动建迭代/需求 |
| Q07 | 同一外部 Bug 能否关联多个平台项目 | 首期建议一条有效关联；跨项目重复不自动导入或迁移 |
| Q08 | 远端删除附件、Bug 或取消正文引用后的处理 | 不自动物理删除本地 Bug 和历史文件；当前引用变更先预览确认 |
| Q09 | 普通评论和导入前的历史是否需要全部复制 | 首期不要求普通评论和全量历史；状态变更的业务说明保留来源 |
| Q10 | 开发成员是否可仅拉取状态及责任人 | 首期保持完整导入/更新只对 write 成员开放；专属入口另行确认 |
| Q11 | 同步成功的无冲突更新是否可以跳过预览确认 | 首期保留确认；是否提供项目可配置策略后续确认 |
| Q12 | 字段同步的默认勾选范围及部分完成策略 | 按本文字段组预览；允许独立附件部分成功，描述与正文图片完整后才应用该组 |

上述问题不影响本次需求文档产出；进入实现前应把答案写回本文件，避免将建议方案误当成用户已确认规则。

## 13. 建议交付切片

1. 先确认映射、权限、冲突和触发方式，定义关联身份、双端基线和同步结果。
2. 完成已有 Bug 的远端读取、差异预览和字段更新，保留原身份与来源。
3. 完成文件内容导入、正文图片转换、双向文件映射复用和部分失败恢复。
4. 完成状态、人员、迭代及需求映射，验证不扩张既有角色权限。
5. 完成禅道新建 Bug 的候选列表、预览、导入、并发去重和批量恢复。
6. 完成两条链路的真实部署验收，评估是否需要升级并发布 MCP、控制面和 Studio 镜像。

两个业务范围都属于本期目标，切片顺序不表示可以只交付其中一个。
