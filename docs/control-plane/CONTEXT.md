# 测试智能体控制平面

本上下文负责组织测试资产、AI 生成任务及其人工审核与执行流程，管理平台业务状态并提供浏览器及 Worker 的后端接口。独立集成 Worker 执行已启用项目的外部写入，数据、权限与任务事务仍归控制面。

## Language

**项目共享服务**：
项目成员共同可见的 LLM、禅道或 GitLab 服务配置，包含名称、服务地址及模型等非凭据信息，由项目所有者管理；创建服务不要求提供个人凭据。
_Avoid_: 共享授权、共享账号

**服务个人授权**：
成员为某项项目共享服务单独配置的本人凭据；未授权仍可查看服务，调用服务时必须使用自己的授权，撤销本人授权不影响其他成员。
_Avoid_: 服务全局授权

**项目成员**：
加入项目并持有该项目角色的已注册用户；角色包括所有者、普通成员、只读成员和开发成员。
_Avoid_: 项目内所有用户

**项目所有者**：
项目中唯一负责成员管理、项目设置、项目删除及外部资源绑定管理的成员；所有权可转移给已有项目成员，原所有者转为普通成员。
_Avoid_: 创建者（用于表示当前所有者时）

**普通成员**：
可共同维护项目需求和用例、发起测试与 AI 生成任务并审核导入候选生成结果的项目成员；共享资产的操作权限不以创建者划分。
_Avoid_: 管理员

**只读成员**：
可查看项目业务资产，但不能修改资产或发起任务的项目成员。
_Avoid_: 游客

**开发成员**：
仅能查看所属项目 Bug、处理记录与附件，并可评论、转派及更新 Bug 状态的项目成员；不能创建或编辑 Bug 基本信息，也不能访问其他项目业务资产。角色按项目配置，同一用户在其他项目可持有不同角色。
_Avoid_: 全局开发账号、只读成员（指开发成员时）

**AI 生成任务**：
由 AI 产生候选测试资产的任务；生成结果在人工审核通过前不属于正式测试资产。
_Avoid_: AI 任务

**候选生成结果**：
AI 生成任务的一次运行产物，供人工审核并决定是否导入正式测试资产。
_Avoid_: 正式用例、已导入用例

**UI 测试用例**：
归属于 UI 测试套件、包含可由 UI Worker 执行步骤的正式测试资产。
_Avoid_: UI 候选用例、手工测试用例

**个人 GitLab 集成连接**：
由控制平面用户使用其个人 GitLab 凭据创建的连接；可访问的代码仓库资源以该用户在 GitLab 中的权限为边界。
_Avoid_: GitLab 授权、项目共享 GitLab 连接

**个人授权连接**：
用户为访问外部基础服务而配置的本人连接，仅由本人管理和使用；项目角色与资源绑定均不授予借用其他用户授权的能力。
_Avoid_: 项目共享授权

**GitLab 个人访问令牌**：
用户在其 GitLab 实例中创建并手动提交给控制平面的访问凭据；不包含用户的 GitLab 登录密码。
_Avoid_: GitLab 密码、系统自动授权

**项目 GitLab 群组绑定**：
项目与特定 GitLab 实例的群组之间的共享资源关联，由项目所有者管理；外部访问使用操作者本人的授权。
_Avoid_: 项目共享 GitLab 连接

**需求代码绑定**：
需求与仓库、分支之间的关联；仓库须位于项目已绑群组的群组树内（含子群组），外部访问使用操作者本人的同实例授权。
_Avoid_: 需求绑定、代码关联

**基线分支**：
对比代码变更时作为起点比较的分支；由用户手工指定，或自动取之前迭代中该仓库最近一次绑定的分支。
_Avoid_: baseline

**迭代状态**：
迭代相对于当前时间所处的阶段：尚未到开始时间为 `planned`，已到开始时间但未到结束时间为 `running`，已到结束时间为 `completed`；它是由计划开始和结束时间推导的时态，不代表人工关闭事件。计划时间发生变化时，状态随之重新计算，包括从 `completed` 重新变为 `running` 或 `planned`。
_Avoid_: 人工状态、结束事件

**迭代计划时间**：
每个迭代都必须具有含明确时区的计划开始时间和计划结束时间，且计划结束时间晚于计划开始时间。到达计划开始或结束时间的瞬间，迭代进入对应的新状态。
_Avoid_: 开放式迭代、无限期迭代

**代码风险分析任务**：
以需求文档、各仓库相对基线的 diff 与现有测试内容为输入、产出风险分析报告（风险点、受影响用例、覆盖缺口）的 AI 任务；不进「候选 → 审核 → 导入」流程。
_Avoid_: 代码审查任务

**测试单测试图谱任务**：
以测试单中本迭代需求的用例与需求内容为输入、产出用例关联图谱（主骨与关联边）的 AI 任务；归属于测试单而非需求，一次生成对应一次运行，不进「候选 → 审核 → 导入」流程。
_Avoid_: 用例图谱（指功能用例生成链路里锚在需求上的派生产物）、测试报告任务

**运行发起者**：
发起某次任务运行的项目成员，为该次操作提供本人授权；与共享任务的创建者可以不同，后续成员主动触发的阶段使用该次操作人的授权。
_Avoid_: 任务创建者（用于表示本次运行操作人时）

**用例库**：
项目范围内全部功能测试用例的检索视图；用例在库中仍属于其所在的测试集与需求，库不构成新的归属。
_Avoid_: 测试库、用例列表

**用例编号**：
功能测试用例的固定身份。人工创建与文件导入的用例在创建时分配新编号；AI 生成用例在导入落库时沿用候选结果里的编号。编号一经落库便不再改变——编辑、覆盖、重新导入都不影响它；候选编号缺失、超长或已被其他用例占用时另发新编号。用例被硬删除时编号随之消失。
_Avoid_: 生成编号、候选编号、模块内序号

**测试单**：
一次手工测试执行的组织单位，归属于一个项目和一个迭代，由从用例库选入的执行条目组成；测试单不带轮次，多轮执行通过新建测试单表达。
_Avoid_: 禅道测试单（指禅道 testtask 时必须写全）、测试计划、测试任务

**执行条目**：
测试单中被执行的一条用例，保存加入时的用例内容快照，并记录执行人分配与执行结果。
_Avoid_: 测试用例（用于表示平台正式测试资产时）、用例实例

**执行结果**：
执行条目上的人工执行结论，包含步骤级结果、实际结果、证据与关联缺陷；终态为通过、失败、阻塞、跳过。
_Avoid_: 审核（该词专指 AI 候选的审核动作）、测试结论

**执行人分配**：
项目所有者把某执行条目指派给一个项目成员的动作；已分配的条目仅该成员可执行，未分配的条目任何具备执行权限的成员均可执行。
_Avoid_: 认领、分派、负责人

**Bug**：
平台内置的问题记录，使用激活、已解决、已关闭三个主状态；是否确认和解决方案独立表达处理进度与结果，与禅道语义一致。已修复与延期处理不同，重新激活是处理动作，完整过程保留在处理记录中。
_Avoid_: 缺陷单（与禅道缺陷混用时必须写全）、问题单

**Bug 解决方案**：
已解决或已关闭 Bug 的处理结论，包括已修复、设计如此、重复 Bug、外部原因、无法复现、延期处理、不予解决和转为需求。已解决不等同于已修复，延期处理不表示最终拒绝。
_Avoid_: 拒绝原因（作为所有非修复结论的统称）

**处理记录与动态**：
Bug 生命周期里每次流转、转派、编辑、补充附件与评论的完整历史（`bug_activities`），多轮记录全部保留、不覆盖。
_Avoid_: 操作日志（专指系统层日志）、审计日志
