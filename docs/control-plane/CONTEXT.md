# 测试智能体控制平面

本上下文负责组织测试资产、AI 生成任务及其人工审核与执行流程，管理平台业务状态并提供浏览器及 Worker 的后端接口。独立集成 Worker 执行已启用项目的外部写入，独立性能 Worker 执行已冻结的 k6 运行；数据、权限与任务事务仍归控制面。

## Language

**项目共享服务**：
项目成员共同可见的 LLM、禅道或 GitLab 服务配置，包含名称、服务地址及模型等非凭据信息，由项目所有者管理；创建服务不要求提供个人凭据。
_Avoid_: 共享授权、共享账号

**服务个人授权**：
成员为某项项目共享服务单独配置的本人凭据；未授权仍可查看服务，调用服务时必须使用自己的授权，撤销本人授权不影响其他成员。
_Avoid_: 服务全局授权

**性能测试集**：
项目内按顺序组织多条性能用例的测试资产。测试集运行创建父运行和有序子运行条目，控制面一次只向 Worker 暴露一个子运行任务，前一条用例结束后才启动下一条；测试集不合并子运行的 k6 结果，也不跨用例共享变量。
_Avoid_: 并行场景、性能分组

**性能用例**：
性能测试集内以 YAML 描述业务步骤、数据参数、负载模型和验收标准的正式性能测试资产；运行时由控制面补充环境、Remote Write 和限制后冻结为运行规格。用例属于一个测试集，测试集内以 `order_no` 排序。
_Avoid_: 压测脚本、k6 脚本

**性能运行**：
一次性能测试集执行的控制面记录，由父运行 `perf_suite_runs` 和有序子运行条目 `perf_suite_run_items` 组成；父运行冻结测试集名称、环境与监控接入快照，子运行冻结用例版本、YAML、数据文件元数据与完整运行规格。生命周期为 `queued/running/stopping/completed/failed/stopped/canceled`，Worker 只回传执行事实。
_Avoid_: Worker 任务、测试报告

**监控接入**：
项目级的 Prometheus Remote Write 连接配置，包含写入地址、加密的写入凭据和启用状态；发起运行时选择一个，并在运行上冻结不含凭据的名称和写入地址快照。本期平台不保存查询配置，也不提供 Prometheus 查询或外部看板入口。
_Avoid_: 监控配置（指全局配置时）、监控看板连接

**性能数据文件**：
以 `perf_case_data` 用途保存在项目私有 S3 中的 CSV/JSON，用例通过文件名引用，运行冻结文件 ID、大小和 SHA-256；控制面按运行快照流式下发给 Worker，数据库不保存文件正文。
_Avoid_: 用例附件（指普通附件时）、测试数据（指内联 `rows` 时）

**项目成员**：
加入项目并持有该项目角色的已注册用户；角色包括所有者、普通成员、只读成员和开发成员。
_Avoid_: 项目内所有用户

**系统超级管理员**：
由启动配置预置的唯一平台账号，负责账号治理、项目治理和跨项目业务资源访问；不依赖项目成员身份，但作为 Bug 责任人、测试单执行人等指派对象时仍需显式加入项目。不能查看或使用他人的个人授权，不能 impersonate 用户。
_Avoid_: 超级用户（指操作系统账号时）、项目所有者

**项目所有者**：
项目中唯一负责成员管理、项目设置、项目删除及外部资源绑定管理的成员；所有权可转移给已有项目成员，原所有者转为普通成员。
_Avoid_: 创建者（用于表示当前所有者时）

**普通成员**：
可共同维护项目需求和用例、发起测试与 AI 生成任务并审核导入候选生成结果的项目成员；共享资产的操作权限不以创建者划分。
_Avoid_: 管理员

**只读成员**：
可查看项目业务资产，但不能修改资产或发起任务的项目成员。
_Avoid_: 游客

**开发成员**：
仅能查看所属项目 Bug、处理记录与附件，并可评论、转派及更新 Bug 状态的项目成员；不能创建或编辑 Bug 基本信息，也不能访问其他项目业务资产。角色按项目配置，同一用户在其他项目可持有不同角色。
_Avoid_: 全局开发账号、只读成员（指开发成员时）

**AI 生成任务**：
由 AI 产生候选测试资产的任务；生成结果在人工审核通过前不属于正式测试资产。
_Avoid_: AI 任务

**候选生成结果**：
AI 生成任务的一次运行产物，供人工审核并决定是否导入正式测试资产。
_Avoid_: 正式用例、已导入用例

**需求评审报告**：
需求分析首阶段生成的提示性报告，包含评审状态、摘要、问题登记表和覆盖度；只供人工判断，不阻断材料整理，也不作为下游输入。
_Avoid_: 需求理解、材料整理结果

**UI 测试用例**：
归属于 UI 测试套件、包含可由 UI Worker 执行步骤的正式测试资产。
_Avoid_: UI 候选用例、手工测试用例

**个人 GitLab 集成连接**：
由控制平面用户使用其个人 GitLab 凭据创建的连接；可访问的代码仓库资源以该用户在 GitLab 中的权限为边界。
_Avoid_: GitLab 授权、项目共享 GitLab 连接

**个人授权连接**：
用户为访问外部基础服务而配置的本人连接，仅由本人管理和使用；项目角色与资源绑定均不授予借用其他用户授权的能力。
_Avoid_: 项目共享授权

**GitLab 个人访问令牌**：
用户在其 GitLab 实例中创建并手动提交给控制平面的访问凭据；不包含用户的 GitLab 登录密码。
_Avoid_: GitLab 密码、系统自动授权

**需求软件仓库关联**：
需求与软件仓库、工作分支、基线分支之间的关联；一个需求可关联多个软件仓库，每条关联独立保存分支。软件仓库须属于同一项目，外部访问使用操作者本人的同实例授权。工作分支与基线分支在关联/更新时校验存在且当前操作人可访问。
_Avoid_: 需求代码绑定、需求绑定、代码关联

**基线分支**：
代码风险分析对比代码变更时的起点分支；在需求关联软件仓库时必须显式选择，不能与工作分支相同，也不再从历史迭代或旧绑定推断。
_Avoid_: baseline、自动基线

**迭代状态**：
迭代相对于当前时间所处的阶段：尚未到开始时间为 `planned`，已到开始时间但未到结束时间为 `running`，已到结束时间为 `completed`；它是由计划开始和结束时间推导的时态，不代表人工关闭事件。计划时间发生变化时，状态随之重新计算，包括从 `completed` 重新变为 `running` 或 `planned`。
_Avoid_: 人工状态、结束事件

**迭代计划时间**：
每个迭代都必须具有含明确时区的计划开始时间和计划结束时间，且计划结束时间晚于计划开始时间。到达计划开始或结束时间的瞬间，迭代进入对应的新状态。
_Avoid_: 开放式迭代、无限期迭代

**代码风险分析任务**：
以已审核材料整理结果、各关联软件仓库的基线与工作分支、现有测试内容为输入，建 run 时解析并固化 `cloneUrl`/`baseCommit`/`headCommit`，由 Worker 为本次 run 准备独立代码工作区；在分析 skill 就绪前先以只读文件工具和上下文回执验证代码上下文链路。不进「候选 → 审核 → 导入」流程。
_Avoid_: 代码审查任务

**仓库画像任务**：
人工运行的独立辅助任务。用户选择已审核材料整理版本后，控制面冻结该版本、全部关联软件仓库工作分支 HEAD 和克隆地址，由 Worker 只读分析并返回仓库角色/职责 JSON。每次成功运行投影为一个不可变画像版本；画像不进入生成链，不在生成链内产生阶段版本或正式资产，也不传给后续任务。
_Avoid_: 代码风险画像、仓库分析阶段

**测试单测试图谱任务**：
以测试单中本迭代需求的用例与需求内容为输入、产出用例关联图谱（主骨与关联边）的 AI 任务；归属于测试单而非需求，一次生成对应一次运行，不进「候选 → 审核 → 导入」流程。
_Avoid_: 用例图谱（指功能用例生成链路里锚在需求上的派生产物）、测试报告任务

**运行发起者**：
发起某次任务运行的项目成员，为该次操作提供本人授权；与共享任务的创建者可以不同，后续成员主动触发的阶段使用该次操作人的授权。
_Avoid_: 任务创建者（用于表示本次运行操作人时）

**用例库**：
项目范围内全部功能测试用例的检索视图；用例在库中仍属于其所在的测试集与需求，库不构成新的归属。
_Avoid_: 测试库、用例列表

**软件仓库**：
项目级软件资产单元，固定对应一个 GitLab 仓库，包含名称、说明、仓库级 base path 和归属接口；创建与换绑时直接选择 GitLab 连接、群组和代码仓库，Git 仓库须位于所选群组的群组树内并使用操作者本人授权校验，且一个软件仓库不可清空其 Git 仓库。软件仓库由项目所有者维护，可被多个需求关联；需求关联上保存各自的工作分支与基线分支。
_Avoid_: 接口应用、应用、接口模块、API 集合（指软件仓库时）

**接口库**：
项目范围内接口定义的检索视图，按软件仓库组织，仓库内按 OpenAPI 标签（首个 tag）分组；分组不建独立表，展示集合为派生标签与软件仓库保存的手工分组名，支持创建空分组、批量重命名、移除和接口移动，未分类不参与维护。接口定义作为后续生成测试用例的输入，不等同于 API 自动化测试用例，也不以执行步骤为内容。
_Avoid_: 接口用例、API 测试集、接口集合

**接口定义**：
归属于一个软件仓库的 HTTP 接口描述，包含方法、相对路径、请求头、Path/Query 参数、请求体、默认成功响应、security、标签和说明，并可关联一个或多个需求。接口身份由所属软件仓库、方法和规范化路径共同确定；接口删除为硬删除。重新导入按方法与路径匹配：已有接口只更新内容并保留库内标签/分组，新接口使用文档标签。
_Avoid_: 接口文档、接口快照（用于本功能时）

**用例编号**：
功能测试用例的固定身份。人工创建与文件导入的用例在创建时分配新编号；AI 生成用例在导入落库时沿用候选结果里的编号。编号一经落库便不再改变——编辑、覆盖、重新导入都不影响它；候选编号缺失、超长或已被其他用例占用时另发新编号。用例被硬删除时编号随之消失。
_Avoid_: 生成编号、候选编号、模块内序号

**测试单**：
一次手工测试执行的组织单位，归属于一个项目和一个迭代，由从用例库选入的执行条目组成；测试单不带轮次，多轮执行通过新建测试单表达。
_Avoid_: 禅道测试单（指禅道 testtask 时必须写全）、测试计划、测试任务

**执行条目**：
测试单中被执行的一条用例，保存加入时的用例内容快照，并记录执行人分配与执行结果。
_Avoid_: 测试用例（用于表示平台正式测试资产时）、用例实例

**执行结果**：
执行条目上的人工执行结论，包含步骤级结果、实际结果、证据与关联缺陷；终态为通过、失败、阻塞、跳过。
_Avoid_: 审核（该词专指 AI 候选的审核动作）、测试结论

**执行人分配**：
项目所有者把某执行条目指派给一个项目成员的动作；已分配的条目仅该成员可执行，未分配的条目任何具备执行权限的成员均可执行。
_Avoid_: 认领、分派、负责人

**Bug**：
平台内置的问题记录，使用激活、已解决、已关闭三个主状态；是否确认和解决方案独立表达处理进度与结果，与禅道语义一致。已修复与延期处理不同，重新激活是处理动作，完整过程保留在处理记录中。
_Avoid_: 缺陷单（与禅道缺陷混用时必须写全）、问题单

**Bug 解决方案**：
已解决或已关闭 Bug 的处理结论，包括已修复、设计如此、重复 Bug、外部原因、无法复现、延期处理、不予解决和转为需求。已解决不等同于已修复，延期处理不表示最终拒绝。
_Avoid_: 拒绝原因（作为所有非修复结论的统称）

**处理记录与动态**：
Bug 生命周期里每次流转、转派、编辑、补充附件与评论的完整历史（`bug_activities`），多轮记录全部保留、不覆盖。
_Avoid_: 操作日志（专指系统层日志）、审计日志
