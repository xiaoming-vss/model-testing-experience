# 独立集成 Worker 实施记录

本记录对应[拆分计划](integration-worker-split-plan.md)和 [ADR 0006](adr/0006-independent-integration-execution.md)。第一期 P0–P5 已在当前本地环境完成：用户授权的本地环境已全量切换至独立 integration-worker，控制面旧远端写工作流与 Studio 同步调用已移除；旧 POST/PATCH 路由和提示 handler 已进一步清理。首轮验收中的 410 属于清理前版本，当前旧写请求返回 405。收尾回归结果和当前环境证据见末节。此前各节按交付阶段保留，不能将早期“尚未交付”或“两项目灰度”描述当作当前状态。

## 已交付的本地执行基础

- 迁移 `20261006_0030`：独立任务表、步骤表、领取回执表及队列、租约、资源查询索引；存在未完成任务或未知意图时拒绝降级删除表。
- `models/integration_job.py`：冻结源输入与派生映射分离，保存运行代次、领取代次、步骤意图和最小回执；资源删除不级联删除执行历史。
- `schemas/integration_job.py`：两类任务与四类步骤的协议模型，限制远端结果字段，错误仅接收约定的安全代码。
- `repositories/integration_job.py`：独立 SQL 数据访问；精确行领取、目标唯一执行权、有界租约扫描，不触发 AI persist。
- `services/integration_job.py`：入队、领取、输入、续租、预约、结果、证据、撤销和失租命令；领域授权、写前复核和业务结果更新通过明确的 Adapter 接入，命令本身不调用外部服务。
- `domain/integration_execution.py`：任务归并、输入摘要、时间标准化及访问材料持久化检查。
- 配置准备：统一配置新增专属令牌与运行代次、灰度项目及提交/领取开关；`manage.py upgrade-config` 幂等补齐缺项并保留原值和权限，执行默认关闭。控制面新认证器仅接受专属令牌，现有 Worker 路由保持原验证器。
- `services/integration_authorization.py`：只读取本地项目 write 权限、Bug 归属、任务绑定服务和发起人本人连接；撤销、移除成员或降为只读/开发成员均拒绝新访问。凭据由独立 Cipher 解密，令牌从 repr 隐藏，替换凭据或端点会改变访问 revision；不执行远端实例发现。
- `BugZentaoPushService.local_context`：从现有推送预检抽出纯本地绑定与本人连接解析；旧 `context` 继续在其后执行远端发现和实例校验。后续异步提交可冻结本地目标，避免在浏览器提交期间等待 MCP。
- `integration_bug_context`、`integration_bug_steps`、`integration_bug`：冻结实际正文、创建参数、文件元数据及字段前后值，目标与源版本独立计算；预约和结果与既有 Bug/文件/正文/字段记录同事务更新。上传票据在当步预约后签发，仅存在 no-store 响应；派发控制面已验证的工具参数，不在控制面调用该工具。
- 浏览器新增 `zentao-sync-jobs`、`zentao-field-update-jobs`、按 Bug 查询任务；内部新增 claim/input/access/heartbeat/prepare/result/evidence/completed 和 `preflight-failure`。prepare 支持明确的 write/noop/failed 决策，无变化不发写许可；前置失败接口只接受没有写入意图的步骤。最后结果或 noop 自动归并任务。
- 授权撤销、成员降级/移除、用户与连接删除已挂接集成撤销；普通成员降为只读时，仅集成失去 write，不改变既有 AI/API/UI read 语义。实例归档、同实例换 MCP、绑定目标变更和资源删除检查未决写入；队列取消与领域 unknown 同事务落库，原意图仍可接收受限晚到证据。
- 控制面已有租约扫描纳入集成任务，不依赖 Worker 在线。新增本地事务包装仅重试 MySQL 1205/1213 的已中止事务，不重试远端写入。写前权限与快照用当前锁定读取，避免 MySQL REPEATABLE READ 的旧快照重新授予权限。

服务命令与领域更新共用请求事务，由调用者最终 commit；发生错误时回滚整个事务。结果事件先检查原写入身份及同键内容，再返回已接受回执，因此权限撤销、租约过期和 completed 缺失不导致重复应用结果。prepare 响应丢失后查询返回预约事实，writeAllowed 为 false，不重新授予远端写入。unknown 阻塞本任务尚未执行的步骤，后续安全补传由新的手动任务决定；晚到证据不会自动重启旧任务。

MySQL 领取按实例身份的 target key 限制一个活跃任务，按 Bug 的 active scope 限制一个活跃提交。空领取响应和历次领取响应独立持久化，Worker 每次新轮询使用新的 request ID，网络重试复用原 ID。协议不接受凭据、签名下载地址或原始 MCP 错误作为执行历史。

## 原步骤恢复、留存与恢复隔离（2026-10-07）

`integration_recovery` 将现有创建/附件 reconcile、字段 options 回读、正文 no-op 和受限旧编码修复接回原 operation 的步骤账本。领域 CAS、步骤结果及恢复回执在同一事务更新；网络回读结束后重新锁定项目、用户和成员，权限或目标变化时拒绝落库。与恢复事实一致的旧 Worker outbox 可确认原结果，不再次追加动态或执行依赖步骤；有矛盾的证据仍拒绝。Worker 新增外部已创建、回传持续断连、进程被杀、人工核对、旧证据回传及新手动补传的跨进程恢复检查。

迁移 `20261007_0031` 新增恢复标记、历史清理时间和索引，以及持久化的 `integration_runtime` 恢复门控。成功历史默认 30 天，明确失败、部分完成和取消历史默认 90 天；每 300 秒最多处理配置的批量数，默认 100。清理仅移除不再参与当前关联的已知终态任务中的源快照和步骤输入，保留请求摘要、原操作身份及不可变结果回执。当前创建/附件/正文/字段关联、write_intent、unknown 和恢复隔离记录均保护，日志记录 compacted/backlog。新事件不能重新应用已清理历史的领域结果，原事件仍取原回执。

联合恢复要求关闭执行、提交和领取，并提供新的专属令牌及运行代次。备份只保存令牌的 SHA-256 指纹用于拒绝复用，不保存令牌明文。恢复工具把所有非终态或含未决步骤的任务标记为 quarantined，保存原步骤证据，并持久化全局门控；误开配置也不能领取或通过旧写入口执行。原配置/令牌不匹配时拒绝 Worker；关联修改、删除和历史清理保护这些隔离任务。`integration_maintenance restore-review` 提供分页核对清单，Studio 显示恢复隔离。该阶段尚未交付核对放行，后续交付见下节。

## 执行能力、观测与浏览器创建（2026-10-07）
