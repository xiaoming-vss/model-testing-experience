# 功能用例推送与未决写入核对

2026-10-21：功能用例使用稳定远端身份、持久化批次与操作账本。原“执行内同名自动更新”
规则已移除。控制面仍通过项目禅道 MCP 执行明确的一次写入；没有把用例编号放进只支持 Bug
的集成 Worker 协议，也没有新增部署服务。Bug 的队列、回执和恢复流程保持独立。

## 选择与授权

用例库的“导入禅道”先输入产品、模块，再预览所选用例。已有稳定映射的用例按远端编号更新；
没有映射但发现同名候选时，必须选择绑定具体编号或新建独立用例。同名本身不构成身份，
同一远端实例中的用例编号不能绑定两条平台用例。预览不发出远端写入。

服务端验证项目、迭代和需求绑定的实例与层级，检查需求所属产品。绑定或更新既有用例前，
再次确认远端用例属于目标执行、产品和需求。业务调用使用本次操作者本人的 MCP Token，
共享绑定创建人的身份不提供凭据；开发成员和只读成员不能推送。

网络预检后，短事务按项目锁顺序重新检查当前项目权限、账号状态、本人授权、MCP 地址、
禅道实例、资源绑定和用例内容。任一项变化都会拒绝发放写许可。权限材料只驻留内存，
不写入批次、映射和操作账本。

## 批次与一次写入

- 原有单测试集与需求批量推送路径保留，新增可选 `requestId`、`choices` 和 `restoreConfirmed`。
  `choices` 按平台用例编号索引：0 表示明确新建，正整数表示明确绑定远端编号，缺省时同名会被拒绝。
  新前端为同一次提交复用 `requestId`；旧客户端不传时由服务端分配，仍受稳定映射和未决互斥保护。
- `function_case_push_requests` 冻结用户提交范围、目标摘要、用例选择、顺序及原内容摘要。
  同一个用户的请求编号不能用于另一批次；重试不会自动纳入测试集新增加的用例。
  尚未发出许可的原批次用例若内容改变，需重新预览并以新编号提交。
- `function_case_remote_identities` 保存平台用例编号与实例内远端编号的对应关系。
  `function_case_push_operations` 在网络调用前持久化原操作编号、目标、正文和一次许可。
- 调用者先提交意图，再执行一次 MCP 写请求，最后在另一事务保存回执和映射。
  数据库事务不跨越远端写入等待；本地回滚不代表远端写入已撤销。
- 重试已有操作只返回回执，不再发放许可。超时、丢失响应、进程中断或回执提交失败时，
  未决互斥键继续保留，刷新页面、换请求编号或换操作者都不能绕过。

逐项结果为 `success/failed/uncertain/pending/skipped`，成功计数只包含明确成功项。
单测试集首次未完成后停止剩余用例；出现未决结果时，批量请求也停止后续测试集。
已提交但尚无回执的操作先显示 pending，许可时间窗过后显示 uncertain，不自动重发。

## 核对和人工解除

新前端重新预览时读取持久化未决记录，阻止推送并提供核对入口。操作状态也可独立查询。
确认已有结果时，需要远端用例编号；服务端只读核对归属及标题、模块、需求、优先级、前置条件、
步骤和预期，完整内容一致才确认原回执。不能用同名或有效编号替代内容核对。

用户已确认采用以下人工解除规则：只有当前项目所有者，在至少五分钟核对窗口后，填写
8–1000 字理由并明确确认“未写入”，才可解除。普通成员和跨项目系统管理员不能代替所有者
作此决定。系统再次读取候选，若找到与原操作内容一致的用例，会拒绝解除并要求确认已有结果。

人工决定不是系统对“远端绝未执行”的证明。操作者需要核对原操作及远端情况，不能仅凭
列表暂时看不到就确认。账本保留原操作、理由、操作者、时间和只读证据摘要。解除只将原操作
标为明确失败，不触发重试；原请求继续返回原回执，新推送必须重新预览并使用新请求编号。

## 恢复与回滚

共用持久化的集成恢复门控：运行代次或专属令牌不匹配、全局恢复尚未放行时，不能发放用例
写许可。全局放行后，当前恢复批次中尚未核对过的用例仍需项目所有者确认远端情况；确认记录
随操作账本保留。已有当前恢复批次的明确核对记录的用例继续按正常成员权限操作，不永久限制
为所有者专用。未决写入仍须先核对，恢复确认不会绕过互斥键。

迁移 0044 增加映射与操作表，0045 增加批次表。业务资产删除不会级联删除这些证据；非空账本
或批次会拒绝迁移降级。部署回滚必须保留这些表，并在入口层暂停用例推送 POST 后再回退应用，
不得重新开放旧的标题匹配写入口或通过清空账本解除未知结果。普通服务重启不需要清理账本。

## 接口

- `POST /v1/function-test-suites/{suiteId}/zentao/testcases/preview`
- `POST /v1/requirements/{requirementId}/zentao/testcases/preview`
- `POST /v1/function-test-suites/{suiteId}/zentao/testcases/import`
- `POST /v1/requirements/{requirementId}/zentao/testcases/import`
- `GET /v1/function-case-push-operations/{operationId}`
- `POST /v1/function-test-suites/{suiteId}/zentao/testcases/operations/{operationId}/reconcile`

核对请求 `resolution=confirm` 需要 `remoteCaseId`；`resolution=not_applied` 需要 `reason` 和
`confirmedNotApplied=true`。项目访问、资源归属、当前所有权和本人授权全部在服务端检查。

## 读取成本与验证范围

一次批量推送复用同一个执行目录。列表已提供标题时，不再为每条已有用例读取详情；仅在列表
缺少标题或需要核验具体绑定/结果时读取详情。分页保留完整性、重复页及最多 100 页的检查。
预览表使用真实客户端分页；显式编号列表最多 10000 项，远端目录最多 100 页。默认全测试集
的本地读取仍纳入后续 D4 查询治理，不将客户端分页误称为数据库分页。

验证包含真实 HTTP、认证和数据库配合模拟 MCP 的契约，独立 MySQL 的锁与唯一性约束，
以及生产组件的前端交互和浅色/深色、桌面/760px 隔离视觉检查。未向真实禅道写入测试用例。
详细实施和本轮验证记录见[整改实施记录](remediation-implementation.md)。
