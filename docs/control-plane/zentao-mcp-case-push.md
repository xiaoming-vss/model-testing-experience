# 用例推送到禅道 MCP

2026-10-03：项目／迭代／需求绑定、Bug 手动推送和功能用例推送均由控制面直接调用项目禅道 MCP，不经过 AIWork 或 connector-zentao。

## 操作与授权

用例库保留「导入禅道」操作及产品 ID、模块 ID 表单；既有单测试集和需求下多测试集接口路径保持不变。
不再选择旧禅道连接。服务端使用项目 MCP 与当前操作者的 Token；需要项目 execute 权限，普通成员使用本人授权，只读和开发成员不能推送。
旧请求中的 connectionId 不再选择外部连接。旧数据不自动迁移或删除；所有者确认切换禅道时清除本项目旧绑定，再按新目标重新绑定。绑定创建人的身份不提供授权。

提交前核对三层有效绑定、实例和父子关系，再查询真实项目、执行、需求及需求详情。产品 ID 必须与绑定需求所属产品一致。
当前 MCP 缺少项目详情工具，沿用完整项目列表验证。任何前置查询失败都不会发出写入。

## 推送规则

- 分页读取目标执行的用例列表，并读取用例详情，按去除首尾空白的标题匹配；执行列表的 case 字段优先于关联行 id。
- 同名更新第一条匹配的用例，否则创建。保持原连接器的执行范围匹配语义；同一批中新建用例的 ID 立即加入匹配表。
- 保留标题、模块、需求、优先级、前置条件、步骤和预期映射；stepType 为 step，type 为 feature。创建额外传产品、项目、执行。
- 项目、执行及用例分页有完整性检查，用例最多读取 100 页、每页 100 条。重复页、不完整页、无效 ID 或详情会阻止写入。
- MCP 工具为 post_testcases 与 put_testcases_testcasID，参数体名为 payload。更新工具路径参数名称沿用部署契约 testcasID。
- 成功必须有明确的 status=success，创建必须返回有效正整数 ID；更新未返回 ID 时使用已匹配 ID。

## 失败与限制

逐条返回 success、failed、uncertain 或 skipped。成功计数只包含明确成功的用例。
同一测试集发生写入失败后停止余下用例；未知结果也会阻止本次批量请求的后续测试集；超时、异常响应或不能确认写入结果时标记 uncertain，不自动重试。
多测试集结果包含每个测试集及其用例明细，部分写入不会被报告为全部成功。
前端保留部分失败详情；出现 uncertain 时禁用本次弹窗的再次提交，用户应先在禅道核对。

这次沿用按标题匹配的推送模式，没有新增持久化的用例推送状态表；关闭弹窗或刷新后不会保留未知结果锁。
本功能不承诺跨请求严格幂等，人工重试前应核对远端结果。Bug 推送原有独立持久化与恢复流程保持不变。

## 连接器退出范围

默认 Compose、manage.py 和平台示例配置已移除连接器服务、8010 端口及控制面依赖。控制面工厂不再构造 ZentaoResourceClient。
旧远端资源读取路由和前端 API 已移除；新统计快照只采集本地执行数据，不再查询禅道 Bug，外部 Bug 指标为未采集而非零。
历史快照仍可读；重新生成同日快照会使用新口径。旧禅道基础服务 Tab 引导至 MCP。
经用户确认，connector-zentao 的源码、依赖文件、启动入口及专属文档已删除；历史实现可从 Git 历史查阅。

MCP Server 和禅道实例本身仍需运行。部署方式见 [MCP 手动部署指南](zentao-mcp-deployment.md)。
