# API / UI 实时执行

API 与 UI 运行保留控制面持久化任务队列和 Worker 租约。Redis 只传递唤醒、控制和运行变化通知，不能证明任务已经领取或完成；状态与测试集报告以数据库为准。执行器不直接访问数据库。

## 路径和状态

- 当前 Worker 使用 `POST /internal/api-worker/tasks/claim-next`，跨 API/UI 队列按创建时间和主键领取；MySQL 使用 `idx_worker_status_created_domain` 索引按顺序领取并跳过已锁行；仅本次领取事务使用 `READ COMMITTED`，避免并发更改状态时产生范围锁死锁，其余事务维持既有隔离级别。旧 Worker 仍可使用原有分域领取接口，混合版本期间不保证跨域的严格顺序。
- 提交事务完成后，控制面在 Redis 写入有界唤醒提示，空闲的新 Worker 通过阻塞读取各取一个提示，再向数据库领取；提示不是任务账本，断线或提示丢失时仍按配置低频检查。空闲兜底及领取失败重试的等待时间在配置值上下浮动 10%，以错开多个 Worker 的定时检查；默认配置为约 27～33 秒。正常空闲时收到通知立即唤醒；领取失败后的退避等待不受通知打断。控制面同时广播版本化提示以兼容旧 Worker；新 Worker 忽略这种广播，但仍处理旧控制面的原广播。混合版本期间旧 Worker 仍可能同时醒来并产生空领取。一个 Worker 一次只执行一个任务；并行容量来自多个 Worker 进程或容器。
- Worker 在开始、测试集条目变化、UI 步骤变化和结束时回传。控制面先提交再通知浏览器，执行权和过期租约仍由数据库校验。UI 步骤上报只携带本次结果的脱敏快照；截图和 Trace 使用受控文件接口上传与校验。浏览器显示测试集截图时，对象存储必须允许当前页面来源跨域读取，配置见[文件存储](file-storage.md)。
- Studio 通过带 Authorization 头的 SSE 订阅，断开后重连并重新查询；正常连接中不固定轮询结果，断连时每 30 秒查询兜底。连接连续 25 秒未收到任何数据或心跳时视为断开：测试集会重连并补查，单用例调试提示连接断开，不重新提交执行。测试集的连续状态通知在浏览器端 200ms 合并，单用例调试的最终结果直接处理。通知到达时如结果查询仍未结束，先合并通知并等待；刷新请求期间又收到通知时，再读取一次，避免遗漏更新。请求超过 5 秒仍未结束会被中止；超时、网络错误或服务暂时不可用时先补查一次，仍失败则在页面保持查看时每 30 秒恢复查询，收到新通知时立即尝试。权限拒绝等不可恢复的客户端错误不会触发这种后台重试。若运行摘要已结束但报告仍显示运行中，最多额外补查三次，每次间隔一秒；报告到达终态后立即停止。历史抽屉仍低频刷新。

Worker 租约过期后，控制面提交异常状态并唤醒旧 Worker 重新检查权限。旧 Worker 在控制检查或 UI 步骤回传收到明确拒绝时停止执行；普通网络错误和服务端暂时不可用仍按原有恢复流程处理。若通知不可用，控制检查使用低频兜底；无法撤销已经发出的外部请求，人工重试前应核对其实际结果。
发起人的项目访问失效时，控制面将任务标记失败，保留已完成结果，结束正在执行的测试集条目和 UI 步骤，并将未开始的条目标为跳过。项目成员移除或失去项目读取权限时，状态事务提交后通知有权查看的页面并唤醒 Worker；其他授权检查发现失效时也在提交后通知。成员降为仍有读取权限的角色时，已提交运行沿用原有权限策略。
- Worker 在线状态在 Redis 中短期过期，仅用于显示“暂未检测到执行节点”“执行节点正忙”或“正在分配”；它是近似提示，不参与领取或权限判断。关闭页面不停止任务。
- 停止请求先在数据库中记录 `stopping`，通过 Redis 唤醒 Worker；通知失效时 Worker 每 10 秒检查一次。未领取任务直接 `canceled`，已领取任务尽快取消在途操作并回传结果，未开始的测试集条目标为 `skipped`。已发出的外部请求无法撤回。失联任务标记 `error`，保留已有结果，不自动重跑；停止请求先于完成提交时，迟到的成功不会覆盖停止状态。

## 单用例调试生命周期

Studio 的单用例调试先建立订阅并等待 Redis 确认，再提交运行，避免快速完成早于订阅。最终响应先经控制面脱敏，使用共享集成密钥加密后发到本次运行的 Redis 通道；控制面复核发起人登录及项目权限、校验加密消息中的运行身份，再传给页面。UI 截图及 Trace 通过实时连接交付；服务端发送后清理运行记录和队列行，浏览器可能仍在接收。文件标记待删并立即尝试清理，失败后由现有文件清理任务重试。单用例关闭或刷新后结果不可恢复，连接中断时最终结果可能丢失。测试集记录、已完成条目和报告继续持久保存。

UI 调试执行结束后，先推送精简的执行状态，截图和 Trace 随后继续传输；页面在接收期间提示产物仍在传输。传输完成后才展示完整结果。网络中断时，即使已显示执行状态，临时产物仍可能无法找回。

标记为实时调试的单用例运行，其状态查询和 UI 临时截图、Trace 下载也仅允许发起人访问，并仍需项目权限；普通历史手动运行和测试集报告继续沿用项目共享权限。
实时单用例不会作为共享的最近运行出现在代码风险分析摘要中，也不会改变 API 用例的迭代统计；已有手动运行和测试集结果仍按原有规则统计。

当 Redis 在提交前不可用，Studio 使用带 `liveDebug` 标记的普通提交接口继续执行；该模式仍会清理记录，页面可能无法拿到结果。只有明确的 503 走此降级，不对未知网络错误自动重新提交，以免重复执行外部操作。控制面崩溃后，独立的后台任务会清理已经终态但未完成清理的实时调试记录。原有未标记的旧客户端与历史记录继续兼容，不会被此清理器追溯删除；升级所有 Studio 后再停用旧客户端，才能使全部新调试都遵循临时生命周期。

后台恢复将 API 和 UI 分开处理；同一批次中某条清理失败时回滚该条并继续其他记录，失败记录保留待后续重试。每个领域每轮最多处理 100 条，并按主键继续向后扫描；每一遍的上限在开始时固定，扫完后回到开头重试，避免一批持续失败的记录挡住后面的记录，也避免不断新增记录使旧失败永远得不到重试。扫描位置仅保存在进程内，进程重启后从头开始；持续失败仍需排查。

UI 产物由浏览器连接的控制面从对象存储按 192 KiB 读取，通过 SSE 分块发送；Redis 只传输加密的对象位置和小型交付确认。发送受网络背压限制，并在传输前及传输期间定期复查权限；大小与 SHA-256 校验通过后才在页面组装为内存 Blob，断线、权限撤销或校验失败不会把不完整文件作为成功结果。重新运行或离开页面时释放本次 Blob 地址。连接持续 30 秒没有交付进展时结束本次交付；进程崩溃留下的终态任务由后台恢复清理。Worker 回传终态后即可继续领取，产物交付在控制面后台进行，每个控制面进程同时最多处理两个 UI 调试结果。

等待产物交付回执期间，控制面每 2 秒检查一次该运行是否还有订阅者；确认无人订阅时立即放弃等待并清理。活跃连接仍按原有心跳和交付超时处理，Redis 或清理任务故障时不能保证固定清理时间。

以真实 Redis 和对象存储直接消费数据流的本机实验中，同时交付两个 32 MiB 产物使控制面进程 RSS 峰值增加约 7.6 MiB；之前整文件编码路径的合成实验增加约 528 MiB。该数据不代表浏览器端或生产环境峰值。Redis 通知故障仍可能使临时调试结果丢失；它不可替代数据库或文件的可靠清理记录。

## 配置和故障

统一配置在 `config/platform.toml`，用 `python3 scripts/manage.py configure --mode docker` 生成。默认 Compose 启动内部 Redis，宿主机只绑定 `127.0.0.1:16379`；本地模式连接同一地址。`[redis].url` 可配置多机共享 Redis，跨主机应使用具备身份认证和 TLS 的 `rediss://` 服务，控制面各实例和 API/UI Worker 必须连接同一实例并共享同一集成密钥。外部 Redis 的连接凭据仅保存在本地忽略的配置和生成的运行配置，不放到日志。`[control_plane.data.db.user]` 的 `pool_size` 和 `max_overflow` 默认分别为 20 和 10；这是每个控制面进程的连接预算，多实例部署应按进程数核算并结合 MySQL 的连接上限调整。

使用私有 CA 时，Redis URL 可通过 `ssl_ca_certs` 指向 CA 文件，并使用 `ssl_check_hostname=True` 校验主机名；URL 参数中的文件路径需进行 URL 编码。该路径必须在所有控制面和 API/UI Worker 进程中可读，容器部署需由部署环境分别挂载到相同路径；默认 Compose 不会自动挂载自定义 CA。使用系统信任的证书时，可使用各镜像的系统信任库。不要关闭证书校验来替代配置 CA。

Redis 不可用时任务仍进入数据库，Worker 低频检查兜底，页面降级查询或明确提示调试结果可能丢失。控制面和代理须允许 SSE 长连接并关闭缓冲；响应使用 `X-Accel-Buffering: no` 并发送心跳。在线状态超过约 35 秒未刷新会过期，故障或滚动升级期间提示可能短暂滞后。

Worker 的 Redis 订阅及在线状态连接失败后，以 2～4 秒的随机间隔重连，避免大批 Worker 在恢复时始终同时建连；任务仍由数据库兜底，停止检查也保留原有低频兜底。不同实例的网络和故障处理耗时可能延长实际恢复时间。

验收应覆盖 Redis 中断及重连、控制面多实例、旧 Worker 和新 Worker 混合、用户权限撤销、领取竞争、租约过期、停止与完成竞争、单用例快速完成、对象存储失败及清理重试。用户确认可接受的目标为正常网络及 Worker 空闲时，提交到领取和状态变化到页面可见的 P95 分别约 1.1 秒。本机 100 路真实 API 调试、10 个独立进程中的 100 个 Worker 与 4 个控制面实例的多次测试均全部完成，提交到领取的 P95 约为 0.99 至 1.47 秒；8 个实例的四次测试约 1.05、1.09、1.06 和 1.16 秒（最后一次附带通知打点），16 个实例一次约 1.70 秒，单实例一次约 4.38 秒。最后一次 8 实例测试中，从提交到最终收到结果的 P95 为 2.42 秒，包含被测接口的执行时间；100 个运行各收到全部通知；此前按顺序配对发送和接收记录得出的延迟估计缺少事件唯一标识，不能可靠证明通知延迟。这些测试不包含测试集查询、页面渲染及代理影响。实际延迟受部署配置和负载影响，目前不能保证持续达到目标。本机另以 10 个 Worker 接收 100 路真实 UI 调试，全部完成，容量不足时提交到领取 P95 约 25.5 秒。将 100 个浏览器 Worker 集中在限额 8 GiB 的隔离容器时触发内存上限和进程回收，测试中止；应按可用资源配置 Worker 数量或横向扩容，不可把 Worker 数量直接视作机器承载能力。100 个浏览器同时运行及目标部署资源下的完整 P95 仍需验证，不能以合成消息或领取接口压测代替。

另一项单次测试使用真实 Chromium 和测试页面订阅 UI 测试集：经过 200 毫秒事件合并、报告查询及 DOM 更新，从发出状态通知到 DOM 更新约 223 毫秒。测试页面模拟了此流程，不能替代真实 Studio 页面及并发场景的 P95 测量。

另在真实 Chromium 中打开实际 Studio 页面，通过开发代理连接隔离的真实控制面、MySQL、Redis、对象存储和 Worker，成功从页面发起 UI 测试集并显示最终成功状态，确认测试集中途存在 SSE 连接。该单次运行中最近一条通知到观察到页面成功约 656 毫秒；包含浏览器观察误差，且通知未严格标记为最终状态事件，不能作为 P95 或 100 并发验收结果。

随后针对同一实际页面串行测试 10 次，在测试集终态提交后、通知发送前打点，浏览器通过 DOM 变化记录成功展示；每次均核对了 SSE 和最终报告。该小样本范围为 327～372 毫秒，按最近秩计算的 P95 为 372 毫秒；它不代表并发负载或目标部署的 P95。

UI Worker 对 Playwright 驱动启动及浏览器启动分别等待最多 45 秒，超时报告异常，需用户手动重试；清理阶段对 Trace 停止、浏览器上下文和浏览器关闭分别等待最多 3 秒。驱动启动中止或退出超时后会尝试强制结束当前执行所创建的驱动，并等待退出；无法确认退出时报告异常。如果进程已创建但句柄晚到，后台会在接下来的 45 秒内尝试回收。真实故障注入验证了驱动启动卡住、句柄晚到和 Chromium 运行时暂停驱动后的回收。强制结束使用 Playwright 1.60.0 的内部进程句柄，因为该版本没有公开的强制关闭接口；升级锁定版本时必须重新验证这个兼容点及浏览器进程回收。超过后台等待期才出现的句柄以及其他操作系统上的进程树回收仍须验证。部署时仍应控制浏览器 Worker 数量，并关注异常任务与资源占用。
