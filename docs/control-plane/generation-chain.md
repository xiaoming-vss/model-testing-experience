# 需求生成链、阶段版本与正式资产导入

一条需求 + 一种生成类型对应一条生成链，链内阶段有草稿和审核通过版本。需求关联的阶段通过需求生成链启动、编辑、审核和导入；不关联需求的独立任务继续使用原入口。公开运行标识 `runId` 是执行 ID，AI Worker 派发和回传使用 `attemptId`。统一执行身份、历史删除与响应结构的决策见 [ADR 0010](adr/0010-unified-ai-execution.md)。

## 版本与草稿

- `ai_generate_tasks` 是链容器；`ai_generation_stages` 按任务和阶段保存当前候选、审核状态和活动尝试，`ai_generation_attempts` 保存属于阶段的冻结输入、输出及执行状态。需求阶段 Worker 队列通过尝试 ID 精确关联阶段；需求工作区历史接口按尝试分页，概览统计尝试和活动任务。代码风险、测试报告、测试单图谱和独立功能/API 任务的运行也使用统一执行与阶段尝试。
- `ai_generate_stage_versions` 只在审核通过时写入，保存产物正文快照、格式、审核信息和生成时读取的上游版本映射。版本按 `(task_id, stage)` 独立编号。
- 最新版本按版本号最大；不存在主线或“设为当前”。下游默认读取上游最新已通过版本，也允许手动选择历史版本；版本保存实际选择的上游版本标识。
- 上游映射为 `null` 时，来源保持未知，不按时间推定；已记录的上游 ID 保留在版本详情中。
- 草稿依赖的上游版本被硬删除时，不删除其生成尝试，而在尝试上写 `invalidated_at` / `invalidated_reason`。作废草稿保留用于诊断，但不再计入待审核草稿，不能审核或继续优化；界面提示后只能重新生成。
- 草稿只取阶段的当前产物尝试，且该阶段审核状态为待审核、尝试尚无版本。审核不通过即丢弃当前候选，界面回到已有已通过版本（没有历史版本则回到未生成）。新拒绝的候选会清除当前阶段未版本化的已结束尝试中的正文、业务输入快照、修订指令和进度副本，仅保留请求指纹以识别重放；已通过版本及其来源尝试保留。已通过但尚未写入版本的当前产物仍作为草稿展示，供崩溃恢复或版本删除后重新审核。
- `busy` 只表示链上存在执行中的运行；待审核草稿由 `draftCount` 单独表达。审核、继续优化和版本导入不因存在草稿而禁用；启动或重新运行阶段只检查本阶段是否已有待审核草稿，其他阶段的草稿不阻塞。

## 接口

| 接口 | 行为 |
| --- | --- |
| GET `/v1/requirements/{id}/generation` | 四条链的全景：阶段、最新版本、草稿、运行状态、叶子导入状态 |
| GET `/v1/requirements/{id}/generation/{kind}` | 单条链详情，草稿正文只在此返回 |
| GET `/.../generation/{kind}/versions/{versionId}` | 已通过版本内容、审核信息和父链摘要 |
| POST `/.../generation/{kind}/stages/{stage}/run` | 单步生成；可指定上游版本 |
| POST `/.../generation/{kind}/stages/{stage}/revision` | 继续优化当前草稿 |
| PUT `/.../generation/{kind}/stages/{stage}/draft` | 校验并保存当前阶段草稿；`expectedAttemptId` 不匹配时拒绝覆盖 |
| POST `/.../generation/{kind}/stages/{stage}/review` | approve / reject；必须提供 `expectedAttemptId`，approve 可暂停或继续 |
| DELETE `/.../generation/{kind}/versions/{versionId}` | 硬删除版本，并作废依赖草稿 |
| GET `/.../generation/{kind}/versions/{versionId}/import-options` | 已记录且可读取的关联版本、正式目标和当前正式来源 |
| POST `/.../generation/{kind}/versions/{versionId}/import` | 按叶子版本导入；冲突预览与覆盖确认沿用原导入器 |

审核决定与版本写入同一事务；历史上已通过但缺少版本的候选仍可补写版本。同一阶段运行中或存在待审核候选时不能再次生成，不同阶段可以并行；重跑或继续优化只作用于当前阶段，其他阶段的草稿保持不动。

稳定阶段表 `ai_generation_stages` 按任务和阶段保存当前候选、活动尝试及版本计数，防止删除最高版本后重新使用同一版本号。审核后尝试继续下一阶段失败时，响应的 `continuationError` 说明原因，已通过的审核和版本保持不变。旧版本依赖仍保留用于追溯，Studio 不提示“基于旧版”。

保存草稿和审核时传入查看时的 `expectedAttemptId`，保存成功后生成新的编辑尝试；持有过期候选标识的保存或审核请求会被拒绝。服务在保存和审核通过时校验阶段产物格式；未保存的编辑在离开时提示确认。需求关联的已审核版本与当前候选通过阶段链查看和操作。

新派发、修订及首次功能生成会锁定所选上游版本；删除版本前也锁定版本并检查活动尝试，发现依赖时拒绝删除。失败信息保存在阶段尝试中，并不改变已通过版本。

## 阶段产物与执行输入隔离

有人工检查点的运行中，每次派发只拥有当前阶段的产物写权限。载荷中的其他阶段字段属于已选择的上游输入快照，可能是旧的已通过版本，不能据此创建前序编辑尝试、移动前序产物指针或改变前序待审核正文。审核通过并继续时，显式审核的阶段仍可保存本次人工审核内容；无检查点的自动流水线继续允许同一次派发产出多个阶段。

各阶段的候选、审核和版本独立。运行时才选择上游已通过版本，并将实际内容、版本编号和本次指令与队列尝试在同一事务冻结；缺少已通过上游时拒绝派发。继续优化沿用该阶段原尝试的输入快照并叠加自身产物，不从整条链的当前投影重建输入。重新生成按本次请求重新选择上游输入。历史尝试缺少来源记录时保持未知，不按时间猜测。

审核通过并继续先保存当前阶段版本，再经过统一的阶段运行入口选择并冻结下一阶段输入。后续阶段运行期间，前序候选可以单独通过或删除，其审核不能改动正在运行阶段的状态、调度指针或输入；其他阶段可以独立生成或优化。Studio 分开处理操作提交中与链执行中，只有目标阶段正在执行时才禁用其单独审核。

`services/stage_storage` 在阶段派发和 Worker 回传边界执行该限制。回归覆盖前序新候选待审核、下游使用旧的已通过版本时的派发、运行及完成，以及材料提取到需求理解的真实阶段链。

## 正式资产导入来源

`ai_generate_version_imports` 每个受影响的正式目标一行，保存：

- 叶子版本 `version_id` 和叶子阶段；
- 已记录且可读取的关联版本 `parent_versions_json`；未知来源保存为 `null`；
- 本次新增或覆盖的正式用例 ID `changed_case_ids_json`；
- 目标类型/目标 ID、导入前后的目标用例总数、是否混合来源、导入人和时间、叶子版本审核快照。

正式目标表 `function_test_suites`、`api_collections`、`ui_test_suites` 增加 `effective_import_id`，指向最近一次成功导入。已审核的最终版本按自身内容、目标、权限和冲突规则导入，不要求上游版本仍存在或可追溯。功能导入按模块自动创建/复用测试集；API 和 UI 导入必须选择当前需求下的正式目标。

导入仍复用现有冲突预览、覆盖确认和用例编号规则。导入器额外返回每个目标的 `changedCaseIds`；适配层在一个事务里写导入记录并更新目标指针。删除版本时同时删除其导入记录，正式资产和 `effective_import_id` 保留为悬空指针；生成链导入选项据此提示来源已删除，正式资产本身不受影响。

## 正式读取边界

导入完成后，正式资产是独立的测试资源，不反向关联生成链版本。正式读取方（功能测试集、API 集合、UI 测试套件、迭代看板、测试报告）不解析 `effective_import_id`，也不展示来源版本或“来源已删除”。看板按当前迭代关联的用例统计。

生成链自身仍保留 `effective_import_id` 和导入记录：导入选项读取它判断目标是否已导入、展示本次导入后的版本指针，并阻止同一版本重复导入。删除版本后指针保留为悬空值，生成链据此提示需要重新导入；正式用例不受影响。

## UI 生成输入与来源追溯

UI 生成以源码 ZIP 和当前需求下的正式功能用例为输入。Studio 首次生成复用功能用例选择器，默认全选，允许按测试集和标题筛选后调整范围；后端验证非空、不重复及需求归属，并将用例原文、源码文件身份、文件名、大小及摘要冻结进运行快照。

首阶段运行请求支持可选 `functionCaseIds` 与 `refreshInputs`（默认 `false`）。旧请求省略用例编号时仍读取当前需求全部正式功能用例。普通重跑沿用运行快照；已有运行上更换输入必须在 `ui_surface` 阶段明确提交 `refreshInputs: true`，从首阶段创建新的输入批次。元素控件阶段执行中不能更换输入；更换输入会取消旧批次仍在执行的后续阶段，迟到回传不能生效。`requestId` 用于重复提交去重。

审核通过并继续时，可用 `requestId` 重放同一审核及后续派发；相同标识必须对应相同审核输入和审核人。审核已保存但下一阶段派发失败时，重试会继续使用该审核版本及其上游版本；成功派发后的重放复用原队列，不重复启动。Studio 在页面存续期间为失败的相同请求保留标识，成功后重新分配。

更换输入会保留已通过版本，将旧运行未版本化的尝试标记为失效。新运行的 UI 设计和 YAML 仅可使用同一运行审核通过的上游，不能混用上一轮产物；历史版本仍可查看、对比和按已有规则导入。当前源码文件或所选正式用例发生变化时，生成链返回 `sourceChanged`。

详细链、草稿及版本详情的 `sourceInputs` 返回源码元信息与冻结的用例正文，Studio 在来源追溯中展示并支持展开。版本审核时将来源复制进版本上下文，不依赖后来更换的任务配置；版本来源读取对应阶段尝试，未记录的信息显示为未记录。该读取结构不包含 Worker 下载地址或授权材料；概览不重复返回完整用例正文。

回归入口：Studio 的 `UiGenerationInputsModal.test.tsx`、`RequirementGenerationPanorama.test.tsx`、`UiGenerationCaseSelector.test.tsx`，以及控制面的 UI 生成链与导入测试。

生成链继续优化请求支持可选 `attachmentFileIds`（默认空列表，最多 6 个）。沿用既有优化附件的项目、上传者、用途、图片格式和大小校验，附件绑定当前尝试，元信息只冻结到本轮尝试的 `revisionAttachments`，通过既有 Worker 图片票据获取；下一轮未选择的图片不自动沿用。

## API 测试两阶段生成

需求画布中的新 API 生成运行依次执行「接口配置提取」和「API 用例生成」。前者生成 JSON，审核通过后形成版本；后者选择已审核的提取版本作为冻结输入，生成 YAML，审核通过后可导入。首阶段支持审核通过并继续、重新生成与优化；删除上游版本时沿用依赖草稿作废规则。阶段输入快照包含 `apiWorkflowVersion: api_two_stage/1.0`。重跑提取会创建该阶段的新尝试，保留已审核版本。

API 阶段运行的补充指令写入本次派发的输入快照；审核通过并继续时，可在审核请求中通过可选 `instruction` 为下一阶段提供指令。省略时沿用现有空指令行为，不改变旧客户端契约。

API 测试集可以在有写权限的同一项目内调整所属需求；更新接口的可选 `requirementId` 不传或为 `null` 时保留原归属，空字符串无效。目标需求的同名集合会阻止修改。测试集、用例及导入来源记录随集合保留；API 运行历史的需求和迭代字段按集合当前归属解析，变更后历史显示的归属也会随之变化。导入目标列表按当前需求筛选。

## 独立阶段存储与派生图谱

实现见 `apps/control-plane/src/testing_agent/services/stage_storage/`。派发和审核锁定阶段及相关版本，同阶段不可并发执行，不同阶段互不阻塞；失效的 Worker 回传不能覆盖当前尝试。版本删除检查在途引用，审核版本及正式用例不会被上游重跑修改。

功能图谱是不审核的派生物，按已审核完整用例版本保存来源，不修改完整用例正文。图谱必须显式关联审核通过的完整用例版本。继续优化图片按尝试授权并冻结，API、功能及需求分析支持图片，UI 阶段暂不支持。

需求关联运行启动 URL 只返回阶段链引导信息；需求生成阶段使用需求生成链阶段运行接口。非需求关联的独立任务使用独立运行协议。

需求阶段不保存详细执行进度或单独的处理建议；Worker 进度回传执行身份、租约和阶段状态校验，失败信息保留并在阶段详情展示。AI Worker 的进度和完成回传使用 `attemptId`，平台接口的 `runId` 仍表示执行 ID。

## 代码风险、测试报告和测试单图谱执行

测试单图谱使用 `ai_executions` 保存执行身份，使用该任务的 `generate` 稳定阶段及独立尝试保存输入、状态、错误和结果。客户端的 `runId` 是执行 ID；AI Worker 队列和回传中的 `attemptId` 是该次尝试 ID。图谱不需要人工审核；同一测试单存在活动尝试时不能再次派发，失败不会覆盖以前成功的结果。平台组装的图谱输入为每条本迭代需求取其最新已审核需求理解版本作为 `requirement_content`，任一需求缺失时拒绝并列出需求名称；调用方自行组装并派发的图谱输入仍按既有契约原样转发，平台不重写其内容。

测试报告同样使用单阶段执行；输入快照冻结本次迭代、日期和每日指标，成功正文可按原接口导出 PDF。同一迭代存在活动报告时不能再次派发，失败记录不会覆盖以前的成功报告。

代码风险使用相同的单阶段生命周期，快照包含需求、仓库、工作/基线分支以及解析固化的 `cloneUrl`、`baseCommit`、`headCommit`；领取、凭据下发和回传均重新检查发起人的项目及个人授权。快照的需求内容取最新已审核需求理解版本，或在发起时通过可选 `requirementUnderstandingVersionId` 指定历史版本，并冻结 `requirementUnderstandingVersion` 以便追溯；没有已审核版本时拒绝发起，不回退 `document_content`。单个代码风险任务存在活动尝试时不能再次派发。

三类辅助任务的并发保护和任务删除检查以稳定阶段的活动尝试为准。代码风险、测试报告、测试单图谱和独立生成任务的历史列表只读取执行记录；辅助任务详情、删除和报告 PDF 只接受执行身份。

独立多阶段执行按执行和派发身份解析 Worker 权限：队列始终指向该次派发的初始尝试，连续生成进入下一阶段时，新的阶段尝试仍属于同一执行及同一派发。每次回传需要重新校验原操作者及其个人授权，并在同一事务中锁定执行和当前阶段；跨执行、已终止执行及过期派发不能改变候选。启动与继续派发使用唯一队列记录预占请求标识，失败时回滚预占，避免 MySQL 缺失键的间隙锁冲突。

独立执行的同一请求标识重放使用当前读取核对操作者、执行和冻结输入，避免 MySQL 可重复读事务中的旧快照漏掉已经提交的派发。Worker 先锁队列、再锁执行；已经持有执行锁的审核重放不会等待被占用的队列行，调用方可稍后用相同请求标识重试。

独立功能导入需指定目标需求；独立 API 导入需指定目标集合。前端按项目提供迭代和需求选择，并按所选需求加载集合。功能、API 和 UI 候选导入与删除使用统一的导入来源记录，正式目标保留 `effective_import_id`。

修订附件的文件授权从冻结的阶段尝试输入核对文件 ID 和所属项目。需求阶段以尝试 ID 绑定附件；独立多阶段执行以执行 ID 绑定，并检查引用附件的尝试与执行属于同一任务。

任务删除按阶段尝试清理 AI 队列；正式资产继续保留，版本来源指针保留“来源已删除”提示，独立候选来源指针清空。删除独立任务前会锁定任务并检查是否存在仍在推进的执行。

授权撤销按派发尝试冻结的操作者、项目和个人连接匹配 AI 任务，并在同一事务内终止匹配的活动尝试。Worker 上下文读取通过队列对应的尝试解析任务及模型连接。

代码风险、测试报告和测试单图谱的发起请求可携带 `requestId`（最长 64 字符）。同一 AI 队列域内，请求标识绑定任务、操作者和规范化请求输入；相同请求重放返回原执行，输入或身份不一致则拒绝，并重新检查操作者及个人授权。不传时每次发起生成新的标识；执行及其队列被手动删除后，原标识可再次使用。Studio 相关入口在页面存续期间为相同输入复用失败请求的标识，成功后重新分配；页面重新加载后不会保留待重试标识。

辅助任务阶段及 AI 队列通过唯一键插入预占，避免对不存在的键加间隙锁；预占和尝试创建处于同一事务中，失败或回滚时不会遗留队列记录。相同业务对象仍由父对象及活动阶段约束互斥。

需求生成链的阶段启动和优化也使用请求指纹：重放必须匹配发起人、任务、阶段、操作、模型连接及所提交的配置、上游选择或优化内容，并重新检查个人模型授权。队列身份在读取上游输入或绑定优化附件前预占；事务回滚时预占、阶段变更和附件绑定一并撤销。

## 历史与删除

代码风险、测试报告和测试单图谱按执行保留每次生成结果。失败记录展示错误，已成功结果继续可查看；同一业务对象存在活动执行时不能再次派发，失败不会覆盖之前成功的结果。历史按执行分页，详情读取正文，列表不返回大字段。

有写权限的用户可以逐条删除已结束的执行记录；运行中的执行禁止删除。删除只清理该执行、阶段尝试和对应 AI 队列，不删除任务、需求、正式用例、测试单或报告。正式测试资产不随执行历史删除。
