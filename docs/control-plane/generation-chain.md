# 需求生成链

需求生成链把需求材料、功能用例、API 用例和 UI 用例拆成独立阶段。每个阶段可以保留多个候选，但最多只有一份当前采用内容。候选不设数量上限，也不会自动删除。历史需求关联和 RAG 不属于本次改造。

## 生成、试用与采用

需求评审和材料整理分别消费需求文档，评审为建议性结果，不阻塞材料整理。功能链依次为测试需求分析、测试点和完整用例；API 链依次为接口提取、用例设计和用例生成；UI 链依次为页面分析、用例设计和用例生成。仓库画像有独立的候选和当前内容。

普通生成读取各上游阶段的当前采用内容。试生成可以显式选择上游候选，即使它尚未采用；服务冻结本次实际选择及完整来源，不会因为其他候选或当前内容发生变化而改写已生成候选。每个阶段同时只允许一个活动生成尝试，成功结果进入候选池；失败不会覆盖当前内容。

采用候选前，服务校验需求、候选令牌、当前内容令牌、根输入和候选自身的冻结来源闭包。采用是阶段本地指针，不要求上游当前内容与候选来源一致，也不要求按依赖顺序逐级采用；上游换采用不会影响已采用的下游内容、候选或导入。采用可以选择继续生成下一阶段；如果后续派发失败，已完成的采用保持有效。决策见 [ADR 0025](adr/0025-independent-stage-adoption.md)。

候选的手工编辑和继续优化都不会直接覆盖已采用内容；已被引用的候选需派生新候选后修改。优化使用冻结的来源和本轮指令，支持的阶段可附加图片。请求标识与操作者、阶段、输入及动作绑定，重放不会重复派发。

## 接口

需求链以 `/v1/requirements/{requirementId}/generation/{kind}` 为前缀，阶段路径为 `/stages/{stage}`：

- `POST /candidate-chain` 初始化工作区；`POST /stages/{stage}/candidate-run` 发起普通或试生成。
- `GET /stages/{stage}/candidates` 和候选详情读取候选；候选编辑、派生、优化及处置使用候选子路径。
- `GET /stages/{stage}/current` 读取当前内容，`POST /stages/{stage}/adoption/check` 预检，`POST /stages/{stage}/adoption` 采用。当前内容与候选详情返回 `basisSources`，列出冻结依据中的阶段、候选、快照及是否为本次直接选择；采用预检只报告该阶段目标或候选已变化等并发阻塞。具体请求契约以路由和 OpenAPI 为准。
- `POST /stages/{stage}/current/import-preview` 预览导入，`POST /stages/{stage}/current/import` 确认导入。具体请求契约以路由和 OpenAPI 为准。

## 正式资产和来源

只有叶子阶段已采用的当前内容可以导入正式资产；导入只校验该内容自身的冻结来源闭包、需求根输入、目标和令牌，不比对当前上游采用链。导入前预览目标冲突，确认时重新校验来源、目标和权限；功能用例按模块创建或复用测试集，API 和 UI 用例选择需求下的正式目标。

`ai_generate_imports` 保存导入正文、来源快照、目标及变更用例；`ai_generate_import_requests` 保存幂等请求。回执独立于候选、任务和运行记录，删除生成记录不删除正式功能、API、UI 用例或其来源回执。旧生成版本和运行历史不迁移。

## 输入与运行

功能链使用材料整理的当前内容或显式选择的候选；测试点和完整用例沿用对应来源快照。API 输入来自所选接口的锁定快照；UI 输入冻结仓库画像、提交和选中的正式功能用例。运行开始后，上游变化不会修改本次输入；再次采用或导入时也只校验该内容自身的冻结来源，不追随当前上游。多上游同时参与生成时，若各来源不属于同一完整分支，服务拒绝并提示用试生成选择一致的一组候选。功能关系图使用当前完整用例来源，独立任务保留原有关系图流程。

代码风险、仓库画像和测试单图谱使用当前采用材料，不读取历史材料版本。Worker 回传以尝试身份和租约校验；阶段可展示活动尝试进度及失败原因。项目和个人连接授权在派发及回传等边界重新检查。

## 实现与验证

- 候选、来源闭包与采用：`services/generation_candidate_*`、`services/generation_source_*`、`services/generation_adoption_application.py`。
- 正式导入：`services/generation_current_import.py`、`services/generation_import_application.py`。
- 数据模型：`models/generation_candidates.py`、`models/ai_generate_import.py`；数据库通过预发布唯一 Alembic 基线初始化。
- 验证：候选端到端、并发、来源一致性、正式导入和独立任务测试位于 `apps/control-plane/tests/`。

## 代码风险、测试报告和测试单图谱执行

测试单图谱使用 `ai_executions` 保存执行身份，使用该任务的 `generate` 稳定阶段及独立尝试保存输入、状态、错误和结果。客户端的 `runId` 是执行 ID；AI Worker 队列和回传中的 `attemptId` 是该次尝试 ID。图谱不需要人工审核；同一测试单存在活动尝试时不能再次派发，失败不会覆盖以前成功的结果。平台组装的图谱输入为每条本迭代需求取其当前采用的材料整理内容作为 `requirement_content`，任一需求缺失时拒绝并列出需求名称；调用方自行组装并派发的图谱输入仍按既有契约原样转发，平台不重写其内容。

测试报告同样使用单阶段执行；输入快照冻结本次迭代、日期和每日指标，成功正文可按原接口导出 PDF。同一迭代存在活动报告时不能再次派发，失败记录不会覆盖以前的成功报告。

代码风险使用相同的单阶段生命周期，快照包含需求、仓库、工作/基线分支以及解析固化的 `cloneUrl`、`baseCommit`、`headCommit`；领取、凭据下发和回传均重新检查发起人的项目及个人授权。快照使用当前采用的材料整理内容及其来源快照；没有当前材料或来源已失效时拒绝发起，不回退 `document_content`。单个代码风险任务存在活动尝试时不能再次派发。

三类辅助任务的并发保护和任务删除检查以稳定阶段的活动尝试为准。代码风险、测试报告、测试单图谱和独立生成任务的历史列表只读取执行记录；辅助任务详情、删除和报告 PDF 只接受执行身份。

独立多阶段执行按执行和派发身份解析 Worker 权限：队列始终指向该次派发的初始尝试，连续生成进入下一阶段时，新的阶段尝试仍属于同一执行及同一派发。每次回传需要重新校验原操作者及其个人授权，并在同一事务中锁定执行和当前阶段；跨执行、已终止执行及过期派发不能改变候选。启动与继续派发使用唯一队列记录预占请求标识，失败时回滚预占，避免 MySQL 缺失键的间隙锁冲突。

独立执行的同一请求标识重放使用当前读取核对操作者、执行和冻结输入，避免 MySQL 可重复读事务中的旧快照漏掉已经提交的派发。Worker 先锁队列、再锁执行；已经持有执行锁的审核重放不会等待被占用的队列行，调用方可稍后用相同请求标识重试。

独立功能导入需指定目标需求；独立 API 导入需指定目标集合。前端按项目提供迭代和需求选择，并按所选需求加载集合。功能、API 和 UI 候选导入与删除使用统一的导入来源记录，正式目标保留 `effective_import_id`。

修订附件的文件授权从冻结的阶段尝试输入核对文件 ID 和所属项目。需求阶段以尝试 ID 绑定附件；独立多阶段执行以执行 ID 绑定，并检查引用附件的尝试与执行属于同一任务。

任务删除按阶段尝试清理 AI 队列；正式资产和自包含导入回执继续保留。删除独立任务前会锁定任务并检查是否存在仍在推进的执行。

授权撤销按派发尝试冻结的操作者、项目和个人连接匹配 AI 任务，并在同一事务内终止匹配的活动尝试。Worker 上下文读取通过队列对应的尝试解析任务及模型连接。

代码风险、测试报告和测试单图谱的发起请求可携带 `requestId`（最长 64 字符）。同一 AI 队列域内，请求标识绑定任务、操作者和规范化请求输入；相同请求重放返回原执行，输入或身份不一致则拒绝，并重新检查操作者及个人授权。不传时每次发起生成新的标识；执行及其队列被手动删除后，原标识可再次使用。Studio 相关入口在页面存续期间为相同输入复用失败请求的标识，成功后重新分配；页面重新加载后不会保留待重试标识。

辅助任务阶段及 AI 队列通过唯一键插入预占，避免对不存在的键加间隙锁；预占和尝试创建处于同一事务中，失败或回滚时不会遗留队列记录。相同业务对象仍由父对象及活动阶段约束互斥。

需求生成链的阶段启动和优化也使用请求指纹：重放必须匹配发起人、任务、阶段、操作、模型连接及所提交的配置、上游选择或优化内容，并重新检查个人模型授权。队列身份在读取上游输入或绑定优化附件前预占；事务回滚时预占、阶段变更和附件绑定一并撤销。

## 历史与删除

代码风险、测试报告和测试单图谱按执行保留每次生成结果。失败记录展示错误，已成功结果继续可查看；同一业务对象存在活动执行时不能再次派发，失败不会覆盖之前成功的结果。历史按执行分页，详情读取正文，列表不返回大字段。

有写权限的用户可以逐条删除已结束的执行记录；运行中的执行禁止删除。删除只清理该执行、阶段尝试和对应 AI 队列，不删除任务、需求、正式用例、测试单或报告。正式测试资产不随执行历史删除。

需求生成任务和代码风险任务属于需求的设计容器，不是独立子资源：删除需求时一并删除该需求名下的 AI 任务、候选和阶段内容，正式资产与自包含导入回执继续保留。项目、迭代层仍沿用既有规则：非辅助 AI 任务阻塞删除，辅助运行容器随父资源清理。
