# 独立集成执行与持久化写入意图

2026-10-06，按已确认的[拆分计划](../integration-worker-split-plan.md)新增独立 integration-worker。控制面保留数据库、个人授权、业务关联、任务租约与结果事务，Worker 通过内部 HTTP 执行禅道 Bug 创建、附件、正文和字段修改。既有 AI/API/UI 队列依赖业务 run 及 AI 阶段持久化，故使用独立集成队列，避免同时改变现有 Worker 契约；一期不增加消息中间件或第二套业务数据库。

远端写入之前，控制面持久化步骤 operation ID 与写入意图。租约只表达执行权，不证明远端写入是否发生；存在未决意图时失租进入 unknown，不自动重发。结果与领域状态在同一事务更新，最后步骤结果自动归并任务，无须依赖另一条 completed 请求。原操作的晚到证据可用于核对，当前权限撤销后也不能获得新的写许可。此决策不改变 ADR 0005 的 Bug 生命周期，也不迁入远端生命周期同步。

存储包含 integration_jobs、integration_job_steps 及 integration_claim_receipts。领取回执单独保存空结果和历次领取响应，避免领取代次变化后覆盖旧请求的幂等依据。新表引用业务资源的业务编号，执行历史在资源删除后保留；步骤和领取回执仍引用任务。回滚应用通常保留加法迁移，存在活跃任务或未知写入时，迁移拒绝删除执行证据。

队列先读有界候选编号，再对主键行使用 SKIP LOCKED；MySQL REPEATABLE READ 下对队列索引进行范围写锁会阻塞其他领取者更新索引。目标执行权由可空唯一键在数据库中协调，不能用进程内锁代替。授权、本地目标变化、领域恢复和实例切换的协调器与 Worker 接入仍按计划后续批次交付。

2026-10-07 补充：只读恢复与原步骤账本在领域事务中一起确认；相同事实的旧回传只确认回执，不重新应用动态或推进旧依赖。历史清理移除过期且不再参与当前关联的快照/输入，保留原请求、操作和结果回执；未知意图及当前关联不能清理。

数据库恢复不会回滚禅道，备份中的 queued 不证明远端未执行。恢复工具持久化全局运行门控及任务隔离标记，要求新的专属令牌和运行代次；配置开关不能绕过门控。外部核对放行前，恢复环境的 Worker 和旧写入口均暂停。

恢复放行按当前关联和恢复任务逐项检查：使用当前项目所有者的本人授权取得只读事实，随后对本地状态、目标与授权版本执行 CAS；核对记录有期限。不能确认的范围显式保留隔离，放行其他已核对范围后仍不能写入该范围。核对通过的旧任务取消，原操作及回执保留，后续操作通过新手动任务发起。正文的语义等价仅用于验证远端内容，不改变原写入操作的字节摘要；已确认正文的后续 no-op 不再次执行未知结果恢复。恢复环境全局放行后只支持新的异步写入口，避免旧入口绕过恢复范围保护。

执行观测与执行授权分开：最近成功联系和能力声明只解释队列，不能产生写许可。远端耗时作为结果事件的可选观测字段，随同事务保存，但不进入领域结果比较；缺省字段沿用旧事件摘要。每个步骤的首次失败/unknown/失租/撤销时间保留，已恢复操作的观测不因领域状态更新而消失。暂停配置时，已有异步任务继续可查询；尚有未知写入时禁止切回旧同步写入口。

2026-10-07 全量切换后，移除控制面的 Bug 远端写工作流。执行模式固定为 worker；未启用的范围阻止异步提交，不切回同步写入。避免执行进程停止时形成第二条无步骤许可的写链路，也让当前未知操作继续由同一账本保护。全量切换初期的 410 提示入口随后删除，旧 POST/PATCH 不再注册路由；短查询、只读恢复与原操作账本确认保留。过期历史附件 pending 可重新准备，但原账本中的未知或成功写入优先于旧领域行，禁止重传。
