# 接口库作为项目级测试生成输入

2026-11-13。新增项目级接口库，用接口定义补充后续测试用例生成的输入。接口库不是 API 自动化用例库：接口只保存方法、路径、参数、请求/响应结构等定义，不包含发送、断言、变量提取或执行记录。本决策记录首版边界。

## 决策

- **项目级归属与应用分组**：接口定义归属项目，并按接口应用分组。应用包含名称、说明、可选的应用级 base path、启用状态和可选 GitLab 代码仓库；不区分前端/后端类型。应用由项目所有者维护，所有者与普通成员维护接口，只读成员只读，开发成员无接口库访问权限。
- **接口身份与内容**：接口身份为 `(app_id, method, normalized_path)`。数据库用 `path_key`（规范化路径的 SHA-256）参与唯一约束，避免 utf8mb4 长路径索引限制。接口保存请求头、Path/Query 参数、请求体、单个默认成功响应、标签、说明、启用状态和来源快照；Path 参数必须与路径占位符一致，Path 参数始终必填。
- **启用状态独立**：应用启用状态与接口启用状态互不改写；应用停用只影响后续生成候选的选取，不级联停用接口。
- **需求关联**：接口只关联需求，不直接关联迭代；迭代通过需求归属推导。关联为多对多，删除接口或需求时关联行级联删除。
- **OpenAPI 导入**：首版支持上传 JSON/YAML 文件或直接粘贴 JSON 文档；直接输入由 Studio 使用共享编辑器校验后包装为内联 JSON 文件提交，后端导入协议不变。不支持 URL 拉取。导入先解析文档并展示 `new / modified / unchanged / library_only` 差异；提交只处理用户勾选的新增或修改项，文档字段覆盖同名接口，库内启用状态和需求关联保留，文档中已移除的接口保持原样。提交上传原始文件并校验 SHA-256 摘要，逐项校验预览版本，避免覆盖并发编辑；解析继续使用有界 YAML/JSON 读取。
- **base path 权限**：文档 base path 与应用当前值不同时，只有项目所有者可以提交；所有者可选择同时更新应用 base path，并用应用版本做并发校验。普通成员的提交被拒绝，不能通过导入绕过应用维护权限。
- **应用仓库与群组解绑**：应用仓库必须位于项目 GitLab 群组绑定的群组树内，且使用操作者本人的 GitLab 授权校验。存在接口应用引用时禁止解绑对应项目群组，直到引用被清除或替换。
- **删除**：应用下仍有接口时禁止删除应用；接口删除为业务硬删除，统一经过 `ResourceDeletion`，不保留回收站。
- **无回填**：不迁移现有 API 自动化集合或 AI `openapi_extract` 候选到接口库，避免把执行资产或未审核候选混入生成输入。
- **Studio 信息架构**：新增一级入口「资产库」，包含用例库、接口库、应用三个页签。接口库不设外层接口表格，打开后直接进入左侧应用折叠树 + 右侧接口编辑器的工作区；接口应用可在「应用」页统一管理，同时作为工作区左侧的可折叠分组。测试页只保留测试单、API 测试、UI 测试。接口详情复用 API 用例编辑器的信息层级，但移除发送、断言、响应控制台和后置操作。

## 接口

- `GET/POST /v1/projects/{project_id}/api-apps`，`GET/PATCH/DELETE /v1/api-apps/{app_id}`。
- `GET /v1/projects/{project_id}/api-interfaces`，`GET/POST /v1/api-apps/{app_id}/interfaces`，`GET/PATCH/DELETE /v1/api-interfaces/{interface_id}`。
- `POST /v1/api-apps/{app_id}/interfaces/import/preview` 与 `POST /v1/api-apps/{app_id}/interfaces/import`；提交使用 multipart，字段包含 `sourceDigest`、`selectedKeys`、`expectedItems`、`applyBasePath`、`expectedAppVersion` 和原始文件。
- 应用和接口均使用整数 `version` 做乐观并发控制；导入提交在单一事务内锁定应用与接口行。

## 后果

- 接口库成为独立于 API 自动化资产的项目级输入，权限、删除和 GitLab 绑定边界明确，不会因导入或生成自动改写正式接口。
- 普通成员可以持续维护接口定义，但不能通过 OpenAPI 文档改变应用级 base path；需要更新时由所有者操作。
- 支持文件导入与直接粘贴 JSON，URL 拉取、批量导出、接口执行和从现有 API 集合回填暂不提供。
- 接口定义与需求关联只表达输入范围，不表示需求已经生成或用例已经覆盖。

## 拒绝的替代方案

- **把接口库做成 API 用例库**：执行配置、断言和运行记录会把生成输入与执行资产混在一起，无法保持接口定义的稳定身份。
- **接口直接关联迭代**：迭代归属应由需求推导，直接关联会产生两个事实来源。
- **普通成员可随导入更新应用 base path**：会绕过应用维护权限，并使应用级配置被单次导入意外改写。
- **文档移除即删除库内接口**：无法区分文档裁剪和真实下线，容易误删仍被引用的生成输入；首版保留并展示为仅库中存在。
- **回填现有 API 集合或 AI 候选**：来源语义不同，且候选尚未审核，不能直接成为正式生成输入。
