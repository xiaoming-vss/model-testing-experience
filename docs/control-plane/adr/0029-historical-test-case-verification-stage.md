# ADR 0029：历史用例核验阶段

- 状态：已接受
- 日期：2026-11-25
- 取代：—
- 被取代：—
- 关联：[ADR 0028](0028-historical-requirement-relations-stage.md)、[ADR 0030 补测测试点](0030-historical-supplemental-test-points.md)、[生成链](../generation-chain.md)

历史用例核验阶段 `historical_test_case_verification` 读取当前采用的历史需求关联产物，只处理其中有明确依据、可随产物采用的规则影响项。采用并继续时使用操作者选择的个人模型连接。功能测试线继续从材料整理提供输入。

沿用的规则留在历史需求关联。纯补充只派发一个空用例批次，提炼新增部分的补测候选。补充同时改变旧行为时，关联阶段将受影响的旧规则单独记为变更、替代或取消。控制面按这些规则影响项及同项目历史需求与测试集绑定分批匹配有效功能用例。冻结输入包含原始位置的命中片段及候选用例的完整快照。Worker 每批使用独立模型会话和默认 Skill `mtx-verify-historical-test-cases`，仅按模型请求补读指定用例的冻结正文。

阶段最终 JSON `historical_test_case_verification_result` 0.1 按批保留全部输入用例的首次结果和可选的补读结果。补读结论替换同批同用例的初次结论，所有规则依据可追溯。控制面校验批次、规则影响项、用例快照、证据位置和补读集合，再将结果保存为生成候选。Studio 默认列出需修改或建议失效的用例，待确认和补测场景各有入口。采用与正式资产处置沿各自入口，本阶段仅保存分析产物。

候选与当前内容读取通过 `materialContent` 向 Studio 返回与 Worker 相同的冻结输入。产物本身只有判定、理由、证据位置和补测场景，规则原文与用例全文只存在于冻结输入中，Studio 据此还原规则对照和带行内批注的用例。该字段随既有的候选与当前内容读取接口返回，授权不变；输入不可用时 Studio 只显示判定和证据位置。历史需求名称与测试集名称不在输入里，由 Studio 按项目查找。
