# ADR 0022：移除性能测试集与用例的启用状态

- 状态：已接受
- 日期：2026-11-18
- 取代：[ADR 0021](0021-performance-suite-serial-execution.md) 中“启用用例”的表述
- 被取代：—
- 关联：[ADR 0021](0021-performance-suite-serial-execution.md)、[ADR 0014](0014-pre-release-single-baseline.md)、[数据库结构](../database-schema.md)、[Studio 性能测试](../../studio/performance-testing.md)

## 背景

性能测试首期给 `perf_suites` 和 `perf_cases` 都加了 `enabled`：列表卡片展示启用状态，运行时跳过停用用例，测试集停用时禁止发起运行。实际使用中，测试集内的用例本身就是有序执行清单，用户通过新增和删除用例控制运行范围；再维护一层启用开关会引入「有用例但全部停用」「停用测试集仍可编辑」等额外状态和前后端校验分支，而停用并不保留任何执行语义。

## 决策

1. `perf_suites` 和 `perf_cases` 删除 `enabled` 列；按 [ADR 0014](0014-pre-release-single-baseline.md) 直接修改唯一 Alembic baseline，不新增迁移。
2. 创建和更新测试集、用例的 API 只接收名称、描述、YAML 等业务字段，响应不再返回 `enabled` 或 `enabled_case_count`；删除 `ErrPerfCaseDisabled`。
3. 测试集列表、工作台、用例编辑器和新建/编辑 Drawer 移除启用状态相关的开关、标签、筛选和文案；运行对话框展示并提交测试集内的全部用例。
4. 发起测试集运行时只校验测试集有用例、项目 `execute` 权限、环境 `kind="perf"`、监控接入同项目且启用，然后为全部用例预创建子运行。
5. 监控接入的 `enabled` 保留：它表示接入是否可用于本次运行，与测试资产的范围控制无关。

## 后果

- 测试集和用例只有「存在 / 不存在」一种状态，列表、工作台和运行入口不再需要处理停用分支。
- 历史运行不受影响：子运行冻结的用例名称、YAML 和数据文件本来就不依赖 `enabled`。
- API 契约发生破坏性变更，前端与后端必须同批发布；项目仍在首个正式版本之前，按 ADR 0014 直接调整 baseline，不保留兼容字段。
- 按旧 baseline 建表的本地开发库需要重建数据库或手工删除两列，服务不再读写这两列。

## 备选方案

- **只移除测试集级启用、保留用例级启用**：运行仍需过滤停用用例，状态分支没有真正减少，不采用。
- **保留字段但永远置为 true**：数据库和 API 继续暴露无意义状态，调用方仍可能依赖，不采用。
- **用软删除替代启用**：删除已能表达「不再参与运行」，再引入软删除会增加查询过滤和恢复语义，超出当前需求，不采用。
