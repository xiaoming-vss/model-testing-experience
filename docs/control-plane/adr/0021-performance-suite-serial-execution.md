# ADR 0021：性能测试集按顺序串行执行用例

- 日期：2026-11-17
- 状态：已接受
- 关联：[ADR 0014](0014-pre-release-single-baseline.md)、[ADR 0020](0020-performance-remote-write-only.md)、[数据库结构](../database-schema.md)、[Studio 性能测试](../../studio/performance-testing.md)

> 本决策中关于“启用用例”的表述已由 [ADR 0022](0022-remove-performance-enabled-state.md) 取代：测试集和用例不再保存启用状态，运行时执行测试集内的全部用例。

## 背景

性能测试首期只有单条用例运行。产品层级调整为「测试集 → 多条用例 → 每条用例一个负载模型 + 多个 API 步骤」，并明确用例之间串行执行，类似 JMeter Thread Group 的顺序执行，而不是多个 k6 scenario 并行、共同产出一份结果。

现有 perf-worker 只认识单个 `perf_runs` 记录和一个 `perf_run` 任务，单次执行、心跳和停止语义都已稳定。若把多条用例合并进一份 k6 脚本，需要改写 Worker 执行协议、停止语义和结果归档；若由控制面并发派发多个子任务，又无法保证顺序。

变量共享范围已经收敛：只在同一条用例的当前 VU / 当前迭代内共享，跨用例不共享。测试集级共享暂不设计。

## 决策

1. 新增项目级 `perf_suites` 和测试集内 `perf_cases.suite_id/order_no`；用例必须归入测试集才能出现在测试集工作台，历史空 `suite_id` 数据保留但不主动迁移。
2. 新增父运行 `perf_suite_runs` 和有序条目 `perf_suite_run_items`。发起测试集运行时，控制面预创建所有启用用例的子 `perf_runs`（冻结各自版本、YAML、数据文件和运行规格），再创建父运行与条目。
3. 复用现有 perf-worker 单用例执行协议：父运行同一时间只给第一条待执行子运行写入一个 `worker_tasks` 记录。子运行进入终态后，控制面再为下一条写任务，保证任意时刻最多一个子运行在执行。
4. 子用例失败不阻断测试集：条目记为 `failed`，继续下一条。父运行最终统一 `completed` / `inconclusive`，只汇总完成、失败、跳过数量，不合并子运行指标做验收判定。
5. 用户停止测试集时，父运行进入 `stopping`，剩余条目记为 `skipped`；正在运行的子运行收到停止请求，停止完成后父运行记为 `canceled` / `stopped`。直接停止子运行会级联停止其父测试集。
6. Worker 完成或租约回收后推进父运行；租约扫描定期 `reconcile_active`，对「子运行已终态但条目未推进」或「父运行有 pending 但没有活动子运行」的测试集做兜底推进，避免完成事件丢失导致父运行长期挂起。
7. 测试集运行和设备的选择只发生在测试集层，所有子运行共用同一 `environment_id` 和监控接入快照。
8. 按 [ADR 0014](0014-pre-release-single-baseline.md) 直接修改唯一 Alembic baseline，不新增迁移；本地开发库以增量 DDL 补齐新表与 `perf_cases` 列。

## 后果

- Worker 协议不变，单用例运行的冻结、停止、心跳和结果回传继续复用。
- 串行顺序由控制面任务写入时机保证；不会出现多个 k6 子运行并发出现在同一测试集内。
- 测试集运行的历史可以逐用例追溯：父运行展示顺序和汇总，条目关联子运行 ID，子运行保留完整 k6 摘要与日志。
- 父运行结果固定「未判定」；后续若增加验收标准，需要单独设计汇总规则，不能复用单用例结果直接判定测试集。
- 跨用例变量共享、测试集级数据文件和失败重试/跳过策略不在本期范围内，后续另行决策。
- 预创建全部子运行会提前消耗运行 ID 和冻结数据；如果测试集包含大量用例，创建请求会一次性写入较多行。当前用例规模有限，先以简单和可追溯为优先。

## 备选方案

- **合并为一份多 scenario k6 脚本**：无法表达严格的顺序执行，且要改 Worker 执行、停止和结果归档协议，不采用。
- **父运行只存用例列表，执行时再创建子运行**：创建响应无法立即展示完整顺序和子运行 ID，失败恢复也更复杂；预创建更易追踪，不采用。
- **控制面并发派发、Worker 侧排队**：Worker 需要新增测试集级调度状态，且停止和租约语义复杂，不采用。
- **本期同时实现测试集级变量共享**：Worker 不支持跨 VU / 跨子运行共享，需新增文件或上下文协议，超出当前范围，不采用。
