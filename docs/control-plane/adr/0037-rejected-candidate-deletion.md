# ADR 0037：已拒绝候选可以删除

- 状态：已接受
- 日期：2026-11-27
- 取代：[ADR 0031](0031-candidate-removal-is-physical-delete.md) 决策 2 中“只允许删除 `available` 候选”的状态限制
- 被取代：—
- 关联：[ADR 0031](0031-candidate-removal-is-physical-delete.md)、[ADR 0032](0032-replays-are-idempotent-for-the-original-identity.md)、[生成链现状](../generation-chain.md)

## 背景

用户拒绝候选后仍能在版本列表中查看它。历史用例核验等阶段积累多个已拒绝版本时，原有删除限制使用户无法手动清理。

## 决策

1. 拥有项目写权限的用户可以删除 `available` 或 `rejected` 状态的非当前候选；当前采用内容仍不能删除。
2. 拒绝操作仍仅适用于 `available` 状态的非当前候选。Studio 在已拒绝候选的「更多操作」菜单只提供「删除候选」，并沿用二次确认。
3. 删除沿用原有处置接口、物理删除事务、候选令牌校验和幂等回执；删除已拒绝候选时使用拒绝操作后产生的候选令牌。同一请求编号的并发重放只落一条回执。
4. 不增加自动清理。ADR 0031 的其余决策（派生指针清空、尝试标记、回执保留）对已拒绝候选同样适用；现有候选无需迁移，不修改 Alembic 基线。

## 后果

- 已拒绝候选被删除后从列表和详情消失，其冻结来源引用按 ADR 0031 的后果失效。
- 令牌不匹配、候选为当前内容或请求身份不一致时仍返回原有错误，不区分候选是否已拒绝。
