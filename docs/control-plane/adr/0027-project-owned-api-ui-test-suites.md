# ADR 0027：API/UI 测试集归项目所有，需求仅作可选关联

- 状态：已接受
- 日期：2026-11-22
- 取代：—
- 被取代：—
- 关联：[ADR 0014](0014-pre-release-single-baseline.md)、[ADR 0026](0026-case-invalidation-marker.md)、[控制面上下文](../CONTEXT.md)、[数据库结构](../database-schema.md)

## 背景

API 测试集（`api_collections`）和 UI 测试集（`ui_test_suites`）原先通过非空 `requirement_id` 归属于需求，需求再通过 `sprint_id` 归属于迭代；测试集列表默认跟随顶部“当前迭代”，运行记录的 `project_id`、`requirement_id`、`sprint_id` 也按测试集当前归属实时推导。

这与持续测试的使用方式冲突：回归测试集需要在多个迭代和 CI 流水线中长期复用，CI 不应为了运行一个测试集先知道当前迭代，也不应被迫每个迭代迁移或重建测试集。性能测试集已经是项目级资产（`perf_suites.project_id`、`(project_id, name)` 唯一），运行在创建时冻结迭代快照，API/UI 测试集与它不一致。

同时，需求仍是 AI 生成和全局分析的重要语义锚点：生成链路从需求出发，模型分析需要知道测试集服务于哪个需求。因此不能简单删除需求关联，而要把“归属”和“语义关联”分开。

## 决策

1. **归属改为项目。** `api_collections`、`ui_test_suites` 增加非空 `project_id`，权限、生命周期和名称唯一性都以项目为边界；唯一约束改为 `(project_id, name)`。`requirement_id` 改为可空，含义降为“来源需求/关联需求”，不再参与权限和唯一性。按 [ADR 0014](0014-pre-release-single-baseline.md) 直接修改唯一 Alembic baseline。
2. **两条创建路径。** 需求详情和 AI 生成导入仍从需求入口创建或定位测试集，必须带 `requirement_id` 且目标属于该需求；测试页提供项目级手工创建入口，可以不关联需求。项目级创建带需求时校验需求属于同一项目。
3. **生成链路保持绑定。** 接收过正式生成导入的测试集以非空 `effective_import_id` 为标记，不允许清空或更换 `requirement_id`，否则后续重新导入无法按“目标属于来源需求”定位。没有生成回执的手工测试集可以自由关联、更换或解除需求。
4. **需求删除自动解绑。** 需求外键使用 `ON DELETE SET NULL` 并移除“需求下存在 API/UI 测试集”的删除阻塞；功能测试集仍保持原阻塞规则。解绑后的测试集继续作为项目级资产存在，历史生成回执仍保留。项目删除必须显式处理 API/UI 测试集，与性能测试集一致。
5. **运行冻结范围快照。** `api_collection_runs`、`api_case_runs`、`ui_test_suite_runs`、`ui_test_case_runs` 增加真实列 `project_id`、`requirement_id`（可空）、`requirement_name`、`sprint_id`（可空）、`sprint_name`；创建运行时写入当时值，读取时不再从测试集当前归属推导。运行请求可带可选 `sprintId`，未带时从关联需求推导，否则为空；CI 只提供测试集、环境和版本等运行参数。
6. **权限改按项目。** 测试集、用例、运行、Worker 任务授权和文件下载统一通过测试集或运行上的 `project_id` 校验项目权限；需求关联只做同项目完整性校验，不再作为访问入口。
7. **迭代筛选移到运行维度。** Studio 的测试集资产列表按项目展示，需求作为可选筛选和展示信息；按迭代筛选改为筛运行记录，使用运行快照而不是测试集当前归属。迭代看板仍只统计属于该迭代需求的资产与执行结果，项目级回归集的运行不进入需求覆盖率分母。
8. **单用例运行同步冻结。** 单用例 API/UI 运行也写入同样的范围快照，避免无需求测试集的用例无法运行，或历史权限与统计口径随需求移动而漂移。

## 后果

- CI 可以用稳定的测试集业务标识定位资产，不需要迭代或需求上下文；测试集可以在多个迭代持续运行。
- 需求仍是生成和分析的锚点：按需求聚合测试集只需一次 join，不需要逐个需求检索。
- 测试集名称改为项目内唯一；迁移前必须处理同一项目不同需求下的重名测试集。
- 需求删除不再被测试集阻塞，但项目删除需要先处理项目级测试集；已有开发库需要按预发布维护流程手工补列并回填 `project_id`。
- 测试集运行、单用例运行和运行报告的响应字段新增 `projectId`、可空的 `requirementId` 及需求/迭代名称快照；Studio 需同步类型和展示。Worker 执行协议不变。
- 项目级运行记录的项目级筛选接口和 Studio 运行记录视图可以后续增量补充，届时不需要迁移历史运行。

## 备选方案

- **保留需求归属，仅在 CI 中硬编码测试集 ID**：权限、唯一性和列表范围仍被需求绑死，测试集无法跨需求复用，不采用。
- **测试集与需求做多对多**：能表达覆盖多个需求，但当前生成链路仍是一次需求对应一个目标测试集；多对多会增加归属歧义和清理复杂度，本轮不做，保留未来以覆盖关系表扩展的空间。
- **为持续测试建立一个“长期迭代”**：只是绕过模型问题，迭代语义、统计和权限仍会失真，不采用。
- **只把测试集改成项目级、完全不保留需求字段**：会丢失 AI 生成和全局分析所需的语义锚点，需要时再逐个反查，不采用。
