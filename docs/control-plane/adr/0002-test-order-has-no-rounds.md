# 测试单不带轮次，多轮执行即多张测试单

测试单是一次执行的载体：执行结果直接记录在执行条目上，同一批用例的第二次执行通过新建测试单表达，新建时可选带入上一张单中结果非「通过」的条目，两张单之间不保存关联关系。之所以不引入「轮次」这一层，是因为轮次会把条目状态变成「条目 × 轮次」的交叉记录，使测试单列表与报告都要按轮次维度展开，而手工测试的实际用法是"跑一轮、修一轮、再跑一轮"，用多张单表达已经足够。代价是平台无法回答「同一批用例跑了几轮」与「首次修复通过率」，这是刻意接受的损失。

**已考虑的其他选项**：把执行结果挂在「条目 × 轮次」的交叉点上（表达力最强，但列表、指标与报告都要按轮次维度展开，复杂度换不来实际用法上的收益）；保留条目级状态、需要第二轮就新建测试单但不带入未通过项（实现最简，但"只跑失败项"退化成人工对照两张单挑条目，几十条时不可行）。
