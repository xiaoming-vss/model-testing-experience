# 接口库标签分组与导入标签归属

2026-11-15。接口库需要支持分组的创建、折叠、重命名、移除和接口移动，并明确重新导入时标签（分组）的归属。分组主要由接口首个 OpenAPI 标签在 Studio 派生；手工创建的空分组保存在软件仓库上。本决策不新增独立分组表，补充批量操作、空分组持久化与导入规则；[ADR 0012](0012-project-interface-library.md) 中「文档字段覆盖同名接口」的标签部分由本决策修订。

## 决策

- **分组派生 + 软件仓库保存手工分组**：接口分组首先取 `tags_json` 中第一个非空标签；无标签接口只在 Studio 归入「未分类」，不落库为标签。Studio 可创建暂时没有接口的分组，名称保存在 `software_repositories.interface_groups_json`，刷新后仍显示。分组展示集合为「派生标签 ∪ 手工分组」，不新增 `interface_groups` 表。分组名 trim 后非空、最多 50 个字符，「未分类」为 UI 保留名，不能作为标签或手工分组名写入。
- **创建分组**：只向软件仓库的手工分组列表追加名称，允许空分组；名称与已有派生标签或手工分组重复时返回 `3819`。空分组不递增软件仓库的 base path 乐观版本。
- **组级操作为批量标签修改**：重命名把成员接口的首个标签替换为目标名并保留其余标签，同时更新手工分组列表；移除把成员接口的全部标签清空并从手工分组列表删除该名称，接口本身保留并归入「未分类」，次要标签也一并清除；移动把目标标签置顶、去重，并保留接口已有标签，目标为空时清空全部标签。
- **重命名冲突拒绝**：目标分组已存在时返回 `3819`，不自动合并；源分组不存在返回 `3818`；目标与当前同名视为无变化，不写库。只有空分组时重命名/移除仍会更新软件仓库上的分组列表并提交。
- **锁顺序与版本**：批量操作先锁软件仓库行，再按 `id.asc()` 锁定该仓库全部接口，与导入提交的锁顺序一致。只有标签实际变化的接口 `version += 1`；接口数量不因组操作变化。移动单个接口只锁该接口，返回完整接口响应。
- **导入按 `(method, path)` 匹配**：已存在的同名接口只更新接口内容，`tags_json` 一律保留库内值；文档标签差异不再计入 `changedFields`，纯标签差异归为 `unchanged`。只有库内不存在的新接口使用导入文档自带的标签，并据此形成新分组。
- **预览暴露标签归属**：导入预览项增加 `tags`（导入后的分组依据）与 `existingTags`（库内值）。新接口两项分别为文档标签与空数组；已有接口两项均为库内标签。Studio 据此展示选中接口的分组、新分组标记和导入结果中的新建分组。
- **权限**：创建、重命名、移除和移动均要求项目写权限；只读成员与无接口库访问权限的开发成员被拒绝。
- **接口**：
  - `POST /v1/software-repositories/{software_repository_id}/interface-groups`
  - `POST /v1/software-repositories/{software_repository_id}/interface-groups/rename`
  - `POST /v1/software-repositories/{software_repository_id}/interface-groups/delete`
  - `PATCH /v1/api-interfaces/{interface_id}/group`

## 后果

- 空分组可以先建立、后移动接口进来，刷新或重新登录不会丢失；软件仓库响应新增 `interfaceGroups`。
- 分组仍然没有独立生命周期表，派生标签与手工分组在读取时合并；名称重复由接口层校验。
- 重新导入可以持续同步接口内容，同时保留库内人工整理的分组；新接口仍按文档标签自动归档。
- 移除分组是清除成员接口全部标签的显式操作，可能清除次要标签；Studio 确认框必须写明影响接口数量、归入「未分类」且接口不会被删除。
- 重命名不能合并分组，用户需要先移动接口或改为统一名称后再次重命名。
- 分组名与 OpenAPI 标签共用 50 字符上限，文档中更长或重复的标签仍按现有标签规范化规则处理。

## 拒绝的替代方案

- **新增 `interface_groups` 表并为接口保存组外键**：会让分组与标签出现两套事实来源，导入、手工编辑和删除都需要双写；当前只需要保留空分组名称，软件仓库上的名称列表足够。
- **空分组只保存在 Studio 内存或 localStorage**：刷新、换设备或其他成员打开后丢失，无法作为正式分组使用。
- **创建分组时要求先选择接口**：无法表达「先建分组、再整理接口」的工作方式，也不能保留空分组。
- **重命名时自动合并到已有分组**：批量移动会产生难以预期的标签覆盖，且没有撤销入口；明确拒绝更容易理解。
- **移除分组只删除首个标签**：有次要标签的接口会进入下一个标签，用户看到的分组并未消失；清除全部标签才能稳定归入「未分类」。
- **重新导入用文档标签覆盖已有接口**：会破坏库内人工分组，使每次导入都重置分组。
- **新接口也继承库内某个同名标签的分组**：新接口不在库内，没有可保留的库内标签，文档标签是唯一来源。
