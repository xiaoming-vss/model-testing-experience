# ADR 0026：用例失效是独立的生命周期标记

- 状态：已接受
- 日期：2026-11-22
- 取代：—
- 被取代：—
- 关联：[ADR 0014](0014-pre-release-single-baseline.md)、[ADR 0022](0022-remove-performance-enabled-state.md)、[数据库结构](../database-schema.md)、[Studio 性能测试](../../studio/performance-testing.md)

## 背景

功能、API、UI、性能四类正式用例原先都没有“失效”生命周期状态：API/UI 只有 `enabled` 执行开关，功能和性能用例没有类似字段。需求变更或接口下线后，用户只能删除用例来阻止它继续参与新的执行与分析；删除会同时丢失历史测试单条目、运行记录和追溯关系。用户需要一个可恢复的标记，把“不再适用于当前需求”与“从未存在过”区分开，并为后续跨类型全局检索和批量修改提供统一口径。

`enabled` 表达“这条用例当前是否参与执行”，性能测试已在 [ADR 0022](0022-remove-performance-enabled-state.md) 移除该语义；失效标记不应重新引入执行开关，也不等同于软删除。

## 决策

1. 四张正式用例表 `function_test_cases`、`api_cases`、`ui_test_cases`、`perf_cases` 增加可空列 `invalidated_at DATETIME NULL`，并建立索引。空值表示有效，非空表示已失效；只保留首次失效时间，不记录原因、操作者或状态枚举。按 [ADR 0014](0014-pre-release-single-baseline.md) 直接修改唯一 Alembic baseline，不新增迁移。
2. 失效是资产生命周期标记，不是执行开关，也不是软删除：API/UI 的 `enabled` 保留原值和语义；失效用例仍占用原有名称/标题唯一约束，仍属于原测试集或 Collection。
3. 四类列表接口增加可选 `invalidated` 查询参数（`true` 只看失效，`false` 只看有效，省略为全部）；四类响应返回 `invalidatedAt`。四个项目级批量端点接收 `{caseIds, invalidated}`，要求项目 `write` 权限，按项目范围加载并锁定用例，任一用例不存在或不属于项目则整体失败；重复失效不刷新首次失效时间，恢复时清空时间。
4. 失效用例退出**新的**执行与分析：API/UI/性能单用例运行拒绝；API Collection、UI 测试集、性能测试集运行在控制面过滤失效用例，全部失效时返回“没有有效用例”；测试单只拒绝新加入失效用例；代码风险分析和 UI 生成的用例输入只读取有效用例。控制面在创建任务或运行前完成过滤，四个 Worker 的执行协议不变。
5. 历史语义保持不变：既有运行、运行快照、测试单执行条目、执行结果、历史统计和已冻结 AI 快照都不受后续失效影响；测试单图谱和用例图解继续读取执行条目快照。
6. 生成候选导入覆盖同名用例时清空 `invalidated_at`，视为用新内容恢复有效；API 每日指标只统计有效 API 用例，避免失效用例永久计入“未执行”分母。
7. Studio 管理列表默认显示全部用例，用内容区紧凑胶囊筛选 `全部 / 有效 / 已失效`，失效用例显示橙色“已失效”标签；API/UI/性能共用“管理用例状态”弹窗，功能用例库沿用现有勾选条。选择/生成类弹窗只请求有效用例；筛选态禁用拖拽排序，避免提交不完整集合。

## 后果

- 用例获得可恢复的退场路径，删除只用于真正移除资产；历史执行证据不再因为需求变化而丢失。
- 失效用例仍参与测试集资产计数和名称唯一性检查；要复用同名标题需改名、删除或通过生成导入覆盖恢复。
- 失效与 `enabled` 是两个正交维度：恢复有效不会自动启用，停用仍由 `enabled` 表达。
- 批量端点按项目范围设计，为后续跨类型统一检索和批量修改保留聚合空间；本轮不提供统一检索页。
- 本轮不记录失效原因、操作者和恢复历史；需要审计时可由后续独立变更补充，不改变当前时间戳语义。
- 控制面响应新增字段和查询参数，属于向后兼容的 API 扩展；Worker 协议、冻结快照和 Python/TypeScript 执行模型无需同步修改。
- 按旧 baseline 建表的本地开发库需要重建数据库或手工补列；服务不再假定四张表缺少 `invalidated_at`。

## 备选方案

- **状态枚举（有效/失效）加原因、操作者字段**：引入状态机、审计写入和前端枚举映射，但当前只需要一个可恢复的二元标记，不采用。
- **软删除 `deleted_at`**：软删除语义是资产被移除，会自然引出“是否还占用名称”“是否还属于测试集”等与用户预期冲突的问题，不采用。
- **直接复用 API/UI 的 `enabled`**：功能/性能没有该字段，且 `enabled` 表示执行范围而非资产生命周期；恢复执行开关不等于恢复用例有效性，不采用。
- **在四类用例上各建一套失效逻辑**：查询参数、批量端点、运行过滤和界面交互会重复四份，后续跨类型检索也无法聚合，不采用。
