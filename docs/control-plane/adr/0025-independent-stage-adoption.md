# ADR 0025：阶段采用是独立指针

- 状态：已接受
- 日期：2026-11-22
- 取代：[ADR 0024](0024-generation-candidates-current.md) 决策 3、4，以及决策 6 中导入重验“完整当前来源链”的部分
- 被取代：—
- 关联：[生成链现状](../generation-chain.md)、[数据库结构](../database-schema.md)、[ADR 0024](0024-generation-candidates-current.md)

## 背景

ADR 0024 把“当前采用”设计成一条彼此一致的链：下游采用时必须确认所有上游阶段当前采用的正是候选冻结来源中的快照，否则标记为未对齐并阻止采用、生成或导入。实际使用中，上游换了采用后，旧的下游内容仍然完整保留自己的冻结来源，却无法继续采用基于旧来源的候选或导入，界面还会把仍被下游引用的旧候选显示成“不一致”。

用户确认采用只是每个阶段自己的指针：它标记“下游默认读取这一份”，不构成整条链的联合唯一状态。下游可以继续引用任意一份仍有效、来源完整且根输入未变的候选；上游换采用不应回溯改写或阻塞下游。

## 决策

1. `ai_generation_stage_contents.source_candidate_id` 是阶段本地采用指针。每个阶段独立采用，不要求按依赖顺序逐级采用；上游换采用不会改变下游当前内容、候选状态或采用能力。
2. 采用只校验候选自身：候选与目标槽位令牌、尝试身份、候选可用性、冻结来源闭包完整性、快照存在与可用、需求根输入和目标槽位并发状态。不再要求上游祖先当前采用内容等于候选冻结来源。
3. 普通生成仍读取各必需上游阶段当前采用的内容；但不再校验上游祖先是否也等于当前采用。多个上游同时参与时，若所选来源不能组成同一完整分支，来源闭包继续返回 `source_conflict`，提示用户用试生成手动选择一组来源一致的候选；不为此改造闭包模型。
4. 正式导入使用当前叶子内容自身的冻结闭包。导入只校验叶子的候选身份、令牌、内容与依据摘要、根输入、目标、`invalidated_at` 和来源闭包；不比对当前上游链。需求原文件变化仍按既有规则使依赖内容失效。
5. 仓库画像的采用和读取使用画像候选自己冻结的 `requirementMaterialCurrent`、需求文档正文、内容/依据/血缘摘要，并与当前需求文档根哈希比较；不再要求当前材料槽位与画像候选记录一致。材料阶段自身的内容与依据自洽检查保留。
6. 删除 `upstreamAlignment` 及其后端对齐服务；候选与当前内容新增 `basisSources`，从冻结 manifest 的完整 `sources` 投影阶段、候选、快照及是否直接选择。Studio 将“上游对齐”改为“依据”，当前内容不再显示生成方式，非当前候选保留生成方式用于比较。
7. 无数据库迁移：指针、令牌和冻结摘要字段已存在；移除的是读取时的联合校验和派生状态。

## 后果

- 采用、清空、导入和仓库画像的并发安全仍依赖槽位令牌、候选令牌、请求回执和事务内复核；取消的只是“祖先必须等于当前指针”的跨阶段门禁。
- `source_conflict` 仍是多上游分支冲突的唯一结果；用户需要在试生成中显式选择同一分支的来源，不能靠切换上游采用自动修复。
- 需求文档变化、候选被拒绝/丢弃/缺失、冻结摘要不一致和槽位失效仍会阻止使用；这些是来源本身失效，不是对齐状态。
- 控制面、Studio 和 AI Worker 共享的冻结输入契约不变；只有控制面响应删除 `upstreamAlignment` 并新增 `basisSources`，Studio 同步更新，旧 Studio 缺失该字段时可降级显示“依据未记录”。
- 历史 ADR 与记录保留为证据；现行行为以本 ADR 和[生成链现状](../generation-chain.md)为准。
