# 统一 AI 执行模型

2026-11-03。需求生成链、代码风险、测试报告、测试单图谱及独立功能/API 任务共用一套执行身份和阶段尝试模型。旧运行账本及其切换迁移已退出代码库；v1 只有当前模型和唯一冻结基线。

## 决策

- **执行与尝试分离**：`ai_executions` 表示一次执行（发起者、输入快照、生命周期），`ai_generation_attempts` 表示阶段内的一次生成、修订或人工编辑。独立任务详情、报告导出和历史列表中的公开 `runId` 是执行 ID；AI Worker 派发、进度和回传中的标识是 `attemptId`。两者通过尝试的 `execution_id` 关联，契约测试固定此含义。API/UI 域共享队列协议继续使用 `runId`，其语义是 API/UI 运行 ID，不受影响。
- **阶段与尝试**：稳定阶段按 `(task_id, stage)` 唯一；需求生成链保留候选、审核版本、上游冻结和版本计数。代码风险、测试报告和测试单图谱使用单阶段执行，不伪造审核；独立多阶段功能/API 任务保留阶段顺序、人工检查点、继续、优化和失败重试。
- **历史与删除**：代码风险、测试报告和测试单图谱按执行保留每次生成结果；失败记录展示错误，已成功结果继续可查看。有写权限的用户可逐条删除已结束记录，运行中禁止删除；正式测试资产不随历史删除。代码风险沿用 [ADR 0003](0003-candidate-run-deletion.md) 的逐条删除规则；测试报告和测试单图谱的删除规则取代 ADR 0003 中“不提供单独删除”的部分，详见 [ADR 0009](0009-auxiliary-ai-history-deletion.md)。
- **字段精简**：阶段尝试不持久化进度明细 `progress_json` 和处理建议 `remediation`。AI Worker 协议不接收 `remediation`，进度只回传当前阶段、状态、配置中间产物和结果摘要；旧版 Worker 多发的字段按现有反序列化策略忽略。平台 AI 响应、历史投影和视图不包含空 `remediation` 字段。
- **响应结构显式化**：独立执行使用显式的 `StandaloneRun` 数据结构和 `dump_run` 响应组装，不再通过 `AiRunView` 一类动态字段投影补旧字段。函数图谱由阶段服务返回，handler 只保留一条数据路径。
- **附件处置**：修订图片通过尝试或执行快照授权。需求文档正文（含富文本内嵌文件 ID 和结构化来源中的文件 ID）、UI 源码、Bug 附件、技能清单和共享对象键仍被保留业务对象引用时，文件转移到对应资源，文件清理服务处理未被引用的 AI 专属元数据。
- **v1 基线**：`Base.metadata` 是唯一结构来源，`20261103_0001_v1_baseline` 是唯一冻结迁移。v1 只支持空库初始化；后续模型变更必须新增迁移，不改写 baseline。现有本地开发库 `testing-agent-control-plane-b` 在结构零差异确认后使用一次性 `alembic stamp --purge` 指向 baseline。

## 后果与边界

- v1 不包含从旧 revision 升级的路径，也不存在旧运行账本表；部署脚本只需对空库执行 `alembic upgrade head`。
- 本地库 stamp 只写 `alembic_version`，不执行 DDL；执行前必须核对结构零差异和行数不变，并保留已验证备份。
- 执行历史与正式资产分离：删除执行记录不清除需求、任务配置、正式功能/API/UI 资产、测试单、Bug、集成任务或源码包。
