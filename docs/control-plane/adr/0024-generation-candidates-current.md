# ADR 0024：生成链多候选与唯一当前结果

- 状态：已接受
- 日期：2026-11-20
- 取代：[ADR 0011](0011-ui-generation-repository-source.md) 中任意画像版本选择的部分、[ADR 0017](0017-api-design-before-generation.md) 中需求关联链以已审核阶段版本作为可选上游的部分
- 被取代：部分被 [ADR 0025](0025-independent-stage-adoption.md) 取代（决策 3、4 及决策 6 的导入重验部分）
- 关联：[生成链现状](../generation-chain.md)、[ADR 0018](0018-requirement-review-advisory.md)、[实施规格](../../records/2026-11-20-generation-candidates-spec.md)

## 背景

需求生成链目前允许阶段保留多个已审核版本，并允许下游选择任意历史版本。用户需要比较多种候选、用候选继续尝试生成，同时要求每个阶段只有一份正式采用的结果，避免下游和将来的历史检索混用多套内容。

本 ADR 记录已确认的目标行为。改造完成前，[生成链现状](../generation-chain.md) 描述现行实现；本决策不表示接口或数据库已经切换。

## 决策

1. 每个需求、生成类型、阶段最多一份当前采用结果，可保留多个候选。候选生成、失败、拒绝或删除不自动替换其他候选或当前结果。
2. 正常生成读取当前有效上游。试生成可为每个必需上游明确选择一份有效候选或当前结果，冻结选中的内容和完整来源；试生成不自动采用或导入。

   功能测试的范围分析和测试点详情可返回该结果生成时冻结的材料正文，用于展示引用依据；候选和当前内容分别使用各自的冻结来源，不追随后来采用的材料，也不返回完整运行快照或凭据。
3. 正式采用按依赖顺序逐级进行。服务端检查完整来源中的各阶段当前结果、候选快照、内容、依据和输入批次；已采用上游与试生成来源一致时，可直接采用现有候选，不要求重新生成。
4. 单纯切换当前采用项不破坏其他完整试验分支；真实根输入失效、来源丢弃或缺失时，依赖该来源的候选不可继续使用。候选是否可试生成与是否对齐当前采用链是不同状态。
5. 已被采用或下游引用的候选快照不可原地改写。采用、编辑及导入使用并发令牌和请求身份；重复请求不能恢复旧结果或重复写入。
6. 确认采用与正式资产导入是两个动作。导入只使用当前有效结果，写入前重验完整来源及目标；正式资产和既有执行快照独立保留。
7. 控制面拥有业务状态、来源校验和导入事务；AI Worker 消费冻结输入并返回候选；Studio 展示选择、比较、来源和阻塞原因。协议格式版本、执行记录、UI 输入批次和 Git commit 不属于需要去除的业务版本。
8. 需求评审仍是提示性阶段，不成为材料整理的前置。API 的接口依据、UI 的仓库 pin 及本次发起人授权继续遵循各自契约；画像在新模型中保留候选和一份当前采用结果。
9. 本次不建设跨需求关联、历史知识库、RAG、向量索引或正式用例版本库。
10. 当前不设置候选数量上限，不按保留期自动删除候选；根据实际使用情况再确定后续清理规则。
11. 用户确认旧生成版本、候选及运行历史不需要迁移；已有正式功能、API 和 UI 测试用例必须保留。本轮不连接或修改业务数据库。
12. 清理残留时，UI 源码选项接口返回单个 `currentProfile`，其中使用 `candidateId` 标识已采用画像；源码检查请求使用 `profileCandidateId`。移除旧画像版本列表及材料版本选择字段，不提供旧接口字段兼容。Studio 和控制面必须协调更新；Git commit 与运行输入快照继续保留。

## 后果

- 控制面、AI Worker 和 Studio 必须共同演进协议并验证生产方和消费方；旧的任意业务版本选择不能静默回退为当前结果。
- 旧生成数据不再作为本阶段迁移目标；不得为了清理旧生成逻辑删除已有正式测试用例，本轮不对业务库执行重建或数据删除。
- 预发布阶段数据库结构继续遵循 [ADR 0014](0014-pre-release-single-baseline.md) 的唯一 baseline；已有数据库的受控转换不等同于执行 stamp。
- 采用请求、候选编辑、回传与导入的并发、授权、幂等及来源失效需要真实 MySQL 和跨项目契约验证。发布要处理在途任务和回传 outbox。
- 历史运行保留期和既有库维护窗口待实施时确定；这些运维参数不改变上述业务规则。
