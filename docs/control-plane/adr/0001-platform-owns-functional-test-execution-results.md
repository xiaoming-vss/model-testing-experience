# 功能测试的执行结果由平台拥有

功能测试用例的人工执行结果此前只存在于禅道：迭代看板的功能通过率、已执行数、失败数由 `load_function_metrics_from_execution` 调 `list_execution_cases` 读出后落成当日快照，平台自身不记录任何逐条执行结果（API/UI 用例则早已有本地 run 表）。我们决定由平台拥有功能测试的执行结果：执行结果产生于测试单的执行条目，迭代看板的功能指标与 AI 测试报告都以本地记录为唯一来源，不再从禅道读取功能执行数据；禅道继续作为缺陷的来源。理由是手工测试的过程信息（实际结果、步骤级判定、失败现场证据）只有被执行者当场输入才存在，禅道里的功能数据只是聚合计数，拿不到任何可用于报告与追溯的逐条证据。

**已考虑的其他选项**：继续以禅道为功能执行数据源（则平台永远只有聚合计数，需求质量档案里承诺的「执行证据」无处可放）；本地与禅道双来源并存并在界面标注（会产生两套口径的数字，且需要长期解释差额）。

**后果**：已落库的历史快照仍显示禅道时代算出的功能数字，直到有人对同一日期重新生成快照——平台不做清理也不加来源标注。用例被删除时引用它的执行条目会级联删除，因此删除用例会同时使相关执行记录与功能指标分母缩小。
