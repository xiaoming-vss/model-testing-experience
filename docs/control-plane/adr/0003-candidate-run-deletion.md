# 候选生成结果可以删除，已导入的也不阻止

运行记录此前只能随其任务一起消失，任务详情页里堆积的历史运行没有出口。我们决定让候选生成结果本身可以删除：入口放在各 AI 任务详情页的运行记录列表里，物理删除该次运行及其阶段、尝试、导入记录与队列行；运行仍在推进（pending/queued/claimed/running）时拒绝删除，因为 worker 还可能写回这次运行的结果。选择硬删除而不是软删除，是因为平台已有「删除即物理删除」的既定约定，删除痕迹不为审计保留。

已导入的运行同样允许删除。导入产生的正式资产（功能用例、API 集合、UI 套件）不随运行记录消失，但 `ai_generate_run_imports` 里「这批资产来自哪次运行」的来源记录会一起消失，界面上的审核时间、审核备注与导入时间也随之消失——这是刻意接受的损失：平台当前不提供来源追溯台账，用一条运行记录的留存换取列表可清理不值得。

**已考虑的其他选项**：只允许删除未审核的运行（避免已审核结果被抹掉，但失败与已取消的运行才是列表里真正的噪音，限制过窄）；把运行记录改成软删除或加归档状态（需要给运行域单独引入与全仓约定相悖的字段，且要处理所有读路径的过滤）；阻止删除已导入的运行（保留来源追溯，但「导入后想清理候选」的常见诉求就无处安放）。

**后果**：删除能力覆盖需求分析、API/UI/功能用例生成与代码风险的运行记录；这些运行记录一旦删除即不可恢复，界面以二次确认提示。测试单图谱、测试报告这两类辅助 AI 任务仍然只随其所属项目、迭代或测试单清理，不提供单独删除。
