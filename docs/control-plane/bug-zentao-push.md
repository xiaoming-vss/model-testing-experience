# Bug 手动推送到禅道

当前由独立 integration-worker 通过项目禅道 MCP 执行远端 Bug 创建、附件、正文图片和字段修改。control-plane 负责浏览器入口、权限、本人授权、任务账本及本地关联，保留短只读查询和原操作核对。下文原预约状态仍用于解释历史领域记录，新的写执行由异步步骤账本控制。

2026-10-04 最新需求确认：**Bug 附件、富文本内图片、当前状态及后续状态变更必须同步；普通评论非必需。** 附件及富文本内图片同步已实现并完成隔离测试，真实禅道图片显示验收仍待有权限的用户补传后完成；状态同步仍待实现。不能将外部创建成功视为完整同步成功。可行性与能力缺口见 [同步分析](bug-zentao-sync-feasibility-2026-10-04.md)。本次不新增附件进度面板，复用现有推送按钮和整体结果提示。

## 配置与目标

项目所有者填写自行部署的 MCP 地址；实际禅道实例由该端点的 `get_zentao_instance` 读取，不再由页面手填。绑定、创建和结果核对使用项目地址和当前操作人的 Token，目标与绑定或旧关联不一致时，先由项目所有者确认切换并清除旧关联，再重新绑定和推送。旧 Bug/附件推送信息归档到 Bug 动态，原禅道侧 Bug 和附件不删除；正在进行的写入完成前不能清理。部署见 [手动部署指南](zentao-mcp-deployment.md)。

- 项目禅道绑定 → `project`。
- Bug 发现迭代的禅道执行绑定 → `execution`，计划修复迭代不参与。
- Bug 所属需求的禅道需求绑定 → `story`。
- 通过 MCP 读取禅道需求详情的 `product` → `productID`。
- 所有绑定需唯一、有效、同实例，且上级关联一致；远端再次核对执行所属项目及需求所属执行。
- Bug 需求仍可在本地创建时留空；缺少完整关联时只阻止推送。

调用使用操作人的个人 MCP Token，不读取绑定创建人的凭据。发起推送要求项目 `write`，
开发成员和只读成员可以查看已有关联结果，但不能推送或补关联。

## 传输内容

标题和描述正文直接映射到 `title`、`steps`。创建阶段暂将本地图片引用替换为 `[图片未同步]`；文件上传成功后通过 Bug 编辑工具补齐长期图片引用。
严重程度 `fatal / serious / normal / minor` 映射为 `1 / 2 / 3 / 4`；
优先级 `high / medium / low` 映射为 `1 / 3 / 4`。新建前在推送弹窗选择影响版本和禅道指派人：

- 影响版本通过本人 Token 读取目标执行的全部版本，按需求所属产品、目标项目和执行过滤，排除已删除版本；同一版本的源代码/下载路径重复行按 ID 合并。支持多选版本 ID，默认主干 `["trunk"]`；主干不能与其他版本混选。
- 禅道指派人通过本人 Token 分页读取内部用户，仅返回账号和姓名，排除已删除、禁用及 `guest/closed` 特殊账号。弹窗按姓名或账号搜索，提交 `assignedTo=account`，不提交用户 ID。留空时不传该字段，由禅道沿用默认规则；不修改平台责任人。
- 候选项在「推送到禅道」弹窗打开时读取，首次创建及已同步 Bug 复用同一弹窗；查询失败可重试，未加载成功时不能确认。提交前再次校验远端版本/用户和弹窗读取时的目标快照，失效或目标变化时停止写入。
- 已关联 Bug 的附件/正文图片补传与这两项编辑共用「推送到禅道」弹窗。打开时读取禅道当前值；用户不修改字段时不调用字段编辑接口，直接补传未完成内容。修改字段后先保存并回读确认，再补传未完成附件/正文图片；字段结果待核对或失败时停止后续补传。完全同步的 Bug 仍保留推送入口，可用来修改这两项，不重复创建。新建任务默认主干且不指定指派人；提交必须提供 requestId。

已同步 Bug 通过「推送到禅道/重试推送到禅道」同一入口编辑这两项，不额外增加编辑按钮。打开时读取原禅道 Bug 当前值，编辑不依赖附件补传是否完成；保存只提交变化字段，并核对原 Bug 编号、实例、关联和当前成员的写权限及本人授权。平台责任人不变，不再创建远端 Bug。远端已被其他人修改时拒绝覆盖，前端重新加载后重新选择；当前已删除或不在候选列表的历史值仍可显示，修改另一项时保留该值。

字段修改独立保存 `_fieldUpdate` 到原推送记录的 JSON 中，不改创建成功状态，也不需要新增数据库迁移。保存前持久化执行权，期间阻止第二次字段写入及目标切换；成功后回读两项并记录动态。明确拒绝或禅道归一化导致未采用选择时显示失败，可重新加载；超时及成功响应后无法回读时显示待核对，后续加载仅回读确认，不自动重复写入。只有回读匹配上次请求才恢复为成功。

旧附件版 MCP 的接口定义缺少版本分页和指派字段，部署时使用[接口定义补丁](zentao-mcp-deployment.md#影响版本与指派人接口定义补丁2026-10-06)。平台检查版本查询工具的分页参数，缺失时明确提示升级，避免只展示默认首屏版本。
附件与正文内嵌图片从已关联、未归档的 `purpose=attachment` 文件中选取，上传实际内容并关联到原禅道 Bug。同一文件同时出现在正文和附件区或正文多次引用时，只保留一个上传映射。
状态、评论及历史仍不传输；平台责任人与禅道指派人不做自动账号映射。前端在确认前展示限制。

## 接口

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | `/v1/bugs/{bugId}/zentao-push` | 查看结果、目标、本人是否具备推送配置；需要时读取 MCP 实例信息，不写入远端 |
| GET | `/v1/bugs/{bugId}/zentao-push/options` | 需要项目写权限及本人 Token，核对目标后返回 `target/builds/users`；已关联时另返回 `current` 的真实远端两项值及原编号，不创建远端 Bug |
| POST | `/v1/bugs/{bugId}/zentao-sync-jobs` | 提交 requestId 和可选 openedBuild/assignedTo/expectedTarget，返回 202；独立 Worker 创建或补传 |
| POST | `/v1/bugs/{bugId}/zentao-field-update-jobs` | 提交 requestId、指定值和预览的原目标/编号/字段，返回 202；仅修改原 Bug 变化字段 |
| GET | `/v1/bugs/{bugId}/zentao-jobs/{jobId}` | 查询任务及步骤结果；202 不表示远端成功 |
| POST | `/v1/bugs/{bugId}/zentao-push/reconcile` | 对待核对结果提交 `{"remoteBugId": 123}`，只读验证后补关联 |
| POST | `/v1/bugs/{bugId}/zentao-push/attachments/{fileId}/reconcile` | 对待核对附件提交 `{"remoteFileId": 101}`，核验所属 Bug、文件名、大小和内容后恢复关联，不上传 |

创建结果状态：`not_pushed`、`preparing`、`creating`、`succeeded`、`failed`、`unknown`。正文图片另外返回 `descriptionStatus: none/pending/syncing/succeeded/failed/unknown`，与 `attachmentStatus` 一起决定整体同步是否完成。
GET 的 `ready` 表示本人配置和本地绑定满足条件；实际发起仍校验权限及远端关系。
新任务提交返回 202，只表示入队；客户端查询 jobStatus 及步骤结果，不能据此判定远端成功。旧同步 POST/PATCH 已删除；同路径 GET 仍用于查询，旧写请求返回 HTTP 405。

## 重复请求与结果不确定

迁移 `20261003_0023` 增加 `bug_zentao_pushes` 和 MCP 实例地址字段。每个本地 Bug
只有一条持久化推送记录，使用数据库唯一约束和条件更新竞争执行权；先提交 `preparing`，
验证远端后再提交 `creating`，最后调用创建工具。字段快照中不保存 Token。

- 并发或重复提交不会再次执行创建；`succeeded` 保留原禅道 ID，仅补传未成功的附件。
- 确定的拒绝（例如上游 HTTP 403）记为 `failed`，修正配置或权限后可手动重试。
- 创建超时、连接中断、5xx 或缺少有效 ID 等记为 `unknown`，禁止重试创建。
- `preparing` 超过六分钟可重新竞争准备权，旧操作 ID 无法进入创建阶段。
- 进程在 `creating` 期间中断，六分钟后展示待核对，不重新创建。
- 待核对时先由用户到禅道确认 Bug；补关联会校验编号、未删除、原推送标题、项目、执行和需求。
- 补关联不会调用创建、更新或删除工具；若无法确定外部结果，保留待核对状态，不能盲目解锁重试。

终态写入 Bug 动态，保留操作人和结果。本地与禅道不存在跨系统事务；外部成功而本地数据库
不可用时，已提交的 `creating` 记录仍阻止重复创建，通过编号核对恢复。

## 独立附件上传与恢复

迁移 `20261004_0026` 增加 `bug_zentao_attachments`，按 Bug/文件建立唯一约束，保存内容摘要、目标实例、远端 Bug/文件 ID、操作人、操作 ID 与结果。记录不保存 Token 或签名 URL。

以下保留历史状态含义，当前每次写入均由集成步骤账本持久化许可后交给 Worker：

1. 先提交 Bug 创建关联，再处理附件；附件失败不改写创建状态，不再次创建 Bug。
2. 每个文件先提交 `pending`，复核当前成员写权限、本人授权、原实例、原 Bug 所属项目、当前文件归属与内容快照。
3. 控制面签发短时 S3 下载 URL，调用专用 `upload_bug_attachment`。MCP 只允许配置中的来源，使用独立无 Token、无代理、禁止重定向的下载客户端。流式下载到临时文件，校验大小和 SHA-256，再以 multipart `file/objectType=bug/objectID` 上传；临时文件及时清理，不传 base64。
4. 调用前提交 `uploading`；明确返回成功和有效文件 ID 后保存 `succeeded`。确定的拒绝或上传前失败记 `failed`，再次推送只重试未成功项；超时、缺少 ID 和异常写入响应记 `unknown`，禁止盲目重传。并发请求通过唯一约束和条件更新争取单个文件的执行权。
5. `pending` 超过六分钟可以恢复准备；`uploading` 超过六分钟转为待核对，不能自动再次上传。已明确成功的文件跳过；原目标或摘要变化也进入待核对。
6. 返回 `attachmentStatus: none/pending/syncing/succeeded/failed/unknown`。`status=succeeded` 只表示 Bug 创建成功；附件或正文图片未成功时，整体提示不能显示全部成功。页面复用现有重试按钮和结果提示，没有新增附件进度、逐文件状态或恢复面板。

待核对附件由有写权限、已配置本人 Token 的成员通过上述接口提交远端文件 ID。`get_bug_attachment` 复核文件确实属于原 Bug，下载实际内容计算摘要；不依靠同名文件认定成功，不写入远端。禅道会压缩部分 JPG/BMP；压缩后的文件无法通过原始字节摘要核对，应保留待核对状态并人工处理，不放宽成仅核对名称。正常上传收到明确 ID 时不受该恢复限制影响。平台移除附件不会删除远端已上传文件。

部署需支持新工具的 MCP 镜像、正确的 `attachment_source_origins` 和数据库迁移，见 [部署说明](zentao-mcp-deployment.md#独立附件工具升级2026-10-04)。当前旧版固定摘要不含上传工具。单文件 MCP 调用超时 180 秒，工具总时限 160 秒；附件顺序处理，代理请求时限和 PHP 上传限制需覆盖实际传输。MCP 默认最大文件 100 MiB、上限 1 GiB，临时磁盘至少需要当前文件及 multipart 副本的空间。

## 正文图片补齐（2026-10-04）

迁移 `20261004_0028` 在原推送记录中增加独立的描述同步状态、操作 ID、时间和内容快照，不改变创建状态。该迁移已应用到本机，升级前推送记录备份位于根目录被忽略的 `.scratch/backups/`。

1. 复用逐文件上传服务，把正文引用的已关联图片纳入同一个文件映射；文件仍须属于当前项目和 Bug。上传失败、未知结果、摘要或目标变化时，不写入图片引用。
2. 从原禅道 Bug 的 `files` 读取对应文件的原生下载链接，核对文件 ID、所属 Bug、删除状态、实例及图片扩展名，将 GET `f=download` 或 PATH_INFO `file-download` 转换为图片读取路由。保留原站点子路径，并以配置中的浏览器实例地址补全 URL；仅保留路由参数，不复制 Token。描述中不保存 S3 签名、平台文件 ID 或服务内部域名。查看图片仍使用禅道登录和文件权限。不能直接向编辑接口提交 `{文件ID.png}`：真实禅道 22.6 的编辑器会编码花括号，生成无法读取的 `%7B文件ID.png%7D`。
3. 使用现有 `put_bugs_bugID` 仅提交 `steps`。更新前核对原 Bug、项目、实例、当前成员权限和本人授权，并再次校验图片及本地正文快照。本地描述或远端描述相对推送基线发生漂移时，按平台当前内容覆盖禅道正文（2026-10-08 起不再拒绝同步），Worker 在步骤数据中记录 `overwrote`（`localEdited`/`remoteEdited`），控制面随推送账本持久化备查，不在界面提示；覆盖仍走一次执行账本，未知结果处理不变。
4. 通过数据库条件更新争取执行权，阻止并发重复修改；`preparing` 超过六分钟可恢复准备，写入中的 `syncing` 超时进入 `unknown`。远端更新响应及回读图片引用均确认后才记成功；回读识别禅道展开后的原生路径。未知结果再次推送先回读核对已提交内容，不重新上传已成功的文件。普通未知结果不再次 PUT；只有旧请求明确提交过花括号图片引用、远端完整正文与该请求一致且仅图片地址被编码时，才转为已确认失败，并重新争取执行权、核对权限和基线后修复原生图片地址。新原生地址的异常结果不会反复触发该恢复流程。
