功能用例图谱的候选入口以当前采用的完整用例为来源，生成和读取均重新核对需求文档、材料、上游候选和当前槽。图谱记录候选、快照、内容、依据及完整来源指纹；同正文但不同候选不会复用另一候选的图谱，切回原候选并恢复相同来源后可再次读取原图谱。图谱请求使用独立幂等标识，旧请求重放不会更改当前用例。独立任务和未切换的旧链继续使用原图谱入口。

候选工作区提供显式“检查当前来源”：检查时重新核验真实输入和完整来源，同时分别展示来源完整性、与当前上游的对齐情况及当前项是否仍标记待更新。检查不修改候选或当前内容；上游后来变化时需要再次检查。检查不自动读取 GitLab 分支 HEAD，UI 固定提交仍由单独的源码检查处理。

当前内容读取另提供轻量的上游身份提示：依据已记录的候选与快照检查上游是否仍被采用；上游被清空、替换或标记失效时，工作区显示相应提示并定期刷新。此提示只比较数据库中的身份，不检查对象存储或远端仓库；完整来源仍以显式检查和后续操作时的重新核验为准。

候选工作区支持“采用并生成下一阶段”：先提交采用与继续请求回执，再使用本次采用得到的当前令牌发起下一阶段。派发时重新核验权限、真实来源及令牌；如果两段之间上游已变化，采用结果保留并显示下一阶段未启动。重复请求使用固定的继续请求标识，成功后重放不会启动第二个 Worker。需求评审仍是提示性阶段，继续到材料整理时检查评审当前项及其来源，但不会把报告加入材料输入。失败后的再次提交仍重新核验当前令牌。

候选可继续优化：请求指定候选与令牌，校验并冻结它的原始来源，成功回传后生成新候选，保留原候选和当前内容。后续使用新候选时还会核验同阶段父候选及其来源；父候选被丢弃或来源失效时不会静默换源。功能、材料及 API 优化支持图片：先在锁外读取已完成上传的对象并核对摘要，再在派发事务中复验文件归属、状态、有效期和元数据，关联到本次尝试。UI 优化继续使用原有不支持附加图片的约束，并用操作者的个人授权重新访问冻结 commit。Worker 仍接收既有候选输入及修订字段；控制面内部保存同阶段父候选身份。隔离 MySQL 测试覆盖图片关联、并发重试及优化结果预检；HTTP 测试覆盖功能和 UI 候选优化与试生成。真实对象存储、GitLab 和模型尚未验收。

对账步骤读取正式测试集、用例及 API 断言和提取规则的实际数据，分别计算数量和摘要，检查正文或归属改变；另检查候选、审核、当前项、画像及导入回执。隔离 MySQL 8.4 演练了旧库形态下的新表初始化，以及需求、草稿、画像和导入回执的事务转换及对账；重复执行、部分建表和字段不一致有检查。补表原语只允许名称以 `_test` 结尾的 MySQL 测试库，MySQL DDL 不能事务回滚，失败时需要恢复测试副本。

隔离副本的单需求演练入口为 `uv run --locked --extra dev python -m testing_agent.cli.generation_rehearsal --project-id <项目ID> --requirement-id <需求ID> --checkpoint-id <操作ID> --task function=<任务ID>`；可重复传入 `--task` 选择其他生成链，也可用 `--profile-task-id` 指定画像任务。通过环境变量 `CONTROL_PLANE_REHEARSAL_DATABASE_URL` 提供仅供销毁的 `mysql+asyncmy` 测试库地址，库名须以 `_test` 结尾；默认不读取对象存储，文件来源标为未知。传 `--verify-objects` 会读取本地配置中的对象存储，因此应配置隔离的测试对象。执行前须停止副本写入和 Worker，输出的标识及摘要按项目数据保护。该入口只用于测试副本，不是业务库升级或上线命令；其他有历史记录的配置尚未归档时会停止。

单需求和项目级演练均可选传 `--gitlab-actor-id <用户ID>`，用该用户的个人授权访问冻结仓库并核验 commit；必要时可加 `--gitlab-connection-id <连接ID>`。不传时 UI 仓库来源保持未知。演练会访问配置指向的 GitLab，应使用隔离的测试服务；即使验证通过，也不代替实际环境验收。

隔离演练可显式传入 `--retain-alternate-histories`：同需求同类型的其他旧任务，其已审核正文、审核信息、待审核草稿及画像结果保留为候选，旧版本导入保留为独立证据；默认任务的选定结果仍是唯一当前项。其他任务候选的来源不推断，标记为未知，不能直接试生成或采用。检查点记录旧任务映射、上游版本标识及原始时间等审计元数据，对账核对映射、正文、审核、当前项、草稿和正式资产；重新执行不会恢复后来改变的当前项。转换还会补齐尚未运行过的阶段和空当前槽。未选择该参数时仍对其他任务历史阻塞；此能力目前只用于停写的隔离测试库。

项目级隔离演练另可传 `--archive-unresolved-standalone`，把目标已不存在的独立任务导入证据保留下来：记录原正文、来源任务项目和目标标识，需求标识留空，并明确标记目标缺失；缺少变更用例标识时也标记未知。该证据仍计入待处理项，不会冒充已核对的目标或修改正式用例。遇到目标存在但范围不一致等矛盾时仍阻塞。

项目级演练可用 `uv run --locked --extra dev python -m testing_agent.cli.generation_project_rehearsal --project-id <项目ID>`，使用同一测试库环境变量及可选的 `--verify-objects`。工具按旧入口的默认任务逐需求处理，已经完成的需求复用检查点；有多个历史配置而无法安全转换的需求单独报告。独立任务的历史导入在来源及目标可核实时保留原回执编号，缺失或冲突的记录单独阻塞。最后核对历史版本与版本导入覆盖、正式用例身份、检查点证据和执行快照摘要。存在阻塞或对账不符时命令返回非零，报告始终不宣称业务上线就绪。

在临时 MySQL 8.4 中，用构造的旧审核内容完成转换并创建检查点后，执行 `mysqldump --single-transaction`，再恢复到独立测试库；恢复前后 75 张表、14 条记录的逐表数量及行摘要一致。演练完成后已清理临时容器和备份文件。这不代表真实业务库的备份、恢复耗时及一致性已经验收。

这些步骤尚不是可对业务库执行的完整迁移：仍需真实对象存储、附件和 GitLab 固定提交验收，其他配置历史归档、覆盖所有数据的对账、独立导入缺失来源处理、业务库升级与备份恢复方案、停写及恢复演练，完成后才能退出旧接口和清理旧表。以上实现未连接实际业务数据库。候选、导入、历史转换和数据库基线联合回归 107 项通过，包含隔离 MySQL 8.4 并发与旧库形态测试；其后检查点及来源核验定向测试 24 项、MySQL 基线及转换测试 8 项通过，控制面静态检查通过。Studio 全量 `npm run verify` 包括 1013 项测试通过，AI Worker UI 及候选契约测试共 98 项通过；外部对象存储、GitLab、模型和真实浏览器尚未完成验收。

剩余工作包括覆盖真实数据的迁移与全量对账、旧入口退出以及完整发布验收。下面的内容为实施过程中的历史记录，其中“尚未接入”等描述以本节后续进展为准。

## 早期阶段记录

建立候选运行、上游选择、冻结来源、采用预检与编辑/清空/导入请求的目标契约类型；控制面和 AI Worker 使用共同 fixture 检查 trial 来源结构，Studio 有对应类型。候选协议已用于内部派发和 Worker 快照，公开生成、采用和导入入口尚未切换。

新增按项目过滤的旧数据只读盘点工具，输出任务及阶段元信息、默认版本建议、直接上游引用状态、候选尝试、导入目标、画像默认来源、UI 批次、正式用例身份及执行快照哈希。输出不包含需求正文、候选正文或快照原文；测试验证查询只发出 SELECT。

新增需求当前链、候选、当前内容和审核回执的模型及预发布单基线表；每阶段当前内容保留空槽令牌，候选有快照标识和冻结时间。事务内存储原语可用令牌条件更新、清空、编辑、冻结或处置候选；它们本身不负责完整来源验证、授权或审核回执。候选分页、详情、编辑、手工派生及单候选拒绝/丢弃接口已接入需求及项目权限校验，列表不读取正文，详情不返回原始来源快照或未筛选的内部上下文；编辑记录新的尝试并轮换快照和候选令牌，派生保留父候选和当前内容，派生及处置在同一事务保存请求回执，不允许处置当前候选。Studio 请求类型与客户端已准备，页面尚未接入。

链绑定及空槽原语会校验需求、任务类型和阶段归属；成功尝试可通过事务原语生成自包含候选，同一尝试的重复回调不会创建第二份候选或恢复后来编辑的旧正文，派生候选会冻结其同阶段父候选。任务存储清理原语先移除当前指针和同链派生引用再清理候选，正式测试资产独立保留；它尚未连接旧任务删除路径。

新增独立的来源闭包核验规则，用于判断祖先快照冲突、缺失、根输入变化和 UI 批次不一致，以及当前来源与候选、快照、正文及依据指纹是否一致。该规则仍需由业务服务加载、授权并锁定可信来源后才能用于实际派发、采用和导入；客户端提供的来源图不能作为事实来源。

已增加从数据库发现并按稳定顺序锁定候选祖先的内部服务，锁定后重新核对正文、快照和清单，再验证来源闭包。需求文档、所选接口和 UI 固定仓库及所选正式功能用例已有根输入指纹与锁定读取基础；富文本附件必须由可信的文档解析结果明确提供，无法确认时保持未知。UI 根输入核验沿用已冻结的 commit，不访问仓库最新 HEAD。

新增内部来源选择原语：普通模式从服务器读取必需阶段的当前内容，试生成模式按请求逐一选定当前内容或候选；对于选中的当前内容，还会逐级核对其祖先当前内容。引用候选先锁候选再锁当前槽，并在同一事务检查正文、来源快照、依据及令牌；结果只返回直接选择的正文与冻结清单。运行依据指纹会使用已锁定修订附件的内容摘要。该原语尚未接入生成接口，调用方仍须提供从真实业务输入锁定并计算的根指纹，失败时整体回滚。

新增内部采用原语，共用当前来源对齐规则，先核对整条祖先，再以令牌原子更新目标当前槽；切换上游会阻止不匹配的下游采用。另有事务内幂等回执封装，重复请求返回原结果，不恢复后来被清空或替换的当前内容。它们不自行授权、计算业务根指纹或提交事务，也尚未接入公开采用接口；采用后自动继续生成尚未实现。

内部采用应用层现已负责审核权限、项目及需求任务锁、真实业务根输入核验、提交与回滚；读取需求文件时不持有业务行锁。UI 候选采用时按该候选冻结的仓库 pin 和用例选择核验，而不是使用当前结果的来源。采用预检逐项返回未采用、来源不一致等上游阻塞，不修改当前内容、不创建审核回执，也不冻结候选。正式采用仍在提交事务中重新核验，已完成请求重放会重新检查权限，不恢复之后变更的当前内容。同一应用层接入清空当前内容：核验审核权限和当前令牌，保留候选；旧清空请求的重放不会清除后来重新采用的内容。此应用层、预检及清空尚未连接公开接口；采用并继续生成仍未实现。

新增内部当前内容清空事务，按当前令牌核对并保存幂等回执；清空不删除候选，旧清空请求重放不会清掉后来重新采用的内容。它同样需要调用方负责权限、父资源锁和提交，尚未接入公开接口。

已新增内部候选派发事务：按请求标识预留 Worker、解析并冻结所选来源、组装实际输入，按同一标识重放时返回原尝试。候选模式允许在已有待审结果后再次生成，但同阶段仍只允许一个活动运行。新协议的 Worker 回传会核对持久化的依据指纹，在完成尝试的同一事务追加候选；无新协议标记的旧运行保持原行为。AI Worker 可解析冻结来源元数据，但不查询候选池，元数据不进入模型输入。当前尚无公开候选生成入口调用该内部事务。

需求文档预处理会在持有业务行锁之前读取并校验对象存储中的正文及正文引用的图片；提交阶段重新锁定需求和文件并检查文件身份。准备时如果正文、图片、对象摘要或资源归属不一致，不能形成可信根输入。此准备过程尚未接入公开生成入口，也未使用实际 S3 完成验收。

新增内部正式导入预览及提交事务：只接受最终阶段当前内容，检查所有祖先当前来源、根输入和目标状态；预览令牌绑定操作者、源及目标指纹并有有效期。功能导入覆盖需求下全部可能受影响的测试集，API 导入包括用例、提取和断言规则，UI 导入检查目标用例。确认后沿用已有导入器写正式资产，并在同一事务写新导入回执；同请求重放返回原结果。三类导入器的预览模式不写正式资产，新流程使用 MySQL 当前锁定读取，避免事务早期快照隐藏新冲突。此流程尚未接入公开入口或 Studio。

新回执保存实际导入正文、来源清单、上游产物及输入指纹，运行和候选被清理后仍可保留；为避免复制凭据、签名地址和原始提示词，输入审计快照只保存必要身份及摘要，不能据此完整还原原始模型提示。回执中的导入正文和上游产物仍是项目业务数据，需要权限保护。独立任务目前仍使用旧回执表，旧回执迁移及读取适配尚未完成。

当前内容导入增加了内部应用层：预览及提交前检查项目执行权限，从服务器数据准备并重验业务根输入；已完成请求的重放仍检查项目权限，但不依赖已清理的来源任务或需求文件。该应用层尚未连接公开接口。另新增旧独立任务回执的转换投影和单条事务原语，可保留原回执标识、导入正文与审核信息，标记缺失的历史输入并拒绝来源身份或目标项目不一致的数据；重复执行会核对已有内容，发生冲突时不覆盖。该原语只供停写维护窗口下的后续迁移工具调用，尚无批处理、全量对账或正式切换入口，也没有对实际业务库执行。

盘点在控制面目录以 `uv run --locked --extra dev python -m testing_agent.cli.generation_inventory --project-id <项目业务标识>` 调用。它不会自行迁移或修改数据；输出包含业务标识和不可逆内容哈希，仍应按项目权限保护。独立任务回执单列 `standaloneImports`，报告来源尝试是否存在及目标是否属于项目，不暴露产物正文；来源存在不代表历史输入和变更用例已经核实。直接来源状态不是完整依赖闭包验证，文档摘要一致也不代表所有根输入有效。
