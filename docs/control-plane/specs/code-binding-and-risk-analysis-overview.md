# 代码绑定与风险分析 — 需求总览

> ⚠️ 本副本已于 2026-08-20 按质询结论更新(配套决策记录 `docs/control-plane/adr/0002-project-shared-gitlab-bindings.md`),领先于源文件;源文件需反向同步本次变更后再作为唯一权威。

## 背景与目标

现状:测试资产以「项目 → 迭代 → 需求」为维度组织;项目可绑定禅道,GitLab 仅有连接管理(无资源访问)。

目标:把需求绑定到代码(仓库 + 分支),以「上一个迭代」为基线做 diff,结合需求文档与现有测试内容产出**代码风险分析**,指导本迭代的回归测试与补测。

## 核心共识(决策记录)

### 1. 绑定模型

- 项目绑定 GitLab **群组**,可绑多个;同一群组不允许重复绑定((项目, provider, 群组)唯一);**项目内所有用户可见可用**(平台暂无成员模型,可见性边界 = 项目内所有用户,见 ADR-0002)。
- 群组可绑任意层级(**含子群组**);需求绑定的仓库须位于项目已绑群组的群组树内(含子群组)。
- GitLab API 拉取使用**绑定创建者的连接**;PAT 失效时任何项目内用户可用自己的连接**接管**(PATCH `connection_id` 更新为自己的)。
- **迭代不绑定**任何代码维度(仅作组织维度)。
- 需求绑定 **(仓库 + 分支)**,可绑多个;选了仓库**必须选分支**;选择器实时拉取 + 搜索。需求绑定不携带 `connection_id`:凭据经由「该仓库所属群组的项目绑定」当前连接获得;风险分析任务创建时把 `connection_id` **快照进任务**,凭据按快照下发(见 ADR-0002)。
- 删除群组绑定时,若存在引用其下仓库的需求绑定,则**阻止删除**并返回受影响绑定清单。
- 绑定配置入口:项目群组在项目主页(`ProjectsPage`);需求代码绑定在需求抽屉(`RequirementDrawer`)。

### 2. 基线规则(修订版)

对需求绑定的**每个仓库**,基线按优先级确定:

1. 手工设置了**基线分支** → 直接使用,不做任何自动查找;
2. 未设置 → 自动查找:当前迭代之前的所有迭代中,该仓库**离本迭代最近一次**绑定的分支(迭代按 `end_time` 排序,空则按创建时间);
3. 该仓库从未被绑定过 → **无基线**,当前分支整体视为全新变更纳入分析;
4. 自动查找失败(分支已删等)→ 任务报错,提示手工指定基线,不静默降级。
5. 命中迭代内该仓库存在**多条绑定**(绑了多个分支)→ 取绑定记录 `created_at` 最新的一条,解析结果标注「发现多条绑定,已取最近一条」;「之前的所有迭代」为**严格口径**,本迭代内其他需求的绑定不作基线。

### 3. diff 语义

按**需求**、**整支 diff**:需求绑定分支与基线的全部差异均视为该需求引入;不做 commit → 需求 的精细关联。

### 4. 风险分析任务

- 独立 AI 任务类型 `code_risk_analysis`,挂在需求上。
- **输入**:需求文档 + 各仓库 diff + 该需求下现有测试内容(功能/API/UI 用例的名称、步骤、断言 + 执行结果字段:**功能用例暂无执行记录、留空标注**(run 表后续补齐);API/UI 取每用例最近一次 run 的 status 与完成时间,不带日志)。
- **输出**:①变更概览(diffstat)②风险点清单(等级/位置/理由)③受影响已有用例清单 ④覆盖缺口与建议新增测试点。
- 不进「候选 → 审核 → 导入」流程(那是用例资产的);**可重复发起**;每次任务记录基线 commit 与各仓库当前 head 的 SHA,报告标注分析基于的提交。
- 发起入口:需求抽屉「代码风险分析」按钮 + ai-testing 任务列表/详情页。

### 5. 架构分工

- **control plane**:绑定数据模型与 API、群组/仓库/分支资源代理端点、基线解析服务、**变更统计端点(compare,短缓存)**、任务快照扩展、GitLab 凭据按任务下发。
- **ai-worker**:新任务类型;任务开始时**直连 GitLab** 拉取 commit 与 diff(凭据由 control plane 按任务下发);截断后注入风险分析技能链;回传结构化报告。
- **testpilot-studio**:项目群组绑定 UI、需求代码绑定 UI、风险分析发起入口与报告页、**迭代代码概览区块**。
- 平台侧技能空间新增 `code-risk-analysis` 技能包(随项目技能同步下发)。

### 6. 失败处理

任一仓库失败(分支被删、权限不足、网络异常)→ **任务整体失败** + 错误信息附补救建议(手工指定基线 / 重新绑定 / 检查 PAT),不静默降级。GitLab 代理与 compare 错误码归入现有 **3401 集成系列**(不引入 42xxx/51xxx)。

### 7. diff 截断策略

给模型**全量 diffstat + 按文件数/行数截断的文件级 diff**(过滤 lockfile、生成文件、二进制),上限做成配置项。

### 8. 代码变更概览(迭代总览)

- 迭代总览页展示:该迭代内需求绑定的仓库/分支清单(按仓库去重聚合)、**代码变更量**(commits 数、增删行数)。**项目级概览本轮不做**(一个项目可能多迭代并行,「当前迭代」口径不清)。
- 变更量由 control plane **打开页面时现算**(GitLab compare API),带短缓存(默认 5 分钟)+ 手动刷新;**不依赖风险分析任务**;**绑定变更(创建/接管/删除)时主动失效缓存**。
- 口径与基线规则完全一致(复用基线解析服务);无基线仓库以 **git 空树 SHA** `4b825dc642cb6eb9a060e54bf8d69288fbee4904` 为 `from` 对比(GitLab compare API 并无 `empty_tree` 参数),标记「新增仓库」。
- 概览接口按仓库独立统计:单仓库失败仅标注该仓库错误(含补救建议),**不整体失败**(与分析任务的 fail-fast 不同,概览是展示场景)。

## 安全约束

GitLab PAT 随「认领时下发」的凭据端点传递给 ai-worker:**仅驻内存、不落盘、不入日志**,沿用现有 llm-credentials 下发模式。连接本身仍为个人所有(ADR-0001);共享的是绑定而非连接(ADR-0002)。

## 不在本轮范围

- UI/API 用例自动生成(等本链路稳定后复用本基础设施扩展);
- **性能测试**(系统目前零基础,单独立项);
- commit → 需求 精细关联、迭代结束时存 commit 快照(留作后续演进)。
