# ZenTao-MCP 手动部署实现与验证记录

日期：2026-10-04。需求方向：用户手动启动服务，项目所有者填写 MCP 地址，平台不管理容器生命周期。

## 已实现

- `deploy/zentao-mcp/` 只保留 `compose.yaml`、`config.example.yaml` 和 README，模板引用已经发布的镜像及固定摘要，不在平台仓库构建镜像。镜像构建在项目外只保留独立 Dockerfile，补丁内嵌、许可证从固定上游源码复制，不依赖额外本地文件。
- 用户直接编辑部署目录的 `config/config.yaml`，执行 `docker compose pull` 与 `docker compose up -d`。MCP 专用的 TOML 段、配置生成脚本及 `manage.py zentao` 命令已移除；平台自身配置生成机制保留。
- 每个部署使用独立名称、配置目录、网络及宿主机端口；用户自行设置名称、端口，冲突由 Docker 启动时报告。
- 项目 MCP 地址可由所有者填写和修改；资源绑定、Bug 推送及用例推送使用所属项目保存的端点和操作人自己的 Token。
- 禅道身份从 MCP 自动读取。目标变化或存在混杂历史时，项目所有者可确认切换，清除本项目旧禅道关联，再重新绑定。旧推送归档到 Bug 动态，其他项目、GitLab 绑定与平台/禅道业务数据保留。普通刷新与个人授权保存不清理关联。
- 页面提供部署说明；完整启动、多项目网络、修改配置、停止和排障流程见 [部署指南](zentao-mcp-deployment.md)。

## 部署后验收

模板实施时未启动或重启用户现有 MCP 服务；临时容器验收使用不可达的虚拟上游与测试 Token，仅调用不访问上游的实例信息工具。真实个人 Token 权限及绑定、推送业务仍需验收，本轮未向真实禅道写入绑定、Bug 或用例。

本机原 Compose 与旧程序已备份，并验证 `compose.rollback.yaml` 配置和旧程序入口；回退材料保存在本机部署目录中，不进入平台仓库或镜像仓库。
