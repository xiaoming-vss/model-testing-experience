# 领域文档

代码按 `apps/<项目>/` 组织，领域文档统一放在 `docs/<项目>/`。通过根目录 [CONTEXT-MAP.md](../../CONTEXT-MAP.md) 定位上下文。

## 阅读顺序

1. 阅读目标项目的 `docs/<项目>/CONTEXT.md`（若存在）。
2. 阅读该项目 `docs/<项目>/adr/` 中与任务相关的架构决策。
3. 跨服务任务还应阅读其他相关项目的上下文与接口契约。

不存在的上下文或 ADR 不需要预先创建或报告缺失；仅在领域术语或决策明确后按需新增。文档使用的源码路径和开发命令默认相对对应应用目录，明确写出的 `apps/`、`docs/`、`scripts/` 路径相对单仓库根目录。

## 术语与决策

使用相应 CONTEXT 中的业务术语，不使用其中明确排除的同义词。若需要引入新术语，先确认是否属于现有概念；确有领域缺口时再记录。

如果方案与已有 ADR 冲突，必须明确指出冲突和原因，不能静默覆盖。各项目 ADR 保留原编号，跨项目引用时带上项目名称，避免相同编号混淆。
