# 领域文档

- 状态：现行
- 负责人：platform maintainers
- 最近复核：2026-11-19
- 复核周期：每季度
- 适用范围：`docs/agents/` 与全仓库领域文档约定
- 变更/废弃：按[规范变更检查清单](#规范变更检查清单)执行；影响跨项目契约时先记录 ADR 并通知消费方。

代码按 `apps/<项目>/` 组织，领域文档统一放在 `docs/<项目>/`。通过根目录 [CONTEXT-MAP.md](../../CONTEXT-MAP.md) 定位上下文。

## 阅读顺序

1. 阅读目标项目的 `docs/<项目>/CONTEXT.md`（若存在）。
2. 阅读该项目 `docs/<项目>/adr/` 中与任务相关的架构决策。
3. 跨服务任务还应阅读其他相关项目的上下文与接口契约。

不存在的上下文或 ADR 不需要预先创建或报告缺失；仅在领域术语或决策明确后按需新增。文档使用的源码路径和开发命令默认相对对应应用目录，明确写出的 `apps/`、`docs/`、`scripts/` 路径相对单仓库根目录。

## 术语与决策

使用相应 CONTEXT 中的业务术语，不使用其中明确排除的同义词。若需要引入新术语，先确认是否属于现有概念；确有领域缺口时再记录。

如果方案与已有 ADR 冲突，必须明确指出冲突和原因，不能静默覆盖。各项目 ADR 保留原编号，跨项目引用时带上项目名称，避免相同编号混淆。

## 规范治理

所有开发规范（根 `AGENTS.md`、各项目 `AGENTS.md`、`development-rules.md`、`docs/agents/*.md`、studio 的 `STRUCTURE.md` / `UI-GUIDELINES.md` 和 `docs/commands.md`）使用统一头部：

- 状态：现行 / 已废弃
- 负责人：角色名，不写个人姓名
- 最近复核：`YYYY-MM-DD`
- 复核周期：默认每季度
- 适用范围：生效的目录、项目或接口
- 变更/废弃：链接到本节检查清单

### 规范变更检查清单

1. **更新日期**：规范内容或适用范围变化时更新“最近复核”；纯文字校对也更新，避免日期误导读者。
2. **判断是否加 ADR**：改变跨项目接口、状态机、权限、数据模型、部署事实源或安全策略时，先在目标项目 `docs/<project>/adr/` 记录或更新 ADR，再改规范；不把 ADR 结论只写在规范正文。
3. **通知消费方**：修改生产方或消费方契约时，在交付说明列出受影响项目，并验证生产方与消费方；跨团队变更通知对应负责人。
4. **废弃规则**：在条目原位置标注“已废弃”、生效日期和替代规则链接；不删除历史 ADR，不用新规则静默覆盖旧语义。
5. **同步检查**：更新 `docs/commands.md` 中的命令入口；文档检查脚本落地后运行 `python3 scripts/check_docs.py`。
6. **状态复核**：每季度复核一次；连续两个周期未复核的规范在状态栏标注“待复核”，但不得自行降级为已废弃。
