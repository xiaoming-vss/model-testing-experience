# 运行页面刷新策略

API/UI 执行和五类 AI 任务详情共用 `apps/studio/src/domain/runs/polling.ts` 的刷新规则：

| 场景 | 刷新间隔 |
| --- | --- |
| 已提交任务、尚未取得详情 | 立即请求；无状态时每 5 秒重试查询 |
| 执行中 `running` | 5 秒 |
| 排队或领取 `pending`、`claimed` | 15 秒 |
| 人工检查点 `waiting_review` | 15 秒，继续发现其他成员推进阶段的操作 |
| 成功、失败、异常、取消等已结束状态 | 停止详情轮询 |
| 展开的历史列表 | 打开时立即请求，之后每 30 秒刷新 |
| 收起的历史列表 | 停止历史轮询；保留首次加载与操作后的缓存刷新 |

AI 页的当前运行详情仅在运行记录区域可见时轮询；代码风险页的报告区域同样跟踪当前运行。任务提交、手工刷新、审核、导入、阶段推进等原有操作仍会立即刷新相关查询。

AI 详情请求结果同步到历史缓存，不再依靠高频历史请求更新当前行。历史仍以低频查询发现其他成员的新运行和更新；当选中运行的状态、阶段、审核、导入状态或更新时间改变时，重新获取其完整详情。已经结束的详情因此仍能发现他人的审核和候选编辑。比当前详情更旧的历史记录不会触发详情回退。

AI 历史按服务端分页加载，默认每页 20 条，可选 10/20/50/100；缓存键包含页码、每页条数以及功能用例的状态筛选。历史只返回摘要，产物内容由选中运行的详情加载。翻页保留全局最新运行与状态统计，运行按钮不会把旧页的第一条记录当成最新运行；审核、导入等操作刷新该任务所有历史页的缓存。详情状态变化同步更新已缓存的当前行、全局最新摘要及统计。功能用例状态筛选在服务端分页前执行。

API/UI 的单用例和当前测试集运行详情负责进度查询。报告关闭时不请求，打开时加载；报告本身不定时轮询。页面使用运行摘要更新状态和统计，报告明细保留最近获取的结果，运行结束后自动请求一次最终报告。可使用报告的手动刷新按钮提前获取明细。

后台标签页沿用 TanStack Query 默认的暂停轮询行为，未启用 `refetchIntervalInBackground`。轮询频率调整不改变鉴权和任务执行机制；历史摘要分页配套的数据库联合索引需要升级到迁移 `20261004_0025`。

以 40 人都查看一个执行中详情并展开历史估算，定时请求约为 `40 / 5 + 40 / 30 ≈ 9.3 次/秒`；历史收起时约 8 次/秒。初次加载、提交任务、最终报告、人工操作及其他页面请求不包含在该估算内。它只说明轮询频率变化，实际 40 人容量仍需生产规格下的负载测试验证。

分页使用真实 `RunHistoryTable`、`ListPagination` 与全局样式在隔离示例页面验证：1680×1000 和 760×1000 均无页面横向溢出；深色主题下翻到第二页，行号从 #21 开始，底栏显示第 21–40 条。该检查覆盖共用组件布局，不代表已登录业务数据的端到端验收。
