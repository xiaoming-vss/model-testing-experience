# Studio

MTX 管理测试生成任务从候选产出、人工审核到正式测试资产落库的生命周期。

## Language

**候选结果**：
生成任务成功产出的、尚可在审核前编辑的测试用例集合。
_Avoid_: 正式用例、导入结果

**源码包**：
UI 用例生成任务唯一的生成来源，是上传到任务并可被后续上传替换的 ZIP 源码归档。
_Avoid_: sourceContent、源码文本、需求附件

**审核**：
对候选结果作出批准或拒绝结论的独立业务动作，不代表正式资产已经创建。
_Avoid_: 导入、确认导入

**正式资产导入**：
将已批准的候选结果写入一个或多个正式测试集合或套件的独立业务动作。
_Avoid_: 审核通过、批准

**冲突预览**：
正式资产导入前展示同名正式用例与候选用例差异、且不写入正式资产的确认状态。
_Avoid_: 导入失败、已导入

**需求质量档案**：
以迭代需求为主线，持续关联需求说明、代码变更、缺陷、测试资产、执行证据及质量分析记录的质量上下文集合。执行证据来自本需求用例所属测试单的执行结果，属于派生关联：引用自用例库、原本属于其他需求的用例，其执行结果不会归入本需求。
_Avoid_: 会话记录、测试报告、需求附件

**人工检查点**：
多阶段 AI 任务在进入下一阶段前暂停并等待人工确认或修订的控制点，不代表候选结果已经完成审核。
_Avoid_: 审核、正式资产导入

**具体需求理解记录**：
需求分析任务在材料提取结果确认后形成的模块化需求产物，包含流程、规则、操作、交互及待确认问题，是功能用例生成复用的上游需求输入。需求分析执行统一为两个阶段。
_Avoid_: 原始 PRD、临时分析结果、功能用例

**代码绑定**：
项目或需求与 GitLab 资源的绑定：项目级绑定 GitLab 群组；需求级绑定（仓库+分支）。绑定只共享实例及资源身份，实时访问始终使用操作人的同实例个人授权。
_Avoid_: 关联、连接

**项目共享服务**：
项目成员共同可见的基础服务配置，包含名称、地址及模型，不包含个人凭据；所有者创建后，成员各自授权才能使用。
_Avoid_: 共享授权、共享账号

**个人授权**：
用户本人保存的基础服务连接。其他成员包括项目所有者均不能使用；每次人工执行、阶段推进或重试选择当前操作人的授权。
_Avoid_: 共享连接、接管

（旧「接管共享连接」术语已由个人授权规则取代。）

**项目角色**：
后端返回的所有者、普通成员、只读成员、开发成员及可用操作。只有所有者维护成员、设置、项目技能和外部绑定。

**开发成员**：
在当前项目仅使用 Bug 模块的成员，可查看 Bug 与附件、评论、转派和更新状态；不能创建或编辑 Bug 基本信息，也不能访问需求、测试资产、执行记录或测试设计。项目切换后按新项目角色重新确定可见功能。
_Avoid_: 全局开发账号

**基线**：
代码风险分析与变更概览的对比基准，按「手工基线分支 > 上个迭代最近一次绑定分支 > 无基线（整体视为全新变更）」的优先级确定。
_Avoid_: 基准分支、对比起点

**代码风险分析**：
独立 AI 任务类型（可重复发起），以需求文档、代码差异与现有测试内容为输入，输出变更概览/风险点清单/受影响用例/覆盖缺口四区块结构化报告。
_Avoid_: 代码审查、风险检测

**Bug 状态**：
激活、已解决、已关闭三个主状态，确认情况与解决方案分别展示；重新激活保留在处理历史中。延期处理属于未关闭的问题，不归为最终拒绝。
_Avoid_: 六状态机、已解决即已修复
