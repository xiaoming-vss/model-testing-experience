# 需求详情的测试设计工作区

需求列表点击名称进入 `/requirements/:requirementId`，默认显示“需求文档”。需求标题下方采用同级 Tab：需求文档、生成全景、需求分析、功能测试、API 测试、UI 测试、代码风险；每个视图占满内容区。生成全景不显示运行次数角标，其余五类计数表示本需求的同类型运行总数，切换不会触发生成。URL 的 `tab` 分别为 `content`、`generation`、`requirement_analysis`、`function`、`api`、`ui`、`codeRisk`，支持刷新和前进后退；旧 `tab=design` 兼容为生成全景。页面不展示数据模型中不存在的负责人、需求序号或版本字段。

## 生成全景与导入

“生成全景”按需求文档、需求分析、功能测试、API 测试、UI 测试、代码风险六条泳道展示。每条链的阶段节点显示最新已通过版本、草稿、运行、失败或作废状态；需求文档和代码风险是只读/独立泳道，不参与版本链。点击阶段打开大弹框，保留版本条、上游版本选择、可视化与 YAML/JSON 原文切换、复制、版本历史、行级 diff、继续优化侧栏，以及审核通过、审核通过并继续、审核不通过。最终阶段不显示“审核通过并继续”；查看历史版本时审核和优化只作用于当前草稿。阶段运行只检查本阶段是否已有待审核产物和链路是否正在执行，其他阶段的待审核产物不再阻止当前阶段重新运行。

上游版本被删除后，依赖它的草稿显示“草稿已作废”和原因，不再提供审核或继续优化，只能重新生成。删除版本后的提示会包含被作废草稿数量。历史版本和作废草稿保留正文用于诊断，不计入待审核草稿数。

叶子阶段（功能完整用例、API 用例、UI YAML）查看已通过版本时提供“导入此版本”。导入弹框展示叶子版本、完整父链、目标正式资产、当前正式来源（版本、导入时间、变更用例数、混合来源）和冲突预览；功能链按模块自动归属测试集，API/UI 必须选择当前需求下的集合或测试集。确认后调用版本级导入接口，成功提示变更用例数，并刷新生成链和正式资产列表。正式目标只保存最新 `effective_import_id`，仅供生成链判断已导入和防止重复导入；来源版本被硬删除后，生成链提示需要重新导入。

## 导入后的正式资产

导入完成后，正式资产就是独立的测试资源：需求详情不提供质量档案页签，用例库、API 测试集和 UI 测试集不展示来源徽标，迭代看板和测试报告也不展示正式来源口径。看板按当前迭代关联的用例统计。`effective_import_id` 和导入记录只保留在生成链内部，用于“已导入”状态和重复导入校验。

代码风险页签与设计类页签同一工作区形态：运行记录按当前需求聚合展示（复用 `RunHistoryTable` 列表外观与公共分页），不提供任务列表或新建任务表单；首次运行自动创建绑定当前需求的任务（按需求自动命名），已有任务自动复用，多条历史任务的记录继续汇总。运行前依次确认本人模型授权（弹窗可填补充指令）与需求各仓库的本人 GitLab 授权；需求未绑定代码仓库时运行禁用，原因仅在悬停或聚焦时提示先完成「代码绑定」。运行产物为「分析报告」，在弹窗中查看；失败运行提供错误信息入口；删除运行记录保留二次确认。

## 创建与复用

点击运行会复用本需求已有配置，自动绑定项目、迭代和需求。需求分析和功能测试首次运行时自动创建后台任务，不要求选择或新增配置；需求分析使用当前需求文件，功能测试使用需求中已有的有效增强文本，兼容普通文本、Markdown 和结构化需求理解，API 使用 OpenAPI/Swagger 文档或已有文档 URL，UI 使用源码 ZIP。功能生成的入口在增强文本为空或结构化内容无效时禁用，原因仅在悬停或聚焦生成按钮时提示，不在运行列表上方常驻显示。

补充指令在运行选择本人模型授权的弹框填写，仅用于本次运行，下次打开重置为空；四类生成即使只有一个模型授权，也必须打开弹框确认。需求分析和功能测试不再展示设置入口，API/UI 设置只展示对应类型的输入材料，不展示配置选择或新增配置。已有任务自动复用，多份历史任务的记录继续汇总展示，不合并或删除。每次运行使用本次操作人的个人模型授权，不能借用任务创建者的授权。需求分析和功能测试在每次运行的模型授权弹窗中配置阶段人工审核，默认开启，可手动关闭；只有一个可用授权时也必须确认本次审核选项。重试阶段和生成图谱仍只选择模型授权。

UI 测试点击“生成用例”后，在本人模型授权弹窗内选择“来源功能用例”，默认选中当前需求全部正式功能用例。选择区使用复选框表格，支持按多个用例集筛选、按标题或编号搜索及分页；显示全局已选数量。表头只选择当前页，另提供全选／取消当前筛选结果和清空全部选择；切换筛选、搜索或翻页保留其他范围的已选内容。弹窗扩大以容纳列表，窄屏正文内部滚动，底部确认动作固定。来源读取失败或未选中任何用例时禁止提交；尚未准备正式用例时提示先在“功能测试”审核并导入正式测试集。该入口固定开启三阶段审核，所选用例编号随 `functionCaseIds` 传入需求页运行接口并冻结到运行快照；切换选择后重新提交使用新的请求身份。独立 UI 任务页沿用同一选择组件。

配置保存和运行提交都带请求 UUID，网络响应丢失后重试沿用同一身份。源码上传失败会保留已创建的任务、所选文件和上传进度，再次保存复用该任务；关闭后也能通过已保存配置恢复上传。任务执行中不能再次启动，需先完成当前运行。

## 运行与产物

运行记录由后端按需求与类型汇总所有历史任务，分页及数量都在服务端计算；需求详情不保留状态筛选；需求标题栏右侧放刷新、设置和运行动作，不再单列运行记录标题，保留30秒轮询。列表只加载摘要，选中运行和打开产物才读取详情。列表行直接显示当前阶段与审核状态，不额外展示阶段概览栏或生成依据入口。运行列表通过独立“创建时间”列显示真实创建时间，运行编号下不再重复时间，需求文件摘要发生变化时提示所选运行来自旧材料快照。

四类任务继续使用原有产物和审核工作区。需求分析保留材料与理解对照、UI 交互、原始 JSON、继续优化的待确认问题预填和审核；用例生成保留候选编辑、批准、导入和覆盖冲突确认，功能用例审核通过后仍可生成或重新生成图谱，并选择本次操作人的模型授权。已拒绝的需求分析只可查看和删除，重新生成发起新运行。其他任务的状态规则保持既有行为。

UI 测试的三阶段运行在「产物」列展示元素控件清单、UI 用例设计和 UI 用例，点击任一产物按该阶段独立打开审核弹窗，不在同一弹窗内用页签切换；只有当前待审核阶段可编辑，审核入口直接定位到当前阶段。弹窗默认展示结构化可视化：阶段一按页面展示控件、定位候选、显示条件和待确认证据；阶段二按场景展示步骤、操作、断言和 sourceQuote 映射；阶段三按用例展示步骤、定位值、可执行度和缺口字段。标题栏可在可视化与 JSON/YAML 原文之间切换，可视化只读，修改、保存与审核在原文视图完成。审核备注和保存、继续优化、审核不通过、审核通过并继续固定在弹窗底部；继续优化与需求分析、功能测试一致，打开右侧优化面板并在底部提交。没有三阶段标记的旧 UI 运行仍只展示「UI 用例」。

需求分析和功能测试的继续优化支持附带最多 6 张、单张不超过 10 MB 的 PNG/JPEG 截图。图片随本次修订指令提交，取消或提交失败后保留草稿，提交成功后清空；图片只作为本次修订的补充依据，不写入产物正文。后台重试沿用同一批图片。UI 三阶段继续优化复用同一侧栏，但当前修订协议不携带图片附件，侧栏不展示图片入口。

行内至多三个操作，直接显示；删除使用图标并保留二次确认，执行中的记录不可删除。已导入运行的删除不影响正式资产。

## 导航与样式

侧栏不保留四类测试设计分组，改为独立“代码风险分析”入口，位于一级导航“迭代”“需求”之后、“测试”之前。需求列表不再重复显示该入口。页面标题直接显示“代码风险分析”，不再提供任务类型选择器；支持按迭代、关键字和状态筛选；四类测试设计与代码风险分析均在需求详情开展。总览不再挂载四类任务查询、操作及弹窗，也不再保留无可用批量动作的多选框或不支持的删除入口。代码风险分析在迭代代码变更区保留入口，独立总览列表仍可创建和管理全局任务。原有任务详情 URL 继续可访问。工作区通过独立的脱离文档宿主复用任务控制器，只有其弹窗挂载到页面，旧任务页面容器不参与工作区布局。弹窗打开安排在初始化 effect 之后，并取消 React StrictMode 中已撤销的 effect，缓存命中时重复查看仍可正常打开与关闭。

需求详情的页签采用轻量下划线 Tab，独立位于需求标题栏上方，计数使用小号次要文字；需求标题、操作栏、文档或运行列表及分页共用一个外框。保留 Tab 语义、方向键导航和运行数量提示，窄屏切换区独立一行并横向滚动。需求标题栏右侧在下载、编辑之后提供当前类型的刷新、设置与运行操作，文档 Tab 隐藏这些操作，代码风险 Tab 提供刷新与运行分析。运行列表四周内收 16px，不再保留单独的操作行，空间不足时操作组换行。顶部信息栏仅在需求文档页签提供下载原文件，编辑需求在各页签保留。文档和运行列表沿用外框的 `--srf-card` 内容面，不再各自增加描边与圆角，表格使用 `RunHistoryTable` 的 list 外观和公共分页，滚动发生在内容区内部。

旧底部展开条、上下分隔拖动组件及相关样式已删除。文档 Tab 保持挂载，切换时保留阅读位置；文档统一通过“需求文档”Tab 阅读，内嵌文档不再显示文件类型、文件名和下载组成的独立工具栏；下载移至页面顶部需求信息栏。正在提交或打开业务弹窗时禁止通过 Tab 切换类型。窄屏 Tab 可横向滚动，工具栏换行。

方案原型归档于 `codex/requirement-tabs-prototype` 分支的 `apps/studio/.codex-requirement-tabs-preview/index.html`；采用 A 版同级 Tab，原因是各类任务共享完整工作区，且入口位于需求标题下方。

## 需求详情交互补充

“返回需求列表”直接进入需求列表，沿用工作台当前项目与迭代范围；浏览器前进、后退继续保留 Tab 切换历史。详情读取失败支持就地重试，Word 与文本预览失败支持重新加载，并保留原文件下载入口。

Tab 的数量提示明确为本需求、当前类型、所有状态的历史运行次数；支持方向键循环切换及 Home/End 首尾导航，普通 Tab 键仅进入当前页签，文档保持挂载。运行按钮的禁用提示区分读取中、读取失败、操作处理中、增强文本缺失和当前任务未结束，仍仅在悬停或聚焦时显示，不增加常驻横幅。

增强文本非空显示“已有内容”，不据此推断已提取、已审核或与当前文档同步；空态说明通过需求分析生成、审核与导入的路径。材料更新提示根据当前类型区分重新分析与重新生成用例。
