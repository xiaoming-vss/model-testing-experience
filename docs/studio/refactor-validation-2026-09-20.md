## 首轮发现的问题与限制

以下测试失败为修复前记录；后续修复结果见文末。真实部署端到端验收及构建体积限制仍然适用。

- 控制面 `test_project_membership_api.py::test_function_stage_reexecution_uses_current_actor` 的 owner/member × retry/revise 四种组合返回 HTTP 400：测试前置数据没有当前业务要求的需求分析增强文本。整改前源码副本运行同四项也失败，未在重构中改变业务前置条件。
- Studio `FunctionalCaseGenerateTaskDetailPage.test.tsx` 的“优化侧栏预填当前编辑中的待确认项，并保留补充内容”在第 882 行查找 `待确认项（2）` 失败。整改前副本可复现相同断言失败，保留原测试与页面行为。
- Ant Design/CodeMirror 重型交互测试在全量并发时会超出原有 30s 限制。本次没有全局放宽测试配置；复跑参数仅用于区分超时与行为失败，不能将全量测试描述为全部通过。
- 自动化覆盖了现有测试和上述补充边界；未连接真实部署环境进行浏览器端到端验收。静态引用图不能证明所有动态业务路径均可达。

在 `apps/studio` 下可复跑本次新增用例：

```sh
npx vitest run src/shared/utils/value.test.ts src/features/api-automation/hooks/apiWorkflows.test.tsx src/test/automationEditors.test.tsx --maxWorkers=1 --testTimeout=120000
```

重型页面失败场景可用同样的单进程与超时参数，通过 `-t` 指定上述测试名称复核。各项目常规检查命令继续使用各自 README 中的入口。


## 后续失败修复

- 控制面权限测试绑定真实需求，并通过需求更新接口准备已导入的增强文本。没有放宽功能用例生成的前置条件；仍验证 owner/member 交替发起阶段重试与修订时使用当前操作人的个人凭据。
- 前端待确认项断言改为切换到可视化、按实际按钮名称展开分区，验证两条当前问题可见且旧问题不存在；不再查找已经过期的括号计数文案。
- 三个重型任务详情页测试共用 `TestThemeProvider`，保留真实主题与组件，只关闭 jsdom 不执行的 CSS 动画，避免弹窗永久停留在进入动画的透明状态。
- CPU 采样定位到按角色查询时的 CSS 继承值计算。类型筛选测试将查询限定在筛选区域，需求分析侧栏测试将查询限定在当前审核弹窗；Vitest 串行运行测试文件，避免重型页面争用 CPU。保留原有 30 秒单项超时，不跳过或删除失败用例。
- 动画关闭后发现 UI 放弃草稿测试依赖旧编辑器残留节点。现在等待旧节点卸载，重新打开弹窗后切换到编辑 YAML，再验证已保存内容恢复且未保存内容消失。
- GitLab 权限撤销测试改为等待 Query 缓存的异步通知完成，再断言两个选择器禁用，保留“没有提交修改请求”的断言。
