# Bug 管理需求核对与页面整理

核对日期：2026-09-28。需求来源：`/home/xiaoming/data/文档/test-agent/需求/Bug管理需求.md`。
范围：当前工作区的 Bug 管理、富文本描述及测试单提交入口；工作区还有其他未提交功能，本次未作全仓库重构。

结论：六状态流转、独立转派、三种拒绝原因、创建人保留、修复与回归说明、多轮状态处理记录已实现。本次补齐多处前端功能和后端校验，但尚不能认定全部满足需求。

## Spec

已修复：

- 列表只有每页数量、没有翻页入口：接入服务端分页，修正总数和页码区间，筛选与项目变更后回第一页。
- 列表缺少状态处理和可选列：新增按状态显示的处理菜单，支持所属需求、创建时间、关联测试单与关联用例四类可选列；创建人仍为默认列。
- 执行入口成功提交后又触发取消返回：分离保存与关闭回调，成功保留在新 Bug 详情；来源路由携带项目，避免套用另一个当前项目。
- 详情需求与执行来源只有文字：需求链接复用应用层文档预览；用例和执行记录跳到来源测试单并选中对应执行条目。该链接仍指向当前条目，不能替代不可变执行历史。
- 创建缺少项目选择：提供有写权限的项目选项；切换项目清理所属项目相关选择与文件引用。计划修复迭代筛选不再误作发现迭代默认值。
- 拒绝历史没有显示必选原因、转派显示用户 ID、编辑历史重复：明确显示原因、前后状态及责任人姓名，修改内容仅展示一次。
- 描述修改历史截断到 120 字：保存完整消毒后的前后正文，可展开对比；此前已经被截断的历史无法恢复。
- API 可以提交空描述：创建和编辑均检查消毒后的有效文字或内嵌图片；拒绝空白及只含脚本的描述。
- 附件下载不校验 HTTP 状态：下载失败显示错误，不再把错误响应当作附件保存。

仍未满足：

1. **P1：具体执行历史不可追溯。** 需求第 6 节要求“回归执行保留新的执行记录”。`control-plane/services/test_order_entry.py` 的 `update` 原地修改执行结论、执行人和执行时间；Bug 的 `source_entry_id` 指向可变条目，没有独立执行记录身份。新建另一张测试单可以保留前一张的结果，但当前系统不保证每次执行保留独立记录。需要在执行领域设计不可变记录，并让 Bug 关联该记录；本次没有改造执行存储模型。
2. **P2：创建后不能补充或调整执行关联。** 需求第 4.4 节把“关联记录”列为不改变状态的操作，目前只有创建时可选择来源，编辑请求及表单不支持更新测试单、用例和执行记录关联，也缺少相应历史。

需求第 7 节的权限、未关闭口径及编号规则是待细化项，不当作已确认需求。本次沿用已有 ADR 0004：项目 write 权限、项目内编号、未关闭不含已拒绝。

## Standards

初审 4 类发现：组件过长及页面混合渲染职责、跨 feature 内部引用、重复缓存刷新、附件下载错误边界。已拆出列表查询、表格列、工具栏、详情头部与侧栏、表单查询与保存逻辑；统一 Bug 缓存刷新入口，删除父子重复刷新、无效 uploading 状态和失效样式；补齐下载错误处理。

跨 feature 的项目权限与全局项目/用户状态引用仍存在，与仓库 S3 只允许经 api/types 通信的目标有差距。项目权限组件和全局作用域目前被大量已有页面直接使用，应在应用层统一注入时一并收敛。本次不把复制包装或改名转导出当成修复，也不宣称已清零全部结构债务。

页面沿用公共工具栏、表格尺寸及主题变量；详情采用左侧正文/历史、右侧基本信息，去掉原先继承工作台面板高度造成的大块空白；窄屏切为单列。表单采用项目和字段分组、双列严重程度/优先级；使用共享富文本编辑器。

## 验证与限制

- Bug 列表、提交成功导航、拒绝/转派动态及侧栏/列表样式测试通过；新增覆盖第二页访问、服务端总数和列表状态操作。
- 后端 Bug API 测试 11 项通过，包含空描述、消毒后空内容、完整描述历史的新增回归测试。
- 类型检查、改动文件 ESLint、主题色检查、生产构建及后端改动文件 Ruff 检查通过。构建仍有现有大包体积提示。
- 浏览器使用隔离样例核对列表、详情、编辑抽屉、空结果，以及浅色/深色和 1680×1000、760×900 布局；未向真实项目写入样例数据。临时样例入口和服务已移除。
- 本地真实站点需要登录，本次未完成真实账号及对象存储附件的端到端验收；自动化和样例布局检查不能替代该验收。

初审规范轴 4 类问题，需求轴 7 类问题加提交导航缺陷；本次修复后，规范轴仍以跨 feature 边界为主要债务，需求轴仍以独立执行历史为最高优先级缺口，并补充识别创建后关联维护缺口。

后续布局修正：Bug 列表卡片填满工具栏下方的可用高度，筛选栏和分页不收缩，表格内容独立滚动。浏览器用 1 条和 50 条隔离样例验证：两种情况下卡片及分页底部位置一致，多条数据仅增加表格滚动高度。

### 列表视觉对齐（2026-09-28）

- 对照测试单、API 测试、UI 测试的现有列表实现，复用 functional-test-page 与公共表格名称样式；编号独立成列，标题采用单行图标与蓝色链接。
- 高级筛选和附加显示列收进工具栏弹层，保留快捷筛选与发现/计划修复迭代切换。
- 去掉旧表格内距，统一状态胶囊、操作图标和浅色分页栏；保留满高与内部滚动。
- 验证：9 项 Bug 相关测试、TypeScript、改动 TSX ESLint、主题颜色检查通过。浏览器使用真实 AppShell 和模拟只读数据，核对浅色/深色、2326×1361 桌面布局与列设置交互；Bug 与测试单名称均为 13px、500 字重、rgb(63, 111, 198)。

### 列表筛选简化（2026-09-28，按最新反馈）

移除迭代类型切换及「我负责的 / 待回归 / 未关闭」快捷栏，固定按发现迭代查询。保留迭代选择和筛选弹层，清空筛选入口移入弹层；同步删除快捷条件状态、映射及样式。此调整替代前述保留快捷筛选的设计。

### 创建表单设计稿试版（2026-09-28）

依据用户提供的 stitch_ui.zip，将侧边抽屉改为居中宽弹框：双列项目与发现迭代、整行标题、四列处理属性、关联信息、富文本描述及附件区，底部固定取消和提交操作。复用原有表单与上传逻辑，保留真实优先级枚举，未添加设计稿中的自动暂存等未实现功能。组件更名为 BugFormModal，移除旧抽屉专用样式。浏览器核对 1680×1000、1280×720 和 390×844 布局；5 项列表与来源提交测试通过。

根据试版反馈继续对照原稿细化：缩小表单间距、添加真实发现迭代徽标与 ESC 提示、使用蓝色缺陷图标、实蓝优先级选中态及提交按钮、横向上传区和附件列表。主按钮通过局部按钮变量适配全局 app-buttons 层，浏览器确认背景为 rgb(29, 78, 216)、文字为白色。自动云同步、AI 查重、草稿等原稿示意功能仍未实现，不展示虚假入口。

### 描述模板预置

按设计图在描述右上角增加标准模板、崩溃 Crash、接口异常三个前端固定模板。空内容直接填入，已有文字或图片时确认替换，取消保留原内容，附件不变。模板切换时重建编辑器以载入新内容，提交继续使用 descriptionHtml。浏览器确认真实编辑器显示模板章节，组件测试覆盖插入和替换保护。

### 详情页设计稿试版（2026-09-28）

按本次 stitch_ui.zip 调整为顶部操作栏、左侧标题/描述/附件/动态卡片和右侧属性/关联卡片。标题独立展示，属性补充状态色及责任人首字头像，关联信息使用独立浅色卡片。操作继续受状态机和权限控制，保留评论、下载、编辑与转派。未引入设计稿中的虚构环境标签、SLA 和视频预览能力。浏览器以模拟只读数据检查 1680px 与 900px 视口，相关 6 项测试通过。

### 详情继续对齐与滚动修复

根因是 api-automation-content 继承了列表的 overflow:hidden，而实际应用外壳也限制溢出。详情改为有界内部纵向滚动，操作栏 sticky。使用真实 AppShell 模拟只读数据验证：720px 高窗口中容器 clientHeight=657、scrollHeight=1159，滚至 scrollTop=502 后底部评论输入框可见。

标准章节描述支持前置条件底色、复现步骤、实际/预期结果并排红绿卡片，保留未知内容和图片；支持渲染/RAW 切换。附件按 MIME 类型为常见图片与 MP4/WebM 提供签名地址预览，其他文件保持下载。4 项章节保真与动态测试通过；浏览器验证 RAW 切换及底部滚动。

### 详情宽度与时间字段修复

移除详情列的 1600px 最大宽度，沿用与顶部操作栏相同的父容器可用宽度。Bug 和活动响应实际使用 createdAt；补充类型并统一通过 pickCreatedAt 兼容 camelCase/snake_case，修复标题提交时间、侧栏创建时间、处理记录、评论及可选创建时间列。3 项动态测试通过，包含两种时间字段的回归覆盖。

### 附件展示精简

附件区按描述中的 data-file-id 排除已嵌入富文本的文件，数量同步使用过滤后的附件数。图片/视频默认不选中、不请求预览地址，点击文件名后才加载，支持再次点击或“收起预览”关闭。自动化测试覆盖正文图片排除、默认不请求、点击展示及收起。

### 评论区位置调整

按最新截图将评论与动态移至右侧关联信息下方。保留输入、发送权限和动态时间；窄栏中时间独占一行，窄屏双列属性布局下评论区跨满整行。

### 编辑回显修复

富文本编辑器回显时为缺少 src 的 data-file-id 图片获取签名地址，通过文档事务补全图片节点，不重置正文/光标，不将临时地址写入保存值。编辑附件区同时显示已有独立附件和新选文件，排除富文本图片重复展示；已有附件可下载，不提供尚未实现的删除动作。后端编辑接口采用追加绑定，新增文件不会覆盖原附件。增加真实 Tiptap 图片回显与附件列表回归测试。
