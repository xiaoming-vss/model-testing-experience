已审核的需求理解默认收起材料面板，内容通栏展示，并隐藏常规“有明确依据”标签及来源定位链接；待确认、冲突和示例状态仍保留。左下角“查看材料／依据”按钮可恢复完整对照，再次收起不改变当前分类和模块选择。待审核记录默认保留材料对照。此变化仅影响显示，不删除原始材料、提取事实、来源或确认状态。

配色统一使用全站 surface、text、accent、border 等语义变量，移除阅读弹窗对公共文本和按钮变量的覆盖；弹窗外框与背景继承公共产物弹窗主题，浅色与深色均跟随全站切换，保留现有阅读布局。

UI 交互的模块和操作入口合并为单一“选择操作”下拉框：按模块分组，支持模块名与操作名搜索，选中值展示“模块 / 操作”。内部以模块 ID 与操作 ID 的组合定位，跨模块切换同步更新控件、行为和操作步骤，保留无控件操作的查看入口及原有指定操作跳转。

## 精简产物 2.0

需求理解阅读入口只接受 2.0，旧版明确报错，不提供自动转换。材料提取的独立 1.0 契约不变。2.0 将来源定位及摘录存放于 `evidence`，由 `evidenceIds` 引用；`requirementEvidence.ts` 只为展示解析来源和缺省确认状态，不改变编辑器、保存请求和导出使用的原始 JSON。任务审核、UI 交互阅读、材料对照和正式需求预览复用该入口，来源按钮继续定位相同材料。证据不存在或证据 ID 重复时显示错误，不静默隐藏依据。

流程的 `conditionRuleIds` 显示关联规则名称，展开后查看规则和依据，不展示孤立 ID。普通概述字符串直接展示；未知、冲突、示例及不适用保持原状态。省略的可选事实仍表示未记录，不能推断默认值或确认结论。证据索引不另行铺满业务正文，原始 JSON 仍可完整查看。

### 精简字段的展示检查

操作的 `ruleIds` 与流程的 `conditionRuleIds` 均可按规则名称展开详情及依据，展开后才渲染正文，避免多处引用导致大量隐藏重复内容。仅使用规则引用的流程分支以规则名称命名，多个条件用“且”连接；`stepId=null` 显示“流程结束”，不误标为未知。

UI 交互页省略没有返回的可选字段及空的可选集合，例如默认值、输入规则、分页、排序、联动和反馈；显式的 unconfirmed/conflicting/not_applicable 事实仍展示。普通概述字符串直接呈现，编辑与导出仍使用原始精简对象。任务审核及正式需求预览共用这些阅读组件；后续测试分析、测试点、用例和图谱的输出协议未改变，无需增加兼容分支。

### 阅读性能

同一需求理解快照通过 RequirementArtifactScope 共用解析结果、证据展开结果及名称索引，快照替换时重新计算，避免逐字段扫描整份产物。UI 控件和模块操作的折叠内容按需挂载；未展开时不渲染隐藏详情。右侧分类切换复用左侧材料面板，仅在来源、定位或材料模式实际变化时更新。
