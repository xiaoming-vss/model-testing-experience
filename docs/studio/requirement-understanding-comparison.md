# 需求理解对照视图

2026-10-07，用户确认第二阶段也采用类似材料对照 B 版的布局。需求理解记录在查看、审核及已审核待导入窗口共用同一阅读组件。

右侧默认显示模块与操作，选择模块后展开首个操作，模块说明、入口及使用流程可单独展开。其余分类为 UI 交互、功能概况、业务流程、业务规则、待确认问题；后面三类支持搜索。更换分类或模块时，从顶部开始阅读，并清除上一项依据高亮。

模块操作展示目的、前提、流程及关联规则；操作内重复的 interaction 展示已移除，交互细节统一由 UI 交互页签读取。每个操作提供“查看 UI 交互”入口，按模块和操作 ID 定位到该操作；即使其控件为空也不会跳到其他有控件的操作。原始产物保留完整交互数据。

UI 交互为独立阅读页签，直接读取已有操作的 interaction，不按操作名称猜测是否属于 UI，也不补充产品事实。默认选择首个有控件记录的模块和操作，可切换到该产物内其他模块及操作。控件、选项及其含义、默认值、输入约束、触发、初始状态、联动、结果、分页、排序、反馈和操作步骤直接展开。无控件记录时明确显示空记录，仍可查看操作的触发与反馈；缺少字段仍显示未明确。示例、待确认、冲突和不适用状态原样保留，选项完整性用中文表达。所有可定位依据复用左侧材料对照，阅读不改写原始 JSON。

左侧复用第一阶段材料面板，可切换材料来源或查看全部已审核提取事实。审核不改变事实的确认状态：待确认、示例、不适用及冲突信息继续保留。

材料提取和需求理解弹框与功能测试用例结果弹框采用相同尺寸：宽度为 `calc(100vw - 56px)`，左右各留28px；高度受视口约束，保留顶部信息和底部操作栏，正文独立滚动。

点击具体说明中的依据，左侧显示对应来源、定位与摘录。材料关联只使用明确证据：同一来源的精确引用、正文段号区间、来源唯一的整张图片，或唯一的字面摘录；不会根据近似文字猜测控件、动作或材料块。图片定位到整张图片，不虚构控件坐标。无法明确对应材料块时仍展示引用信息。

理解阶段补充来源通过当前产物的来源登记查看；缺少上游材料提取记录时显示说明，同时继续展示理解内容与已有引用。原始 JSON 编辑、保存、审核不通过、继续优化和审核后导入流程保持原有接口及校验。两个阶段的主体结构保留，问题闭环约束见本文末尾。

2026-10-07 问题闭环规则：两阶段业务阅读只展示尚未解决的问题和剩余缺口，计数只包含未解决条目；没有待确认问题时隐藏分类，当前分类自动回到事实或模块。旧产物中的 resolved 条目及其关联问题提示不进入业务阅读，原始 JSON 编辑仍保持输入原貌，需通过继续优化补齐正文并返回新契约。新生成、保存和审核后的产物不保留已解决问题及关联引用；答复依据保存在对应业务事实的来源引用中。未答复的问题与相关未知状态仍保留。

独立 UI 页签验证：48项相关测试、ESLint、TypeScript、主题检查和生产构建通过。使用当前实际需求理解产物的只读快照，在2324×1517检查默认前端操作的8个控件、未知默认值与命名冲突、线框图引用定位 B16、正文滚动到底；760×1000上下排列且无页面横向溢出，1680×1000深色操作栏可见并消费原有主题边框。截图及隔离复现数据位于 .scratch/requirement-ui-interaction/。

已拒绝的运行作为只读终态：列表及产物窗口仅支持查看，原始 JSON 为只读，菜单保留删除运行；保存、优化、重试、审核及导入不可用。重新生成发起新运行。详见 [需求分析审核规则](../control-plane/requirement-analysis-review.md)。产物弹框绑定运行 ID，首次选择较早运行也可直接打开。

2026-10-07 继续优化预填：首次打开当前运行阶段的优化侧栏时，从当前产物草稿提取尚未解决的问题，按原编号逐题生成“答复”占位。材料提取与需求理解均适用；历史已解决问题不带入，无待确认问题时留空。取消后重新打开及提交失败保留已填写草稿。仅依据明确补充的信息修订，未填项继续待确认；原样模板不能提交，支持直接改写为其他优化要求。沿用阶段修订接口，同时携带左侧未保存的产物修改。

需求分析运行记录操作列按界面规范直接展示至多三项操作：待审核记录显示审核与删除图标；失败记录显示错误信息、符合条件的阶段重试及删除图标；已拒绝记录仅显示删除图标。删除复用全站动作图标及悬停提示，仍需确认；执行中的记录保持删除禁用和原权限门控。
