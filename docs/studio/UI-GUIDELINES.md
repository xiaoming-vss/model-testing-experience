# 界面与交互规范（Studio）

本文件维护前端页面的布局与交互约定。代码组织、样式归属与依赖方向见 [STRUCTURE.md](STRUCTURE.md)，开发命令见 [README.md](README.md)。本文件中的源码路径相对 `apps/studio/`。

最近整理：2026-10-13。以下章节描述当前生效规则；带日期的验收记录仅说明当时验证范围，不作为旧配色或旧尺寸的实现依据。

## 适用范围与现状

新增列表页和修改中的列表页遵循本规范。详情页、编辑器、图谱与弹窗可以按任务需要采用不同布局，不机械套用列表尺寸。保留业务所需的目录树、进度条与环境选择，不为外观一致而编造功能或字段。

截至 2026-09-24，以下两组页面已完成本次布局调整：

- 测试：测试单、API 测试、UI 测试、用例库。
- 测试设计：需求分析、功能测试、API 测试、UI 测试、代码风险分析，共用 `UnifiedAiTestingPage`。

“已实现”不等于“已有自动化检查”。本文件末尾分别列出检查覆盖与人工验证要求；其他存量页面尚未完成全面对齐。

## 导航与创建

应用顶栏桌面高度为56px，左右与公共页面边距对齐；项目和迭代选择器放在同一个细边框圆角容器内。侧栏品牌区高64px、Logo为40px，折叠导航保持76px宽、58px项高和图标下方文字。900px以下顶栏按内容换行，540px以下项目与迭代分行，操作入口保持可见。

侧边栏展开宽度为 192px，折叠为 76px 图标轨，底部提供展开／收起按钮。展开导航为 36px 高、8px 圆角和 13px 字号；浅色选中项使用浅蓝灰底、钢蓝字与 600 字重，不加描边或阴影。顶部 Tab 使用蓝灰底、细边框，选中项为浅底钢蓝字。系统中文字体缺少粗体时允许合成字重，避免选中态变细。

测试页 Tab 与基础服务页一致：外层 `margin: 12px var(--app-page-gutter) 0`，顶部与左右均为 12px，与下方内容面板左边界对齐；窄屏沿用公共页边距，不另加 24px 内收。实现为 `features/testing/styles/navigation.css` 与基础服务的 `.base-services-navigation`。

## 列表页面布局

新增及修改中的列表页、卡片页默认采用“外置 Tab + 单一内容外框”。无 Tab 的页面直接显示内容外框。标题、筛选与操作栏、内容区和已有分页共用一个外框，并按主题角色区分表面；外框保留 12px 圆角及细描边，内部工具栏仅保留底部分隔线。卡片网格中的业务卡片保留自身边界与间距。

公共实现位于 `shared/styles/surface-tokens.css`，页面显式接入以下结构；未迁移的旧 `tp-board` 保持兼容，不作为新页面模板：

```tsx
<div className="page-class tp-surface tp-list-surface">
  {/* 页面级 Tab 位于外框上方 */}
  <section className="tp-board tp-list-panel">
    <div className="tp-list-toolbar">{/* 标题、筛选、操作 */}</div>
    <div className="tp-list-body">
      <div className="tp-list-scroll">{/* 表格、卡片网格或空态 */}</div>
      <div className="table-footer">{/* 已有分页或数量统计 */}</div>
    </div>
  </section>
</div>
```

- `tp-surface` 放在外框的祖先节点，提供主题 token 与样式作用域。`tp-list-body` 在需要中间包装层时使用，不增加第二层表面。
- 内容滚动区四周内收 16px，表头、行背景及分隔线随内容内收；分页在滚动区外，位于同一外框底部。保留 `flex` / `min-height: 0` / `min-width: 0` 高度链。
- 工具栏与内容之间不另加页面背景间隙。状态筛选条可放在同一外框内。Tab、标题和筛选的业务顺序由页面决定，窄屏允许换行，表格在内容区内部横向滚动。
- 空态、加载、错误、只读权限都使用同一外框。分页只复用真实能力，不新增虚假分页。
- 需求详情：下划线 Tab 独立位于外框上方，窄屏横向滚动；需求标题与操作共用顶栏，下载原文件仅在需求文档 Tab 显示，编辑需求保留，刷新、设置、运行跟随当前设计类型显示。运行列表内收 16px，文档保留自己的阅读布局。
- 已接入：需求、迭代、测试单、API/UI 测试、Bug、代码风险分析、基础服务四类 Tab 和需求详情。用例库的目录树、编辑器、图谱等复合布局按自身语义处理；未迁移页面不因公共样式更新自动改变布局。

| 项目 | 规范值 | 当前适用范围与实现 |
| --- | --- | --- |
| 左右外边距 | 12px | 全局工作台页面；`src/index.css` 定义 `--app-page-gutter`，页面外层 padding / margin 引用该变量 |
| 上／下外边距 | 12px / 16px | 四个测试列表桌面布局，同上 |
| 工具栏最小高度 | 56px | 四个测试列表；`shared/styles/surface-tokens.css` 的 `.tp-list-toolbar` |
| 工具栏内边距 | 上下 10px、左右 16px | 同上 |
| 外框／内部工具栏圆角 | 12px / 0 | 外框使用 `--srf-radius-card`，内部工具栏仅底部分隔线 |
| 工具栏表面 | 与分页栏同色，浅色比表头浅一档、底部分隔线、无额外阴影 | `--app-list-toolbar-bg`，深色回退 `--srf-card`；边框 `--srf-card-border` |
| 测试设计状态栏 | 单行最小高度 37px，内边距 6px 16px | `features/ai-testing/styles/task-list-v2.css` |
| 状态栏操作按钮 | 高度 24px，左右内边距 8px | 同上；有无批量删除按钮均保持栏高一致 |

全局左右外边距通过 `--app-page-gutter` 管理：项目与迭代工作台、测试、测试设计、基础服务、Skill 库、复用工作台容器的详情页及个人设置均引用此变量，窄屏规则使用同一值。个人设置的居中最大阅读宽度保留；登录页不属于工作台外壳。此变量只用于页面外层，不替换表格单元格、卡片内部、表单、弹窗与抽屉的内边距。56px 工具栏已用于四个测试列表、基础服务和项目总览顶部信息栏；项目总览名称、角色与描述横向排列，长描述省略并可悬停查看，窄屏允许换行；基础服务分类按钮采用 28px 最小高度，以容纳在紧凑工具栏中。

迭代详情顶部信息栏同样复用 `tp-surface` / `tp-list-toolbar` 的 56px 最小高度、10px 16px 内边距和 12px 圆角；迭代名称使用 `tp-list-title`，统计标签与数字单行排列，操作间距 8px，窄屏允许换行增高。详情内容卡片保持自身布局。

不要为了紧凑而缩小正文或可点击区域。空间不足时允许工具栏、状态栏换行并自动增高；表格按需横向滚动。上述最小高度不应变成裁切内容的固定高度。

公共标题操作栏和底部分页栏在浅色模式共用 `--app-list-toolbar-bg`（`#F8FAFD`），比表头浅一档；分别保留底部／顶部细分隔线，无额外阴影。应用顶部导航栏继续使用 `#F5F8FC`，分页栏不再复用该颜色。标题栏规则由 `shared/styles/surface-tokens.css` 提供，分页尺寸由 `shared/styles/pagination.css` 提供，当前浅色分页背景映射集中在 `app/styles/theme.css`。深色不使用此浅色覆盖，沿用各自主题表面。


## 全站工具栏一致性（强制）

浅色配色以本文件开头的最新色值为准。控件、表头、侧栏选中项共享浅蓝色系，内容区为柔白，主操作使用浅蓝底钢蓝字。旧玻璃层映射到公共表面，避免重复叠加白色。颜色定义只在浅色主题范围生效，成功、危险、待处理等状态色保留独立语义。

旧玻璃卡片的数字后缀描边变量在浅色模式统一引用 `--app-surface-border`，所有数字后缀内高光变量取 `transparent`，不再通过白色描边和顶部内阴影模拟亮边。正常态、悬停态、伪元素和外阴影需分开检查；外阴影与悬停强调边框保留各自语义角色。

所有工作台列表（项目需求、测试单、API/UI 测试、用例库、测试设计、基础服务及后续新增列表）遵循相同的页面外边距和工具栏尺寸。同类区域不得因所属模块不同而另设背景、留白或控件宽度。

- 页面外层透明，沿用应用公共背景；禁止列表页叠加独立底色或渐变造成边缘色差。
- 列表外框内的工具栏复用 `tp-surface` 下的 `tp-list-toolbar`：最小高度 56px，内边距上下 10px、左右 16px；圆角由外框承担。页面只负责业务排布，不得覆盖公共尺寸。
- 筛选项之间、标签与控件之间、操作按钮之间统一 8px。文字标签不加 padding 或额外 margin。
- 迭代、需求等普通选择框宽 180px；关键词搜索框宽 288px，内部输入框占满容器。窄屏允许缩窄和换行，禁止横向撑破卡片或裁切操作。
- 颜色使用公共语义 token，浅色和暗色采用同一布局规则。白色卡片在暗色模式使用对应主题表面。
- 编辑器、详情内容、表单及弹窗按各自语义布局，不套用列表搜索框宽度；若列表确需例外，必须在本文记录具体页面及原因，不能在页面样式中暗中覆盖。

实现来源：`shared/styles/surface-tokens.css`。改动公共规则时检查所有消费页面，运行列表样式一致性测试及 `check:theme`，并在同一窗口和侧栏状态下检查桌面、窄屏的实际边界及换行。自动化测试通过不能替代浏览器视觉验收。

## 筛选与操作位置

- 工具栏最左侧必须显示当前页面标题，使用共享 `tp-list-title`（15px、600 字重、24px 行高、无额外 margin），名称与侧栏页面一致；代码风险分析直接显示同名标题，不再提供任务类型选择器。随后依次为迭代 → 需求 → 类型／环境 → 搜索，右侧放刷新、新建等动作，只展示该页面需要的项。标题与筛选项保持统一的 8px 间距，窄屏允许筛选换行。
- 状态过滤属于列表内容卡片，采用紧凑栏；不要让右侧按钮决定不同页面的栏高。
- 没有有效分类的“全部”快捷栏不单独占一行。API 测试和测试单的快速过滤整行已移除；用例库仍保留优先级过滤，测试设计仍保留任务状态过滤。
- 列表页不再展示 UI 引擎／默认视口介绍横幅，也不展示 API Base URL／环境变量数量摘要条。相关配置继续在对应配置入口维护。
- 全局与局部同一筛选必须同步，禁止显示相互矛盾的范围。目前列表中仍有与顶部同步的迭代选择。减少重复选择器是后续建议，未经单独调整不宣称已移除。

以上位置与响应式排布需要浏览器检查；页面测试主要覆盖筛选行为，不验证真实坐标。

## 表格、名称和操作列

工作台列表名称统一采用统一链接样式：13px / 24px、正常字重，浅色链接文字使用 `--app-list-name`，行高沿用公共列表的 48px。共享实现为 `shared/styles/list-name.css`，覆盖需求、Bug、测试单、功能/API/UI 测试集及测试设计任务名称。保留原始标题、单行省略及悬停全文，悬停／键盘聚焦显示下划线；深色模式沿用深色链接变量。页面标题、编辑器正文和状态标签不套用名称样式。

名称字体栈为 Arial、微软雅黑、Noto Sans CJK SC、sans-serif，字重 400。页面标题仍用 15px/600，不将列表名称规则应用到正文、编辑器和状态标签。

全站数据表（包括详情运行记录、弹窗表格）统一使用 `shared/styles/table-row-dividers.css` 的横向行分隔线，通过全局入口加载。分隔色取 `--app-list-row-border`，浅色使用浅蓝灰行分隔色，深色使用 GitHub Dark 描边；普通行和悬停行均保留横线，不添加竖线，测量行、展开行、空态除外。页面不再单独设置分隔色。

新页面优先使用 Ant Design Table，自动继承全局规则。确需自绘数据列表时，复用相同的 1px 实线及 `--app-list-row-border`，不使用局部透明线或近背景色弱化分隔。主题值只在登记的 token 文件维护；feature 不重定义该变量。列表行的 hover、选中和固定列仍保留分隔线。

## 通用交互与视觉

以下为新增页面的约定，存量页面逐步核对：

- 全站原生滚动条统一由 `shared/styles/scrollbars.css` 维护，并从全局入口加载。Chromium / WebKit 的纵向宽度与横向高度均为 8px，滑块使用 2px 透明内边和 4px 圆角；轨道透明，滑块与悬停色消费公共主题 token。不支持像素尺寸的浏览器使用原生 `thin` 回退。页面、弹窗与编辑器不再单独隐藏或改写滚动条，滚动方向和容器内边距仍由原布局负责。`scrollbarConsistency.test.ts` 检查入口加载与局部覆盖；浏览器检查尺寸和滚动。
- 使用共享颜色变量和按钮组件。主操作、成功、危险、待处理的颜色语义保持一致，避免页面自行定义另一套颜色。
- 区分未选择项目、首次无数据、筛选无结果、加载中、加载失败。分别提供选择范围、创建、清空筛选、重试等适用操作。
- 删除等危险操作应明确对象及后果，保留现有权限检查与确认流程。接口不支持的批量动作不展示可用按钮。
- 图标按钮必须有明确的无障碍名称，并使用提示说明用途。键盘焦点可见，按钮和链接语义正确。
- 刷新入口统一使用 `ActionButton operation="refresh"`（有权限要求时经 `ProjectActionButton`），由共享组件固定为透明底纯图标按钮，沿用 28px 尺寸和 6px 圆角，禁止背景滤镜。业务文案保留为无障碍名称及悬停提示，加载与禁用状态保持原行为。刷新放在对应页面、面板或卡片的右侧操作区；有新建、运行等主操作时紧邻主操作左侧，没有主操作时放在最右侧。清空筛选、失败重试不当作刷新入口。共享组件测试验证外观类型、提示和点击行为，位置需浏览器检查。
- 视觉精简不改变接口、权限、筛选范围或已有业务行为；确需删减功能时按明确需求执行。

## 实现归属与检查

测试设计中的鱼骨图谱默认横向展示：每条独立业务主线水平对齐、等距从左向右排列；分支从锚点上方或下方展开，后续节点继续向右。主轴卡片间留 180px，上下分支卡片间留 144px；分支拥挤时向外换行，不撑大主线间距。主线优先直线，其余连线优先曲线；同侧的分支连接分散出入口，并按主线、短连接、长连接的顺序路由，同时避开卡片。主线与主线、分支与主线的交叉及重合是禁止条件，不能作为带惩罚的候选回退；共享用例在每条主线中使用独立的显示副本（标记“共享”，编号、详情和执行状态仍对应同一 case_id），避免只放一张卡片而产生跨行主线；共享节点上的多条连接也分配独立出入口。分支之间选择冲突较少的路径。初次加载和重新路由期间由 Worker 分批返回已验证的路径，主线先出现，不等待所有复杂路径计算结束；显示已绘制数量。计算失败或 15 秒无进展时保留已验证路径并提供重试，不清空整图。拖动期间仅提供临时预览，松手后恢复约束。若当前节点位置确实无法路由，保留原始关联数据，并显示未绘制关联数量及调整位置提示，不静默绘制冲突路径。大图默认以 80% 定位主线起点，“查看全图”提供整体概览。纵向模式复用同一布局并交换主轴。`caseRelationsGraph.test.ts` 覆盖主线间距、分支方向和节点不重叠，`relationsEdgePath.test.ts` 覆盖曲线、出入口分散、连线重合、绕开主线及卡片避障。浏览器用 126 用例、122 关联、6 条共享起点主线样例检查所有连线可见、阅读视图与概览，并核对共享副本仍打开原用例；`relationsRouting.test.ts` 覆盖共享主线的首批结果与最终完整性，hook 测试覆盖渐进显示和超时保留；该样例不替代真实业务数据的视觉验收。

## 产物预览弹窗

### 统一标题栏、底栏与复制入口

需求分析、功能测试、API 测试、UI 测试中的产物阅读和候选审核弹窗统一遵循以下规则；代码风险目前使用页面报告展示，不额外创建弹窗。以后新增产物弹窗也必须复用这些规则。

- 顶部标题栏和底部操作栏使用列表工具栏背景 `--app-list-toolbar-bg`，与正文之间使用 `--app-surface-border` 的 1px 分隔线。正文保持公共内容背景；浅色、深色跟随全站主题，禁止另设局部配色。
- 外壳不额外叠加内边距。标题栏内距为上下16px、左24px、右64px，右侧预留关闭按钮；正文内距为16px 24px；操作底栏内距为12px 24px、最小高度58px。640px以下左右内距收为16px。
- 标题栏与底栏固定，只有正文内部滚动。无底部操作的只读弹窗也保留58px浅色底栏区域和分隔线，和业务内容、JSON／YAML、审核模式保持一致，不增设重复关闭按钮，也不虚构分页控件。
- 展示模式开关放在标题右侧，使用 `ArtifactViewTabs` / `ArtifactModeSwitch`。JSON模式必须提供“复制”入口，复制当前可见草稿（包含未保存修改），不得复制旧接口结果。YAML候选编辑也提供复制，并明确无障碍名称为“复制 YAML”。
- 优先使用标题模式开关旁的公共复制按钮；已有 JSON 编辑器工具栏的图谱保留原工具栏复制，不叠加第二个复制入口。复制须等待剪贴板写入成功再提示成功，失败时提示重试或手动复制。
- 公共上下栏实现位于 `features/ai-testing/styles/artifact-view-switch.css`，复用 `functional-artifact-modal`、`ai-task-run-result-modal`、`ai-task-import-result-modal` 的公共外壳。尺寸与正文滚动仍由下述尺寸规则及各产物组件管理，不在页面重复定义上下栏样式。


运行产物的大型阅读弹窗使用统一尺寸。当前适用入口：材料提取结果、需求理解记录、测试需求分析、测试点、完整用例、用例图谱；同一产物窗口切换业务内容、原始 JSON 或编辑模式时，外框尺寸保持一致。

- 宽度：`min(2000px, calc(100vw - 56px))`，通过 Modal 的 `width` 设置并启用 `centered`。
- 桌面高度：`min(94dvh, 1200px)`；最大高度为 `calc(100dvh - 32px)`。
- 窄屏或低屏：宽度不超过640px或高度不超过700px时，高度使用 `calc(100dvh - 32px)`。
- 复用 `features/ai-testing/styles/functional-artifact-modal.css` 的 `functional-artifact-modal` 类，并在页面显式引入。该文件是这些弹窗外框尺寸的共同实现；后续调整统一修改，避免各入口另设大小。
- 标题、工具栏、底部操作固定，业务正文、目录、JSON编辑器在分配的剩余空间内滚动，图谱画布使用剩余高度。高度链须保留 `min-height: 0`，不能让长内容撑开弹窗。
- 测试需求分析和测试点的阶段审核窗口复用同一产物预览尺寸，审核前后及继续优化时外框保持一致；审核备注与操作固定在底栏。错误信息、删除确认、普通表单以及其他独立阶段审核窗口按自身用途布局，不因本规则自动放大。

验证时覆盖上述入口的同视口宽高一致性、业务／JSON切换、长内容到底可达、底部操作可见，以及桌面、窄屏、低屏。相关页面测试和布局测试须通过；浏览器尺寸与滚动检查不能用 jsdom 结果替代。
