# 界面与交互规范（Studio）

本文件维护前端页面的布局与交互约定。代码组织、样式归属与依赖方向见 [STRUCTURE.md](STRUCTURE.md)，开发命令见 [README.md](README.md)。本文件中的源码路径相对 `apps/studio/`。

## 适用范围与现状

新增列表页和修改中的列表页遵循本规范。详情页、编辑器、图谱与弹窗可以按任务需要采用不同布局，不机械套用列表尺寸。保留业务所需的目录树、进度条与环境选择，不为外观一致而编造功能或字段。

截至 2026-09-24，以下两组页面已完成本次布局调整：

- 测试：测试单、API 测试、UI 测试、用例库。
- 测试设计：需求分析、功能测试、API 测试、UI 测试、代码风险分析，共用 `UnifiedAiTestingPage`。

“已实现”不等于“已有自动化检查”。本文件末尾分别列出检查覆盖与人工验证要求；其他存量页面尚未完成全面对齐。

## 导航与创建

| 规则 | 当前实现与检查 |
| --- | --- |
| 同级入口放侧栏；页面内不重复摆放同一组 Tab | `app/layouts/AppSidebar.tsx`；侧栏测试覆盖展开、收起、路由选中与测试范围参数保留 |
| 项目总览子菜单为迭代 → 需求，页面内不保留重复切换器 | `/projects?board=sprints` 与 `board=requirements`；默认迭代，刷新与前进后退由 URL 保持选中状态 |
| 测试子菜单顺序为测试单 → API 测试 → UI 测试 → 用例库 | `AppSidebar.tsx`；顺序由配置维护，人工检查 |
| 测试设计子菜单顺序为需求分析 → 功能测试 → API 测试 → UI 测试 → 代码风险分析 | `AppSidebar.tsx`；任务类型存入 URL 的 `kind` 参数，详情页高亮所属类型 |
| Skill 库归基础服务 | `/base-services?tab=skills`；旧 `/ai-testing/skills` 和 `?tab=skills` 入口保持跳转兼容，人工验证 |
| 创建动作跟随当前类型，不再重复选择模板 | `UnifiedAiTestingPage.tsx`；对应页面测试覆盖五类创建入口及 UI 创建校验 |
| 数量徽标使用真实查询结果，并说明统计范围 | 测试设计数量按当前项目、迭代统计，不随列表搜索词变化；`useAiTestingTaskCounts.ts` |

侧栏展开／收起不改变当前业务页面。当前项必须有可识别的选中状态；可展开组提供 `aria-expanded`，当前链接提供 `aria-current`。

## 列表页面布局

结构采用“筛选工具栏 + 内容卡片 + 卡片内分页”。外层布局容器保持透明，工具栏与内容卡片各自承载白色表面，避免无意义的卡片套卡片。用例库允许在内容区并列目录树与表格。

| 项目 | 规范值 | 当前适用范围与实现 |
| --- | --- | --- |
| 左右外边距 | 12px | 全局工作台页面；`src/index.css` 定义 `--app-page-gutter`，页面外层 padding / margin 引用该变量 |
| 上／下外边距 | 12px / 16px | 四个测试列表桌面布局，同上 |
| 工具栏最小高度 | 56px | 四个测试列表；`shared/styles/surface-tokens.css` 的 `.tp-list-toolbar` |
| 工具栏内边距 | 上下 10px、左右 16px | 同上 |
| 工具栏圆角 | 12px | 同上，使用 `--srf-radius-card` |
| 工具栏表面 | 白底、细边框、无额外阴影 | 使用 `--srf-card`、`--srf-card-border` |
| 测试设计状态栏 | 单行最小高度 37px，内边距 6px 16px | `features/ai-testing/styles/task-list-v2.css` |
| 状态栏操作按钮 | 高度 24px，左右内边距 8px | 同上；有无批量删除按钮均保持栏高一致 |

全局左右外边距通过 `--app-page-gutter` 管理：项目与迭代工作台、测试、测试设计、基础服务、Skill 库、复用工作台容器的详情页及个人设置均引用此变量，窄屏规则使用同一值。个人设置的居中最大阅读宽度保留；登录页不属于工作台外壳。此变量只用于页面外层，不替换表格单元格、卡片内部、表单、弹窗与抽屉的内边距。56px 工具栏已用于四个测试列表、基础服务和项目总览顶部信息栏；项目总览名称、角色与描述横向排列，长描述省略并可悬停查看，窄屏允许换行；基础服务分类按钮采用 28px 最小高度，以容纳在紧凑工具栏中。

不要为了紧凑而缩小正文或可点击区域。空间不足时允许工具栏、状态栏换行并自动增高；表格按需横向滚动。上述最小高度不应变成裁切内容的固定高度。

## 筛选与操作位置

- 左侧放筛选及搜索，右侧放刷新、新建等动作。常规顺序为迭代 → 需求 → 类型／环境 → 搜索，只展示该页面需要的项。
- 状态过滤属于列表内容卡片，采用紧凑栏；不要让右侧按钮决定不同页面的栏高。
- 没有有效分类的“全部”快捷栏不单独占一行。API 测试和测试单的快速过滤整行已移除；用例库仍保留优先级过滤，测试设计仍保留任务状态过滤。
- 列表页不再展示 UI 引擎／默认视口介绍横幅，也不展示 API Base URL／环境变量数量摘要条。相关配置继续在对应配置入口维护。
- 全局与局部同一筛选必须同步，禁止显示相互矛盾的范围。目前列表中仍有与顶部同步的迭代选择。减少重复选择器是后续建议，未经单独调整不宣称已移除。

以上位置与响应式排布需要浏览器检查；页面测试主要覆盖筛选行为，不验证真实坐标。

## 表格、名称和操作列

| 项目 | 规则 | 实现／验证 |
| --- | --- | --- |
| 表头 | 高度 42px，左右内边距 16px，圆角 8px | `shared/styles/list-table.css`；`listSurfaceConsistency.test.ts` |
| 数据行 | 高度基准 48px，内边距 8px 16px | 同上；内容较高时不裁切 |
| 名称 | 同类对象使用一致字阶、颜色及交互；长名称省略，悬停可查看全文 | `listNameConsistency.test.ts` 覆盖部分样式，真实溢出人工验证 |
| 名称图标 | 适用时使用已有图标体系；容器 22×22px、圆角 6px、与文字间距 8px | API 测试、测试单已按此实现；用例库的编号可作为对象标识，不强制额外堆图标 |
| 操作列 | 靠右，常规顺序为执行 → 编辑 → 删除，只显示支持的动作 | 各页面列配置及行为测试 |
| 操作列宽 | 必须容纳按钮、按钮间距和左右各 16px 留白，不强制所有页面使用相同列宽 | 用例库两按钮列宽现为 110px；人工检查最后一个按钮无溢出 |
| 分页 | 列表卡片底部：左侧数量，右侧分页；无分页能力时不添加虚假分页 | 各页面现有分页实现与接口能力 |

执行完成率与通过率是不同指标，不用同一颜色或文案暗示“已执行即全部通过”。状态提供文字，不能只靠颜色表达。

## 通用交互与视觉

以下为新增页面的约定，存量页面逐步核对：

- 使用共享颜色变量和按钮组件。主操作、成功、危险、待处理的颜色语义保持一致，避免页面自行定义另一套颜色。
- 区分未选择项目、首次无数据、筛选无结果、加载中、加载失败。分别提供选择范围、创建、清空筛选、重试等适用操作。
- 删除等危险操作应明确对象及后果，保留现有权限检查与确认流程。接口不支持的批量动作不展示可用按钮。
- 图标按钮必须有明确的无障碍名称，并使用提示说明用途。键盘焦点可见，按钮和链接语义正确。
- 视觉精简不改变接口、权限、筛选范围或已有业务行为；确需删减功能时按明确需求执行。

## 实现归属与检查

共用尺寸与表面优先维护在共享样式中，页面通过 `.tp-list-surface`、`.tp-list-table`、`.tp-surface`、`.tp-list-toolbar` 等既有类接入。feature 内部布局留在各自样式目录；业务导航编排归 `app/`。不要为同一视觉部件复制一套独立尺寸。完整代码规则见 [STRUCTURE.md](STRUCTURE.md)。

现有自动化覆盖：

- `src/app/styles/listSurfaceConsistency.test.ts`：部分表头、行高、内边距、背景及圆角约定。
- `src/app/styles/listNameConsistency.test.ts`：部分列表名称的样式一致性；已知覆盖限制见该测试及 STRUCTURE。
- `src/app/layouts/AppSidebar.test.tsx`：侧栏交互、选中状态与范围参数。
- `src/features/ai-testing/pages/UnifiedAiTestingPage.test.tsx`：任务切换、创建、搜索、运行等行为。
- 测试资产各页面的 `*.test.tsx`：各自搜索、刷新、列表及操作行为。

**尚无自动化几何约束的项目**：12px 外边距、56px 工具栏、37px 状态栏、操作列右侧留白、分页实际位置与窄屏换行。不能把通过现有测试等同于这些尺寸已获验证，也不能用 jsdom 代替浏览器布局检查。

修改后的验证：

1. 运行改动对应的页面／样式测试；TSX 变更运行类型检查与相关 ESLint。
2. 在同一窗口尺寸、同一侧栏状态下逐页比较左右边界、工具栏和状态栏高度；建议桌面 1680×1000，再核对较窄窗口。
3. 覆盖有数据、空数据、长名称、无删除按钮及筛选换行，确认按钮不贴边、内容不裁切、分页可见。
4. 新增自动化约束后在本节补充具体测试，不能仅写“已统一”或“已验证”。

未来新增视觉规则同时登记实现位置、适用范围和检查方式。设计草图与存量实现冲突时，以用户最新确认及本规范为准，并同步代码和检查，不保留相互矛盾的文档。

需求列表使用独立筛选卡片与表格容器：左侧迭代筛选、右侧新建需求，表格内不再叠加卡片网格内边距；项目信息与成员、设置入口仅在迭代页展示。

无多选框的资源列表在名称前使用 22px 图标容器（14px 图标、6px 圆角、8px 名称间距）。运行、编辑、删除通过共享 ActionButton 的 operation 选择统一图标；行内与卡片纯图标按钮统一 28px、6px 圆角，删除使用危险色，禁用状态保留统一弱化色与权限提示。
