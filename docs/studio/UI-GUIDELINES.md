## 适用范围与现状

新增列表页和修改中的列表页遵循本规范。详情页、编辑器、图谱与弹窗可以按任务需要采用不同布局，不机械套用列表尺寸。保留业务所需的目录树、进度条与环境选择，不为外观一致而编造功能或字段。

截至 2026-11-13，以下页面已完成本次布局调整：

- 测试：测试单、API 测试、UI 测试、性能测试；资产库：用例库、接口库、应用。
- 测试设计：需求分析、功能测试、API 测试、UI 测试、代码风险分析，统一从需求详情的生成全景图谱泳道进入。

“已实现”不等于“已有自动化检查”。本文件末尾分别列出检查覆盖与人工验证要求；其他存量页面尚未完成全面对齐。

浅色配色在 `shared/styles/indigo-amber-light-tokens.css` 维护，Ant Design 的具体色值在 `app/providers/ThemeProvider.tsx` 同步。feature 样式消费变量，不另写局部色盘。深色与业务状态色保持独立；浅色专用组件配置不得通过对象展开继承到深色主题。

界面无衬线字体由 `index.css` 的 `--app-font-sans` 统一提供：系统 Apple 字体、Segoe UI、苹方、冬青黑体、微软雅黑依次回退。Ant Design、工作台及说明文字共享此变量；基础字号 13px，保留既有列表、元信息和标题字阶，代码区域保留等宽字体。截图无法确定原字体文件，因此按参考图风格使用本地字体栈。

## 导航与创建

应用顶栏桌面最小高度为56px，品牌、项目选择器、一级导航及操作入口依次同排；项目以紧凑路径展示，选择器保留原有切换与项目设置功能。Logo 为32px，测试阶段反馈联系方式通过顶栏入口打开。900px以下顶栏按内容换行，540px以下项目选择器与操作入口分行，操作入口保持可见。

全局一级导航与项目选择器位于同一顶栏，使用 36px 高、8px 圆角和 13px 字号；选中项使用强调色文字、600 字重和浅色底板；切换时底板平滑移动，系统要求减少动态效果时关闭过渡。一级导航之间切换时，内容按导航顺序从对应方向轻微滑入并淡入；同一模块内部切换不触发该过渡。 顶栏项目由用户切换时，内容按下拉选项顺序上下滑入并淡入；初始化和自动恢复选择不播放。窄屏导航可横向滚动；滚动条隐藏，避免顶栏下方出现横向滚动条。顶部 Tab 使用蓝灰底、细边框，选中项为浅底钢蓝字。系统中文字体缺少粗体时允许合成字重，避免选中态变细。

测试、资产库与基础服务的一级入口统一使用顶部悬停浮层：默认只显示一级入口，悬停（或聚焦后按 ArrowDown）展开各自页签，选中态复用浅底强调 token；页面内不再保留常驻 Tab 栏，内容面板直接铺开，减少重复导航。测试页签为测试单 → API 测试 → UI 测试 → 性能测试；资产库为用例库 → 接口库 → 软件仓库；基础服务为 GitLab → LLM 模型 → MCP → Skill 库 → 性能监控。浮层通过 Popover 挂载到 body，避免顶部导航横向滚动容器裁剪；触屏首次点按进入默认页并展开页签，Escape 收起并把焦点还给入口。实现为 `app/layouts/TopNavTabMenu.tsx`。

顶部导航统一使用线性 SVG 图标 `app/layouts/SidebarIcon.tsx`，形状与性能测试原型一致；图标继承当前导航文字颜色，选中状态和 `aria-current` 随路由同步。

## 面包屑（强制）

带层级返回的页面统一使用同一种面包屑，不再用次级灰色小字伪装成标题旁注：

- 可点击层级使用主色（普通页面 `--app-accent`，`tp-surface` 页面 `--srf-accent`）、13px 字号、24px 行高，内边距 0 5px、圆角 5px；悬停显示对应主题的 accent-soft 底、accent-strong 文字和下划线，键盘聚焦显示 2px 主色轮廓。
- 层级之间使用弱化的右箭头图标（`RightOutlined`，10px、muted 色），不使用裸斜杠作为唯一层级提示；同一页面的分隔符保持一致。存量 UI 测试集顶栏的斜杠分隔在后续改动时按右箭头收敛。
- 当前项使用正文色、13px 字号、600 字重、20px 行高，单行省略，不加背景或 hover；最后一级不可点击。
- 层级顺序为“上级列表 → 当前上下文 → 当前对象”。已有明确返回按钮的顶栏保留按钮，面包屑只表达位置，不重复生成返回动作。
- 参考实现：需求详情 `requirement-detail-crumbs` 与测试单执行工作台 `test-order-workspace-breadcrumb`。新增页面优先复用现有字号、颜色和交互，不另建第二套面包屑皮肤。

验证：测试单 `TestOrderWorkspacePage.test.tsx` 断言面包屑展示用例名称与返回行为；改动时运行 `npm run check:theme`，并在浅色／深色下检查默认、悬停、键盘聚焦及窄屏省略。

## 列表页面布局

新增及修改中的列表页、卡片页默认采用“外置 Tab + 单一内容外框”。无 Tab 的页面直接显示内容外框。标题、筛选与操作栏、内容区和已有分页共用一个外框，并按主题角色区分表面；外框保留 12px 圆角及细描边，内部工具栏仅保留底部分隔线。卡片网格中的业务卡片保留自身边界与间距。需求与迭代列表的卡片板面使用 `--app-board-gradient` 无缝渐变，滚动区和分页共用同一层背景；顶部标题／项目信息卡片独立在上方，详见下方的双容器例外。深色主题使用对应的深色渐变。

需求与迭代列表是当前的双容器例外：标题／项目信息、总数和操作独立成顶部标题卡片，使用共享表头底色 `--srf-list-header-bg`，下方卡片板面单独成框，两者之间保留 12px 页面背景间距；卡片板面继续使用 `--app-board-gradient`，内部保持 16px 内收和底部分页。该例外不改变其他列表页的单一外框约定。

需求与迭代卡片统一为“名称 → 摘要 → 信息块 → 白色底栏”的结构：名称首行、摘要行紧随其后，版本/时间或开始/结束时间放在浅灰信息块，绑定与操作放在与卡片同白的底栏；卡片操作图标统一使用主题蓝。需求页与迭代页共用全宽自动填充网格：卡片最小宽度 328px、最小高度 218px，桌面按可用宽度自动排成多列；板面吃满可用高度，内容超出时在板面内滚动。900px 以下回退两列、680px 以下单列，板面保持填满可用高度并在内部滚动，分页固定。

公共实现位于 `shared/styles/surface-tokens.css`，页面显式接入以下结构；未迁移的旧 `tp-board` 保持兼容，不作为新页面模板：

```tsx
<div className="page-class tp-surface tp-list-surface">
  {/* 页面级 Tab 位于外框上方 */}
  <section className="tp-board tp-list-panel">
    <div className="tp-list-toolbar">{/* 标题、筛选、操作 */}</div>
    <div className="tp-list-body">
      <div className="tp-list-scroll">{/* 表格、卡片网格或空态 */}</div>
      <div className="table-footer">{/* 已有分页或数量统计 */}</div>
    </div>
  </section>
</div>
```

- `tp-surface` 放在外框的祖先节点，提供主题 token 与样式作用域。`tp-list-body` 在需要中间包装层时使用，不增加第二层表面。
- 内容滚动区四周内收 16px，表头、行背景及分隔线随内容内收；分页在滚动区外，位于同一外框底部。保留 `flex` / `min-height: 0` / `min-width: 0` 高度链。
- 工具栏与内容之间不另加页面背景间隙。状态筛选条可放在同一外框内。Tab、标题和筛选的业务顺序由页面决定，窄屏允许换行，表格在内容区内部横向滚动。
- 空态、加载、错误、只读权限都使用同一外框。分页只复用真实能力，不新增虚假分页。列表空态/加载态统一使用 `shared/components/ListEmptyState.tsx`（220px 居中占位，动作作为 children），不要在页面重复拼 `grid min-h-[220px] place-items-center`。
- `ListSurface` 统一承接 `tp-board` / `tp-list-panel` / `tp-list-body` / `tp-list-scroll` / `table-footer`，页面只通过 `toolbar`、`notices`、`footer`、`children` 和兼容类接入；`aria-labelledby` 用于外部标题关联。
- 需求详情：不显示页面级 Tab，需求标题与操作共用顶栏，下载原文件与编辑需求常驻；正文为生成全景与运行记录，需求文档、代码风险和生成设置从泳道入口以弹窗打开。运行列表内收 16px，文档弹窗保留自己的阅读布局。

## 通用交互与视觉

以下为新增页面的约定，存量页面逐步核对：

- 全站原生滚动条统一由 `shared/styles/scrollbars.css` 维护，并从全局入口加载。Chromium / WebKit 的纵向宽度与横向高度均为 8px，滑块使用 2px 透明内边和 4px 圆角；轨道透明，滑块与悬停色消费公共主题 token。不支持像素尺寸的浏览器使用原生 `thin` 回退。页面、弹窗与编辑器不再单独隐藏或改写滚动条，滚动方向和容器内边距仍由原布局负责。`scrollbarConsistency.test.ts` 检查入口加载与局部覆盖；浏览器检查尺寸和滚动。
- 使用共享颜色变量和按钮组件。主操作、成功、危险、待处理的颜色语义保持一致，避免页面自行定义另一套颜色。
- 区分未选择项目、首次无数据、筛选无结果、加载中、加载失败。分别提供选择范围、创建、清空筛选、重试等适用操作。
- 删除等危险操作应明确对象及后果，保留现有权限检查与确认流程。接口不支持的批量动作不展示可用按钮。
- 图标按钮必须有明确的无障碍名称，并使用提示说明用途。键盘焦点可见，按钮和链接语义正确。
- 刷新入口统一使用 `ActionButton operation="refresh"`（有权限要求时经 `ProjectActionButton`），由共享组件固定为透明底纯图标按钮，沿用 28px 尺寸和 6px 圆角，禁止背景滤镜。业务文案保留为无障碍名称及悬停提示，加载与禁用状态保持原行为。刷新固定在对应页面、面板或卡片右侧操作组的最左侧，新建、导入、导出、运行等其余动作依次排在其后；整组仍靠右对齐，窄屏换行时刷新保持在操作组首位。清空筛选、失败重试不当作刷新入口。共享组件测试验证外观类型、提示和点击行为，位置需浏览器检查。
- 操作结果的瞬时反馈（成功、警告、失败）统一使用顶部居中的 `notify` 轻提示（`shared/utils/toast.tsx`）：默认 4.8 秒、失败 6 秒后自动消失，最多同时显示 3 条，悬停暂停倒计时，并提供“关闭提示”按钮。需要持续可见且会阻塞当前操作的错误继续以内联 `Alert` 留在对应区域，不用会自动消失的轻提示替代。
- 视觉精简不改变接口、权限、筛选范围或已有业务行为；确需删减功能时按明确需求执行。

节点上的次要操作（如可编辑候选中的删除用例）默认隐藏，鼠标悬停节点或键盘聚焦时显示，节点布局预先留出操作宽度以避免悬停时跳动；触屏等无悬停环境保持常显。主操作和节点标题保持常显，同一操作不得同时以图标和文字重复出现。

## 实现归属与检查

测试设计中的用例图谱采用层级视图：每条独立业务主线成组横向排列，分支按用例树向下展开；共享用例在每条主线中使用独立的显示副本（标记“共享”，编号、详情和执行状态仍对应同一 case_id），避免只放一张卡片而产生跨行主线；共享节点上的多条连接也分配独立出入口。主线优先直线，其余连线优先曲线；同侧的分支连接分散出入口，并按主线、短连接、长连接的顺序路由，同时避开卡片。主线与主线、分支与主线的交叉及重合是禁止条件，不能作为带惩罚的候选回退；共享用例在每条主线中使用独立的显示副本（标记“共享”，编号、详情和执行状态仍对应同一 case_id），避免只放一张卡片而产生跨行主线；共享节点上的多条连接也分配独立出入口。分支之间选择冲突较少的路径。初次加载和重新路由期间由 Worker 分批返回已验证的路径，主线先出现，不等待所有复杂路径计算结束；显示已绘制数量。计算失败或 15 秒无进展时保留已验证路径并提供重试，不清空整图。拖动期间仅提供临时预览，松手后恢复约束。若当前节点位置确实无法路由，保留原始关联数据，并显示未绘制关联数量及调整位置提示，不静默绘制冲突路径。大图默认以 80% 定位主线起点，“查看全图”提供整体概览。`caseRelationsGraph.test.ts` 覆盖图模型解析与用例归属，`relationsEdgePath.test.ts` 覆盖曲线、出入口分散、连线重合、绕开主线及卡片避障。浏览器用 126 用例、122 关联、6 条共享起点主线样例检查所有连线可见、阅读视图与概览，并核对共享副本仍打开原用例；`relationsRouting.test.ts` 覆盖共享主线的首批结果与最终完整性，hook 测试覆盖渐进显示和超时保留；该样例不替代真实业务数据的视觉验收。

- 软件仓库页为单栏项目级管理列表：显示软件仓库、Git 仓库、base path、接口数、更新时间和操作；支持搜索、刷新、新建软件仓库，行内编辑/换绑/删除。点击软件仓库行进入该软件仓库的接口库工作区。软件仓库下仍有接口或需求关联时禁止删除。
- 只读成员看到同一布局，但输入、保存、删除和快捷注入均不可用；软件仓库维护只在「软件仓库」页进行，项目所有者才能创建、编辑、换绑或删除软件仓库，接口库不提供这些入口。软件仓库下仍有接口或需求关联时删除按钮禁用。
- OpenAPI 导入弹窗为三步：选择软件仓库和文档 → 预览差异（新增/修改/未变化/仅库中存在）→ 结果。预览按方法与路径匹配：已有接口只更新接口内容，保留库内标签和分组，标签差异不计入修改；新接口使用文档标签并创建分组。请求体示例和默认成功响应示例优先取文档示例，文档未提供时导入按对应 Schema 生成占位示例并保存，列出全部字段；重新导入会给没有示例的已有接口补上示例，并计入「修改」的 bodyExample 或 responseExample。预览使用左侧分组导航和右侧分组列表：导航展示全部分组及接口数，支持搜索与点击定位；分组标题带组级选择框、接口数和「新建分组」标记（仅当新接口的目标分组在当前库中不存在时显示），组级选择框批量勾选组内可导入接口；列表工具栏展示已选/可导入数量。每行显示方法、名称、路径和变更类型，不在行内重复分组名。第一步支持上传 JSON/YAML 文件或直接粘贴 JSON；直接输入使用共享 `TextCodeEditor`，前端校验 JSON 后包装为内联文件提交。文档 base path 与软件仓库不同时，普通成员不能提交，所有者可选择同时更新软件仓库 base path。结果页列出本次由新接口创建的分组。
- 接口编辑器的 JSON 校验使用共享 `TextCodeEditor`；无效 JSON 阻止保存并保留原文，格式化操作只在 JSON 有效时可用。接口详情页不复制 API 测试的发送按钮、响应控制台、断言和后置操作。

## 结构化文档输入

输入或编辑 JSON、YAML 等结构化文档时，复用 `src/shared/components/TextCodeEditor/TextCodeEditor.tsx`，提供对应格式的语法高亮、行号和折叠；支持两种格式的输入使用 `auto` 识别。需要格式化时提供明确的格式化操作，解析失败应提示并保留原文，不因展示而改写用户内容。只读和保存中状态应禁止编辑，长文档使用编辑器内部滚动。需求画布的 API 生成设置不再提供 OpenAPI / Swagger 文档编辑器或文档载入入口，接口来源统一使用接口库选择器。API 分组侧栏展示最新仓库画像版本识别出的后端／全栈仓库及推荐标记，接口选择器默认以这些仓库为范围；建议不构成限制，选择器可切换到需求关联软件仓库或项目全部接口。选择器额外提供按接口标签筛选，标签选项来自当前查询结果；软件仓库与标签筛选共同决定「全选筛选结果」的范围，切换范围时清空这两个筛选。

### 接口用例设计

接口用例设计产物使用左侧接口导航 + 右侧用例详情的单页布局。左侧显示接口数、正向／反向／边界覆盖条、未覆盖约束数量与定位入口，并支持按名称、路径或方法搜索；接口列表在视口内粘性滚动，1200px 以下改为顶部横向列表。右侧展示当前接口的方法、名称、路径和覆盖摘要，按正向／反向／边界分组；分类筛选与全部展开／收起位于工具栏，用例详情拆为意图、请求变更、预期结果、设计依据和用例 ID。未覆盖约束独立成区，展示字段、约束和未生成原因；没有未覆盖时显示已覆盖状态。接口路径提供复制入口，成功与失败使用公共 `notify`。

### 接口配置提取

接口配置提取产物使用左侧接口导航 + 右侧接口契约详情的单页布局。左侧显示接口数、请求／响应字段、认证头、关键提取与变量依赖，支持按名称／路径／方法搜索；接口项展示方法、名称、路径、字段数及认证头／关键提取标记，1200px 以下改为顶部横向列表。右侧展示方法、名称、路径与请求／响应字段数，契约摘要条展示变量依赖、关键提取与认证头；请求按请求头、Path、Query、Body／Form 分表，响应使用字段树。

## LDAP 认证设置

LDAP 管理页复用公共 `tp-list-panel` 单一外框、标题栏和 16px 内收滚动正文；页面外边距使用 `--app-page-gutter`。这是设置表单，不增加 Tab 或分页。底部保存与重新加载固定，桌面字段双列，720px 以下单列；颜色跟随公共主题。启停确认、密码只写、配置检查行为保持不变。隔离示例已检查桌面与390px窄屏；真实配置未改写。

完整用例候选结果在具有写权限时，右侧详情默认展示可编辑表单，不设“编辑用例／完成编辑”切换。名称、文本标签及文本／字符串数组详情直接编辑同一候选草稿，数组按每行一项保留数组结构；编号只读，复杂结构继续通过 JSON 模式编辑。修改同步至树图与 JSON，由“保存为新候选”调用候选结果接口持久化。当前采用内容保持只读。

测试需求分析阶段候选复用预览的可收缩高度链：分类页签、左侧搜索区和侧栏候选操作固定，左侧目录列表与右侧详情分别独立滚动，长目录不撑开整个分类正文。业务规则、场景因素、场景拆解沿用相同目录容器。

场景拆解目录以验证目标作为条目名称，保留场景编号，长文本截断并通过悬停展示全文；验证目标为空时回退到原场景名称或序号。右侧详情标题保持原有场景名称。

生成全景内的需求文档、阶段产物与派生用例图谱采用容器内阅读例外：单击卡片直接打开阅读区，键盘 Enter／空格也可打开；返回流程后收起详情侧栏。需求文档、阶段产物、代码风险与派生用例图谱沿用这套直接打开交互，未配置 UI 链的“开始”入口在侧栏展示生成来源摘要，其余未配置链的“开始”按钮仍直接打开配置。阅读区占满左侧画布容器，不添加页面遮罩或焦点锁定；右侧阶段信息栏保持可见、可操作，与正文共享当前查看内容与候选选择，并展示冻结来源追溯（基于哪个上游候选产出）和完整冻结依据；默认展示当前采用内容，候选通过侧栏候选磁贴切换，不再设置常驻候选栏。标题栏不设返回按钮，阅读态通过页面面包屑的上级需求返回，侧栏顶部只显示阶段标题，返回时保留画布的缩放和平移位置。 阅读区以所选卡片为中心轻微放大进入，返回时反向收回；系统要求减少动态效果时立即切换。 进入及返回时，阶段详情栏外框保持固定，栏内信息轻微淡入上移。阶段阅读时，聚焦卡、当前采用内容、候选磁贴、来源状态与生成新版本集中在右侧栏；可视化／JSON 或 YAML 切换与冻结来源放入聚焦卡，正文全宽且不再保留阶段标题工具行，正文直接从阅读区顶部开始；原文编辑器不再自带内层边框，两种视图与阅读区外框连成整体；阶段阅读区直接展示正文，阅读态返回通过页面面包屑的上级需求完成，右侧栏顶部只显示阶段标题，移除弹窗内容外壳和正文内收边距，不重复展示版本摘要、追溯和底部操作条。继续优化在右侧栏填写，正文保持原宽度。正文内部滚动沿用公共产物规则；窄屏改为阅读区在上、阶段信息与操作在下。

生成全景侧栏采用三段布局：固定头部只显示阶段标题，不再重复状态、链路摘要或返回入口；阅读态返回通过页面面包屑的上级需求完成；中间是当前查看聚焦卡、查看候选时的当前采用入口、候选磁贴、来源状态、最近生成与生成新版本，独立滚动，内容区顶部保留 16px 间距；来源状态与最近生成以分割线分组，不再各自套卡片，生成新版本放在内容区最后并在内容不足时贴底，点击开始生成后在同一步选择来源、模型和生成要求，来源下拉默认选中当前上游，也可直接改选候选；底部固定采用主按钮及其右侧下拉菜单中的采用并生成下一阶段、拒绝／删除，编辑、继续优化并排；选中已拒绝候选时不显示采用，改为「更多操作」下拉且只提供删除，删除需二次确认，完成后候选从列表移除并回到当前采用内容；查看当前采用内容的最终阶段，底部改为固定「导入正式用例」入口，点击后在弹窗内预览同名冲突并确认。同阶段候选通过候选磁贴切换，聚焦卡展示当前查看内容与内容概况；采用与下拉组成 36px 高的连体控件，编辑与继续优化等宽并排、间距 7px。窄屏恢复为纵向自然排列，避免在有限高度内叠加多个滚动区。

进入卡片阅读区后，可通过侧栏边缘中部的抽屉把手收起或展开侧栏；收起时保留带图标的窄栏和展开把手，正文平滑扩展，保留当前阅读和侧栏状态，展开后可继续操作。窄屏把手位于侧栏顶部，系统要求减少动态效果时取消过渡。

需求详情采用三个独立面板：顶部需求工具栏占满整行，下方左侧画布／阅读区与右侧信息栏并排。页面仅负责 12px 面板间距与统一页面外边距；工作区宿主透明且无内边距，不再套列表面板外框。窄屏仍按工具栏、正文、信息栏纵向排列。

选中 UI 测试大分组的标题或空白区域时，侧栏展示当前画像及候选、前端仓库、Commit 和功能用例摘要，未配置链的“开始”入口也选中此分组。点击“配置并生成”打开三步弹窗，依次选择源码、选择用例、核对配置。返回上一步保留所选内容，底部操作与滚动正文分开。点击内部阶段卡片仅显示该阶段信息，不展示源码配置；首次启动自动建立 UI 生成设置，仅保存配置不发起生成。只读成员仅查看，运行期间禁用更换输入；画像缺失、无前端仓库或授权不可用时显示阻止态和引导。当前仓库来源与候选的输入快照分开显示，启动后不改写历史快照。

生成全景中，运行中阶段每 1 秒沿直接出边向紧邻下游发出一束柔紫色光线，保持高速行进和渐淡拖尾；不递归延伸到后续节点，运行结束后恢复普通连线。光束沿真实曲线路径前进，隐藏画布时暂停，并遵循系统减少动态效果设置。

默认布局采用左侧需求文档、中部需求分析、右上功能测试、右侧中下部 API／UI 测试及左下独立代码风险。功能测试分组默认定位为 (1050, -228)，与需求分析、API 和 UI 分组拉开纵向间距；需求分析分组默认定位为 (375, 211)，外框固定 560×320：第一行为材料整理与历史需求关联，第二行为需求评审（左）和仓库画像（居中偏右）。需求文档分别连入需求评审和材料整理，到材料整理的连线从出口上抬后在两行之间走线，不下绕穿过评审连线。历史用例核验在功能测试分组左下角，从历史需求关联跨分组连入。材料整理直接出线至历史需求关联与测试范围风险分析，并从右侧端口绕行连入仓库画像左侧。画像向 API 与 UI 分组出线。功能测试、API 测试与 UI 测试三条三阶段链路的外框均向右增加 96px、向下扩展至 280px 高。内部阶段卡片保持 126px 宽、至少 84px 高；功能测试按“测试需求分析左上、测试点中下、完整用例右上”，API 测试按“接口配置提取左上、接口用例设计中下、API 用例生成右上”，UI 测试按“元素控件清单左上、UI 用例设计中下、用例 YAML 右上”排列，连线依次连接；接口用例设计使用独立图标。派生用例图谱随功能测试外框右移到分组之外，初始视图计入其完整宽度。

需求分析分组使用固定的 560×320 外框，为两行卡片、拖动和连线留出空间；内部卡片尺寸及连线关系保持不变。

生成全景统一采用通透光泽方案：画布采用纯色底与清晰点阵（24px 间距、1.15px 点半径，沿用主题网格色并随画布平移缩放），卡片采用斜向光泽填充，运行卡片每 3 秒扫过一束表面高光；分类分组使用 2.2px 圆点虚线边框，以 10 秒周期缓慢流动，阶段卡片边框为 2px。分组隐藏时暂停边框动画，减少动态效果时静态展示。内部阶段卡片可拖动但限制在所属分组边界内，不自动撑大分组。需求文档仅展示入口卡片，移除“需求文档／只读来源”外层标题；代码风险保留独立链标题。二者外层容器透明且不画边框；连线端点贴合实际卡片边缘，未开始链的入线连接内部开始卡片，不连接分类外框；派生用例图谱继续位于功能测试分组右侧之外。

### UI 测试集执行流程画布

UI 测试集详情的左侧提供测试集和用例步骤两层流程画布，桌面端左侧图谱与右侧回放按约 7:3 分配宽度，窄屏沿用上下布局。右侧将执行回放、关键帧和控制台收在同一个外框中，保留截图回放、快照和日志操作。回放画面按测试集配置的视口宽高比自适应高度，截图完整显示；视口缺失时回退到 16:9。顶部面包屑显示测试集流程及当前用例步骤，用例选择、排序与新建都落在画布卡片上：点击用例卡片进入用例，拖拽卡片调整顺序，流程末尾的虚线「+ 添加用例 / + 添加步骤」卡片新增草稿用例或步骤。用例信息置于步骤画布上方，单击步骤节点后在画布下方编辑该步骤，可通过前后按钮切换。步骤配置面板采用紧凑高度并可折叠；点击步骤节点或遇到校验错误时展开，折叠不丢弃表单内容。其他步骤的表单状态和校验保留；校验失败时切换到相应步骤。运行及导入入口继续保留。画布使用 React Flow：节点可拖动摆放，通过连接点建立连线、拖动连线端点重新连接，选中连线可删除或还原。节点位置仅保存在当前浏览器，不决定执行顺序。

连线编辑是本地草稿；只有包含全部节点、无分支且无环的完整顺序可以应用。用例顺序应用后使用既有顺序更新接口，步骤顺序应用后仍需保存用例。连线不完整时提示实际执行顺序尚未更改；离开画布会丢弃未应用的连线。画布和状态使用项目主题 token，保持浅色与深色一致。
