# 基础服务 MCP 配置

入口为 `/base-services?tab=mcp`，工具栏提供“新增 MCP”。项目所有者填写服务名称、完整 MCP 地址，并选择 MCP 类型；当前仅支持“禅道（ZenTao）”，每项目可以新增多份，名称不可重复。创建不包含凭据，创建后通过卡片“授权”填写本人 Token；其他成员各自授权。未配置时显示空状态，创建窗口提供 [手动部署说明](../control-plane/zentao-mcp-deployment.md)。

页面部署说明引导用户复制 `deploy/zentao-mcp/` 的配置，编辑禅道目标和独立名称、端口后，直接执行 `docker compose pull` 与 `docker compose up -d`。模板使用已发布镜像，不要求 Python、平台 TOML 或镜像构建。

服务名称由所有者填写并可修改，MCP 类型创建后只读，当前只接受 `zentao`；旧服务名称原样保留。MCP 地址可由所有者填写或修改，保留完整端口、路径及末尾斜杠。实例地址只读，保存本人 Token 后从项目 MCP 读取。页面保存配置不会启动、重启或停止外部服务。

卡片分别展示本人授权、连接检查和实际实例。本人已配置授权不代表禅道业务权限有效；检查失败保留配置，并展示可理解的原因。具备本人授权时可刷新实例信息；检查过程中展示“检查中”。成员不能编辑地址或删除项目连接，撤销本人授权不影响其他成员。

内置 MCP 复用模型服务卡片的网格、尺寸、内边距和操作栏。顶部展示名称与本人授权，随后展示 MCP 地址、禅道实例、连接状态和最近授权时间。卡片不提供独立切换按钮；修改 MCP 地址或处理“需更新配置”时，在编辑服务中勾选复选框并保存，清理范围在表单中展示，避免提示内容撑高卡片。长地址省略并可悬停查看，浅色与深色共用布局。

MCP 地址必须从平台后端可达。容器中的后端不能用宿主机含义的 `127.0.0.1`；多项目推荐各自容器与端点，详见部署指南的地址表。

修改地址后需勾选“我确认切换禅道目标，并在需要时清除本项目旧绑定”，点击保存即核对新 MCP 并完成切换；再次修改地址会取消勾选，要求重新确认。已有混杂旧关联时，也可在编辑中勾选并保存当前地址。未勾选时禁止保存，服务不可达时原地址与关联保持不变。同一目标只迁移 MCP 地址时保留关联；目标变化或存在混杂历史时，清除本项目禅道绑定、测试单外部缺陷号、Bug 和附件推送关联，再重新绑定；旧推送记录留在 Bug 动态，原禅道数据、平台业务数据和其他项目保留。旧目标授权失效；明确为新目标保存的本人 Token 可保留。普通刷新、保存 Token 或删除连接不自动执行清理。

只有项目绑定弹窗选择 MCP；迭代、需求绑定、Bug 推送、附件和用例推送自动沿用项目绑定的选择。项目选择改变后清空待选远端项目，重新读取新服务候选。缺少该服务的本人 Token 时引导授权，不回退其他服务。项目绑定换到另一套禅道时显示清理确认复选框，勾选后才可保存；同实例更换 MCP 保留关联。所选服务删除时引导到项目绑定重新选择。Bug 与用例推送继续使用原业务入口、权限与失败处理，不绑定 AIWork 任务，也不自动写入 nanobot 配置。
