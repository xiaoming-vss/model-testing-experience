# AI 测试任务 Worker

本上下文负责接收平台派发的 AI 测试任务，并生成可回传平台的测试产物。它是拉取式 Worker，不监听端口。

## Language

**仓库源码**：
`ui_case_generate` 任务首阶段快照携带的单个前端仓库 pin（仓库、分支、冻结 commit）和 `gitlabCredentialsUrl`。Worker 使用本次 UI 发起人的个人 GitLab 凭据克隆该 commit，检出后的整个仓库目录是三阶段共用的源码根，`.git` 在交给模型前删除。
_Avoid_: 源码归档、源码 ZIP、源码包

**UI 测试用例**：
由 `ui_case_generate` 生成的可执行 UI 自动化用例；任务产物是 YAML 顶层列表，每一项均包含 `name`、`enabled`、`stepsJson` 和 `orderNo`。
_Avoid_: UI 用例 JSON、测试步骤列表

**用例编号**：
功能用例产物中的 `case_id`，由平台在生成校验通过后分配，UUID，跨所有用例集唯一，代表用例身份。修订时按「同模块 + 标题」→「同模块 + 内容」→「同模块 + 相对顺序」依次认回旧用例：编辑不改编号，只有用例被删除时其编号才随之消失，且永不复用。技能或模型输出的同名值一律丢弃。
_Avoid_: 模型生成的编号、集合内顺序编号

**系统默认技能**：
平台统一维护、所有项目自动可用的任务执行能力。项目成员不可修改，更新直接覆盖，不保留历史版本。
_Avoid_: 项目预置包、手工技能包

**技能按需获取**：
任务执行前获取当前阶段所需默认技能的过程。项目自定义技能本期不自动参与任务执行。
_Avoid_: 技能预置

**需求软件仓库关联**：
需求与软件仓库、工作分支、基线分支的关联，一个需求可关联多个软件仓库；代码风险分析按关联拉取固定 commit 的代码。基线分支在关联时必填，不再从历史迭代推断。
_Avoid_: 代码绑定、需求绑定

**任务租约**：
控制面按 started、heartbeat 和 progress 续租的执行权。Worker 以最后一次成功心跳或进度计算本地租约；连续心跳失败或租约到期后停止在下一个进度检查点并丢弃结果，由控制面租约回收结束尝试。
_Avoid_: 无限执行权、本地超时替代租约

**结果 outbox**：
完成回传失败时原子保存最终 `TaskResult` 的本地目录。只在租约仍有效时重试，不重新调用模型；过期结果仅保留诊断，不再投递。
_Avoid_: 结果重跑、模型输出缓存

**取消**：
AI 队列没有停止信号，Worker 不产生 `canceled`；该状态仅为控制面协议兼容保留。
_Avoid_: AI 任务取消、stopRequested

**代码工作区**：
每次代码风险分析 run 在任务 workspace 的 `runs/<attemptId>/code/` 下为每个关联软件仓库绑定的 Git 仓库检出固定 commit 的代码；模型通过只读工具在此工作区读取文件。成功 run 删除工作区，失败 run 保留 24 小时供排查。
_Avoid_: 共享代码目录、全局缓存

**仓库画像**：
人工运行的独立辅助任务，读取所选已审核材料整理版本和全部需求关联软件仓库，只 checkout 各仓库工作分支 HEAD，用只读工具判断仓库角色并输出固定 JSON。画像不进入生成链；UI 生成只消费其中的前端仓库角色、分支和 HEAD commit 作为源码选择依据，画像正文不注入任何下游 prompt。工作区成功删除、失败保留 24 小时。本条定义画像的内容、生成边界和输出结构；控制面任务字段与 Studio 展示引用本条。
_Avoid_: 代码风险画像、仓库分析报告

**不可分析仓库**：
仓库画像快照或工作区准备阶段无法解析授权、分支或 HEAD 的仓库；Worker 在结果中补为 `role=unknown`、`confidence=0`、`evidence=[]`，其他仓库继续分析。全部仓库不可分析时本次运行失败。
_Avoid_: 忽略仓库、部分成功

**上下文回执**：
代码分析 skill 就绪前，占位 prompt 要求模型回传的 YAML 结构；记录收到的仓库/HEAD commit、模型摘要、读取文件与使用工具，用于验证代码上下文确实送达模型，不代表正式风险结论。
_Avoid_: 风险报告、正式分析结果

**需求评审报告**：
需求分析首阶段生成的提示性结构化报告，由 Worker 生成。字段、评审语义和阶段边界以[控制面上下文](../control-plane/CONTEXT.md)的「需求评审报告」为准；报告只供人工判断，不阻断材料整理，也不传给下游阶段。
_Avoid_: 需求理解、材料整理结果

**材料整理结果**：
需求分析第二阶段整理并审核的结构化材料，保留业务流程、操作、交互、来源和问题；功能用例生成与代码风险分析复用该产物。需求分析包含提示性需求评审和材料整理两个相互独立的阶段。
_Avoid_: 增强文本

**测试点依据与覆盖复核**：
功能测试点生成后，以审核通过的材料整理结果和明确用户答复核对条件、结果与覆盖。需求分析是下游推导，不能单独补充材料未支持的事实；来源缺失、冲突或未确认的部分保留待确认。复核时带入此前意见供模型检查冲突，最多修订三次；仍不通过时，失败详情展示具体复核意见，候选不进入审核。复核由模型执行，结论仍需人工判断。

**继续优化图片**：
随阶段修订指令提交的 PNG/JPEG 截图，由控制面冻结在本轮尝试的输入快照中；Worker 按任务票据下载后作为多模态媒体输入，不进入生成产物正文。
_Avoid_: 需求材料图片、富文本图片

**现有测试内容**：
代码风险分析快照输入中，该需求下全部功能/API/UI 用例的定义与执行状态（API/UI 取最近一次 run）；模型据此判断影响面。
_Avoid_: 受影响用例（那是输出子集，勿与输入混用）

**受影响用例**：
风险分析报告中标出的、被代码改动影响的已有用例子集。
_Avoid_: 受影响测试、被影响用例

## 任务类型

`worker/dispatcher.py` 分派九种任务，未知类型返回 `不支持的任务类型: <type>`：

`requirement_analysis`、`functional_case_generate`、`api_case_generate`、`ui_case_generate`、`code_risk_analysis`、`repository_profile`、`test_report_generate`、`test_order_graph`、`test_order_case_visualization`

前八种是生成类任务，沿用候选、审核或运行结果协议。`test_order_case_visualization` 是单阶段辅助阅读任务：控制面读取执行条目冻结正文，Worker 通过 `mtx-analyze-case-visualization` 返回 `ready`、`partial` 或 `unsupported`，不进入候选审核或正式资产导入；其输入、输出上限和失败语义见[单条目图解任务](case-visualization.md)。该类型不是待删除的旧协议，而是当前受支持的辅助任务；移除前必须同时更新控制面任务创建、Worker 分派、默认技能和 Studio 入口。

`functional_case_generate` 的 `relation_analysis` 阶段为需求画布生成用例图谱。控制面冻结所选完整用例版本及其生成时使用的材料整理结果，首次生成和重新生成均只将这两份内容交给 `mtx-analyze-test-case-relations`。输出沿用关系协议 2.0。

`test_order_graph` 的图谱输入由控制端组装（需求、用例、需求用例关联）经 `configJson.graphInput` 传入，`cases[]` 字段名与 `mtx-analyze-test-case-relations` 的输入契约一致，因此不需要转换层。执行时使用 `update-test-case-graph` 按批次累积图谱。
