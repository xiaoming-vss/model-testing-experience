# 错误码规范

## 目标

错误码用于让调用方稳定识别失败类型，避免只能依赖错误文案做分支判断。

## 编号规则

- `0`：成功
- `42xxx`：参数错误
- `50xxx`：系统错误
- `51xxx`：禅道集成错误

后续如果业务模块继续扩展，建议按模块预留子区间，避免多人并行开发时冲突。

示例：

- `42000-42099`：通用参数错误
- `42100-42199`：项目模块参数错误
- `50000-50099`：通用系统错误
- `51000-51099`：禅道通用集成错误
- `51100-51199`：禅道项目模块错误
- `51200-51299`：禅道认证模块错误

## 当前已使用错误码

- `0`：成功
- `42000`：请求参数不合法
- `42200`：请求参数校验失败
- `50000`：系统内部错误
- `51001`：禅道配置不完整
- `51002`：禅道上游请求失败
- `51003`：禅道返回内容不合法

## 使用约定

- `message` 面向调用方，保持可读和稳定
- `errors` 用于补充字段级错误明细
- 不同模块新增错误码时，先在本文档登记区间
- 若只是错误文案不同，不要重复新增错误码
