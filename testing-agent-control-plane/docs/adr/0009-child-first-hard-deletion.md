# 业务资源逐级硬删除

删除接口实际移除数据库记录，释放名称和资源绑定唯一键；存在独立业务子资源时拒绝删除父级，要求用户先清理子级，避免一次操作隐式删除整棵业务资产。执行记录不构成删除前置条件，随所属用例、测试集或 AI 生成任务自动清理，候选生成结果、Worker 队列、用例规则及文件也属于附属数据；已导入的正式测试资产不随 AI 生成任务删除。

项目的迭代、环境、技能和共享服务，迭代的需求，需求的测试集/集合，以及测试集/集合的用例均须逐级删除；各层的资源绑定和独立 AI 任务也须先删除。测试报告任务是内部运行容器，随迭代清理。共享服务删除自动撤销所有个人授权并删除连接，单独撤销授权仅删除本人连接，保留共享服务。正在执行的记录和队列一并移除，旧 Worker 回传不得重新创建已删除数据。

后端返回 HTTP 409、提示及 `data.blockers`（资源类型、名称、数量）；业务父子外键使用 RESTRICT，附属执行数据使用 CASCADE 或同事务显式清理。可选 AI 归属和多态绑定通过父级行锁保护；文件在数据库提交成功后删除，回滚保留文件，文件删除失败记录日志供清理。

本决策取代 ADR-0003、0006、0007 中“当前接口软删除、删除后仍占用唯一键”的现状描述，落实 ADR-0006 的硬删除方向；初始化方式不变：冻结初始迁移，通过新增 `20260917_0008` 表达约束。随后通过 `20260917_0009` 移除 17 张业务表的 `deleted_at`、软删除模型及查询过滤，并去掉重复索引或改为业务字段索引。迁移在任何 DDL 前检查旧删除标记，发现未清理记录时拒绝执行，要求先明确归档清理；删除后重建使用新 ID。历史归档表保存原始快照，不参与业务查询。
