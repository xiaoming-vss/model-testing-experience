# 项目共享 GitLab 绑定模型

GitLab 绑定(项目↔群组、需求↔仓库+分支)是项目级共享资产:查询不过滤 `user_id`,项目内所有用户可见可用,任何项目内用户可把自己的连接接管到绑定上。控制平面没有成员模型(项目只有所有者),引入成员体系超出本轮范围,因此可见性边界定为「项目内所有用户」而非「项目成员」。

需求级绑定不携带 `connection_id`:GitLab 调用使用该仓库所属群组的项目绑定当前连接(接管后自动跟随);风险分析任务创建时把 `connection_id` 快照进任务、凭据按快照下发,保证同一任务可复现。配套约束:同一群组不允许重复绑定((项目, provider, 群组)唯一);删除群组绑定时若仍有需求绑定引用其下仓库,则阻止删除并返回受影响绑定清单。

**Considered Options**: 引入项目成员模型(范围大,邀请/角色/权限需另行设计);仅所有者可见(与共享需求矛盾)。此决策依赖平台当前无权限体系的事实,若未来引入成员/角色模型,应重新审视并以 superseded 状态更新本 ADR。
