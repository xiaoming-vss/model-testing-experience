# 项目成员与个人授权边界

项目采用所有者、普通成员、只读成员三种固定角色，由 PyCasbin 判断项目操作权限。业务资产在项目内共享，基础服务中的所有外部调用使用当前操作者自己的授权，覆盖 GitLab、禅道和 LLM；未授权时不可使用，也不能借用其他成员或所有者的凭据。

本方案取代 ADR-0002 的共享凭据与接管语义：项目绑定只表达外部实例及资源关联，其管理仅限项目所有者；实际访问通过操作者本人的同实例连接完成。代价是每位使用者需要配置自己的外部授权，收益是项目角色与外部个人权限边界保持独立，绑定不会扩张某个成员的外部权限。

每个项目保持唯一所有者，可转移给已有成员，原所有者变为普通成员；所有者退出或注销前须转移或删除项目。所有者无权管理他人的个人授权。

实施契约见 [项目协作与个人授权接口](../api/project-membership.md)，验收依据为 [功能规格](../../.scratch/project-membership/spec.md)。

实现保留 `projects.user_id` 为唯一所有者来源，`project_members` 只保存 member/viewer，避免所有者数据在两处同步。固定角色策略由 PyCasbin 评估，角色关系从当前数据库查询。每次 AI 阶段尝试记录实际请求人和本人连接引用，执行器下发前重新检查；公开 API 运行历史与加密执行输入分开保存。

资源身份包含外部服务实例；因此本功能调整 ADR-0006 中不含实例的绑定唯一键组成，仍保留其冻结初始迁移、新库初始化、规范数字 ID、软删除占用及并发保护要求。
