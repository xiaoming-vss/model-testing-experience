# 04 工单补充：以当前源码包作为 UI 用例生成来源

本附录补充“新增 UI 候选用例生成任务完整生命周期”工单，并以这里确认的规则覆盖原规格中泛化的来源描述。

## 已确认规则

- UI 生成任务的初版来源类型为 `source_archive`；后续 Git 拉取使用 `git_repository`，不属于本次范围。
- UI 生成任务必须绑定 `requirementId`，用于标识任务和运行归属的需求。
- 当前源码 ZIP 是必要生成来源；任务可以在缺包时保存为草稿，但缺少有效源码包时禁止运行。
- 如果绑定需求当前存在需求文档，它自动成为补充来源；没有文档不阻止运行，也不需要额外开关。
- 需求文档不冻结版本，AI Worker 获取时读取当前文档。
- 源码包通过独立接口上传或替换，任务只维护一个当前源码包。
- 运行不冻结源码版本。AI Worker 实际下载时获取任务当时最新的源码包；上传新版后旧包可以清理。
- 初版只接受 `.zip`，不支持 tar、tar.gz、rar 或 7z。
- 压缩包最大 100 MiB，解压后总大小最大 1 GiB，最多 50,000 个文件。
- 拒绝绝对路径、`..` 路径穿越、符号链接和重复路径。
- 校验失败不得创建或替换任务当前源码包。
- 控制平面只做 ZIP 安全与容量校验，原样保存压缩包并按原始字节计算 SHA-256，不清理或重打包内容。
- 任务详情使用独立 `sourceArchive` 对象返回源码包 ID、文件名、大小、SHA-256 和上传时间；`sourceContent` 为空。
- 普通用户只能查看源码包元数据并上传替换，不提供源码包下载接口，也不暴露服务器存储路径。
- AI Worker 使用现有 Worker Token，通过与 Worker 任务绑定的内部接口下载当前源码包。
- 控制平面只负责上传、存储、任务关联、元数据和下载契约；Worker 如何解压、筛选、分析源码、生成步骤或校验哈希不属于 04 工单。

## 04 工单新增验收标准

- [x] `sourceType=source_archive` 的 UI 任务必须绑定 `requirementId`。
- [x] 用户可通过独立接口上传或替换任务当前源码 ZIP。
- [x] 缺少有效源码包的任务可以保存，但运行请求被明确拒绝。
- [x] 上传严格执行格式、压缩大小、解压大小、文件数和 ZIP 条目安全限制。
- [x] 校验失败保持原任务源码包不变；成功后保存原始字节及 SHA-256。
- [x] 任务详情返回 `sourceArchive` 元数据对象，且不返回存储路径或用户下载地址。
- [x] 已创建的运行在 AI Worker 下载时取得任务最新源码包，而不是运行创建时的源码版本。
- [x] 绑定需求存在当前文档时可供 Worker 获取；文档缺失不阻止运行，文档更新后读取当前版本。
- [x] 源码包和需求文档下载接口均受 Worker Token 与任务归属校验保护。
- [x] 应用 HTTP 契约测试覆盖所有权、上传替换、缺包运行、ZIP 安全边界、最新包下载和可选需求文档。

## 不在范围内

- Git 仓库地址、分支、提交、凭据或 Worker 自行拉取源码。
- 为运行保存或冻结源码包版本。
- 为运行保存或冻结需求文档版本。
- 普通用户下载已上传源码包。
- AI Worker 内部的源码分析实现。
